## Question

Design an answer engine: a user types a question and gets a cited, streamed answer. Your end-to-end budget is 3 seconds to a complete short answer.

## Brief answer

Use parallel search, bounded reranking, compact evidence, and fast generation, with a strict deadline controller. A three-second complete-answer target requires short outputs and a measured tail-latency budget; streaming improves perceived responsiveness but does not by itself meet the completion deadline. Unsupported or late evidence must produce a qualified response rather than fabricated citations.

## Detailed answer

**Suggested approach.** An illustrative budget is 100 ms ingress/query routing, 500 ms parallel lexical/dense search, 250 ms reranking, 350 ms prefill, 1,500 ms decoding, and 300 ms transport/slack. These are design allocations, not measured service performance. At 80 tokens/second, the decoding allocation permits roughly 120 output tokens.

Cache immutable source representations and common safe queries, and overlap independent retrieval branches. Use a deadline-aware fallback from expensive reranking to a cheaper scorer. Generate source IDs from retrieved evidence and resolve citations in code. Check claim support before releasing sensitive factual statements; post-hoc correction cannot fully retract already streamed misinformation. Test cold caches, breaking news, conflicting sources, overloaded workers, and long queries. Report deadline success and supported-answer rate jointly so latency optimizations do not hide quality loss.

### Coordinate deadlines and evidence

Carry one absolute deadline through every stage. A retrieval branch finishing after the evidence cutoff must not mutate a prompt whose generation has already started. The coordinator can accept a bounded partial candidate set if it still covers the query, or return an explicit limited answer if the missing branch is essential. A queue that waits indefinitely for a “better” reranker undermines the three-second contract.

For a short factual question, retrieve and verify a small evidence bundle before decoding. Stream complete claim segments, keeping the evidence IDs attached internally. If verifying every claim before release exceeds the budget, reduce answer length or the supported task scope; changing the UI to stream does not remove the verification work.

Capacity planning must include bursts and cold starts. Measure completion latency jointly with supported-answer success under the intended concurrency, rather than summing isolated stage benchmarks. Cache hits can improve the median while misses dominate the tail. Track both paths separately and provide admission control so overload becomes a bounded failure rather than a queue that violates every request's deadline.
