## Question

When would you put a whole contract in the context window instead of retrieving over it? Defend the answer with numbers.

## Brief answer

Use whole-contract context when the document comfortably fits the usable budget, the question needs broad interactions, and measured quality and latency justify the cost. Use retrieval for larger collections, repeated narrow questions, or tight latency limits. Compare total workload cost and evidence coverage instead of treating the advertised context window as usable capacity.

## Detailed answer

An illustrative 200-page contract at 500 words/page and 1.3 tokens/word is about 130,000 tokens, before instructions, exhibits, definitions added separately, and output. On a hypothetical \$2/million-input-token model, one uncached pass costs about \$0.26 in input alone. Eighteen independent passes cost about \$4.68 before outputs and retries; those are arithmetic examples, not current provider prices.

A 12,000-token retrieved context would cost \$0.024 per pass at the same assumed rate, but missing a decisive clause can make it unacceptable. Test both approaches on dependency-heavy questions and include caching, extraction quality, prefill latency, and review time. Whole-context reading still needs citations and completeness checks; fitting the text does not guarantee the model attends to every qualification.

### Compare an entire workload

The relevant alternative is not always eighteen uncached full-document calls versus eighteen independent retrieval calls. A shared prefix cache or a single structured pass answering several checklist items can amortize full-document reading. Conversely, a cache miss after an amendment may require another expensive prefill. Model those paths using their observed frequency rather than assuming every request receives the best cache rate.

For an advertised 128,000-token window with 8,000 reserved for instructions and output, only 120,000 tokens remain for the contract. The illustrative 130,000-token document does not fit, even before exhibits. On a larger-window model it may fit, but measured evidence coverage and latency still decide whether full-context reading is useful.

Choose full context for a bounded agreement when interactions across many provisions are essential and tests show it improves review quality. Choose retrieval for narrow repeated queries across a large room, with explicit expansion for definitions and amendments. Include the cost of a reviewer finding a missed exception: lower token spend is not an overall saving if it materially increases consequential omissions or manual rework.
