## Question

How much VRAM is needed for full fine-tuning?

## Brief answer

Full fine-tuning memory includes weights, gradients, optimizer states, activations, and runtime buffers; parameter count alone is insufficient.

## Detailed answer

A common mixed-precision Adam estimate is 16 bytes per parameter: 2 for BF16 weights, 2 for BF16 gradients, 4 for an FP32 master copy, and 8 for two FP32 moments. Calculated example: 7 billion parameters need about 112 GB, or 104 GiB, for those states alone. Frameworks that store gradients or master weights differently have different totals.

Add activation memory, temporary kernels, communication buffers, and allocator headroom. Activation checkpointing, FSDP/ZeRO sharding, and offload change the per-GPU requirement; GPU capacities cannot simply be summed without a suitable parallel strategy. Profile the intended sequence length and microbatch.

Separate persistent state from tensors whose size depends on the batch. The parameter-state estimate is roughly fixed for a chosen optimizer and precision scheme. Activations depend strongly on microbatch size, sequence length, hidden width, number of layers, and which tensors are retained for backward. Increasing sequence length can therefore cause an out-of-memory error without changing model parameter count.

Gradient accumulation lets several small microbatches contribute to one optimizer update, reducing activation memory relative to one large microbatch. It does not remove parameter, gradient, or optimizer storage. Activation checkpointing discards some forward intermediates and recomputes them during backward, trading compute for memory. Sharding distributes states but introduces communication and transient all-gather buffers.

For the 7B estimate, 112 GB is a decimal byte count; dividing by $2^{30}$ gives about 104.3 GiB. It is not a complete single-device requirement or a claim that four nominal 28 GB devices suffice. Check the framework's state layout, largest transient allocation, and actual memory after warmup. Run a representative forward/backward/update step with the intended sequence lengths before committing to hardware or parallelism.
