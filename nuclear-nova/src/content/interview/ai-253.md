## Question

Design an on-prem deployment of an open-weight model for a European bank that cannot send data to any external API.

## Brief answer

Deploy the entire data path inside the approved environment: model inference, embeddings, retrieval, telemetry and administrative tooling. Treat disconnected operation as an architectural requirement, including updates and failure recovery, rather than merely changing the model endpoint.

## Detailed answer

Inventory outbound dependencies such as package registries, model downloads, license checks and external logging. Import signed, scanned artifacts through a controlled process and pin all versions. Integrate the bank's identity system, per-document authorization, encryption/key ownership and audit retention. Benchmark its actual GPU fleet for model weights, KV cache, failover headroom and workload peaks. Define patch delivery, offline evaluation and rollback before launch. An open-weight license does not automatically establish regulatory compliance; the bank's legal/security owners must determine applicable obligations. Use synthetic data for initial validation and enforce the no-external-API boundary with network controls.

### Build the disconnected operational path

The bank's gateway authenticates users through internal identity services. Retrieval applies document permissions, local embedding/reranking services prepare evidence, and an internal model pool generates responses. Tool execution goes through narrowly scoped internal APIs, with audit records kept under the bank's access and retention controls. No component should silently use an external fallback.

Package weights, tokenizer, runtime, container images, dependencies, and configuration into a verified release bundle. Test installation and startup with outbound networking disabled, including error paths that might otherwise contact telemetry or model registries. Size for peak demand and one failed replica, not just a successful single request. Define who imports security patches, refreshes documents, validates a new model, and restores backups. Use a representative offline evaluation suite and a rollback bundle. The engineering design enforces the stated data boundary; compliance decisions and approved retention or operational rules must be supplied by responsible bank owners, not inferred from the model being open weight.
