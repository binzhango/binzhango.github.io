## Question

How to improve prompt representativeness?

## Brief answer

Make prompts representative by sampling the actual deployment distribution and deliberately covering important rare cases.

## Detailed answer

Build a coverage map across tasks, languages, user expertise, context lengths, ambiguity, and output formats. Use appropriately handled real usage examples when available, then add targeted cases where coverage is weak. Preserve natural imperfections such as incomplete requests instead of polishing every prompt into an ideal benchmark question. Evaluate both traffic-weighted performance and critical slices so common easy requests do not conceal consequential failures.

Representativeness has two goals that should be measured separately: matching common traffic and covering important failures. Sample a traffic-weighted development set to estimate ordinary user outcomes. Maintain an additional challenge set for rare but consequential cases, such as ambiguous units, contradictory documents, and malformed tool outputs. A single aggregate score can hide poor performance on the latter.

For a coding assistant, cover short bug reports, complete stack traces, missing dependencies, unfamiliar repositories, and requests with inconsistent requirements. Real users may provide fragments, typos, or irrelevant context. If training prompts are all polished and explicit, the model may not learn when to ask a focused clarification.

Build a coverage matrix and count independent examples in each cell rather than only total rows. Inspect whether one source supplies nearly all difficult examples or one template dominates a task. Use source-level splits and refresh the sample when usage changes. Avoid manufacturing demographic or behavioral assumptions without evidence; collect the dimensions relevant to the actual workflow and test whether performance differences lead to actionable improvements.
