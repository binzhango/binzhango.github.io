## Question

Compare LoRA, prefix tuning, prompt tuning and full fine-tuning. When would you choose each?

## Brief answer

Prompt tuning learns input embeddings; prefix tuning learns additional conditioning states; LoRA modifies selected linear operations through low-rank updates; full fine-tuning updates the backbone. Choose by task capacity, memory, serving support and measured quality.

## Detailed answer

Soft prompts and prefixes are compact but consume context or attention work and may be less effective for some model/task sizes. LoRA offers a useful capacity/storage compromise and can sometimes be merged into compatible base weights. Full tuning has the broadest update freedom but needs much more optimizer memory and checkpoint storage. Benchmark equal-quality serving cost, not just the number of trainable parameters; adapter dispatch and multi-tenant loading can dominate deployment complexity.

Prompt tuning adds learned virtual token embeddings to the input. Prefix tuning injects learned conditioning, often at multiple attention layers. Both keep backbone weights unchanged but occupy attention context and require the serving engine to handle the learned states. LoRA instead changes selected linear maps through low-rank updates; full tuning can change every model parameter.

For many small tenant-specific style adaptations, compact prompts or adapters simplify storage compared with keeping a complete model copy per tenant. For a difficult domain shift with sufficient high-quality data and compute, full tuning may offer needed capacity. These are hypotheses to test: a large model can respond well to a small soft prompt, while a smaller model may need a more expressive update.

Measure training peak memory, artifact size, target quality, general capability retention and inference overhead. A method with fewer trainable parameters can still use large activation memory and add per-request work. Adapter multiplexing may reduce storage but complicate batching when concurrent requests use different weights. If a merged LoRA model meets quality and latency targets, it can be operationally simpler than loading adapters dynamically. Choose the least complex method that clears the quality requirement under the actual deployment constraints.
