## Question

Build a function that fetches paginated data from a REST API, handling page size and total-page logic.

## Brief answer

Fetch each page using the API's documented pagination contract, validate its metadata, and stop according to a stable snapshot or cursor. Respect page size and rate limits, and preserve errors rather than returning a silently partial dataset. Page-number APIs can skip or duplicate records if the underlying collection changes during traversal.

## Detailed answer

This synchronous core injects the HTTP adapter for testing. The adapter returns `{'items': [...], 'total_pages': int}` and is responsible for bounded timeouts and permitted retries. The core fails if total-page metadata changes, prompting the caller to retry against a snapshot where supported.

```python
def fetch_all(fetch_page, page_size=100, max_pages=10000):
    if page_size < 1 or max_pages < 1:
        raise ValueError('invalid limits')
    first = fetch_page(page=1, page_size=page_size)
    total = first['total_pages']
    if not isinstance(total, int) or isinstance(total, bool) or not 0 <= total <= max_pages:
        raise ValueError('invalid total_pages')
    if total == 0:
        if first['items']: raise ValueError('inconsistent empty result')
        return []
    result = list(first['items'])
    if len(result) > page_size: raise ValueError('oversized page')
    for page in range(2, total + 1):
        data = fetch_page(page=page, page_size=page_size)
        if data['total_pages'] != total or len(data['items']) > page_size:
            raise ValueError('pagination changed')
        result.extend(data['items'])
    return result

pages = {1: {'items': [1, 2], 'total_pages': 2}, 2: {'items': [3], 'total_pages': 2}}
assert fetch_all(lambda page, page_size: pages[page], 2) == [1, 2, 3]
```

Time and memory are O(number of returned items); expose a page iterator for larger datasets. Test empty results, exact page boundaries, metadata changes, HTTP failure on a later page, and invalid limits. Prefer cursor/snapshot pagination when available; deduplication alone cannot recover skipped records.

### Pagination needs a consistency contract

The first response establishes the page count, and each later response must agree. For page size two and pages [1,2], [3], the result is [1,2,3]. A zero-page response must contain no items. The `max_pages` bound prevents an erroneous server value from causing an effectively unbounded request loop.

Stable `total_pages` does not prove stable contents: an insertion on page one can shift items between later pages without changing the total. Prefer a snapshot token or cursor tied to a consistent ordering when the API supports it. If only page numbers exist, document that limitation, use stable IDs for duplicate detection, and recognize that skipped records remain possible. The injected adapter should set timeouts, honor rate limits, and retry only safe reads with bounded backoff. A later-page failure raises rather than returning a misleading complete result. For very large datasets, yield pages or items to a consumer so memory stays bounded, while preserving a clear partial-progress/restart contract.
