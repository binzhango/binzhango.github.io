## Question

What does the term ‘out-of-core learning’ refer to in machine learning?

## Brief answer

Out-of-core learning processes data in chunks because the full dataset does not fit in RAM.

## Detailed answer

A typical pipeline streams records, computes features with bounded memory, and updates an incremental estimator. The feature representation must remain consistent across chunks; fitting a new vocabulary independently on every chunk would break this contract. Mini-batch training enables out-of-core processing only if loading, preprocessing, and caching also avoid materializing the full dataset.

The memory budget must cover an entire pipeline, not just the estimator. Imagine a 200 GB log collection and 16 GB of RAM. Read a bounded block, parse it, transform features, update the model, and discard the block before reading the next. A hashing representation can keep the feature dimension fixed without storing an ever-growing vocabulary. An incremental linear classifier can update its coefficients through `partial_fit`; a conventional estimator whose `fit` requires the full matrix cannot simply be substituted.

Some preprocessing needs an additional pass. For standardization, first accumulate counts, means, and variances, then transform chunks using those fixed statistics during training. Alternatively, deliberately use an online procedure and account for its changing state. Repeated passes may improve optimization but increase disk traffic.

Order matters when adjacent chunks come from different dates or categories. Shuffle within a bounded buffer or interleave sources where appropriate. Keep a separate holdout stream, record the last consumed position for recovery, and distinguish learning from finite data on disk from adapting continuously to a changing live distribution.
