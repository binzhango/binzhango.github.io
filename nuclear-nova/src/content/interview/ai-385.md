## Question

Implement a streaming top-k with a bounded-memory sketch; implement a sliding-window rate counter.

## Brief answer

Use a fixed-size frequency sketch for count estimates plus a bounded candidate set for heavy hitters, and use time buckets for an approximate sliding-window counter. A sketch alone cannot enumerate unknown top keys. Define the approximation: the example retains Misra–Gries candidates and uses one-second buckets, so the rate window is discrete rather than an exact continuous-time interval.

## Detailed answer

This runnable standard-library implementation assumes nondecreasing integer timestamps and counts the last `seconds` buckets, including the current one.

```python
from collections import deque

class HeavyHitters:
    def __init__(self, capacity):
        if capacity < 1: raise ValueError("positive capacity")
        self.capacity, self.counters, self.total = capacity, {}, 0

    def add(self, key):
        self.total += 1
        if key in self.counters:
            self.counters[key] += 1
        elif len(self.counters) < self.capacity:
            self.counters[key] = 1
        else:
            for item in list(self.counters):
                self.counters[item] -= 1
                if self.counters[item] == 0: del self.counters[item]

    def candidates(self):
        return sorted(self.counters.items(), key=lambda item: -item[1])

class WindowCounter:
    def __init__(self, seconds):
        if seconds < 1: raise ValueError("positive window")
        self.seconds, self.buckets, self.total, self.last = seconds, deque(), 0, -1

    def count(self, now, increment=0):
        if not isinstance(now, int) or now < self.last or increment < 0:
            raise ValueError("ordered integer time and nonnegative count required")
        self.last = now
        while self.buckets and self.buckets[0][0] <= now - self.seconds:
            self.total -= self.buckets.popleft()[1]
        if increment:
            if self.buckets and self.buckets[-1][0] == now:
                self.buckets[-1][1] += increment
            else: self.buckets.append([now, increment])
            self.total += increment
        return self.total

h = HeavyHitters(2)
for key in 'aaaaabbc': h.add(key)
assert h.candidates()[0][0] == 'a' and len(h.counters) <= 2
w = WindowCounter(3)
assert w.count(10, 2) == 2 and w.count(11, 3) == 5
assert w.count(13) == 3 and w.count(20) == 0
```

Misra–Gries uses bounded counters and retains every item with frequency greater than $N/(m+1)$, but its remaining counts are underestimates and not an exact top-k order. Use a second pass for exact candidate counts when available. The window counter stores at most one bucket per second in its window; continuous-time boundaries need finer buckets or per-event storage. Both examples require synchronization if shared across threads.

### Two bounded-memory mechanisms

Misra–Gries cancels groups of distinct items when all counters are occupied. Any item frequent enough cannot be completely canceled, which yields the stated threshold guarantee. Its remaining count is a lower bound, so sorting counters returns candidate order rather than a certified exact top-k. With capacity m, memory is $O(m)$ and the simple decrement-all step costs $O(m)$; most updates are constant time.

The window counter aggregates all events in one integer-second bucket, then removes buckets at or before `now - seconds`. For a three-second window queried at 13, it includes timestamps 11, 12, and 13 and excludes 10. Each bucket is inserted and removed once, giving amortized constant-time updates and at most O(seconds) buckets. The integer-bucket definition differs from an exact continuous-time rolling window. Out-of-order events are rejected here; a distributed event-time implementation would need watermarks, late-arrival policy, and deduplication rather than feeding arbitrary timestamps into this class.
