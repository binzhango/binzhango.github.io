## Question

Low-level design: sketch the classes and interfaces for the tool-calling layer of an agent host, where tools can come from native code, an OpenAPI spec, or an MCP server.

## Brief answer

Suggested approach: Use one typed tool contract with adapters for native functions, OpenAPI operations, and MCP servers. Keep authorization, argument validation, execution deadlines, and audit logging in the host rather than duplicating them inside each adapter. The model proposes tool calls; the host decides whether a call is permitted and how its result is represented.

## Detailed answer

A minimal interface separates description from execution:

```python
from dataclasses import dataclass
from typing import Any, Protocol

@dataclass(frozen=True)
class ToolSpec:
    name: str
    input_schema: dict
    output_schema: dict
    side_effecting: bool

@dataclass(frozen=True)
class CallContext:
    principal: str
    deadline: float
    idempotency_key: str

class ToolAdapter(Protocol):
    spec: ToolSpec
    async def invoke(self, arguments: dict, context: CallContext) -> Any: ...
```

A registry resolves versioned names. An executor validates JSON schema, checks principal and resource scope, requests required confirmation, invokes with cancellation, and validates/truncates results. Native adapters call code; OpenAPI adapters construct constrained HTTP requests; MCP adapters negotiate the server protocol and map errors. Never let arbitrary model text select a network origin or credentials.

Classify errors as invalid arguments, denied, transient, or permanent. Retry side effects only with verified idempotency; a timeout is an unknown outcome, not proof of failure. Treat tool descriptions and returned text as untrusted data. Application permission policy remains the host's responsibility.

### Trace one call through the interfaces

A model proposes `calendar.create_event.v2` with a title, time, and attendees. The registry returns its schema and adapter. The executor parses arguments, resolves the caller's identity, checks allowed calendar scope, validates time zones and attendee IDs, and obtains any required user approval. Only then does the adapter receive credentials scoped to that operation. The returned event ID is validated and recorded with the idempotency key.

Separate `ToolError` categories from raw transport exceptions so the planner can repair arguments without retrying a forbidden action. A registry should reject name collisions and incompatible schema updates rather than silently routing to a different tool. Store discovery metadata with a trust boundary: an MCP server's description is not permission to access another server's credentials. For OpenAPI, preconfigure origins and operation mappings instead of permitting arbitrary URLs. Test timeout after successful creation, schema drift, malicious result text, and cancellation; each should preserve a verifiable action history.
