## Question

What matters more for an agentic coding tool like Claude Code: the model or the harness? Design the loop.

## Brief answer

The model supplies reasoning and coding ability; the harness determines what context it sees, which actions it may take and how errors are detected. Neither substitutes for the other. Build the loop around observable repository state, bounded tool execution and verification, then compare model and harness changes independently on the same representative tasks.

## Detailed answer

Suggested loop: inspect the request and repository, gather relevant files, formulate a small change, execute an allowlisted tool, observe the result, run targeted verification and decide whether to continue or report. Keep tool outputs separate from trusted instructions. Persist enough state to recover from interruption and avoid repeating side effects.

The harness controls context selection, diff size, command timeouts, sandbox boundaries, permissions and test feedback. A stronger model may need fewer attempts, but poor retrieval can hide the relevant function and permissive execution can damage unrelated work. Conversely, a polished harness cannot make a model understand an algorithm it consistently gets wrong.

Evaluate task completion, regression rate, unnecessary edits, total latency and cost. Use an ablation matrix: fixed model with different harnesses, then fixed harness with different models. Report failures such as test overfitting, destructive commands and unsupported completion claims, rather than reducing quality to the number of tool calls.

A concrete failure decomposition makes the comparison useful. If the agent edits the wrong file because retrieval missed the implementation, changing the model may not solve it. If it finds the right function but repeatedly produces an incorrect algorithm despite clear tests, the model is a likely bottleneck. If it overwrites user work or retries a destructive command, the execution harness needs stronger boundaries regardless of model capability.

Keep the loop state explicit: current objective, files inspected, hypothesis, edits made and verified results. Tests should return concise failures with stable artifact references, not an unbounded terminal dump. A passing visible test should trigger diff review and relevant regression checks, since an agent can overfit the immediate assertion.

Use hidden tests and tasks requiring multi-file reasoning, dependency diagnosis and recovery after failed attempts. Compare total successful task cost, not just first-attempt accuracy or token price. The model and harness interact, so the best combination may differ by repository and task distribution; the ablation matrix reveals those interactions without relying on anecdotes.
