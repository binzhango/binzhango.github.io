## Question

If a model performs well on training data but poorly on unseen data, what issue is occurring, and how might you address it?

## Brief answer

A large training-to-test gap often indicates overfitting, but distribution shift or a pipeline mismatch can produce the same symptom.

## Detailed answer

First evaluate untouched data drawn from the training distribution. If performance is already poor there, consider regularization, earlier stopping, deduplication, or more representative examples. If that holdout works but production-like data fails, investigate domain shift. Also check preprocessing consistency, label definitions, and group or time leakage. Simplifying the model is one possible remedy, not a universal fix.

Use three comparisons rather than applying regularization immediately. Measure training performance, a clean holdout from the same data source, and a holdout representing deployment. If training accuracy is 99% and same-source holdout accuracy is 75%, inspect model complexity, effective dataset size, and near-duplicate handling. If both are 95% but deployment is 70%, a shifted vocabulary, sensor, population, or labeling policy is more plausible.

Learning curves help choose a remedy. A large generalization gap that narrows as more independent examples are added suggests additional data could help. Training and validation errors that are both high suggest underfitting or inadequate input information. Early stopping chooses a checkpoint before validation begins deteriorating; regularization constrains the fitted solution; augmentation teaches selected invariances.

Do not tune directly against the final holdout while investigating. Create a development set for repeated decisions, preserve the test set, and check whether the proposed fix helps important subgroups. A reduced training score can be acceptable if deployment performance and calibration improve.
