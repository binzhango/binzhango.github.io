## Question

What are prompt templates and prompt values?

## Brief answer

A prompt template fills named variables into a reusable text or message structure; a prompt value is the formatted result passed to a model.

## Detailed answer

A chat template can preserve system, user, and assistant roles instead of concatenating everything into one string. Validate required variables and keep user content separate from application instructions. Formatting does not enforce instruction priority or prevent prompt injection. Budget tokens after formatting, especially when inserting history and retrieved documents. The tokenizer's model-specific chat template is a separate serialization layer from an application prompt template.

Suppose an application template contains a task instruction, a `question` variable, and an `evidence` variable. Formatting substitutes those values while preserving their intended roles and boundaries. The resulting prompt value is the concrete text or message sequence for this request. A separate model-specific chat serializer then turns those messages into the token pattern expected by the checkpoint.

Keep untrusted excerpts as clearly labeled data. A document saying “ignore prior instructions” should remain evidence text, not become a new system instruction merely because it was inserted into a template. Delimiters help the model interpret boundaries, but the application must still enforce permissions and validate outputs independently.

Inspect the fully formatted prompt, including history, demonstrations, and retrieved passages. It can exceed a token budget even when every individual variable looks small. Reserve room for the answer and define a deterministic truncation or selection policy that preserves required facts. Validate missing variables and unexpected types early. Good templating makes requests consistent and testable; it does not guarantee factuality, eliminate prompt injection, or compensate for poor evidence.
