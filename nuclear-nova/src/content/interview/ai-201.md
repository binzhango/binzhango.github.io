## Question

Design the training setup for a model that doesn't fit on one accelerator, say 70B parameters on a pod.

## Brief answer

Budget parameters, gradients, optimizer states and activations separately, then combine sharding and parallelism according to the cluster interconnect. A 70B model cannot be sized from weights alone: mixed-precision Adam training can require roughly a terabyte of model states before activations, depending on implementation. Use activation checkpointing and microbatching to fit the remaining memory.

## Detailed answer

An illustrative state budget with BF16 weights and gradients plus FP32 master weights and two FP32 moments is 16 bytes per parameter: 70 billion parameters imply 1.12 TB decimal. Some implementations store different copies, so inspect the actual optimizer and sharding behavior rather than treating this as a universal constant.

Shard model states with FSDP/ZeRO-style methods, use tensor parallelism across fast links for large matrix operations, and add pipeline parallelism when layers must span devices. Data parallelism then scales independent batches. Choose microbatch count to balance pipeline bubbles, activation memory and global batch requirements.

Profile communication overlap, network topology, checkpoint I/O and data-loader throughput. Test numerical equivalence on a small model and recover from an interrupted distributed checkpoint. More devices can reduce per-device memory while increasing synchronization overhead; report goodput and convergence, not only nominal device count.

ZeRO describes partitioning optimizer state, gradients and parameters to reduce redundant memory across data-parallel workers.

Choose parallelism from a per-device memory ledger and communication map. Sharding optimizer moments can save substantial redundant state, but parameter all-gathers may add traffic. Tensor parallelism reduces individual matrix sizes while requiring frequent collectives; pipeline parallelism distributes layers but creates bubbles if too few microbatches are available. Activation checkpointing saves stored tensors by recomputing them during backward.

For a fixed global batch, increasing device count can reduce local microbatch size until kernels and pipelines become inefficient. Conversely, increasing global batch to fill devices changes optimization and may require a new learning-rate schedule. Benchmark time to the desired validation quality, not merely tokens per second.

Checkpoint parameters, optimizer state, scheduler, RNG and data position consistently across shards. Test restore on a small run and verify that subsequent loss behavior matches expectations. Data loading, checkpoint storage and network topology need capacity alongside GPUs. A training job that fits in aggregate accelerator memory can still fail because one pipeline stage or expert shard has a higher peak than the average.
