## Question

A user says “send Maya the photos from Saturday's hike.” Design the on-device path from that utterance to a structured app action with resolved parameters.

## Brief answer

Suggested approach: parse the request into an action schema, resolve “Maya” and “Saturday's hike” using authorized local data, present the resolved recipients and photos, and send only after the required confirmation. A valid tool call is the final representation of a grounded decision, not evidence that ambiguous entities were resolved correctly.

## Detailed answer

Use the user's timezone and calendar context to interpret Saturday, then query the photo library using date, location, and image metadata or local embeddings. Resolve contacts through stable IDs and conversation context. If multiple Mayas or hikes match, ask a targeted clarification instead of guessing.

The action gateway checks photo permissions, sharing destination, account, and message scope. Build a preview showing exactly which assets will leave the device. Execute with a transaction or idempotency key and verify the send receipt; a timeout requires status reconciliation before retry. Keep the model away from unrestricted contact or photo export APIs. Test missing permissions, duplicate contacts, edited timestamps, offline operation, and partial upload failures.

### Resolve ambiguity before constructing the send

Convert the utterance into intent fields: action=share photos, recipient=Maya, event=Saturday's hike. Resolution services map these natural-language fields to stable contact and asset IDs. “Saturday” depends on the user's timezone and conversational reference date; “Maya” may identify several contacts. The model should request the smallest missing distinction, such as which Maya, instead of exposing a broad contact list.

The execution plan contains selected photo IDs, destination account, recipient ID, and a preview of what will be shared. Validate permissions immediately before execution and record the resulting upload/send receipt. If three of five photos upload before failure, reconcile the partial result rather than repeating all five blindly. Search and model inference can remain local, while the eventual send is an explicitly authorized external action. Test burst photos, screenshots, edited timestamps, deleted assets, and a contact renamed between planning and execution. The final response should describe the actual delivered set, not the intended one.
