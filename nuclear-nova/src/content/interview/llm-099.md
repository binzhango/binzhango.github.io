## Question

What are key aspects of training data?

## Brief answer

Training data must have correct targets, representative coverage, useful diversity, consistent formatting, and reliable provenance.

## Detailed answer

Quantity is only one dimension. Duplicates change example weighting, long answers can dominate token-level objectives, and contaminated benchmarks produce misleading progress. Track task mixtures, lengths, label quality, and source overlap. Ensure each example teaches the intended behavior: a well-written answer that ignores the supplied context can train the wrong habit for a grounded assistant.

Data quality includes the relationship between prompt and answer. In a grounded task, an answer may be factually plausible but unsupported by the supplied evidence; training on it teaches the model to ignore the evidence. In a coding task, syntactically valid code may violate a constraint or fail boundary cases. Review targets against the requested operation, not only fluency.

Mixture and duplication determine effective weighting. If one source appears in ten near-identical copies, it receives more optimization pressure than a unique example elsewhere. Under token averaging, longer responses contribute more targets, so a small number of verbose tasks can dominate the objective. Track those quantities rather than only row counts.

Inspect rare but important cases: missing inputs, ambiguous instructions, conflicting sources, tool errors, and requests outside scope. Split related records together, remove evaluation contamination, and preserve provenance for later corrections. Use automated structural checks plus sampled semantic review; neither alone covers all errors. The practical goal is a dataset whose supervision reflects the behavior you want under the situations the model will actually encounter.
