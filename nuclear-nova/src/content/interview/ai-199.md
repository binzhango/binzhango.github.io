## Question

You have a binary loan-approval classifier and limited access to feature weights. How do you explain a rejection?

## Brief answer

Explain the actual decision rule and the factors supported by available evidence; do not invent a causal explanation from inaccessible weights. A local surrogate or counterfactual can help investigate behavior, but it is an approximation whose fidelity must be checked. In a real lending workflow, authorized compliance and model-governance teams must validate the required explanation process.

## Detailed answer

Suggested technical approach: recover the exact input features, preprocessing, model version, score and threshold for the decision. Verify data accuracy and distinguish a policy rule from the learned model's score. If a transparent model or approved reason-code system exists, use its documented mapping rather than generating prose from intuition.

With query access, test plausible feature perturbations and compare local surrogate predictions with the original model. Counterfactuals should respect feasible changes and dependencies; changing an immutable attribute or independently altering correlated variables can produce misleading advice. Feature attribution describes a model's behavior under assumptions, not the causal effect of changing a person's circumstances.

Report uncertainty and route disputed or consequential cases to the designated review process. The interview answer should emphasize faithful evidence and correction paths. It should not promise that SHAP, LIME or a language-model explanation automatically satisfies legal or fairness obligations.

LIME provides one concrete local-surrogate method; its neighborhood and fidelity assumptions still require validation for the decision being explained.

An illustrative local test changes one feasible financial input while holding the approved preprocessing and other inputs fixed, then observes the score change. This can reveal sensitivity, but it does not prove that changing that factor in the real world would cause the same outcome. Correlated features and policy rules can make naive counterfactuals impossible or misleading.

A local surrogate should be tested on nearby cases not used to fit it, with an explicit fidelity measure. If its predictions disagree substantially with the actual model, do not present its feature ranking as the reason for the decision. Likewise, a fluent language-model explanation generated from a score alone is unsupported.

The user-facing process should offer a way to correct inaccurate source data and request review through the authorized channel. Preserve the exact decision version and evidence so the explanation is reproducible. This technical framework does not prescribe lending compliance requirements; those depend on the applicable context and must be validated by the responsible specialists.
