## Question

What are FlashAttention advantages?

## Brief answer

FlashAttention lowers attention-intermediate memory use and can speed training and prefill for supported hardware and shapes.

## Detailed answer

Avoiding the full attention matrix can make longer sequences feasible. Gains depend on sequence length, dtype, head dimension, GPU, masks, and kernel version; short workloads may gain little. It does not remove the autoregressive KV cache or make dense attention linear-time. Distinguish the original algorithm from later implementations when quoting benchmarks.

The principal memory saving is in intermediates: the algorithm need not keep every query-key score and probability for backward or output computation. That can make a larger sequence or microbatch fit, which may improve useful throughput beyond the speedup of one kernel. Recomputation during backward spends arithmetic to avoid expensive stored intermediates.

Separate this from model-state storage. Parameters, optimizer moments, and the autoregressive KV cache still occupy memory. If a training run is dominated by optimizer state rather than attention matrices, the total saving may be modest. Likewise, short sequences can offer less opportunity to amortize kernel setup or exploit tiling.

Benchmark using the target mask, dtype, sequence length, head dimensions, and hardware. Report whether the result is attention-kernel time, a complete training step, or end-to-end request latency. Include compilation or warmup consistently. An application may become faster because a larger batch now fits, but that is a different experiment from comparing equal batch sizes. The algorithm enables more efficient execution of supported attention; it does not establish the model's ability to reason over the extra context.
