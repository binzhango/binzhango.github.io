## Question

Design a deduplication pipeline for a web-scale pretraining corpus. It has to run as a streaming process.

## Brief answer

Use a durable streaming pipeline that canonicalizes content, removes exact duplicates by hash and identifies near duplicates through compact fingerprints plus candidate verification. Partition state by stable keys and explicitly define the retention horizon.

## Detailed answer

Normalize boilerplate and encoding without deleting meaningful code or language distinctions. Exact hashes can be stored in a disk-backed index; a Bloom filter may avoid lookups but should not alone discard unique documents when false positives are unacceptable. Near-duplicate candidates can use shingled MinHash/LSH, followed by a stronger similarity check. A single-pass bounded-memory system cannot remember every unique document forever exactly, so retain external state or accept a measured approximation/window. Use deterministic representative selection and record duplicate relationships for provenance. Check cross-split leakage and content-quality effects, not only the percentage of bytes removed.

### Separate exact identity from similarity

Canonicalize encoding and obvious boilerplate, then hash normalized content. A persistent hash index detects exact repeats even when the stream exceeds RAM. A Bloom filter can cheaply identify definite nonmembers and possible members; verify possible members in the durable index before discarding if false-positive loss is unacceptable. Near duplicates need a different mechanism because a one-character change alters a cryptographic hash completely.

Create token or character shingles, compute compact MinHash signatures, and use locality-sensitive buckets to generate candidate pairs. Verify their similarity before selecting a representative. Maintain provenance linking discarded documents to retained ones, including normalization version, so decisions can be audited or reversed. A streaming design also needs checkpointed offsets and idempotent state updates to survive replay. Define whether the retention horizon is lifetime or a time window; bounded local memory cannot exactly remember every unique document forever. Evaluate rare-language and code retention alongside duplicate rate, because aggressive normalization or similarity thresholds can erase legitimate diversity.
