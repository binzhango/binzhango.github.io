## Question

What are the benefits of MQA?

## Brief answer

MQA reduces KV cache memory and decoding memory traffic, often enabling larger batches or faster token generation.

## Detailed answer

Its largest benefit is commonly in memory-bandwidth-limited decoding. It does not reduce all model FLOPs by the query-head count, eliminate attention's sequence-length dependence, or guarantee equal quality. If the FFN or another subsystem dominates latency, end-to-end gains can be smaller. Compare tokens per second, time per output token, peak memory, and task quality at matched workloads.

Imagine cache capacity is the limiting factor for simultaneous conversations. Reducing the number of KV heads decreases the bytes needed for every stored token, so the same available memory can hold more requests or longer contexts. Larger batches can then amortize weight reads and improve aggregate throughput. This is a capacity benefit even when individual-request latency is constrained by something else.

During one-token decoding, the new query still needs to interact with earlier positions for every query head. MQA therefore does not divide all attention arithmetic by the query-head count. Instead, compact shared keys and values reduce how much unique cached data must be transferred, provided the kernel reuses it effectively.

Use a workload matrix rather than a single throughput number: vary prompt length, generated length, concurrency, and cache precision. Record whether the comparison is latency per request or total tokens across requests. Check held-out quality because reducing independent K/V representations can change model behavior. If the application is dominated by long FFNs, network latency, or tool calls, those components limit the end-to-end speedup.
