## Question

K closest points to origin; top-k frequent elements; minimum number of conference rooms.

## Brief answer

These are three separate heap exercises. Use squared distance for k closest points, frequency counts plus selection for top-k elements, and a min-heap of meeting end times for room allocation. State tie and interval conventions; they affect deterministic output and whether back-to-back meetings share a room.

## Detailed answer

```python
import heapq
from collections import Counter

def closest_points(points, k):
    if k < 0: raise ValueError('negative k')
    return heapq.nsmallest(k, points, key=lambda p:(p[0]*p[0]+p[1]*p[1], p))

def frequent(values, k):
    if k < 0: raise ValueError('negative k')
    counts = Counter(values)
    return heapq.nsmallest(k, counts, key=lambda x:(-counts[x], x))

def rooms(intervals):
    heap, peak = [], 0
    for start,end in sorted(intervals):
        if end <= start: raise ValueError('nonempty half-open intervals required')
        while heap and heap[0] <= start: heapq.heappop(heap)
        heapq.heappush(heap,end); peak = max(peak,len(heap))
    return peak

assert closest_points([(3,4),(1,1),(0,2)],2) == [(1,1),(0,2)]
assert frequent(['b','a','b','a','c'],2) == ['a','b']
assert rooms([(0,10),(5,8),(10,12)]) == 2
```

The top-k functions use comparable values for tie-breaking. Selection is typically O(n log k), though library strategies may vary with k; counting needs O(u) memory for u unique items. Meeting rooms costs O(n log n) because of sorting. A streaming top-k heap still needs a strategy for changing counts; storing one stale heap entry per update can grow without bound.

For nearest points, compare squared Euclidean distance so no square root is needed; the ordering is unchanged for nonnegative distances. For frequencies, count first and select by descending count, with a deterministic secondary key. These examples assume comparable point/value types for ties; heterogeneous Python objects may require an explicit tie key.

For rooms, the heap contains end times of meetings active at the current start. Remove every meeting ending at or before that start, then add the new end and update peak occupancy. Half-open intervals allow a meeting ending at ten and another starting at ten to share one room. Removing only one expired meeting would leave stale occupancy when several finished.

Test k zero, k larger than input, duplicate points, equal frequencies and nested meeting intervals. The shared use of a heap does not make the data semantics identical. In a live frequency stream, priorities change after insertion, so a static selection heap cannot be reused without updating entries or rebuilding from authoritative counts.
