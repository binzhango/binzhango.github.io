## Question

How to improve results via post-retrieval processing?

## Brief answer

Post-retrieval processing improves evidence through deduplication, reranking, context expansion, and budget-aware selection.

## Detailed answer

Remove near-identical chunks, rerank against the specific question, and restore neighboring sentences or parent sections when needed. Enforce authorization before passing candidates to a model or external reranker. Diversify evidence for multi-part questions and preserve source IDs through compression. A compressor can omit a crucial exception, so compare answers against the original evidence and measure changes in recall as well as prompt size.

Treat candidate retrieval as a recall stage and post-processing as an evidence-selection stage. A broad candidate pool may contain near duplicates, stale versions, or passages that match only part of the question. Deduplicate by source and content, rerank for the actual information need, and preserve complementary passages needed for a complete answer.

For example, a question comparing two product versions needs evidence for both versions. Selecting the top five nearly identical passages about the newer version wastes the budget. A coverage-aware selection can retain one strong passage per version plus a definition explaining the comparison metric. Parent expansion can add a missing exception, but should not automatically insert the whole document.

Compression is especially risky for qualifications and tables. A summary that drops “except for refurbished units” changes the policy. Keep provenance to original spans and verify critical compressed claims. Enforce access filters before sending content to an external reranker or model. Measure support coverage before and after processing, prompt token count, and answer correctness so a smaller context is accepted only when it preserves the information the question requires.
