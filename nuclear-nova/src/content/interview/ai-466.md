## Question

Given a repository snapshot (path → content), build a Merkle tree and write the function returning which files changed between two snapshots without comparing every file's content.

## Brief answer

Persist a hash on every file and directory, compare root hashes, and descend only into subtrees whose hashes differ. This avoids rereading unchanged file content after hashes have been built. Creating hashes from two entirely new raw snapshots still requires reading their bytes; a Merkle tree cannot eliminate that initial work.

## Detailed answer

This runnable reference builds immutable-by-convention nodes and reports added, deleted, and modified paths. It treats a file-to-directory replacement as a deleted file plus added descendants.

```python
import hashlib
import json

def build_tree(snapshot):
    tree = {}
    for path, content in snapshot.items():
        parts = path.split('/')
        if any(p in ('', '.', '..') for p in parts):
            raise ValueError('invalid path')
        node = tree
        for p in parts[:-1]:
            node = node.setdefault(p, {})
            if not isinstance(node, dict):
                raise ValueError('path collision')
        if parts[-1] in node:
            raise ValueError('path collision')
        node[parts[-1]] = bytes(content)
    def freeze(value):
        if isinstance(value, bytes):
            return ('f', hashlib.sha256(b'f' + value).hexdigest(), {})
        children = {k: freeze(v) for k, v in sorted(value.items())}
        payload = json.dumps([(k, v[0], v[1]) for k, v in children.items()]).encode()
        return ('d', hashlib.sha256(b'd' + payload).hexdigest(), children)
    return freeze(tree)

def changed(a, b, prefix=''):
    if a is not None and b is not None and a[:2] == b[:2]:
        return []
    if (a and a[0] == 'f') or (b and b[0] == 'f'):
        paths = [prefix]
    else:
        paths = []
    ac = a[2] if a and a[0] == 'd' else {}
    bc = b[2] if b and b[0] == 'd' else {}
    for name in sorted(ac.keys() | bc.keys()):
        paths += changed(ac.get(name), bc.get(name), f'{prefix}/{name}'.lstrip('/'))
    return paths

assert changed(build_tree({'a': b'x', 'b': b'y'}), build_tree({'a': b'z', 'b': b'y'})) == ['a']
assert changed(build_tree({}), build_tree({'dir/a': b'x'})) == ['dir/a']
```

Diff cost follows visited directory entries and changed paths. This implementation also sorts child-name unions at each visited directory, so a flat directory with N children costs O(N log N); constructing returned paths and repeatedly extending lists adds depth-dependent work. High-fanout directories still require inspecting child names. Store sorted child maps and reuse unchanged nodes for incremental snapshots.

### Why unchanged subtrees are skipped

Imagine two snapshots containing `docs/guide.md`, `src/a.py`, and `src/b.py`, with only `src/a.py` modified. The root hashes differ, so comparison visits both top-level entries. The `docs` hashes match and its entire subtree is skipped. The `src` hashes differ, so its children are inspected: `b.py` is skipped and `a.py` is returned. With persistent hashes, no unchanged file bytes need to be reread during this comparison.

An added directory requires enumerating its descendant files because the caller asked for file paths, not merely a changed directory marker. Replacing file `x` with directory `x/y` returns both `x` and `x/y`, allowing the caller to represent deletion and addition without confusing their types. Renames are reported as removal and addition unless a separate hash-based rename detector is added.

The complexity depends on representation as well as the algorithm. A flat map with a million children must still enumerate those names when its hash changes. A balanced tree over directory entries can narrow that work. Persisted snapshots also need atomic publication so a root never refers to partially written children, and readers need a stable snapshot while comparison runs.
