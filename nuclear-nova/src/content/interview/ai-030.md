## Question

What is chunked prefill, and why does it improve tail latency under mixed traffic?

## Brief answer

Chunked prefill breaks long prompts into bounded pieces so the scheduler can interleave them with decoding. It limits the period during which a large prefill monopolizes compute and delays active streams.

## Detailed answer

Choose chunk and token budgets using the device’s measured cost curves. Too-large chunks recreate decode stalls; too-small chunks increase scheduling and kernel overhead and may slow prompt completion. Reserve decode capacity, enforce admission fairness and track prompt progress so a long request cannot starve indefinitely. Evaluate both long-prompt TTFT and short-request ITL under mixed arrivals. Improvements depend on scheduler policy and hardware, not chunking alone.

A long prompt might otherwise run as one large prefill operation while dozens of users wait for their next streamed token. Chunking splits that prompt into consecutive segments whose KV state accumulates across scheduler iterations. Between segments, the scheduler can advance existing decode requests, limiting the longest uninterrupted prefill interval.

For illustration, a 16,384-token prompt could be processed in eight chunks of 2,048 tokens. This is a scheduling example, not a recommended default. The attention for a later chunk still reads the earlier prefix, and its causal mask must allow preceding chunks while masking future tokens inside the current chunk. Incorrect offsets can silently change model output even when tensor shapes look valid.

Small chunks create more scheduling decisions and can reduce matrix efficiency. Large chunks preserve efficient compute but reintroduce long pauses. A useful scheduler reserves decode capacity, uses remaining token budget for prefill, and ages waiting prompts so decode-heavy traffic cannot starve them indefinitely. Tune under realistic mixtures of prompt lengths and arrival bursts. Record long-prompt TTFT and short-request inter-token percentiles together: a configuration that protects active streams by making new users wait unboundedly has merely moved the latency problem.
