## Question

What is RLVR (RL with verifiable rewards) and where does it beat a learned reward model?

## Brief answer

RLVR uses rewards from checkable outcomes such as passing tests or solving a problem with a known answer. It works especially well when verification is cheaper and more reliable than judging an entire response subjectively.

## Detailed answer

Run generated code in an isolated evaluator with hidden tests, or compare a derived result against a trusted verifier. The verifier must resist shortcuts, leakage and malformed-output exploits. Passing weak tests can reward an incorrect general solution, and exact-answer matching may penalize valid alternative representations. Keep held-out tasks and adversarial evaluator tests. Use learned or human judgments for dimensions such as clarity where a mechanical reward is incomplete.

Verification turns a hard generation problem into a cheaper checking problem. A code policy can propose a solution, run it in an isolated environment against hidden tests and receive a reward based on outcomes. A mathematical task can compare a normalized final answer or check a formal proof. The learning algorithm may be PPO, GRPO or another policy optimizer; RLVR describes the reward source, not one specific optimizer.

A binary pass/fail reward is simple but can be sparse. If every sampled response fails, the optimizer has little information about which direction is better. Curriculum design, stronger starting policies, multiple samples or carefully chosen partial rewards can help, but partial rewards create new shortcuts. A solution that passes visible examples by hard-coding them has optimized the test proxy without learning the intended algorithm.

Keep the verifier outside the model's control, isolate execution, limit resources and protect hidden tests. Test malformed outputs, timeouts and attempts to read evaluator state. Evaluate on new problems and stronger checks, not only the training reward. Mechanical rewards are strongest where correctness has a reliable specification; open-ended helpfulness, tone and many real-world judgments still need human or learned assessment. A correct final answer also does not prove that every intermediate explanation is faithful or logically valid.
