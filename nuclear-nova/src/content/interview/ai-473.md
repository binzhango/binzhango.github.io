## Question

Design an agentic AI system that can autonomously adapt to new tasks.

## Brief answer

Separate reusable tools and skills from task-specific plans, and let the agent adapt through observed outcomes within explicit authority and resource limits. “New tasks” should mean recombining validated capabilities and learning useful procedures, not unrestricted self-modification or silent expansion of permissions.

## Detailed answer

**Suggested approach.** A planner selects a goal decomposition, an executor invokes typed tools, and a verifier checks intermediate and final outcomes. Durable memory stores task facts and reviewed procedures with provenance; untrusted observations cannot rewrite policy. On unfamiliar tasks, the agent asks for missing constraints or runs a bounded experiment before committing to a larger plan.

Persist checkpoints so failures can be diagnosed and resumed. New procedures are tested in a sandbox and promoted only after held-out evaluations. Keep an explicit budget for steps, tokens, money, and elapsed time, plus a termination condition for repeated failure. Measure transfer to genuinely unseen tasks, tool misuse, recovery, and calibration of uncertainty. Compare against a fixed workflow baseline: adaptation is useful only if its additional flexibility exceeds its coordination and evaluation cost.

### Adapt through observable state

For an unfamiliar reporting task, the planner may know how to query data and create a document but not the required business definition. It should first identify that missing contract, obtain or infer only authorized constraints, and run a small query to test the data assumptions. Successful tool execution is feedback about one step, not proof that the overall report is correct.

Represent a reusable procedure as inputs, preconditions, actions, expected outputs, and known failure cases. Store a successful task as a candidate procedure, then test it on changed inputs before treating it as reusable memory. This prevents one accidental success from becoming an unquestioned rule for future tasks. Keep policies and authorization outside the editable procedure store.

The verifier should use independent observations where possible: compare a requested record count with a trusted query, or open a generated artifact and check its contents. If the same model invents both the plan and the success criterion after execution, it can rationalize a failure. Bound exploration and distinguish “I learned a new procedure” from “I changed my own model weights”; the proposed system primarily adapts its workflow and stored knowledge.
