## Question

What are agents and toolkits?

## Brief answer

An agent uses a model to select actions from available tools; a toolkit groups related tools and their interfaces.

## Detailed answer

A tool exposes a schema and executable behavior, while the agent loop interprets model requests, validates arguments, executes permitted calls, and returns results. Enforce permissions in code, not only in the prompt. Add timeouts, bounded iterations, error handling, and approval points for actions that require them. Use deterministic workflows when the action sequence is known; an agent loop adds flexibility and additional failure modes.

A typical agent iteration sends the current state and available tool schemas to the model, receives a proposed call, validates the tool name and arguments, executes the allowed operation, and adds the result back into state. The loop ends when the model produces a final answer or the application reaches a step, time, or cost limit. A toolkit merely packages related operations, such as searching records and fetching a record by ID.

For a support agent, a search tool can retrieve account information, while an update tool changes a record. Those require different permissions and retry behavior. Validate account scope server-side, limit accepted fields, and use idempotency where repeating an update would be harmful. The model's assertion that it has permission is not an authorization check.

Test empty results, malformed arguments, timeouts, contradictory tool responses, and loops that repeatedly call the same tool. Prefer a deterministic workflow when the correct sequence is known. Agent flexibility is useful when intermediate results determine the next action, but it adds an uncertain planning layer that must be constrained and observed.
