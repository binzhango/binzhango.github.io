## Question

Merge ranked results from N connector shards into a global top-k, applying a per-user permission filter. Do it efficiently.

## Brief answer

Merge descending shard streams with a heap, checking permission before accepting a result and deduplicating document IDs. Continue fetching until k authorized results are found or all streams are exhausted. Filtering each shard's initial top-k alone can miss valid lower-ranked results when many higher-ranked candidates are forbidden.

## Detailed answer

This reference assumes shard scores share one comparable scale and each iterator yields `(score, document_id)` in descending order. Permission checks must use current trusted identity and must not expose rejected content.

```python
import heapq

def authorized_topk(shards, k, allowed):
    if k < 0:
        raise ValueError('negative k')
    iterators = [iter(s) for s in shards]
    heap, result, seen = [], [], set()
    def advance(i):
        try:
            score, doc = next(iterators[i])
            heapq.heappush(heap, (-score, i, doc))
        except StopIteration:
            pass
    for i in range(len(iterators)):
        advance(i)
    while heap and len(result) < k:
        negative, i, doc = heapq.heappop(heap)
        if doc not in seen and allowed(doc):
            result.append((-negative, doc))
            seen.add(doc)
        advance(i)
    return result

assert authorized_topk([[(9, 'x'), (5, 'a')], [(8, 'b'), (4, 'a')]], 2,
                       lambda d: d != 'x') == [(8, 'b'), (5, 'a')]
```

For m consumed candidates across n shards, heap work is O(m log n), with O(n + k) memory apart from iterators. Authorization can dominate; use permission bitsets or safe batched checks. If scores are incomparable, use rank fusion rather than claiming this merge yields a meaningful global ranking. Test empty shards, duplicates, all-denied results, ties, and permission revocation.

### Why the heap returns the next best candidate

The heap contains the highest unconsumed item from every nonempty shard. Because each shard is already sorted, no unseen item can outrank its shard's current head. Popping the global maximum therefore considers candidates in descending score order. After inspecting that item, advance only its originating shard and restore the invariant.

If the top result is unauthorized, discard it and keep consuming. For shards `[9:x, 5:a]` and `[8:b, 4:a]`, denying x still returns b followed by a. Stopping after examining two raw candidates would incorrectly return only b. Deduplication occurs when a document is accepted, preserving the highest-scored authorized occurrence under the shared-score assumption.

Remote shard iterators need paginated continuation and a deadline. If a shard fails early, the result is partial rather than guaranteed global top-k; expose that state to the caller. Authorization should be pushed down where possible to reduce wasted retrieval, then checked again before content is revealed. The core's `k=0` result is empty, although it still initializes shard iterators; a production API can return immediately to avoid unnecessary remote calls.
