## Question

A chat assistant re-sends a long conversation history on every turn. How do you avoid recomputing all of it, and what are the pitfalls?

## Brief answer

Reuse KV state for an exact, unchanged token prefix, computing only newly appended tokens. Prefix caching saves prompt computation, not the need for new tokens to attend to the existing context. Correct cache identity includes model weights, tokenizer/template, positional settings, adapters, and isolation boundaries—not merely the visible conversation text.

## Detailed answer

Tokenize the full prompt deterministically and find the longest reusable prefix. Store cache blocks with reference counts and copy-on-write semantics so two conversations cannot mutate shared state. Route to a worker holding the prefix when locality outweighs queue delay; otherwise transfer or recompute it.

Editing an earlier message, changing a system prompt, or inserting retrieved text invalidates the cache from the first differing token. Eviction, memory pressure, and low reuse can make caching unprofitable. Partition by tenant or enforce a deliberate safe-sharing policy; caches must not leak private text through access or timing. Track hit rate in saved tokens and actual first-token latency, not request counts alone.

### Cache boundaries in a conversation

Suppose the serialized prompt contains a 2,000-token system prefix, 8,000 tokens of previous conversation, and a new 100-token message. If the first 10,000 tokens are identical to a cached sequence, only the new suffix needs fresh prefill computation. The next generated token still attends to the full available history, so its decode cost has not become a 100-token problem.

Place stable instructions before frequently changing material when the model template allows it. A timestamp inserted at the beginning can invalidate every later cache block. Cache keys should incorporate token IDs and configuration fingerprints, not raw text alone, because templates and tokenizers alter the actual input. Retain reference counts while requests execute, and evict only unreferenced blocks. Measure saved prefill GPU time against cache occupancy and eviction cost; a high request hit rate for tiny prefixes may be less valuable than a few long-prefix hits.
