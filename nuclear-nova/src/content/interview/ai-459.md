## Question

Design the ranking system combining BM25, dense retrieval and LLM reranking across multiple indexes.

## Brief answer

Retrieve in parallel from lexical and dense indexes, normalize identity and permissions, fuse rankings, then spend expensive reranking only on a bounded candidate set. Raw BM25 and vector scores are not directly comparable across indexes. Use rank fusion or calibrated learned ranking and evaluate the whole candidate funnel.

## Detailed answer

**Suggested approach.** Give each retrieval branch its own candidate quota so one high-volume index cannot crowd out the others. Deduplicate document versions and filter unauthorized results before exposing content to the model. Reciprocal-rank fusion is a practical baseline: sum `1 / (k + rank)` over lists, with a fixed tuning constant and documented branch weights. Train a reranker later using relevance labels and unbiased exposure data.

Add freshness, source quality, exact entity matches, and query intent as explicit features rather than hiding them in prompts. An LLM reranker should receive only the top bounded set and treat retrieved text as data. Measure candidate recall, final nDCG, evidential coverage, p95 latency, and cost by query category. Test missing shards, score-distribution drift, duplicated syndicated pages, and disagreement between lexical precision and semantic similarity.

### Work through fusion and escalation

With reciprocal-rank fusion and k = 60, a passage ranked first lexically and tenth semantically receives `1/61 + 1/70`, about 0.0307. A passage ranked second in only one list receives about 0.0161. This rewards corroboration across retrieval methods without pretending that a BM25 score of 12 and a cosine similarity of 0.8 share a scale. Branch weights can express measured differences in reliability, but need evaluation rather than intuition.

After fusion, collapse duplicates carefully. Two chunks from one document may contain complementary evidence; two syndicated copies of the same paragraph usually do not. Preserve version and source identity while constructing a final candidate set with enough topic coverage for the query.

Escalate to an expensive reranker when the cheap ranking is ambiguous or the query needs comparison across facets. Fixed top-k limits provide predictable cost; conditional escalation can save compute but adds a routing decision that can fail. Log candidates and scores at every stage so a missed answer can be traced to retrieval, fusion, reranking, or context selection instead of being blamed vaguely on the LLM.
