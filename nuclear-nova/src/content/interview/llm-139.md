## Question

How can pdfplumber extract text and tables?

## Brief answer

`pdfplumber` extracts native PDF text and tables using character geometry, lines, and configurable table-detection strategies; it is not an OCR engine.

## Detailed answer

For a born-digital PDF, inspect `extract_words()` and `extract_text()`, crop a known table region if necessary, and use `find_tables()` or `extract_tables()`. Choose line-based, text-based, or explicit boundaries through table settings. Visual debugging with `debug_tablefinder()` helps tune intersection and alignment tolerances. Validate merged cells and repeated headers against the page image. Scanned pages need an OCR stage or another parser.

This runnable command-line example requires `pdfplumber` and a local born-digital PDF. It emits one JSON record per page, preserving page numbers and explicit `null` cells rather than silently shifting a table's columns. Run it as `python extract_pdf.py report.pdf`.

```python
import json
import sys
from pathlib import Path
import pdfplumber

def extract_pdf(path):
    records = []
    with pdfplumber.open(path) as pdf:
        for page_number, page in enumerate(pdf.pages, start=1):
            records.append({
                "page": page_number,
                "text": page.extract_text() or "",
                "tables": page.extract_tables(),
            })
    return records

if __name__ == "__main__":
    if len(sys.argv) != 2:
        raise SystemExit("Usage: python extract_pdf.py input.pdf")
    path = Path(sys.argv[1])
    if not path.is_file():
        raise SystemExit("Input PDF does not exist")
    print(json.dumps(extract_pdf(path), ensure_ascii=False, indent=2))
```

An empty text field is a signal to inspect the page, not proof that the page is blank; a scan may need OCR. Default table settings work best for suitable ruled tables. Crop known regions and adjust line or text strategies when the layout differs. Validate important cells against the rendered PDF, especially merged headers, footnotes, decimal values, and tables continued across pages. Processing cost depends on page content and geometric complexity; for very large PDFs, write each page record incrementally rather than accumulating all results in memory.
