## Question

Design Cursor's tab (next-edit prediction) system: it must feel instant (sub-100 ms perceived latency) for millions of daily users.

## Brief answer

Make next-edit prediction speculative and local to the user's current intent. Use incremental editor events, a compact context snapshot, warm model capacity, and aggressive cancellation so suggestions are ready before the user pauses. Sub-100 ms perceived latency is a product target, not a promise that a remote large model finishes every request within 100 ms.

## Detailed answer

**Suggested approach.** Debounce edits lightly, reuse stable prefix context, predict likely next-edit regions, and prefetch small candidates. Tag each request with document version, cursor state, and surrounding-text hashes. Display only suggestions still valid for the current buffer; stale predictions are discarded rather than applied optimistically. A small local model or cached candidate can cover common cases during cloud latency.

Optimize acceptance-weighted usefulness and time saved, not just suggestion frequency. Track suggestion age, p95 visible latency, acceptance followed by undo, and keystroke interference. Keep private buffers out of unauthorized telemetry. Test rapid typing, cursor jumps, multiple cursors, IME composition, and offline transitions. Speculation consumes extra inference, so cap it using observed acceptance probability and cancel work as soon as the context changes.

### Protect the typing loop

Maintain a small state machine per buffer: an edit updates the document version, cancels obsolete inference, and creates a candidate request from the current cursor neighborhood. A returned suggestion includes its base version and expected surrounding text. Rendering first checks that those anchors still match. Accepting the suggestion is one undoable edit, while continued typing invalidates incompatible candidates immediately.

For example, a candidate replacing a return expression must be discarded if the user changes the function signature before it arrives. Attempting to “helpfully” insert it anyway can create syntactically valid but semantically stale code. The system must also avoid showing speculative text during IME composition or in places where it would disrupt accessibility tooling.

Separate model latency, time until a useful suggestion is ready, and user-visible delay after a pause. Speculative work can improve the last measure while raising total compute. Evaluate useful accepted characters that survive subsequent editing, cancellation rate, and cost per useful suggestion. A smaller fast model can handle routine local edits while a slower model serves explicitly requested multi-file work; one universal model need not cover both latency contracts.
