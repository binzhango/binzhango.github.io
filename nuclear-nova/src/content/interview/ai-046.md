## Question

What is the difference between structured output and function calling?

## Brief answer

Structured output constrains the format of a model response. Function calling expresses a proposed invocation of an application-defined tool; the application still validates, authorizes and executes it.

## Detailed answer

Both can use JSON schemas, but valid JSON is neither factual correctness nor permission. A structured invoice object may contain an invented amount, and a well-formed delete call may be unauthorized. Validate types, business rules and resource ownership separately. Supply tool results with explicit success/error states, and allow the model to produce a final user response after execution. Treat schema conformance as an interface property, not a safety guarantee.

An extraction response such as an invoice object is data intended for the application or user. A tool call such as `lookup_invoice(invoice_id)` is a request for the application to perform an operation. Both may be represented as schema-conforming JSON, but their lifecycle differs: tool calls require dispatch and a result round trip before a final answer can describe what happened.

Schema constraints can prevent malformed syntax, missing required fields or invalid enum values. They cannot prove that an invoice number exists, that a total is correct, or that the caller owns the referenced account. Apply semantic validation after parsing, then authorization immediately before execution. Never turn arbitrary model text into code or a shell command simply because it arrived in a JSON field.

A robust tool result includes a call ID, an explicit status and bounded data or a typed error. The model can then explain the confirmed result, request clarification or choose another permitted action. Consequential operations may require an approval bound to the exact payload. Evaluate schema compliance separately from task correctness and unauthorized-action rate. A system can achieve 100% valid JSON while still making consistently wrong decisions.
