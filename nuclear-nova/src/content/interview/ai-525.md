## Question

A conversation runs past the context window. What do you keep, and how do you decide?

## Brief answer

Keep immutable policy, the current request, unresolved commitments, recent turns, and evidence needed for the next action. Summarize older conversation into structured facts with provenance, and retrieve archived details on demand. Do not let a lossy summary overwrite permissions, transaction receipts, or the user's latest correction.

## Detailed answer

**Suggested approach.** Separate durable task state from conversational wording: goals, constraints, decisions, open questions, completed actions, and source IDs. Reserve tokens for the next tool result and answer before packing context. Retain complete tool-call/result pairs and explicit unresolved failures. A summary should label uncertainty and reference archived turns for verification.

Evaluate memory with tasks that revisit old commitments, change preferences, and require exact numbers. Check contradictions between summaries and recent messages and prefer the latest verified statement within its scope. Sensitive facts need retention and deletion controls just like raw transcripts. A longer window can delay compaction, but it does not remove the need to select relevant state or control cost. Avoid summarizing every turn if it merely adds latency and repeated distortion.

### Compact facts without rewriting authority

Imagine an older turn says the user prefers a morning appointment, while a recent correction says afternoons are now required. The durable state should replace that preference with the latest scoped correction and retain provenance, not average the two into “flexible timing.” A completed booking receipt belongs in durable transaction state; summarizing it as “booking discussed” loses a fact required for later cancellation or reconciliation.

Use separate stores for conversation text, structured task state, and retrievable long-term evidence. The next prompt includes the current goal, applicable constraints, unresolved decisions, recent complete interaction units, and only the older facts needed now. A summary is a view over evidence, not permission to invent missing details.

Test compaction with delayed references: ask for an exact amount mentioned early, revisit a changed preference, or request continuation of an interrupted tool action. Compare behavior before and after compaction and inspect lost qualifications. If an exact value cannot be retained reliably, preserve a pointer and retrieve it. Summarization saves tokens only when the resulting state still supports the next decision correctly.
