## Question

A customer 10x'd their indexed documents and reports answer quality “got noticeably worse.” Drive the investigation.

## Brief answer

Reproduce the regression on a fixed query set and separate corpus growth from changes in ingestion, embeddings, search parameters and context assembly. Ten times more documents creates both more distractors and greater indexing pressure.

## Detailed answer

Check that source-to-index lag, deletion handling and permission filters still work. Compare exact-neighbor retrieval with the approximate index to isolate recall loss; increased corpus size may require a different search breadth or partitioning strategy. Inspect duplicate documents, chunk-size changes, language/domain shifts and embedding-profile mismatches. Then test the reranker and generator with identical candidate evidence. More retrieved text can dilute useful context, so raising top-k is not automatically the solution. Report failure rates by query segment and ship a measured fix with regression cases, rather than attributing every quality drop to the model.

### Use controlled substitutions to isolate the cause

Run the same query set against the old corpus snapshot and the new one with the same embedding model and index settings. Then compare exact vector search with the approximate index on a tractable sample. If exact search still finds the expected evidence but approximate search does not, increase search breadth or revisit partitioning rather than changing the generator.

If both retrieval methods rank distractors above the evidence, inspect duplicate content, document quality, chunk boundaries, and new domain/language distributions. Verify that vectors from incompatible embedding versions were not mixed. Give the generator the old correct evidence and then the new candidate set to test context dilution and reranker behavior. Increasing top-k can worsen answer quality by adding conflicting or obsolete passages. Segment failures by task and corpus source, apply the smallest measured repair, and preserve cases in the regression suite. Also inspect freshness and deletion lag: larger volume can expose ingestion backlogs that look like semantic failure.
