## Question

What are the directions of improvement for attention?

## Brief answer

Improve attention by reducing memory traffic, restricting connectivity, sharing KV heads, compressing state, or changing the attention formulation.

## Detailed answer

FlashAttention preserves dense softmax attention while improving its execution. Sliding-window or block-sparse attention reduces attended pairs; MQA/GQA reduce KV cache size; low-rank and kernel-based methods change the approximation or representation. Retrieval can reduce how much context must enter the model. Choose based on the actual bottleneck—prefill compute, decode bandwidth, memory, or quality—and measure the relevant workloads. These techniques are often complementary.

Start by naming the resource being reduced. A fused exact-attention kernel avoids storing a large intermediate matrix while keeping the same allowed token interactions. A local mask changes those interactions, reducing work but preventing direct access to distant tokens. Sharing KV heads reduces stored and transferred keys and values, while retaining separate query heads. These mechanisms solve different bottlenecks and can be combined in one model.

For a document chat system, long prompts may make prefill expensive, while many simultaneous conversations make KV storage the capacity constraint. Retrieval can reduce prompt length; GQA can reduce per-conversation cache; an efficient attention kernel can reduce prefill memory traffic. A local-attention model might process longer streams but needs other paths to connect distant evidence.

Measure time to first token, time per output token, throughput at realistic concurrency, memory, and answer quality. Compare against the same prompt and output lengths. If reducing context removes the needed exception from a policy, a faster answer is not an improvement. Architectural approximations generally require compatible training, while an exact backend replacement should be checked for numerical and mask equivalence.
