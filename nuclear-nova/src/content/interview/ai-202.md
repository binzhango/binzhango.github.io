## Question

Design the serving system for a multimodal assistant (text + image in, streaming text out) at hundreds of millions of users.

## Brief answer

Use a multimodal ingestion path that validates and preprocesses images, an encoder that produces visual representations, and a language-model serving fleet that streams text. Budget image-token expansion explicitly: one image can create many tokens and significant prefill work. Keep attachment storage, authorization and generation lifecycle separate from GPU execution.

## Detailed answer

Suggested flow: upload images through scoped object-storage access, scan and decode them under size limits, normalize resolution and generate visual tokens. Build the model input from text plus image representations with a documented ordering. Route compatible requests to replicas with enough KV and encoder capacity.

Batch image encoding where useful, cache only under appropriate user/model/version boundaries, and avoid letting large images starve text-only traffic. Continuous batching and token-aware admission still apply, but prompt cost estimation must include visual token counts and encoder time.

Evaluate OCR, spatial reasoning, image-text conflicts and misleading images alongside text quality. Monitor first-token latency by image size/count and failure rates for corrupt uploads. Test deletion propagation and cross-tenant access. Hundreds of millions of users require workload-based capacity estimates; user count alone does not determine image encoder or decoder demand.

Image preprocessing is both a security and capacity boundary. Validate format, decoded dimensions and file size before GPU work; a small compressed file can expand into a large image. Keep uploads in scoped object storage and version preprocessing so cached visual representations cannot be confused across model or resolution changes.

Estimate each request's cost using image count, patch/token expansion, text length and expected output. A large image can consume substantial encoder compute and language-model context, so request-count quotas alone are misleading. Separate or fairly schedule image-heavy and text-only traffic, and release both encoder and decoder resources on cancellation.

Evaluate whether a correct answer depends on small text, object count or spatial relations, since reducing resolution to save cost affects those tasks differently. Preserve attachment authorization through derived embeddings and caches, and propagate deletions. Load tests should include corrupt files, many-image prompts and cold-cache bursts. The result is a multimodal capacity model, not simply a text-serving fleet with an upload button attached.
