## Question

Why do LLMs need an external (vector) knowledge base?

## Brief answer

External knowledge sources provide current, private, or precisely attributable information that a model's parameters may not reliably contain.

## Detailed answer

A vector database is one option, not a requirement. Lexical search, SQL, document stores, graph queries, and APIs can supply better evidence for some tasks. Retrieval can update information without retraining the generator, but introduces ingestion, authorization, ranking, and evidence-quality requirements. An LLM does not need an external knowledge base for every task, such as rewriting a user-provided paragraph.

Model parameters compress patterns learned during training; they are not an inspectable table of every source fact. A model may lack a private handbook entirely or recall an old public policy. An external source supplies the relevant current information at request time and makes it possible to show where a claim came from.

Choose the retrieval mechanism by the question. Semantic search is useful for paraphrased natural-language requests. SQL is better for exact filters and aggregates over structured records. Lexical search handles identifiers and error codes well. An API may be the authoritative source for a live status. A vector database is useful when approximate semantic matching over many precomputed embeddings fits the workload, not because all knowledge must be stored as vectors.

For “What is my current order status?”, query the authorized order system rather than expecting a model or stale document index to know it. For “Explain the return policy,” retrieve the current policy text. The application still needs access control, freshness, evidence selection, and answer validation. External knowledge improves available information; it does not guarantee the model interprets it correctly.
