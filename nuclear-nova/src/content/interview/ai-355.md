## Question

You have one on-device base model but a dozen features: summarization, rewriting, reply suggestions, tone adjustment. How do you specialise without shipping a dozen models?

## Brief answer

Share one base model and load small feature-specific adapters or prompts as needed. Adapters can specialize behavior without duplicating all base weights, while a unified instruction-tuned model may handle related features with no extra weights. Choose based on quality, adapter load cost, and compatibility rather than assuming every feature needs its own checkpoint.

## Detailed answer

Keep feature specifications and evaluation sets separate: summarization values faithfulness, rewriting preserves intent, and reply suggestions need contextual appropriateness. Train adapters on the relevant examples while freezing the base, then test interference when adapters are switched. Bind each adapter to a compatible base-model revision and quantization configuration.

Cache only active or likely-needed adapters and release memory under pressure. Avoid blindly combining adapters whose effects were never evaluated together. Version rollout and rollback independently, while ensuring a base update triggers adapter regression tests. Apple's published on-device approach uses dynamically loaded feature adapters, providing a concrete example of this pattern.

### Adapters make specialization small

For a linear layer W, a LoRA-style adapter adds a low-rank update BA. If W is 4,096×4,096 and rank r=16, the adapter has $16(4096+4096)=131,072$ parameters instead of 16,777,216 for a separate full matrix. This illustrates why feature-specific updates can be loaded cheaply, though applying adapters across many layers still adds memory and computation.

The base model supplies general language capabilities; a summarization adapter can teach faithful compression, while a rewrite adapter teaches style transformations. Keep their evaluation criteria distinct and pass the feature identity through a controlled interface. Changing adapters should invalidate incompatible cached states, because intermediate representations may differ. Merge an adapter into weights only when the deployment benefits outweigh losing easy switching. A base-model update requires rechecking all adapters and their quantization assumptions. If prompt conditioning alone achieves the required behavior, it may be simpler than training an adapter for every feature.
