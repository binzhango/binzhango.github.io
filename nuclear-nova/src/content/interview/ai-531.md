## Question

Users complain that characters drift out of persona after a long session. Diagnose it.

## Brief answer

Separate persona-definition failures from memory loss, conflicting user instructions, sampling effects, and model-version changes. Reproduce drift with long-session traces and identify the turn where behavior diverges. Reinforce a compact stable persona and verified state, but avoid preserving harmful or obsolete instructions merely for consistency.

## Detailed answer

Inspect whether the persona was truncated, summarized incorrectly, or contradicted by retrieved memories. Check cache invalidation after persona edits and whether the model interprets quoted dialogue as instructions. Build evaluation conversations that revisit identity, tone, relationships, and commitments after distractions; score both consistency and appropriate adaptation.

Use a stable persona prefix, structured session facts with provenance, and selective recall rather than repeatedly appending a long biography. Train or tune on long-horizon examples if prompting alone is inadequate. Track drift by session length and category, and review false positives where a legitimate character change was requested. The tradeoff is rigidity: a system that never changes can also ignore user corrections or become repetitive.

### Find the first point where state diverges

Replay a saved long session while logging the exact prompt, persona version, selected memories, and truncation decisions at each turn. If the persona disappears from the prompt after compaction, the failure is context construction. If it remains intact but behavior changes only after a model upgrade, investigate model compatibility. If a retrieved memory contains an old or conflicting persona, the failure is memory scope and precedence.

Use paired tests that insert irrelevant turns while preserving the same underlying character commitments. Check whether the model still recalls stable facts and whether it appropriately accepts a current authorized correction. Consistency should not mean repeating an outdated fact after the user explicitly changes the scenario.

A compact persona should separate stable identity and style from mutable session facts. Reinstate the stable part at a predictable prefix location, retrieve relevant facts with provenance, and invalidate caches after edits. Evaluate both drift and excessive rigidity: a character can stay “in persona” while becoming repetitive, ignoring context, or refusing legitimate creative direction. The target is coherent behavior under the intended interaction rules, not identical wording across every turn.
