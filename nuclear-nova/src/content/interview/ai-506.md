## Question

Design an agent that takes a draft NDA and returns a redlined Word document reflecting the firm's playbook, not a chat response.

## Brief answer

Represent the firm's playbook as versioned rules, detect relevant clauses, propose minimal changes with reasons, and write genuine tracked changes into the original Word structure. Preserve formatting, numbering, comments, and document identity. The deliverable is a reviewer-controlled redline, not a regenerated document that silently rewrites everything.

## Detailed answer

**Suggested approach.** Parse the DOCX package into paragraphs, runs, tables, and stable anchors. Match each playbook rule to evidence and generate a structured edit proposal containing original span, replacement, rationale, and rule ID. Validate anchors against the source version before applying changes. Use WordprocessingML revision elements for insertions/deletions and comments for unresolved ambiguity.

Render and inspect the resulting document, compare accepted-change text with the intended edits, and reopen it in a compatible Word viewer. Test edits across runs, tables, lists, and existing revisions. Keep a manifest of applied and rejected proposals, and require professional review before execution or external use. Measure missed mandatory clauses, unwanted edits, formatting damage, and reviewer time. Unsupported document constructs should be flagged, not flattened invisibly.

### Keep edits attached to document structure

A visible phrase in Word can span several XML runs because of bold text, spell-checking markup, or existing revisions. Build a mapping from normalized paragraph text back to those runs. A proposal that replaces a phrase must identify the original span and its surrounding context, then verify the source has not changed before altering the corresponding nodes. Global string replacement can modify the wrong repeated clause or damage markup.

Apply the smallest edit that satisfies the playbook, recording the rule version and reviewer-facing rationale. Preserve untouched runs, numbering relationships, table cells, and document parts. Existing tracked changes require an explicit policy: review the intended current text, retain the previous revision history where supported, and flag ambiguous overlapping edits.

Validation has two layers. First, compare the text obtained by accepting the new revisions with the intended proposed text. Second, render the document and inspect pagination, tables, numbering, and comments. A DOCX that is syntactically valid can still contain a misleading redline or broken layout. The reviewer should be able to accept or reject individual changes without losing the original document's structure.
