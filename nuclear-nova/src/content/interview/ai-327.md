## Question

Find the top-K most frequent items in a high-volume event stream with bounded memory.

## Brief answer

Use a heavy-hitter algorithm such as Space-Saving when memory must stay bounded and the key space is large. It keeps a fixed number of candidate keys with estimated counts and errors. Results are approximate: return uncertainty and avoid claiming exact top-k when candidate intervals overlap or the stream distribution is too flat.

## Detailed answer

This simple Space-Saving reference uses $m$ counters and $O(m)$ update time when replacement is needed. A heap or indexed structure can improve update cost, with extra bookkeeping.

```python
class SpaceSaving:
    def __init__(self, capacity):
        if capacity < 1:
            raise ValueError("positive capacity required")
        self.capacity = capacity
        self.counts = {}  # key -> (estimate, maximum overestimate)

    def add(self, key):
        if key in self.counts:
            count, error = self.counts[key]
            self.counts[key] = (count + 1, error)
        elif len(self.counts) < self.capacity:
            self.counts[key] = (1, 0)
        else:
            victim = min(self.counts, key=lambda x: self.counts[x][0])
            count, _ = self.counts.pop(victim)
            self.counts[key] = (count + 1, count)

    def top(self, k):
        return sorted(self.counts.items(), key=lambda x: -x[1][0])[:max(k, 0)]

s = SpaceSaving(2)
for item in ["a"] * 8 + ["b", "c"]:
    s.add(item)
assert s.top(1)[0][0] == "a"
assert len(s.counts) == 2
assert s.counts["c"] == (2, 1)  # true count is between 1 and 2
```

For each retained key, true frequency lies between estimate minus error and estimate. Choose capacity larger than k, define lifetime versus windowed counts, and specify how distributed summaries are merged; naive concatenation is not a valid general merge rule. The Space-Saving paper presents the algorithm and guarantees.

### Alternative sketches and distributed windows

Choose capacity based on the minimum frequency worth detecting, not just the requested output k. Misra–Gries with m counters retains all keys whose frequency exceeds $N/(m+1)$; a second pass over stored data can obtain exact counts for candidates. Count-Min Sketch uses hashed counters and gives overestimates with probabilistic error bounds under its hash assumptions.

For distributed processing, use compatible hash seeds for mergeable sketches and a documented merge method for candidate summaries. Define event-time windows, late-data policy, duplicate handling, and expiration. Report uncertainty when top candidates have overlapping bounds. Test skewed and nearly uniform streams: the latter may have no clearly identifiable top-k under the available memory. Use exact sampled windows as a monitoring baseline for approximation quality.

### Understand replacement error

With two counters containing A=8 and B=1, a new C replaces B and receives estimate 2 with error 1. The algorithm does not claim C occurred twice; it records that C's true count lies between 1 and 2. The inflated estimate prevents a newly tracked key from being unfairly treated as if it could never have appeared before it entered the table.

For retained candidates whose intervals overlap, report approximate rank rather than asserting an exact order. A capacity of k counters is often too small to distinguish k nearly tied keys, so size memory for an acceptable frequency error and workload skew. Test a dominant key followed by a long distribution shift, as lifetime heavy hitters respond differently from windowed ones. A sliding-window requirement needs expiration-aware summaries or time buckets; decrementing this implementation naively invalidates its guarantees.
