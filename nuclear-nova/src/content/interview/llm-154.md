## Question

How do you diagnose missing content in a RAG system?

## Brief answer

If required content is absent from the corpus or was lost during ingestion, retrieval tuning alone cannot recover it.

## Detailed answer

Check source availability, ingestion logs, parser output, OCR, chunk exclusions, permissions, and index freshness. Compare a known source passage with its indexed representation. Repair or reingest the missing content, then run a targeted retrieval check. If no authorized evidence exists, ask for the source or return an explicit insufficient-evidence response rather than synthesizing a plausible answer.

Start with a known expected passage and trace its identity. Confirm that the original document exists in the allowed corpus and that its version is current. Inspect ingestion logs and parsed text for that exact page or section. If the passage is missing there, check OCR, unsupported file types, extraction exclusions, and document-size limits before examining retrieval settings.

If parsing preserved it, locate the chunk and its index entry. Verify that document updates did not leave an obsolete chunk active, and that deletion or reindexing completed consistently. Check access filters using the intended user identity; a correctly excluded restricted source is not a retrieval bug to bypass.

After repair, run a targeted query that should recover the passage, then a natural paraphrase from the evaluation set. Add both the ingestion case and the question as regression fixtures. If the information is not in any authorized source, return that limitation or request the needed material. A plausible generated answer cannot fill an evidence gap reliably, and increasing top-k cannot retrieve a record that never entered the searchable collection.
