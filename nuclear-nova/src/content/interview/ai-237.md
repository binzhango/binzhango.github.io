## Question

Write an iterator class that lazily flattens an arbitrarily nested list of lists/integers: no generators, explicit state.

## Brief answer

Use an explicit stack of list iterators and advance until an integer is found. Each nested list adds an iterator; an exhausted iterator is popped. This avoids recursion and generators while preserving lazy traversal.

## Detailed answer

The input contract is a finite, acyclic tree of lists and integers. This implementation does not copy the input and does not support concurrent mutation of its lists. Empty lists are skipped and repeated exhaustion continues to raise `StopIteration`.

```python
class FlattenIterator:
    def __init__(self, values):
        self.stack = [iter(values)]

    def __iter__(self):
        return self

    def __next__(self):
        while self.stack:
            try:
                value = next(self.stack[-1])
            except StopIteration:
                self.stack.pop()
                continue
            if isinstance(value, list):
                self.stack.append(iter(value))
            elif type(value) is int:
                return value
            else:
                raise TypeError('expected list or integer')
        raise StopIteration

assert list(FlattenIterator([1, [], [2, [3]], 4])) == [1, 2, 3, 4]
assert list(FlattenIterator([[], [[]]])) == []
deep = 7
for _ in range(2000):
    deep = [deep]
assert list(FlattenIterator(deep)) == [7]
```

Total traversal time is O(n) in all visited list/element nodes, with O(d) auxiliary state for maximum nesting depth. One `next()` may cross many empty lists, so it is not worst-case O(1). For a `hasNext()` interface, add one buffered value and an explicit empty-buffer sentinel; repeated probes must not consume additional integers.

### The stack is the suspended traversal

For `[1, [2, [3]], 4]`, the first call returns 1 from the root iterator. Encountering the nested list pushes its iterator; later encountering `[3]` pushes another. When an inner iterator ends, popping it resumes its parent exactly where it stopped. No recursive call stack or precomputed flattened output is needed.

Laziness means the iterator can return early without visiting the rest of the structure. A deeply nested empty branch can still make one call expensive, so only total traversal is linear; do not claim constant worst-case latency for `next`. The explicit state grows with nesting depth, not total output size. The strict `type(value) is int` check excludes Boolean values even though Python considers them integer subclasses. Cyclic lists would never finish under this tree contract; either reject them through separate validation or document the unsupported input. For a `hasNext` extension, cache one discovered integer and consume it only on `next`, so repeated probes do not advance the sequence.
