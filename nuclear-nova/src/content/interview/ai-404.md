## Question

When would you fine-tune instead of using RAG or prompt engineering, and if you do, LoRA or full fine-tuning?

## Brief answer

Use prompting for behavior that the base model already supports, RAG for current or access-controlled knowledge, and fine-tuning for persistent task behavior, style, or domain patterns supported by enough examples. These techniques can be combined. Fine-tuning is not a reliable database update mechanism, and RAG cannot fix every reasoning or format-following weakness.

## Detailed answer

Start with a representative heldout set and inspect failure causes. If answers lack evidence, improve retrieval and source quality. If the evidence is present but the model repeatedly mishandles a specialized task, compare better prompting, model choice, and supervised adaptation.

LoRA trains a small low-rank parameter set, reducing optimizer memory and simplifying distribution of task variants. Full fine-tuning updates all weights and offers more flexibility but needs more memory, data discipline, and regression testing. Choose based on measured quality and operational cost, not a belief that full tuning is inherently superior. Validate privacy, memorization, catastrophic forgetting, and base-model compatibility, and keep retrieval for facts that change frequently.

### Match the intervention to the failure

If the model cannot answer a policy question because the policy is missing or outdated, retrieval addresses evidence freshness. If it receives the correct passage but repeatedly emits the wrong structured format, prompting or fine-tuning addresses behavior. If a task requires a capability the base model lacks, neither a few examples nor a small adapter is guaranteed to create it; compare a more suitable model.

LoRA represents weight changes with low-rank matrices, reducing trainable parameters and optimizer state while leaving the base mostly fixed. It is attractive for several task variants and limited memory. Full fine-tuning offers unrestricted parameter updates but costs more and can overwrite broad capabilities. Evaluate both on heldout task families and general regression tests, with equivalent data quality and useful compute budgets. Frequently changing facts should still come from current sources after tuning. Treat fine-tuning data as a product asset with provenance, redaction, and deletion considerations, rather than using raw support logs because they are available.
