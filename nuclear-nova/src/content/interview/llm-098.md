## Question

What’s the typical SFT workflow?

## Brief answer

A typical SFT workflow is baseline evaluation, dataset preparation, format and loss checks, pilot training, full training, checkpoint selection, and deployment validation.

## Detailed answer

Render several tokenized examples and inspect exactly which targets contribute to loss. Run a small-batch sanity check, then tune learning rate, effective batch size, duration, and PEFT settings if used. Track validation metrics and general-capability regressions. Select on held-out task utility; preserve the tokenizer, template, training configuration, and data version. Recheck the final exported or quantized artifact because deployment transformations can alter behavior.

Begin with a fixed baseline evaluation and a documented target behavior. Prepare leakage-safe splits, tokenize representative examples, and print their loss masks. Check that each example contains supervised answer tokens and that packed examples do not accidentally attend across boundaries when the intended training design forbids it.

Run a pilot that can overfit a tiny clean sample, then train on a small realistic mixture and compare held-out task metrics. Tune learning rate, microbatch size, accumulation, duration, and trainable modules using the development set. Track general-capability regressions as well as target gains, and save intermediate checkpoints so selection is not limited to the final step.

Effective batch size equals microbatch size times accumulation steps times data-parallel replicas when examples are distributed conventionally; variable token lengths still change the number of supervised tokens per update. Record both examples and tokens. After selecting a checkpoint, export the required weights or adapter together with tokenizer and configuration. Test the actual inference template, numerical precision, output schema, and failure cases. A training run that completes without an exception is not sufficient evidence that the deployed assistant learned the intended behavior.
