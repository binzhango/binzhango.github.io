## Question

Conversations average around 180 messages. Design the cache used between turns.

## Brief answer

Cache immutable conversation prefixes and the associated KV blocks by exact token sequence, model/runtime version, and privacy scope. Keep durable conversation state separate from accelerator memory so eviction does not lose history. A 180-message average calls for a retention policy, not unlimited GPU-resident sessions.

## Detailed answer

**Suggested approach.** Represent each session as an append-only token chain with references to reusable prefix blocks. Reuse the stable system/persona prefix and unchanged history; invalidate from the first changed token after an edit or compaction. Store cache metadata in a scheduler-visible service and evict inactive sessions using size, recency, and expected recomputation cost.

Offload cold blocks to host memory only when transfer costs beat recomputation under the latency target. Bind cache keys to tenant and model details to prevent cross-user leakage or invalid reuse. Monitor hit rate by reused tokens, not just requests, along with eviction churn and first-token latency. Test model upgrades, persona edits, deleted messages, concurrent turns, and permission changes. Durable transcripts remain the source of truth; a KV cache is disposable derived state.

### Cache a versioned token prefix

Store blocks under a key containing the exact prefix tokens, model weights revision, tokenizer and chat-template version, relevant positional configuration, and privacy scope. A conversation turn appends blocks; editing an earlier message invalidates the suffix after that edit. Keeping cached states beyond the first changed token would reuse activations computed from different input and can produce incorrect output.

The session record maps durable conversation revisions to disposable cache blocks. Reference counts permit safe sharing of an identical system prefix where the privacy policy allows it. Eviction releases accelerator blocks without deleting the transcript, so an inactive conversation can resume by recomputing its state. Concurrent turns should branch from explicit revisions rather than racing to mutate one shared suffix.

Count saved token work and memory occupancy, not only cache-hit requests. Reusing ten tokens and reusing ten thousand both count as a hit but have very different value. A practical eviction score considers block size, recency, expected reuse, and recomputation cost. Long sessions may need compaction even with caching because caching lowers repeated compute but does not make retained state free.
