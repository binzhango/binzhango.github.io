## Question

After fine-tuning on a customer's task, target accuracy is up but the model got worse at everything else. What happened and what do you do?

## Brief answer

This is a likely specialization/forgetting tradeoff, but first rule out evaluation and inference changes. Compare the same prompts, tokenizer, chat template and decoding settings before attributing every regression to changed weights.

## Detailed answer

Inspect whether the fine-tuning data is narrow, repetitive, mislabeled or incompatible with the desired assistant format. Check update magnitude, learning rate, training duration and retained-capability evaluation. Reduce the learning rate or stop earlier, mix representative retention data, or compare a limited adapter with full tuning. A frozen backbone does not guarantee unchanged outputs when adapters are active. Keep both target-task and general suites in the release gate, and quantify the tradeoff instead of accepting one improved score. If the new task mainly needs fresh knowledge, retrieval may avoid unnecessary weight changes.

### Specialization can move useful representations

Fine-tuning repeatedly rewards patterns in a narrower dataset. Large or prolonged updates can move weights away from representations that supported other tasks, while the model also learns style and formatting artifacts of the new examples. If every answer in training uses one language or template, broad instruction behavior may deteriorate even when target accuracy rises.

Compare a frozen-base prompt baseline, early checkpoints, an adapter, and full tuning on the same target and retention suites. Check per-task trade-offs rather than one averaged general score. Mix representative retention data when permitted, reduce learning rate or update scope, and stop at the checkpoint that meets both acceptance criteria. An adapter preserves the base file but still changes active outputs, so it needs the same regression evaluation. If the customer task is primarily fetching current policies, retrieval may solve it with less risk of forgetting. Preserve the exact tokenizer/template and decoding settings to distinguish actual weight changes from an accidental inference mismatch.
