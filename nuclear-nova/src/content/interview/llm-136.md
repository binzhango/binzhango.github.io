## Question

Why is table recognition important?

## Brief answer

Table recognition preserves relationships among values, row labels, column headers, units, and footnotes.

## Detailed answer

A value such as “12.4” is meaningless without its metric, time period, and units. Flattening a table into arbitrary text can associate it with the wrong row or column. Store a structured representation and a readable serialization with source coordinates. For exact aggregates or arithmetic, retrieve the relevant table and use validated computation instead of relying solely on a language model's interpretation.

Consider a table with columns “2024 revenue,” “2025 revenue,” and “USD millions.” The cell `12.4` only becomes a fact when connected to its row entity, year, measure, and unit. Flattening cells into a stream of numbers can preserve every character while destroying those relationships. Merged headers and footnotes may further restrict which cells a label applies to.

Store a structured table with rows, columns, spans, and source coordinates, plus a readable representation for retrieval. Include repeated header context when a table is split into chunks. If a question asks for the percentage increase from 10 to 12.4, calculate $(12.4-10)/10\times100=24\%$ after verifying that both values use the same measure and units.

Validate extraction with shape checks, header consistency, and domain-specific constraints where appropriate. Totals can help detect a lost row, but not every table total is a simple sum. Use deterministic computation for exact aggregates, and cite the original cells or table region. A language model can explain the result, while the extraction and calculation pipeline establishes which values were actually used.
