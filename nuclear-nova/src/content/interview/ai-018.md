## Question

What is continuous (in-flight) batching and why did it replace static batching?

## Brief answer

Continuous batching admits and removes requests between generation steps instead of waiting for an entire fixed batch to finish. It reduces idle slots when response lengths differ and supports better utilization under interactive traffic.

## Detailed answer

After each iteration, retire completed sequences, reclaim their cache blocks, and admit waiting work within token and memory budgets. Scheduling only by request count is unsafe because prompts and outputs differ greatly in size. Include fairness, cancellation, maximum waits and output reservations to prevent overload. Continuous batching is common, but static batches remain useful for predictable offline jobs. Measure throughput together with tail latency and admission delay, not GPU occupancy alone.

Imagine three requests with output lengths 2, 20 and 200 tokens. In a static batch, two slots stop doing useful work early while the longest request continues. Continuous batching replaces a finished request with a waiting one at the next scheduling boundary, so the GPU processes more useful tokens without waiting for the whole group.

The scheduler must make several decisions together: which decode requests receive a step, which new prompts can enter, how much prefill to run, and whether enough KV space remains for growth. A token budget reflects work more accurately than a fixed request limit. A 20,000-token prompt and a ten-token prompt are not interchangeable admissions. Preemption can recover capacity but may require recomputation or expensive cache movement.

Fairness matters because maximizing immediate throughput can starve long prompts or low-volume tenants. Use aging, per-tenant quotas and explicit latency classes, and ensure cancellation promptly releases cache blocks. Evaluate under bursty open-loop arrivals so the test includes queue buildup; a closed-loop client can hide overload by slowing its own request rate. The desired outcome is sustained throughput within TTFT and inter-token limits, not merely a full GPU queue.
