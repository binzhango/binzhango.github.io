## Question

Design a rate limiter for an LLM API where cost scales with tokens, not requests.

## Brief answer

Charge admission against token budgets, reserving estimated input plus a bounded output allowance before execution and reconciling actual usage afterward. Use separate controls for rate, concurrent requests and outstanding reserved work.

## Detailed answer

A tenant that sends one million-token request is different from one sending ten short requests. Resolve tokenization and model-specific prices at the gateway; a reservation must include a hard generation cap, not an unbounded estimate. Debit atomically, return a retry delay when the bucket lacks capacity, and refund unused output reservation once. Idempotency keys prevent retries and repeated stream-finalization events from double charging. In a distributed service, use a strongly consistent quota authority or bounded leased budgets with a documented overshoot limit. Track canceled requests and provider-reported usage so reconciliation cannot create free expensive work or permanently strand reservations.

### Work through admission and settlement

Suppose a tenant has 10,000 available token credits. A request contains 2,000 input tokens and permits at most 1,000 output tokens, so admission reserves 3,000. If it produces 400 output tokens, actual usage is 2,400 and 600 credits can be refunded once. If the stream disconnects after generating those tokens, the generated work still counts even if the client did not read it all.

A token bucket permits bounded bursts and refills at the tenant's allowed rate. Separate a concurrency cap because many long-lived small requests can exhaust cache while remaining within token rate. If different models have different costs, define weighted credits or separate model budgets rather than treating every token as equal dollars. Distributed admission must atomically check and debit; two gateways reading the same balance cannot both spend it. Retain request IDs and finalization state, reconcile crashes, and bound unsettled reservations. Report retry timing and overload clearly instead of accepting work that cannot meet its resource contract.
