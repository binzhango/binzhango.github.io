## Question

Devin runs asynchronously in the cloud; Windsurf's Cascade runs in the editor next to the user. What actually changes between those two products, technically?

## Brief answer

A cloud agent optimizes durable asynchronous execution and isolated workspaces; an editor agent optimizes immediate interaction with live buffers and user intent. The distinction changes state ownership, latency, conflict handling, credentials, and notification design. Product names illustrate deployment styles here, not undocumented claims about their current internals.

## Detailed answer

For an asynchronous cloud workflow, capture a task specification and repository base, persist progress, survive long waits, and deliver an auditable patch or pull request. The user may be absent, so escalation and pause states must be explicit. Credentials should be scoped to the remote environment and expire independently of a laptop session.

An editor workflow must observe unsaved changes, cursor position, and rapid user corrections. Suggestions become stale quickly, so cancellation, buffer-version checks, low-latency context updates, and coherent undo behavior dominate. It also needs boundaries between local-only data and cloud requests. Both require permission enforcement and verification, but their failure recovery differs: cloud agents resume durable tasks, while editor agents must avoid interrupting or overwriting an active human workflow.

### State ownership changes the protocol

In a cloud task, the repository snapshot and durable task ledger define the work state. The agent can continue while the user disconnects, but cannot assume the user's local branch remains unchanged. Its deliverable needs a base revision and a mergeable patch, plus a clear waiting state when input or authorization is required.

In an editor, the active buffer is authoritative even when it has never been saved. Every proposed edit needs a buffer version or expected-text anchor, and cancellation should react to new typing or a changed selection. A cloud-style agent that simply overwrites files after a long run would violate that ownership model.

The architecture can share a planner, model gateway, and tool schemas while using different execution adapters. The cloud adapter provides durable jobs and asynchronous notifications; the editor adapter provides low-latency buffer transactions and undo. Test each against its own failure conditions: reconnect after a long external wait for the former, and simultaneous user edits plus stale model output for the latter. Deployment location affects these contracts even if both products call the same underlying model.
