## Question

Convert a binary tree to a circular doubly linked list.

## Brief answer

Traverse the binary tree in order, link each visited node to its predecessor and then connect the first and last nodes to make the list circular. Reuse left as previous and right as next. If the input is a BST, the resulting order is sorted; for a general binary tree it is simply the in-order sequence.

## Detailed answer

```python
from dataclasses import dataclass

@dataclass
class Node:
    value: int
    left: object = None
    right: object = None

def circular_list(root):
    head = previous = None
    def visit(node):
        nonlocal head, previous
        if node is None: return
        original_right = node.right
        visit(node.left)
        if previous is None: head = node
        else: previous.right = node
        node.left = previous
        previous = node
        visit(original_right)
    visit(root)
    if head is not None:
        head.left = previous; previous.right = head
    return head

head = circular_list(Node(2, Node(1), Node(3)))
assert [head.value, head.right.value, head.right.right.value] == [1,2,3]
assert head.right.right.right is head and head.left.value == 3
assert circular_list(None) is None
```

The conversion mutates the original tree, so callers must not continue using it as a tree. Saving the original right child avoids confusion while rewiring pointers. Time is O(n) and recursive auxiliary space O(height), not O(1). A singleton must point to itself in both directions; verify forward and backward traversal for exactly n nodes to catch broken cycles.

In-order traversal visits the left subtree, then the node, then the right subtree. At the moment a node is visited, `previous` is exactly its predecessor in that order, so linking `previous.right = node` and `node.left = previous` builds the list incrementally. The first visited node becomes `head`; the final `previous` is the tail.

Only after traversal completes should the circular links be installed. Setting them too early can make a traversal follow a newly created cycle rather than the original tree. Saving the original right child protects traversal while pointers are repurposed. A single-node tree must end with both pointers referencing itself.

Validate by walking exactly n steps forward and backward, checking reciprocal links and return to the head. Do not use an unbounded traversal to test a potentially broken cycle. The input is consumed by the conversion; callers requiring the original tree need copied nodes. Sorted output is guaranteed only when the original tree satisfies the BST ordering property.
