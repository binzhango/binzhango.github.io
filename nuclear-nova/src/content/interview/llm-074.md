## Question

How important are negative samples in contrastive learning, and how to handle costly negative sampling?

## Brief answer

Useful negatives teach the distinctions a retriever must make; in-batch negatives, cached embeddings, and mined candidates reduce collection cost.

## Detailed answer

Random negatives are cheap but can become too easy. Hard negatives resemble the query yet do not answer it, producing a more informative comparison. Filter false negatives, because another relevant document should not be pushed away merely because it lacks an annotation. Mix easy and hard examples, refresh stale mined candidates, and evaluate on held-out queries. Larger batches increase negative coverage but also memory use and false-negative risk.

In-batch negatives reuse other examples' documents, giving many comparisons without a separate search for each query. Their cost is largely the similarity matrix and larger training batch. The assumption is that another query's positive document is negative for the current query, which fails when several queries ask about the same subject or share valid answers.

Hard-negative mining runs a retriever to find high-ranked but non-answering passages. For “What is the warranty period?”, a passage about the return period is more informative than an unrelated cooking article because it teaches a distinction the deployed retriever may confuse. Verify negatives using labels, source evidence, or review; the highest-ranked unlabeled document may actually contain another correct answer.

Use a mixture so training retains broad separation while learning close distinctions. Refresh mined candidates as the model improves, because yesterday's hard examples can become trivial. Cached document embeddings reduce encoding cost but become stale when the encoder changes. Track retrieval recall on held-out queries and difficult entity/version slices rather than using training loss alone to decide whether the negative pool is useful.
