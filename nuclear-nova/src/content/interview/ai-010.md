## Question

What is a mixture-of-experts architecture and how does it scale capacity without scaling FLOPs?

## Brief answer

A sparse mixture of experts routes each token to a small subset of feed-forward experts. This increases total parameter capacity while limiting the number of expert parameters used for each token.

## Detailed answer

A router scores experts, selects a top-k subset, and combines their outputs. Total parameter memory still grows, and routing adds communication and load-balancing costs. Hot experts can bottleneck a distributed step; auxiliary objectives or routing strategies encourage more balanced utilization. Attention and shared layers also consume compute, so “constant FLOPs” is an approximation under a fixed routing configuration. Report total parameters, active parameters, communication, and measured latency separately.

A typical sparse layer replaces one feed-forward network with $E$ alternatives. For token state $x$, a router computes scores, selects $k$ experts and returns a weighted sum of their outputs. If $E=64$ and $k=2$, only two expert networks process that token, even though all 64 sets of weights exist. Increasing $E$ with fixed expert width and fixed $k$ increases capacity much more than per-token arithmetic.

The hidden cost is moving tokens to the devices holding the selected experts. Dispatch gathers token states by expert, expert matrix multiplications run, and a combine operation returns weighted results to the original token order. Uneven routing can leave one device busy while others wait. Capacity limits may drop or reroute excess tokens, so their semantics must be included in correctness and quality evaluation.

Expert specialization is learned and need not align neatly with human topics. A token does not reliably choose a named “math expert.” Sparse activation also does not mean weights for inactive experts can be removed permanently; later tokens may need them. Small batches can produce tiny inefficient expert matrix operations, while larger batches improve utilization but increase latency. Compare training quality per compute and serving latency per memory footprint separately.
