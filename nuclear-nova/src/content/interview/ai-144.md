## Question

Design APIs for developers to access Anthropic's models securely and efficiently.

## Brief answer

Offer versioned model-inference APIs with scoped authentication, token-aware quotas, explicit model selection and streaming. Separate request validation and authorization from model execution. Stable error codes, request IDs, usage accounting and documented retry behavior matter as much as the generation payload for developers operating production systems.

## Detailed answer

Suggested endpoints cover model discovery, message generation, batch jobs and asynchronous job status. A generation request includes model/version, typed messages, bounded output tokens and optional tool schemas. Streaming events identify start, content deltas, tool-call deltas, usage and terminal status; clients must distinguish completion from a broken connection.

Store API keys as protected credentials, scope them by project and restrict sensitive operations independently. Enforce payload limits, per-tenant resource budgets and fair scheduling. Idempotency keys should have a defined retention period and behavior when the same key arrives with different content.

Document which errors are retryable and provide retry-after information for throttling. Support observability without logging raw sensitive prompts by default. Evaluate SDK ergonomics with malformed tool arguments, partial streams and canceled requests. These are proposed public contracts, not assertions about the current API of any named provider.

Make the API contract precise about lifecycle. A request ID identifies an attempt, while an idempotency key identifies one logical operation; retries can have different attempt IDs but the same logical key. Reject reuse of that key with materially different payloads. A streaming response needs a terminal event so clients can distinguish completed output from a disconnected transport.

Quota accounting should reserve estimated work before admission and reconcile actual usage afterward, including canceled streams and retries. Per-project limits prevent one compromised key or runaway client from consuming an organization's entire budget. Version model capability metadata so clients can discover whether tools, structured output or modalities are supported without trial-and-error failures.

Security checks belong before model execution and before any downstream tool effect. Protect credentials, scope access, bound payloads and avoid echoing sensitive input in errors. Test SDKs with arbitrary stream chunk boundaries, malformed events, retryable throttles and permanent validation errors. Developer experience is improved by predictable semantics and actionable errors, not by hiding all provider-specific behavior behind an interface that silently changes meaning.
