## Question

How would you cut LLM serving cost by 10x? Enumerate every lever and rank them.

## Brief answer

Start with the dominant cost in measured production traffic, then reduce unnecessary work, improve batching and caching, and select a smaller or lower-precision model where quality permits. A tenfold saving is a hypothesis, not a guaranteed tuning result.

## Detailed answer

Compute cost per successful task, including retries and tool calls. First cap runaway outputs and eliminate repeated requests; next improve prefix reuse, scheduling and utilization. Test retrieval/context reduction, model routing, distillation and quantization behind quality gates. Hardware or provider changes come after workload characterization. Rank changes by expected saved GPU-seconds, implementation effort and quality risk. If the current stack is already efficient, changing the product workload may be necessary to reach 10x.

Construct a cost model before ranking optimizations. If 70% of GPU time is spent generating unnecessarily long responses, optimizing prompt tokenization cannot deliver 10x. If most requests queue behind underfilled replicas, better routing and batching may matter more than quantization. Measure input tokens, generated tokens, retries, cache reuse and successful task completion for each major workload.

A practical ranking is: remove duplicate or abandoned work; shorten outputs and irrelevant context; reuse identical prefixes and safe application results; improve continuous batching and replica utilization; route easy tasks to smaller models; quantize or distill within quality limits; then consider specialized kernels, hardware changes and prefill/decode separation. The order changes with the measured bottleneck. Speculative decoding can reduce latency but does not automatically reduce total compute cost.

An illustrative combination of halving generated tokens, doubling useful utilization and reducing model cost by 2.5x would multiply to 10x only if the savings are independent. They often are not: a smaller model might change batching efficiency, and a cache can leave less room for concurrent KV. Roll out one change at a time with paired quality checks and compare cost per resolved task, including retries and escalations, rather than cost per raw token alone.
