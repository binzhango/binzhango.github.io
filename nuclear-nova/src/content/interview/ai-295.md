## Question

Qwen2.5-Coder trains with repository-level fill-in-the-middle using tokens like <|fim_prefix|>, <|fim_suffix|>, <|repo_name|>. Write the function that formats a repo-level FIM example, and explain why repo-level beats file-level.

## Brief answer

Serialize repository identity and relevant neighboring files, then represent the target file with prefix, suffix, and a missing-middle marker. The training target is the withheld middle. Repository context can resolve imported types and cross-file contracts, but only if the useful files fit the context and the missing answer is not leaked elsewhere.

## Detailed answer

This explicit training-example convention uses Qwen2.5-Coder's documented special markers. Check the checkpoint's expected layout before training; formatting is part of the model interface.
```python
TOKENS = ("<|repo_name|>", "<|file_sep|>", "<|fim_prefix|>",
          "<|fim_suffix|>", "<|fim_middle|>", "<|endoftext|>")

def repo_fim(repo, files, target, start, end):
    if target not in files or not 0 <= start <= end <= len(files[target]):
        raise ValueError("invalid target span")
    values = [repo, *files.keys(), *files.values()]
    if any(t in value for t in TOKENS for value in values):
        raise ValueError("reserved marker in source")
    context = f"<|repo_name|>{repo}\n"
    for path in sorted(files):
        if path != target:
            context += f"<|file_sep|>{path}\n{files[path]}\n"
    text = files[target]
    prompt = (context + f"<|file_sep|>{target}\n<|fim_prefix|>"
              + text[:start] + "<|fim_suffix|>" + text[end:]
              + "<|fim_middle|>")
    return prompt, text[start:end] + "<|endoftext|>"

prompt, answer = repo_fim("demo", {"a.py": "x=12\n"}, "a.py", 2, 4)
assert "12" not in prompt and answer == "12<|endoftext|>"
assert prompt.endswith("<|fim_middle|>")
assert repo_fim("r", {"x": ""}, "x", 0, 0)[1] == "<|endoftext|>"
```

Offsets are Python character offsets, not token offsets. Apply token-budget selection before serialization and mask prompt tokens in a completion-only loss. Test cross-file symbol resolution against file-only examples; extra irrelevant files can reduce quality rather than improve it.

### Why the surrounding repository helps

Suppose the missing body calls `load_customer`, whose return type and error behavior are defined in another file. A file-only example forces the model to guess that contract; repository context can show that it returns `None` for missing customers and uses cents for monetary values. The target suffix also constrains what fits after the hole, which is why fill-in-the-middle differs from ordinary continuation.

The function returns the serialized prompt separately from the supervised completion. Masking the prompt's loss prevents training from spending most of its objective copying irrelevant context. It rejects reserved markers inside source so unescaped source text cannot accidentally alter the example structure. Output length is linear in included text size; for large repositories, build fragments and join them once to avoid repeated string-copying costs. Selecting useful files is a separate retrieval problem. Split train and evaluation by repository family and revision lineage: near-identical forks can leak solutions even when filenames differ. Check empty holes, Unicode offsets, and budget truncation that preserves all required control markers.
