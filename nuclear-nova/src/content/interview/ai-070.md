## Question

How do you detect and measure hallucinations in a production RAG system?

## Brief answer

Measure unsupported claims against the evidence actually available to the system, separating factual error, unsupported inference and citation mismatch. Sample both ordinary traffic and high-risk failure slices.

## Detailed answer

Break responses into claims and check each against cited spans and trusted references. A claim may be true externally but unsupported by the supplied RAG context, so report grounding separately from world accuracy. Audit automated entailment judgments with humans, especially for numbers, negation and temporal qualifiers. Log the document versions used and whether the query was answerable. Include abstention quality so reducing hallucinations by refusing everything cannot appear successful.

Store the evidence bundle used for each sampled answer, including document revisions and retrieval decisions. Then split the answer into checkable claims. A claim can be supported, contradicted, absent from the evidence or too ambiguous to judge. Preserve qualifiers: “may,” “must,” “before” and “after” can change the meaning even when the same nouns and numbers appear.

For example, a passage saying a feature is available only on the enterprise plan does not support an answer saying it is available to every customer. A citation to that passage is syntactically valid but substantively wrong. Conversely, an externally true statement may still violate a product requirement that answers rely solely on approved documents. Track world accuracy and evidence grounding separately.

Measure unsupported-claim rate, severity-weighted errors, citation precision and completeness, with answer-level metrics for whether any material hallucination occurred. Include unanswerable queries and score whether abstention was appropriate. Audit automatic entailment classifiers against human review, particularly for tables, arithmetic and temporal conflicts. For diagnosis, rerun generation with gold evidence: if errors disappear, improve retrieval or context assembly; if they remain, improve generation instructions, model capability or validation. Reducing output length or refusing everything must not count as success without preserving useful task completion.
