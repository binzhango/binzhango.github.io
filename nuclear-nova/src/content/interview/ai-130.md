## Question

SQL: determine whether any user has overlapping subscription date ranges.

## Brief answer

Two half-open subscription ranges overlap when each starts before the other ends. Self-join rows for the same user, compare each pair once and treat a null end as unbounded. Adjacent ranges that meet at an endpoint do not overlap under this convention.

## Detailed answer

Assume valid nonempty intervals `[start_at, end_at)` and unique subscription IDs.

```sql
SELECT DISTINCT a.user_id
FROM subscriptions a
JOIN subscriptions b
  ON a.user_id = b.user_id
 AND a.subscription_id < b.subscription_id
 AND (b.end_at IS NULL OR a.start_at < b.end_at)
 AND (a.end_at IS NULL OR b.start_at < a.end_at);
```

To return a boolean, wrap the query in `SELECT EXISTS(...)`. Validate `end_at > start_at` when the end exists; malformed intervals otherwise make reasoning unreliable. A common faulty optimization compares only each interval's end with the next start: it misses nested long intervals when shorter intervals intervene. A running maximum of prior end times can support a sorted window-function solution, provided open-ended intervals are handled explicitly. Test identical ranges, nesting, touching endpoints, different users and unbounded subscriptions.

The overlap condition follows from excluding the two non-overlap cases: A ends at or before B starts, or B ends at or before A starts. Negating those conditions gives strict inequalities for half-open intervals. Thus `[1,3)` and `[3,5)` touch but do not overlap, while `[1,4)` and `[3,5)` do.

The self-join compares each pair for a user once through the subscription-ID ordering. A null end is treated as infinity, so it overlaps any later-starting interval unless that interval ended before the open interval began. Define time zones and timestamp precision consistently before comparison; mixing local dates with instants can create apparent overlaps around boundaries.

A pairwise join can be quadratic within a user. A sorted approach can track the maximum prior end, but comparing only the immediately previous interval is wrong when a long interval contains several short ones. Keep an exact self-join as a small-data oracle for testing the optimized version. Include nested intervals, identical starts, unbounded ends and invalid zero-length records in the validation suite.
