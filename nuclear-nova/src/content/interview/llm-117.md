## Question

How can Agents access conversation context?

## Brief answer

Agents access conversation context through explicit state or retrieved memory that the application supplies to each model call.

## Detailed answer

Combine recent messages, relevant past facts, tool results, and application state within a token budget. Scope storage and retrieval to the correct user and conversation; an embedding similarity score is not an authorization decision. Distinguish short-term thread state from long-term information shared across sessions. Store provenance and support updates or deletion, because old preferences and summaries can become stale.

Context construction is an explicit application operation. Load the correct thread state, select recent messages, retrieve any relevant durable memories, add trusted application facts and tool results, then fit those pieces into the model's token budget. The model has no inherent access to a database of previous conversations unless the application exposes it.

For “use the shipping address I gave last time,” a system may need long-term memory rather than the current thread transcript. Retrieve the stored address with its provenance and update time, confirm it belongs to the current user, and account for any later correction. Similarity matching alone can retrieve a plausible but wrong person's address if authorization is omitted.

Treat summaries as derived records that can lose details. Preserve links or identifiers to original messages for exact constraints, and allow stale memories to be corrected or deleted. Test delayed references, contradictory updates, separate users with similar topics, and resumed threads. Useful memory means supplying the right information for this call; merely storing more messages can increase noise and privacy exposure without improving the answer.
