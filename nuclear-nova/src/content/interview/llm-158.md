## Question

How does RAG-Fusion work, and what are its benefits and tradeoffs?

## Brief answer

RAG-Fusion generates multiple search queries, retrieves a ranked list for each, and fuses the lists before generation, often with reciprocal rank fusion (RRF).

## Detailed answer

For document $d$:

$$
\operatorname{RRF}(d)=\sum_{r:d\in r}\frac{1}{c+\operatorname{rank}_r(d)},
$$

where ranks start at 1 and $c>0$ controls rank sensitivity. Keep stable document IDs, merge repeated results, and usually retain the original query. A document ranking 1st and 3rd in two lists with $c=60$ scores $1/61+1/63\approx0.03227$. RRF combines ranks without needing comparable raw scores; the score is not a relevance probability.

Multiple formulations can improve coverage, but add cost and query-drift risk. RRF alone is a general fusion method and does not require an LLM.

Suppose a user asks why a deployment becomes slow after scaling. Query generation might produce alternatives about startup latency, resource contention, and network communication. Each search returns a ranked list; RRF gives a document credit when it ranks well in one or several lists, using stable document IDs to combine occurrences. This avoids treating raw scores from different retrievers as directly comparable.

The constant $c$ controls how sharply rank differences matter. With a large constant, repeated appearance across lists can matter more than a small difference between first and second place. Documents absent from a list contribute zero for that list. After fusion, rerank or select evidence against the original question, then generate from the actual passages.

The main failure is drift: generated queries can assume a cause the user did not establish. Retain the original query, preserve exact entities and constraints, and limit redundant alternatives. Evaluate recall, answer support, added latency, and whether fusion overweights duplicate sources. The fused score is a ranking heuristic, not a probability that a document is true or that its explanation applies to the user's situation.
