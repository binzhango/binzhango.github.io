## Question

A serving system pairs LPX accelerators with NVIDIA GPUs doing prefill and decode attention. Design the serving path across those systems.

## Brief answer

Suggested approach: keep prompt prefill and decode attention/KV state on GPUs, and send intermediate activations to LPX for FFN or MoE execution during each decode layer. This is attention–FFN disaggregation, not just a one-time KV handoff between prefill and decode workers. The repeated cross-system round trips must fit the token-latency budget.

## Detailed answer

NVIDIA's March 2026 LPX architecture description presents this heterogeneous split. Pin model weights, quantization, tensor layouts, and numerical conventions across both backends.

The orchestrator assigns a compatible GPU/LPX group, schedules prefill, then coordinates attention outputs, FFN execution, residual integration, and subsequent layers. Use bounded queues, backpressure, request cancellation, and per-request state ownership. Estimate bytes and round trips per generated token; network latency can dominate even when bandwidth is ample. Handle one-side failure by terminating or restarting from a verified boundary rather than combining stale activations. Benchmark against a GPU-only path at matched context, concurrency, quality, and tail latency.

### Follow one decode layer across backends

In this proposed heterogeneous path, the GPU maintains the attention state and computes the layer's attention contribution. The FFN or selected expert work executes on LPX, and its output returns for the residual and subsequent layer computation as required by the implementation. That is an attention–FFN split within decoding, not simply “GPU prefill, LPX all decode.”

The orchestrator must preserve tensor layout, precision, request identity, and sequence position across every transfer. Bound in-flight activations and propagate cancellation so one stalled side cannot exhaust the other's memory. Account for repeated round trips across layers: low transfer latency can matter more than aggregate bandwidth for a small batch. Keep a GPU-only comparison path and measure complete first-token, inter-token, and task latency with realistic context and concurrency. Published architectural intentions do not establish a measured advantage for an arbitrary model; treat product performance numbers as configuration-specific claims until reproduced for the workload.
