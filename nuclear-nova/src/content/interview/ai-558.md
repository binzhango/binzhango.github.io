## Question

A colleague wants to move the semantic layer to the cloud so you can use a much bigger model. Walk me through the latency budget.

## Brief answer

Keep fast stabilization and safety control onboard; consider cloud computation only for slower semantic planning whose results can tolerate delay and loss. Budget capture, encoding, uplink, queueing, inference, downlink, and local validation, including tail latency. Average network latency is not a sufficient basis for a robot control loop.

## Detailed answer

**Suggested approach.** If a low-level loop runs at 200 Hz, it has 5 ms per cycle; a remote round trip of even 50 ms spans ten cycles before inference. Use the cloud to propose goals or scene interpretations while a local controller continues safely using fresh observations. Tag proposals with observation timestamps and reject stale or incompatible results.

Measure jitter, packet loss, reconnection, and outage behavior in the intended environment. Define a maximum semantic-command age and a local fallback when it expires. Compare task quality gains from the larger model with bandwidth, privacy, power, and reliability costs. Do not stream raw control commands from an unbounded-latency service and assume interpolation restores safety.

### Define what happens while the remote answer is missing

An illustrative semantic request might spend 10 ms encoding, 20 ms uploading, 15 ms queued, 80 ms in inference, 20 ms returning, and 5 ms validating: 150 ms in total. At a 200 Hz local loop, that spans 30 control cycles. These are hypothetical budget entries; measure their distributions together on the actual network, especially the tails and outages.

The robot needs meaningful local behavior for all those cycles. It can continue a previously validated short-horizon action using fresh sensors, slow or pause when uncertainty increases, and enter a tested safe state when semantic guidance becomes too old. A cloud response should carry the observation time and goal version that produced it. Reject a response about an object that has moved or a task the operator has canceled.

Avoid a queue of obsolete observations. For many semantic updates, processing the newest eligible observation is more useful than completing every old frame. Cancel or discard stale requests and bound the amount of pending work.

Compare the larger model's measured task benefit against the extra failure modes. If a local model already provides adequate goals, added cloud complexity may not be justified. If cloud semantics materially improves task selection, use an asynchronous interface whose loss does not remove local stabilization, collision constraints, or emergency handling.
