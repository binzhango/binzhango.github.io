## Question

SQL: return each employee's current salary after an ETL error inserted a new salary row every year.

## Brief answer

Choose the latest effective salary row per employee using a window function and a deterministic tie-breaker. Do not take the maximum salary: a pay cut or currency change makes that incorrect. Restrict the input to rows effective as of the reporting time so a scheduled future salary is not treated as current.

## Detailed answer

Assume `salaries(employee_id, salary, effective_at, salary_row_id)` and a bound parameter `:as_of`.

```sql
WITH ranked AS (
  SELECT employee_id, salary, effective_at,
         ROW_NUMBER() OVER (
           PARTITION BY employee_id
           ORDER BY effective_at DESC, salary_row_id DESC
         ) AS rn
  FROM salaries
  WHERE effective_at <= :as_of
)
SELECT employee_id, salary, effective_at
FROM ranked
WHERE rn = 1;
```

The row ID tie-break is an explicit policy, not evidence that the later inserted row is correct. If the ETL error duplicated an old salary with a new effective date, this query cannot recover the true salary from corrupted facts; reconcile against the payroll source or audit log first. Add uniqueness/version constraints and make ingestion idempotent. Include employees without any salary through a left join only if the report requires them.

`ROW_NUMBER` chooses one entire row, preserving the association between salary and effective date. Aggregating `MAX(salary)` and `MAX(effective_at)` independently can combine values that never occurred together. A pay cut illustrates the problem: a salary of 120 effective last year and 110 effective this year should return 110 as current.

The `:as_of` boundary excludes scheduled future changes. If multiple rows share the same effective timestamp, the descending row ID is a declared tie policy; a source version or correction timestamp may be a more meaningful rule in a real payroll feed. Preserve currency and employment status if they affect interpretation.

Most importantly, distinguish duplicate storage from corrupted facts. A window function can remove repeated historical rows, but it cannot infer the true salary if ETL assigned an incorrect new effective date to an old amount. Reconcile those records against the authoritative source and fix ingestion with stable event IDs or uniqueness constraints. Test pay cuts, future rows, tied timestamps and employees with no effective salary, then state whether the report omits or explicitly includes missing values.
