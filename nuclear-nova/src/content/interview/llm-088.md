## Question

How to select domain data for continued pretraining?

## Brief answer

Choose domain-pretraining text that is relevant, accurate, diverse, and suitable for the intended use, then validate the mixture against downstream tasks.

## Detailed answer

Inspect provenance, freshness, duplication, language, formatting, and contamination of held-out evaluations. Preserve useful structures such as code, equations, and document boundaries. Domain relevance alone does not establish quality: repeated boilerplate or unreliable claims can dominate training. Mix general text when necessary to retain broader capabilities, and run small ablations before committing a full compute budget.

Score candidate sources along separate axes: relevance to expected tasks, correctness, diversity, freshness, and compatibility with intended use. A highly relevant forum may contain unresolved speculation; an authoritative manual may contain repeated navigation boilerplate. Cleaning should retain useful domain structure while reducing content that would dominate token counts without teaching the desired language or concepts.

For a software-domain corpus, preserve code blocks, version labels, API names, and explanations connecting code to behavior. Avoid joining unrelated files in a way that invents dependencies. Deduplicate near-identical versions carefully: retaining meaningful changes can be useful, while repeating the same license header thousands of times changes weighting without adding domain knowledge.

Run small controlled mixtures before a full continuation. Compare domain held-out likelihood, downstream task results, and general-capability regressions. Weighting a domain source more heavily is a hypothesis about useful exposure, not proof of quality. Keep the final evaluation documents and their derivatives out of the training corpus, and record data versions so a gain or regression can be traced to the changed mixture.
