## Question

Write an efficient ring buffer for high-rate sensor data with a fixed memory budget.

## Brief answer

Use a preallocated circular buffer with head index and current size, making append and pop constant time. Decide whether overflow drops the oldest sample, rejects the new sample, or blocks; that policy is part of the interface. For high-rate fixed-memory sensing, store fixed-size records rather than arbitrary Python objects that may retain unbounded payloads.

## Detailed answer

This runnable standard-library reference stores double-precision samples, drops the oldest on overflow, and uses a lock for safe multi-threaded access. It is not a hard real-time or lock-free implementation.

```python
from array import array
from threading import Lock

class RingBuffer:
    def __init__(self, capacity):
        if capacity < 1:
            raise ValueError("positive capacity required")
        self.data = array('d', [0.0]) * capacity
        self.head = self.size = self.dropped = 0
        self.lock = Lock()

    def append(self, value):
        value = float(value)
        with self.lock:
            pos = (self.head + self.size) % len(self.data)
            self.data[pos] = value
            if self.size == len(self.data):
                self.head = (self.head + 1) % len(self.data)
                self.dropped += 1
            else:
                self.size += 1

    def pop(self):
        with self.lock:
            if not self.size:
                raise IndexError("empty buffer")
            value = self.data[self.head]
            self.head = (self.head + 1) % len(self.data)
            self.size -= 1
            return value

r = RingBuffer(2)
for value in [1, 2, 3]: r.append(value)
assert r.dropped == 1 and r.pop() == 2 and r.pop() == 3
try:
    r.pop(); raise AssertionError("expected empty buffer")
except IndexError:
    pass
```

Payload storage is approximately eight bytes per slot plus fixed object/lock overhead. Include timestamps or sequence numbers in a fixed record layout when detecting dropped samples matters. A native single-producer/single-consumer implementation can use atomic indices, but requires correct memory ordering and a documented ownership model.

### The indices define the invariant

`head` points to the oldest sample and `size` counts live samples. The insertion position is `(head + size) mod capacity`. When full, writing there replaces the oldest sample and advances `head`; otherwise `size` grows. Popping reads the oldest value, advances `head`, and decreases `size`. These updates occur under one lock so readers never observe a partially updated state.

A capacity of 10,000 double samples uses approximately 80,000 bytes for payload and retains one second at a 10 kHz sample rate. Add timestamp and channel fields when reconstructing timing matters, and size for the worst expected consumer pause. Append and pop are constant time, while float conversion occurs before taking the lock. Overwrite-oldest is a deliberate loss policy; a control system might instead reject new data or signal an error. Report drops and sequence gaps so consumers cannot mistake missing samples for a continuous stream. Hard real-time behavior requires a native implementation and bounded scheduling, not merely a fixed-size Python array.
