## Question

How do you keep an index fresh when the underlying corpus changes continuously?

## Brief answer

Use versioned, idempotent ingestion driven by source changes, with reconciliation scans for missed events. Updates and deletions must propagate to text, vector, keyword and permission indexes together.

## Detailed answer

Identify documents by stable source ID and content revision; derive chunk IDs from that revision. Build new chunks before publishing the new document version, then retire old ones. Record tombstones for deletion and retry events through a durable queue. Track source-to-index lag and sample source/index consistency. An embedding-model change requires a separately built compatible index, not mixing new vectors into the old space.

Treat a source event as a hint about a versioned document, not as an instruction to append text blindly. Fetch the authoritative revision, compute its content hash, and skip work if that revision is already indexed. Durable checkpoints and idempotent writes allow an interrupted worker to replay events safely. A delayed old event must not overwrite a newer version.

Publish updates through an atomic logical pointer: generate the new chunks and embeddings, verify them, then mark that document revision active. Queries should not mix half of the old document with half of the new one. Deletion tombstones need priority and must cover keyword entries, vectors, source text and answer caches. Permission revocations require a separate urgency policy because stale content and stale authorization have different consequences.

Track both pipeline lag and semantic freshness. A queue can be empty while a connector silently stopped receiving events. Periodic reconciliation compares source IDs, versions and deletions against indexed state to detect this. For embedding-model changes, build a parallel index with a compatible query encoder and switch them together. Keep replayable source snapshots or revision pointers so a parser bug can be repaired without relying on whatever data happens to remain in an ephemeral event stream.
