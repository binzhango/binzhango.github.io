## Question

Kimi K2 uses Multi-head Latent Attention (MLA). Explain what it does and how it compares to GQA for KV-cache reduction.

## Brief answer

GQA shares key/value heads across groups of query heads. MLA instead caches a learned low-dimensional representation from which key/value information is produced, plus the positional information its design requires. Both reduce persistent cache size, but use different parameterizations and need compatible kernels; the best choice depends on measured quality and serving efficiency.

## Detailed answer

For GQA, cache bytes per token are approximately $2L n_{kv}d_h b$, for layers $L$, KV heads $n_{kv}$, head dimension $d_h$, and bytes per element $b$. Reducing KV heads directly reduces storage and reads.

For MLA, count the latent dimension and separately cached positional component per layer rather than pretending that all attention heads disappear. Projection absorption can avoid explicitly materializing every reconstructed key/value during decode, but adds implementation constraints. Compare equal batch sizes, context lengths, precision, and quality targets; a theoretical compression ratio is not a throughput measurement. Kimi K2 uses MLA, as documented in its 2025 technical report. A smaller cache can enable larger batches, while projection and kernel overhead may offset gains on short or tiny workloads.

### A numerical comparison

Take one layer with 32 query heads of width 128. Ordinary multi-head attention stores 8,192 KV values per token: 32 heads × 128 dimensions × two tensors. Eight-head GQA stores 2,048. An illustrative MLA layout with a 512-dimensional latent and a 64-dimensional positional key stores 576 values. At two bytes each, these are 16,384, 4,096, and 1,152 bytes per layer per token. These assumed dimensions demonstrate the accounting, not a claim about every Kimi checkpoint.

MLA learns a down-projection from the token representation into the compact latent. Query-dependent scoring and value aggregation can use transformed weights so decoding need not reconstruct a full historical cache. RoPE requires special care because a position-dependent rotation cannot generally be absorbed into a fixed projection in the same way. GQA is simpler to support with existing attention kernels. MLA may win on long-context capacity while losing some advantage if the serving backend expands latents or uses inefficient small projections.
