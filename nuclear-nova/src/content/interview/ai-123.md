## Question

Build an OOP system for managing courses, grades and students.

## Brief answer

Separate student and course identity from enrollment and assessment records. An enrollment links a student to a course and owns that student's grades. Validate references and grading policy centrally; changing a student's name or a course description must not change historical grades or create duplicate enrollments.

## Detailed answer

This illustrative implementation uses one numeric course grade per enrollment and unweighted averages. A real weighted-assignment scheme needs explicit missing-grade and retake policies.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Student:
    id: str
    name: str

@dataclass(frozen=True)
class Course:
    id: str
    title: str

class School:
    def __init__(self): self.students, self.courses, self.grades = {}, {}, {}
    def enroll(self, student, course):
        if student not in self.students or course not in self.courses: raise KeyError('unknown identity')
        key = (student, course)
        if key in self.grades: raise ValueError('already enrolled')
        self.grades[key] = None
    def grade(self, student, course, score):
        if (student, course) not in self.grades: raise KeyError('not enrolled')
        if not 0 <= score <= 100: raise ValueError('grade out of range')
        self.grades[student, course] = score
    def average(self, student):
        values = [g for (s, _), g in self.grades.items() if s == student and g is not None]
        return sum(values)/len(values) if values else None

s = School(); s.students['u'] = Student('u','Ada'); s.courses['c'] = Course('c','ML')
s.enroll('u','c'); s.grade('u','c', 90); assert s.average('u') == 90
```

The key invariant is one enrollment per student/course pair. Test duplicate enrollment, unknown identities, ungraded courses and boundary scores. Authorization and audit history belong around grade-changing operations; they should not be hidden in presentation code.

An enrollment is a relationship with its own lifecycle, rather than a list duplicated independently inside both Student and Course. The `(student_id, course_id)` key prevents two records for the same enrollment and gives one place to enforce grade updates. Stable IDs keep identity separate from names, which can change or collide.

In this simplified policy, an ungraded course is excluded from the average instead of treated as zero. That choice materially changes results and should be explicit. A weighted scheme would sum `score × weight` and divide by included weight, with policies for missing assignments, retakes and dropped courses. Historical grade changes should preserve an audit record rather than silently overwrite evidence in an administrative system.

Average calculation scans enrollments in this implementation, so it is $O(e)$ for total enrollment count; an index by student can reduce unrelated work. Test boundary scores, no graded courses, duplicate enrollment and unknown IDs. OOP is useful here when it protects invariants and ownership; adding inheritance hierarchies for every entity without a behavioral need would make the design harder to extend.
