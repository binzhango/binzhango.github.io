## Question

How would you build the evaluation system for a large consumer AI assistant before and after each model release?

## Brief answer

Version a release evaluation bundle covering assistant usefulness, factual support, safety, tool execution, personalization and operational performance. Compare each candidate against the deployed baseline offline, then use a guarded online canary with explicit rollback conditions.

## Detailed answer

Construct representative conversational tasks and adversarial cases with known outcomes, including long sessions and language coverage. Separate model failures from retrieval, memory, tool and orchestration failures. Pin judge rubrics and calibrate automated ratings against human reviews; randomized response order helps detect judge bias. Online measures should include successful task completion, corrections, latency, cost and harmful-action rates, not just thumbs-up feedback. Retain deployment and evidence versions for incident replay. Freeze a release set while continually adding new failures to a separate development set; otherwise repeated tuning contaminates the gate.

### Use layers to locate the regression

Maintain separate tests for the model with known-good evidence, retrieval with relevance labels, tools with deterministic contracts, and complete multi-turn workflows. If grounded answers worsen, this decomposition reveals whether the new model ignores evidence or the retrieval pipeline stopped finding it. For action tasks, judge final external state and unauthorized side effects, not merely the assistant's explanation.

A release bundle pins model, prompt/template, tool schemas, source/index versions, judge rubric, and traffic configuration. Run paired comparisons on representative and severe-error slices, then shadow and canary deployment. Human review calibrates automated judges and investigates disagreement. Define stop conditions before seeing results, including severe harmful actions and latency or cost regressions. Keep a frozen acceptance set separate from newly discovered development cases so repeated tuning does not erase its independence. After release, sample routine successful-looking sessions as well as complaints; silent failures may never receive a negative rating. Track useful outcomes and recovery, not engagement alone.
