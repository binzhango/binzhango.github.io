## Question

An enterprise wants semantic search over ~100M documents but is balking at vector-index cost. Walk me through embedding compression options and the maths.

## Brief answer

Start with vector dimensionality, precision and index overhead before choosing compression. For 100 million 1,024-dimensional vectors, raw FP32 storage is 409.6 GB; FP16 halves that and one byte per dimension reduces it to 102.4 GB before scales and index structures.

## Detailed answer

A 64-byte product-quantization code would use 6.4 GB for codes alone, plus codebooks, IDs and search structures. Keep these decimal units explicit. Lower dimensions help only if the model supports that representation or a trained reduction preserves relevance; arbitrary truncation can break quality. Graph edges may dominate after vector compression, and retaining original vectors for reranking adds storage back. Compare recall against full-precision exact neighbors under real tenant filters and multilingual queries. Measure rebuild/update costs and latency as well as memory.

### Compression moves the dominant cost

Raw storage is document count times vector dimension times bytes per element: $10^8\times1024\times4=409.6$ billion bytes. A product quantizer divides vectors into subvectors and stores a small codebook index for each, approximating distances from lookup tables. A 64-byte code yields 6.4 GB of codes, but not a 6.4 GB complete search service.

Add document IDs, graph edges or inverted-list structures, codebooks, metadata, replicas, and any original vectors retained for refinement. After aggressive vector compression, graph connectivity may dominate memory. Scalar quantization preserves dimensions with lower-precision values; dimensional reduction changes the representation and requires validation; binary codes trade still more information for compactness. Evaluate against full-precision exact neighbors on realistic query and tenant-filter distributions, then measure downstream evidence quality. A lower recall loss on average can conceal failures for rare terminology or another language. Include index rebuild, update, and storage-replication cost when comparing schemes, not just the vector payload.
