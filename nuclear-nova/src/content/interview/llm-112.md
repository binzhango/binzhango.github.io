## Question

What are example selectors, and when are they useful?

## Brief answer

An example selector chooses which few-shot demonstrations to include for a particular request.

## Detailed answer

Selectors may use semantic similarity, token budget, diversity, or task metadata. Similar examples can improve relevance, but picking only near-duplicates can narrow behavior or leak answers from an evaluation set. Select demonstrations from an approved training pool, reserve room for the actual request and evidence, and evaluate whether the chosen examples improve outputs compared with a fixed small set.

For a request to extract an invoice, a selector might choose demonstrations of invoices with similar layout or missing fields rather than unrelated chat examples. Semantic similarity is one signal, but task type, language, output schema, and difficult edge cases can be more important than topic overlap. A near-identical example with a different output contract can teach the wrong behavior.

The selector operates under a context budget. Reserve tokens for instructions, the actual input, evidence, and output before allocating space to demonstrations. Prefer a small set that covers the needed behavior without repeating essentially the same case. A diversity criterion can prevent the nearest-neighbor list from being dominated by copies of one source.

Evaluate selection as part of the system: compare a fixed baseline set, similarity-based selection, and any diversity rules on independent queries. Keep evaluation answers out of the candidate pool, including paraphrases and source-derived variants. If retrieval of demonstrations fails, use a tested fallback. Demonstration relevance is useful only insofar as it improves correct behavior on the new request, not because it produces a high embedding score.
