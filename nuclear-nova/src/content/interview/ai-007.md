## Question

What is positional encoding in transformers, and how has it evolved (sinusoidal → learned → RoPE → ALiBi)?

## Brief answer

Position representations let attention distinguish token order. Sinusoidal and learned embeddings add position information to token states; RoPE rotates queries and keys; ALiBi adds head-specific distance biases to attention scores. These are alternative designs, not a universal replacement sequence.

## Detailed answer

Learned tables normally need adaptation beyond their trained positions. Sinusoids define values at new positions but do not guarantee useful extrapolation. RoPE makes query–key interactions depend on relative offsets through rotations. ALiBi penalizes distant keys with linear biases. Evaluate long-context retrieval and language quality rather than assuming a larger configured window means reliable use of it.

Without position information, full self-attention is permutation equivariant: permuting the inputs permutes their outputs rather than encoding which item came first. A causal mask supplies an ordering constraint but is not a complete replacement for useful distance representations. The model needs to distinguish sequences such as “dog bites person” and “person bites dog.”

Absolute embeddings add a vector $p_t$ to the token embedding at position $t$. Learned embeddings optimize each position vector directly; sinusoidal embeddings use fixed frequencies, allowing relative offsets to be expressed through trigonometric identities. RoPE instead rotates query/key coordinate pairs, making their inner product depend on the difference between positions. ALiBi leaves those vectors unrotated and subtracts a distance-dependent bias from attention logits, with different slopes across heads.

Each choice introduces an inductive bias. A stronger distance penalty encourages local attention but can discourage useful distant evidence. A learned table has an explicit range, whereas a mathematical formula can be evaluated outside its training range without guaranteeing the model understands those values. Compare positional methods under matched training budgets and measure short-context quality, long-range retrieval and position-dependent errors. Extending the configured context changes memory and runtime too, even when position values are cheap to generate.
