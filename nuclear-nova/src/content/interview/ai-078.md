## Question

What is prompt injection (direct and indirect), and what is your layered defence?

## Brief answer

Prompt injection attempts to make the model follow untrusted instructions that conflict with its legitimate task. Direct attacks arrive in user input; indirect attacks arrive through documents, web pages, messages or tool results.

## Detailed answer

Keep privileged instructions separate from data, but do not treat delimiters as a security boundary. Enforce tool permissions, destination restrictions and sensitive-data handling outside the model. Validate outputs before execution, require approval for consequential changes and limit what each retrieval can expose. Test malicious instructions inside realistic evidence, including encoded and multi-step attempts. Filtering and model training reduce risk but do not replace authorization checks.

The vulnerable boundary is between information the model should read and instructions it is allowed to obey. A retrieved page might contain text asking the assistant to send internal records elsewhere. Even if that text is clearly marked as a quote, the model can still be influenced; formatting is a helpful signal, not an authorization mechanism.

Reduce the blast radius outside the model. Retrieve only data the user may access, scope tool credentials to the task, constrain network destinations and validate proposed actions against a policy. Separate read-only tools from writes, and bind approvals to exact consequential payloads. A model should never gain authority merely because a document claims that an administrator requested it.

Test realistic attack chains: malicious source text, a proposed tool call, a sensitive result and an attempted outbound action. Block secret-bearing URLs, unauthorized recipients and unexpected data flows independently of whether the generated explanation sounds benign. Use input/output classifiers and instruction hierarchy as additional layers, but monitor false positives and missed attacks. Recovery requires identifying affected actions and revoking or rotating exposed credentials if an incident occurred. The goal is to make a mistaken model decision unable to cross a protected boundary, rather than assuming prompting can make mistakes impossible.
