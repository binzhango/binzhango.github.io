## Question

How would you evaluate an Indic LLM properly? Why is running translated English benchmarks not enough?

## Brief answer

Use native-language tasks, native annotators, and slices covering scripts, dialects, transliteration, and code-switching. Translated English benchmarks can measure translation artifacts or imported cultural knowledge rather than useful local ability. Separate comprehension, factuality, reasoning, tool use, and generation quality, and evaluate the intended domain rather than one aggregate score.

## Detailed answer

Build items from real user needs with clear references: local entities, dates, number formats, education, government services, and conversational styles. Validate that every question has an unambiguous answer in its own language. Include languages with little web data and report their uncertainty rather than hiding them in a macro average.

Compare native and translated versions to locate translation-induced gaps. Use fluent raters for naturalness and pragmatic appropriateness, and automatic checks for exact entities and structured outputs. Test refusals, unsupported claims, and adversarial instructions in each language. Keep task and source splits separate from training augmentation. For voice deployments, add accents, background noise, and code-mixed speech because text-only competence does not imply usable spoken interaction.

### A native benchmark needs native failure cases

Translation can preserve a question's nominal answer while changing difficulty, cultural assumptions, or natural phrasing. Build some tasks directly with native speakers: extracting a district name from a local notice, explaining an eligibility condition, resolving code-switching, or formatting an amount. Keep the original evidence and explicit scoring fields so raters do not reward fluency while missing factual errors.

For each language, report task counts, uncertainty, comprehension, factual correctness, language adherence, and critical-entity accuracy. A model may answer a multiple-choice question correctly while producing unusable free-form instructions. Include unsupported questions to measure calibrated abstention and counterfactual pairs that change a decisive number or negation. Audit raters and translations for dialect preferences. Aggregate scores are useful for summaries, but launch decisions should inspect the weakest supported language and consequential task slices rather than allowing high-resource languages to conceal failures.
