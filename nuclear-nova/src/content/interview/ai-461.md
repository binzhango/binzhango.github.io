## Question

How does an answer engine handle breaking news: a query about something that happened 20 minutes ago?

## Brief answer

Route time-sensitive queries to a fresh index and trusted live sources, then distinguish verified facts from rapidly changing reports. Use event time, publication time, and crawl time separately. A recently crawled old article is not fresh evidence, and many copies of one report are not independent confirmation.

## Detailed answer

**Suggested approach.** Detect temporal intent from the query and event entities, query news feeds and the incremental crawl in parallel, and prioritize primary statements where available. Cluster syndicated reports, preserve corrections, and show an explicit “as of” timestamp. Retrieve conflicting accounts rather than averaging them into a false consensus.

Use short cache lifetimes or event-driven invalidation for active stories. If evidence is sparse, state what is confirmed and which detail remains unresolved; do not fill gaps from model memory. Measure time from source publication to searchable evidence, correction propagation, citation freshness, and supported-claim precision. Test clock skew, backdated articles, a retracted announcement, and a story whose key entity shares a name with an older event. The latency target may require a concise provisional answer with links instead of a comprehensive synthesis.

### Build an event timeline before synthesis

Suppose a service outage begins at 14:00, a user report appears at 14:05, and the provider posts a partial restoration at 14:18. A 14:20 answer must distinguish the event's start time from when each source became known. An article crawled at 14:19 could still contain the original 14:05 state. Store content versions so the answer can identify the latest supported status and avoid combining an old total-outage claim with a newer partial-restoration claim as though they were simultaneous.

Cluster reports by upstream evidence. Ten outlets quoting one anonymous post provide less independent confirmation than an official status change plus direct observations. Ranking should therefore consider both recency and evidential independence, while keeping disagreement visible.

Use an event-specific cache key and invalidate when a material source version changes. Corrections need to flow through retrieval caches, answer caches, and any generated summary. Measure correction lag as well as first-publication lag: a system that is fast to repeat a mistake but slow to retract it is not usefully fresh.
