## Question

How to choose a distributed training framework?

## Brief answer

Choose a distributed training approach from the model's memory needs, cluster interconnect, required parallelism, and operational support.

## Detailed answer

Data parallelism replicates computation across batches; FSDP and ZeRO shard training states; tensor and pipeline parallelism split computation; expert parallelism distributes MoE experts. PyTorch FSDP, DeepSpeed, and Megatron-based stacks serve different combinations of those needs. Check checkpoint portability, restart behavior, kernel support, and integration with the existing codebase, then benchmark a representative run.

Choose the parallelism needed before choosing the brand of framework. If the model and optimizer fit on one device, ordinary data parallelism may be enough. If persistent training states do not fit, sharding them can reduce memory per rank. If an individual layer or its computation is too large, tensor parallelism splits its matrices. Pipeline parallelism distributes layers but introduces scheduling and activation-transfer considerations. MoE adds expert routing and all-to-all communication.

Cluster topology changes the tradeoff. Frequent tensor-parallel collectives are sensitive to interconnect bandwidth and latency; slow links can erase compute gains. FSDP-style parameter gathering has transient memory requirements even when the average shard size looks small. Combining strategies increases configuration and checkpoint complexity.

Benchmark a representative step, including backward and optimizer update, then test saving and resuming after interruption. Check optimizer-state portability, tokenizer/config preservation, numerical support, observability, and the team's ability to debug failures. A framework that exposes every parallelism option is not automatically the best choice for a modest job. Prefer the simplest supported strategy that fits memory and achieves acceptable sustained throughput.
