## Question

Time-to-first-token for your on-device feature is 1.8 s. Walk me through diagnosing and fixing it.

## Brief answer

Break the 1.8 seconds into model loading, prompt construction/tokenization, prefill, first decode step, and UI delivery. Optimize the measured dominant stage on the actual device. Cold-start latency, long prompts, unsupported operators, and thermal throttling require different fixes; replacing the model without a trace can miss the bottleneck entirely.

## Detailed answer

Compare cold and warm runs, short and long prompts, and cool versus sustained device conditions. Record memory pressure and backend placement to detect CPU fallbacks or repeated transfers. If loading dominates, cache appropriately and reduce artifact overhead without monopolizing memory. If prefill dominates, remove redundant context, reuse valid prefixes, and use supported fused kernels.

Check that quantization produces native efficient operations rather than expensive dequantization paths. Batch or parallelize independent preprocessing where it helps, and keep tokenization off the UI thread. Evaluate any smaller-model or shorter-context alternative against task quality. Report p50/p95 time to first useful output, energy, and application responsiveness; a one-off benchmark on the newest phone is insufficient.

### Decompose the 1.8 seconds

An illustrative trace could show 600 ms loading weights, 150 ms tokenization, 850 ms prefill, and 200 ms queue/runtime overhead. Keeping a warm model can remove much of the first component but consumes memory between requests. Shortening a redundant prompt targets prefill; moving tokenization off the UI thread improves responsiveness but may not reduce total latency by itself. Use the measured breakdown rather than applying every optimization.

Instrument backend events and synchronize correctly so asynchronous accelerator submission is not mistaken for completed computation. Compare a cold start after memory pressure with a warm repeated prefix, and record thermal state. Check whether unsupported operators bounce between CPU and accelerator. Set a target for first useful output, not just the first token if it is punctuation or an empty acknowledgment. Revalidate long prompts and rare feature inputs after changes, since an aggressive context cap can meet latency while silently dropping the information needed to answer.
