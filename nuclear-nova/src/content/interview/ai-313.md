## Question

Build a Voice Activity Detector from scratch. How do you make it robust for phone-quality Indian-language audio?

## Brief answer

Start with a causal energy detector using short frames, an adaptive noise floor, separate on/off thresholds, and a hangover period. It is a runnable baseline, not a production-quality speech classifier: music, clicks, and nonstationary noise can fool it. A deployable phone VAD usually needs supervised acoustic features and evaluation on target codecs, speakers, and environments.

## Detailed answer

The following detector assumes mono normalized floating-point audio in 20 ms frames. It adapts its noise floor only during non-speech decisions and holds speech briefly to avoid chopping weak syllables.

```python
import math

class VAD:
    def __init__(self, noise_db=-60.0, hangover=8):
        self.noise_db = noise_db
        self.hangover = hangover
        self.remaining = 0

    def step(self, frame):
        if not frame:
            return False
        db = 10 * math.log10(sum(x*x for x in frame) / len(frame) + 1e-12)
        margin = 6 if self.remaining else 10
        speech = db > self.noise_db + margin
        if speech:
            self.remaining = self.hangover
        else:
            self.noise_db = 0.98*self.noise_db + 0.02*db
            self.remaining = max(0, self.remaining - 1)
        return speech or self.remaining > 0

v = VAD(hangover=2)
assert not v.step([0.] * 160)
assert v.step([0.1, -0.1] * 80)
assert v.step([0.] * 160)
assert not v.step([0.] * 160)
assert not v.step([])
```

For 8 kHz telephony, resample and frame consistently, train with codec artifacts and regional-language conversational speech, and include quiet unvoiced consonants. Measure false activation, clipped onset, clipped ending, and endpoint delay. Silence-based endpointing and speech detection are related but different decisions; do not terminate every natural pause.

### What this baseline can and cannot detect

At 8 kHz, a 20 ms frame contains 160 samples. Squaring and averaging estimates signal energy, and the logarithm expresses its ratio on a decibel scale. Separate start and continuation thresholds create hysteresis: speech needs stronger evidence to begin than to continue. Hangover retains a short tail so low-energy endings are not immediately cut off. Each frame takes $O(n)$ work for n samples and constant state.

Energy alone cannot reliably distinguish speech from a horn, fan, or music, and a sudden noise increase may be misclassified as speech rather than updating the noise estimate. Quiet speech at startup is another failure case. A stronger detector uses spectral features or a trained classifier on realistic telephony data, with onset buffering to recover initial consonants. Keep VAD distinct from semantic turn completion: a short pause inside a number is not necessarily the end of the user's request. Tune delay against clipped-speech error using annotated conversations.
