## Question

Take a working GenAI agent prototype to production for an enterprise. What's your checklist between demo and launch?

## Brief answer

Suggested approach: convert the prototype into a bounded, observable service with explicit task scope, permissioned tools, reproducible evaluations, and failure recovery. Production readiness includes data access, latency, cost, security, operations, and user experience—not just wrapping the demo in an API. Keep the first launch narrower than the set of tasks the model can attempt.

## Detailed answer

Version prompts, models, retrieval sources, tools, and schemas. Add identity propagation, tenant isolation, argument validation, idempotency, cancellation, quotas, and bounded retries. Treat documents and tool outputs as untrusted inputs. Define human approval or escalation points for consequential or ambiguous actions.

Build a representative evaluation suite and adversarial tests, then load-test with realistic tool latency and outages. Trace actions and outcomes while minimizing sensitive logs. Establish SLOs, dashboards, on-call ownership, rollback, and a model-deprecation plan. Pilot with users and measure completed tasks, incorrect actions, interventions, and cost. Do not equate an agent's final “done” message with a verified result in the external system.

### Replace implicit demo assumptions with contracts

A prototype may assume one user, trusted documents, healthy tools, and a model that always returns parseable arguments. Production must specify caller identity, allowed resources, tool schemas, deadlines, retry rules, and how success is verified. A durable task record should distinguish planned actions, submitted actions, and confirmed outcomes so recovery does not repeat side effects.

Start with a bounded workflow and a representative evaluation set. Add an executor that validates every tool call independently of the model, plus an observation path that checks the resulting external state. Trace enough information to diagnose failures without logging unnecessary private content. Load-test long trajectories and inject tool timeouts, model errors, and cancellation. Establish incident ownership and a model-upgrade contract before launch. Pilot with users and observe where they intervene or repeat work. The release criterion is dependable completion of the supported workflow, including understandable failure and recovery, not that the agent can produce an impressive uninterrupted demonstration.
