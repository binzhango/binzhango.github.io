## Question

Explain the ReAct pattern and what it solves over chain-of-thought alone.

## Brief answer

ReAct interleaves model-directed reasoning and external actions with observations. Tool results let the system obtain evidence and update its next step instead of relying only on an internally generated chain of reasoning.

## Detailed answer

For example, a question about a repository can trigger file search, then a targeted read, then a grounded response. The application owns execution, permissions and limits; the model only proposes actions. Tool output is untrusted data and may contain instructions that must not override the user’s goal. Expose concise progress and evidence rather than private reasoning traces.

The loop separates proposal, execution and observation. A model proposes a search or calculation; the application validates and runs it; the resulting observation becomes context for the next decision. This closes the feedback gap in a purely generated reasoning sequence, where a mistaken assumption can propagate through many fluent steps without contact with external evidence.

For example, to answer which function introduced a regression, the agent can search for the symbol, read the implementation, inspect a relevant change and run a focused test. A failed test is an observation that should change the next action. The application should retain concise task state and evidence IDs rather than treating every generated thought as a verified fact.

The pattern does not by itself solve planning or reliability. A model can select the wrong tool, misread a result or repeat an unproductive action. Enforce an allowlist, argument validation, execution budgets and termination conditions outside the model. Distinguish tool output from instructions, especially when reading web pages or repository files. Evaluate whether observations actually improve success over a direct response or fixed workflow; extra tool calls that do not reduce uncertainty merely add latency and new failure opportunities.
