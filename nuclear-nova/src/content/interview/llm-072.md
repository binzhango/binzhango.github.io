## Question

Besides cosine similarity, what other similarity metrics exist?

## Brief answer

Alternatives include dot product, Euclidean or Manhattan distance, Jaccard similarity, edit distance, BM25, and learned pairwise scores.

## Detailed answer

Choose according to the representation and task: Jaccard compares sets, edit distance compares strings, and BM25 ranks lexical matches. These are not all mathematical metrics. For unit-normalized vectors, $\lVert u-v\rVert_2^2=2-2u^\top v$, so cosine, dot product, and Euclidean distance induce equivalent rankings. Without normalization, vector magnitude changes the relationship. A cross-encoder can score a query-document pair directly but costs more than comparing precomputed embeddings.

The geometry should match the meaning of the representation. Cosine ignores overall magnitude and compares direction. Dot product retains magnitude, which may contain useful learned relevance information or an unwanted document-length effect. Euclidean distance compares absolute position in the embedding space. Manhattan distance adds coordinatewise absolute differences and can behave differently when a few coordinates have large deviations.

For text, lexical and semantic scores capture different signals. BM25 can identify an exact error code that a dense embedding blurs with similar codes. A semantic encoder can match “cancel subscription” with “terminate membership” even without exact word overlap. A cross-encoder jointly reads query and passage, allowing detailed interactions, but it must run for each pair rather than using one precomputed vector per document.

Choose by held-out ranking quality and latency, not by mathematical elegance alone. Use the embedding model's intended normalization and metric; changing them can change rankings. For hybrid retrieval, raw BM25 and vector scores need compatible calibration or rank-based fusion. Similarity does not establish that a passage answers the question, satisfies permissions, or is factually correct.
