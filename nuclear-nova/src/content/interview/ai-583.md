## Question

Debug a program that models infection spread across a social graph.

## Brief answer

Clarify the spread model and timestep semantics before debugging. A common bug updates infections in place, allowing newly infected people to infect others in the same round and making results depend on node order. Compute each next state from the previous state, seed randomness for reproducibility, and distinguish a model error from an implementation error.

## Detailed answer

This deterministic SI example assumes infection persists and transmits to every neighbor in the next round. It is an algorithm fixture, not an epidemiological model for real-world decisions.

```python
def spread(graph, initial, rounds):
    if rounds < 0: raise ValueError('negative rounds')
    nodes = set(graph) | {v for values in graph.values() for v in values}
    infected = set(initial)
    if not infected <= nodes: raise ValueError('unknown initial node')
    history = [set(infected)]
    for _ in range(rounds):
        new = {v for u in infected for v in graph.get(u, ())}
        infected = infected | new
        history.append(set(infected))
    return history

assert spread({'a': ['b'], 'b': ['c'], 'c': []}, {'a'}, 1)[-1] == {'a', 'b'}
assert spread({'a': ['b'], 'b': ['c'], 'c': []}, {'a'}, 2)[-1] == {'a', 'b', 'c'}
```

Test a chain, cycle, disconnected component, empty seed, and directed versus undirected interpretation. For stochastic SIR, define infection/recovery ordering, independent contact probabilities, and reproducible random streams; then compare with analytically tractable tiny graphs. Complexity here is O(rounds × edges) in the worst case. Do not tune parameters to conceal a state-update defect.

### One timestep must use one prior state

In the chain A→B→C with A initially infected, one synchronous round infects B but not C. Updating a shared set while iterating can let B infect C immediately, producing two rounds of spread in one and making output depend on traversal order. The implementation forms the entire neighbor set from the old infected set, then commits the union once.

The graph is directed as written; add reciprocal edges explicitly for an undirected interpretation. In SI, infection never disappears, so the infected set is monotone and remains a subset of known nodes. These are useful invariants for property tests. A stochastic SIR model adds recovery and transmission probabilities, whose ordering must be specified: can someone who recovers this step still transmit? Seeded randomness helps reproduce an implementation failure, but does not validate epidemiological assumptions. Test tiny graphs with analytically predictable outcomes, empty seeds, cycles, disconnected nodes, and zero rounds before using larger simulations. Keep parameter calibration separate from debugging state transitions.
