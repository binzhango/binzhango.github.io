## Question

What are the main pain points in RAG and their solutions?

## Brief answer

The main RAG failure points are missing or corrupted sources, poor candidate retrieval, bad ranking or context assembly, and unsupported generation.

## Detailed answer

Diagnose them in order: confirm the answer exists in the authorized corpus, inspect parsed text, inspect retrieved candidates, inspect packed context, and finally inspect the generated claims. A missing source needs ingestion work; a lost qualifier needs context repair; a model that ignores available evidence needs generation changes. Maintain examples for each failure class so a fix can be tested at the responsible stage.

A useful debugging record includes the question, expected support, parsed source text, candidate list, reranked list, packed prompt, and generated answer. Following one failure through these artifacts identifies where information disappeared or changed. Without them, teams often tune generation settings for an ingestion problem or increase retrieval depth for a missing document.

For example, if the source contains a table but parsing drops its header, repair extraction. If the intact table is indexed but not retrieved for an exact part number, add lexical or structured matching. If it is retrieved but removed as a duplicate, fix deduplication. If the model sees it and uses the wrong units, improve extraction or calculation rather than adding more passages.

Build regression examples for each failure class and measure the responsible stage before and after a fix. Keep an insufficient-evidence path when no authorized source supports the answer. Balance quality with latency, context cost, and freshness; increasing every cutoff can make a system slower and noisier. A reliable RAG pipeline is a sequence of validated information transformations, not merely a model connected to a vector database.
