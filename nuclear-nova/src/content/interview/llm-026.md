## Question

Explain the difference between encoder-only, decoder-only, and encoder-decoder models.

## Brief answer

Encoder-only models build contextual representations, decoder-only models generate autoregressively, and encoder-decoder models map a separately encoded input to an output sequence.

## Detailed answer

BERT-style encoders commonly use bidirectional attention for classification, tagging, and reranking. A suitable pooling method and retrieval training are still needed for high-quality sentence embeddings. GPT/Llama-style decoders predict the next token using a causal mask. T5/BART-style encoder-decoders use bidirectional source attention plus causal output attention and cross-attention. These are architectural tendencies rather than absolute restrictions on possible tasks.

Consider three tasks on the same review text. Sentiment classification needs a fixed label: an encoder can contextualize the whole review and feed a pooled representation into a small classifier. Translating the review needs a new sequence: an encoder-decoder can encode the review once and generate the translation with cross-attention. Writing a continuation needs an open-ended next-token distribution: a decoder-only model handles that directly.

The attention masks explain the distinction. An encoder token can usually read tokens before and after it. A causal decoder token can read preceding tokens but not future output. An encoder-decoder contains both patterns plus a bridge from decoder queries to source keys and values. Padding still needs masking in all three.

These choices affect training and latency, not merely supported tasks. A decoder can classify by generating a label, and an encoder can produce useful embeddings after appropriate training. Compare the complete pipeline, including pooling, task heads, output validation, and generation length. Raw pretrained representations are not automatically optimized for sentence similarity or any other downstream objective.
