## Question

Qwen's reasoning models train with RL using verifiable rewards on maths and code. Why is that preferred over PPO with a learned reward model for these domains?

## Brief answer

Verifiable rewards give direct feedback from answer checkers or executable tests, reducing dependence on a subjective learned reward model. They are useful when correctness can be assessed reliably and cheaply. RLVR describes the reward source, while PPO describes an optimization algorithm; they are not mutually exclusive, and PPO can optimize verifiable rewards.

## Detailed answer

For code, execute in a resource-limited sandbox with hidden tests; for math, normalize answers and check equivalence where feasible. Reward validity as well as the final score so malformed or evasive responses cannot exploit the evaluator. Maintain a test set that the policy never uses for optimization.

A learned reward model can misrank plausible explanations and be reward-hacked, but a verifier can also be incomplete: passing visible tests does not prove a correct program, and an answer checker may accept a wrong derivation. Track exploit cases, generalization, and diversity. Use human or learned judgments for aspects without reliable automatic verification, such as clarity and usefulness. Qwen3's reasoning post-training is one documented application.

### Reward source and optimizer are different axes

PPO is an optimization algorithm; a learned reward model or an executable verifier supplies reward. PPO can therefore optimize a verifiable reward, and a different policy-gradient method can optimize a learned preference score. The meaningful comparison in this question is reliable task verification versus subjective learned scoring, not mutually exclusive algorithm names.

For a sorting program, the verifier can check output order, preservation of input elements, empty input, duplicates, and resource limits. A program passing only three visible examples is not necessarily correct, so use hidden and property-based tests. For math, checking the final number is useful but can miss an invalid argument when the reasoning itself matters. Reward only what the verifier establishes, maintain adversarial tests against reward exploits, and separately evaluate clarity or helpfulness. Automatic rewards scale well where correctness is formalizable; open-ended advice still needs a broader judgment process.
