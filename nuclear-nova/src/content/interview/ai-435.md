## Question

Design the Hugging Face Hub: millions of git repos where individual files are tens to hundreds of GB.

## Brief answer

Keep Git responsible for commits, trees, permissions, and small pointer files; store large immutable blobs or chunks in object storage. A commit publishes a manifest only after every referenced object is durable. Scale repository metadata separately from uploads and downloads, with resumable transfers, content hashes, authorization, and cacheable immutable URLs.

## Detailed answer

**Suggested approach.** Split the system into a repository service, content-addressed object service, transfer gateway, and search index. An upload first stages chunks, verifies checksums, and then atomically updates a branch reference using compare-and-swap. A failed upload leaves collectible temporary objects, never a commit pointing to missing bytes. Downloads resolve a commit to immutable objects and use range requests through a CDN; private access is authorized before issuing short-lived download credentials.

Partition metadata by repository ID and protect popular repositories with read replicas and caches. Garbage collection traces reachable commits and respects retention before deleting shared chunks. Cross-tenant deduplication must not reveal another tenant's file existence. Measure commit latency, resumable-upload success, download throughput, and orphan storage. Hugging Face's documented Xet backend uses pointer files and chunk-level deduplication; the architecture above is a proposed design, not a claim about its internal implementation.

### Upload, publish, and recover

For a hypothetical 100 GB checkpoint, divide the transfer into bounded chunks and give each upload an ID. The client asks which hashes already exist, uploads missing chunks with retryable part numbers, and submits a manifest containing byte lengths and checksums. A finalized manifest is immutable. Updating `main` is a separate operation that succeeds only if its previous commit still matches the client's expected parent. Two simultaneous publishers therefore cannot silently overwrite each other's branch update.

Downloading a pinned commit remains reproducible even while the branch moves. An interrupted download resumes from verified ranges; a corrupted range is fetched again without restarting the entire file. Cache authorization decisions briefly, but never make a private artifact public just because its bytes share a hash with another object.

Storage cost is approximately retained unique bytes times replication, plus request and egress costs. Deduplication reduces the first term but introduces reference tracking and expensive garbage collection. Begin with coarse immutable objects and reliable publication semantics; add content-defined chunking where measured repeated uploads justify the operational complexity.
