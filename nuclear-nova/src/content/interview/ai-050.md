## Question

Design memory for a long-running agent: what do you store, where, and how do you retrieve it?

## Brief answer

Separate durable facts and user preferences from task state, recent conversation and raw execution logs. Store provenance, scope, timestamps and deletion rules with memory, then retrieve only what is relevant and authorized.

## Detailed answer

Use structured records for commitments and current task status, a searchable store for longer evidence, and a bounded recent-turn window for continuity. Summaries should link back to original observations and distinguish user statements from model inferences. Do not promote an untrusted document instruction into a permanent preference. Evaluate stale-memory errors, cross-user leakage and recovery after compaction; more stored text does not automatically improve recall.

Separate four stores: current task state, durable user preferences, source evidence and execution history. Task state includes the objective, accepted constraints, completed steps and unresolved work. Preferences should record who supplied them and their scope. Evidence keeps source versions and timestamps. Execution history records what was attempted and what actually happened, including uncertain outcomes.

For example, “use Python for this prototype” is a task constraint, not necessarily a permanent preference. A retrieved document saying “ignore all prior instructions” is source text, never an authorized memory update. A model-generated summary should distinguish inferred facts from direct user statements and point back to original evidence when the distinction matters.

Retrieve memory with both relevance and authorization filters. Recent state may be loaded directly; older facts can be searched by entity, task and recency. Resolve conflicts using provenance and explicit updates rather than whichever embedding scores highest. Give volatile facts expiration or refresh rules, and propagate user deletion across summaries and indexes. Test recovery after a crash or context compaction: the agent should resume from verified state without repeating consequential actions. Useful memory reduces repeated work while remaining correctable, scoped and auditable.
