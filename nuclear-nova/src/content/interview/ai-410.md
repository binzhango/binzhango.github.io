## Question

Write the host-side runtime that feeds a deterministic accelerator across many chips. What is genuinely hard about it?

## Brief answer

A host runtime must stage inputs, reserve a compatible multi-chip group, start the compiled program coherently, collect outputs, and release resources even on cancellation. Deterministic chip execution does not make host I/O or failures deterministic. The hard parts are backpressure, version/layout agreement, partial launch recovery, and preventing a failed run from corrupting the next tenant's state.

## Detailed answer

This runnable asyncio reference models one exclusive chip group and injected asynchronous device operations. Real drivers must implement `abort` as a bounded operation that fences or resets outstanding work before reuse.

```python
import asyncio

class Runtime:
    def __init__(self, device):
        self.device = device
        self.lock = asyncio.Lock()

    async def run(self, program, inputs, timeout=5.0):
        async with self.lock:
            try:
                async def execute():
                    await self.device.stage(program, inputs)
                    await self.device.start()
                    return await self.device.collect()
                return await asyncio.wait_for(execute(), timeout)
            finally:
                await self.device.abort()  # fence and clear, even after success

class FakeDevice:
    def __init__(self): self.active = False; self.cleared = 0
    async def stage(self, program, inputs):
        if program != 'double-v1': raise ValueError('incompatible program')
        self.inputs = inputs
    async def start(self): self.active = True
    async def collect(self):
        await asyncio.sleep(0)
        return [2*x for x in self.inputs]
    async def abort(self): self.active = False; self.cleared += 1

async def test():
    device = FakeDevice(); runtime = Runtime(device)
    assert await runtime.run('double-v1', [2, 3]) == [4, 6]
    assert not device.active and device.cleared == 1
    try: await runtime.run('wrong', [1])
    except ValueError: pass
    else: raise AssertionError('expected validation failure')
    assert device.cleared == 2

asyncio.run(test())
```

Add bounded input queues, pinned buffers, checksums, group-health checks, and program fingerprints in production. If cleanup fails, quarantine the chip group; do not return it to the pool. Retry only after establishing whether a run had side effects, and keep request IDs separate from device execution IDs.

### The hard contract is safe reuse

The runtime lock gives one request exclusive ownership of the modeled chip group. It stages a compatible program and input, starts execution, and collects results under a timeout. The `finally` block fences and clears outstanding activity before another request can acquire the group. A timeout does not itself prove that hardware stopped; the driver's abort/fence contract is essential.

Across many chips, verify that every participant has the same program fingerprint, compatible shapes, and expected buffer layout before launch. Coordinate start and completion, detect partial failures, and quarantine groups whose cleanup cannot be established. Bounded queues provide backpressure rather than accumulating unlimited host memory. The sample's fake device demonstrates orchestration, not DMA, real distributed launch, or performance. Production code must also handle cancellation during cleanup and distinguish a caller timeout from a device fault. Record request and execution identifiers so a late result from an old run cannot be delivered to a new request using the same buffers.
