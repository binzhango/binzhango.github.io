## Question

What are key LLM training tips?

## Brief answer

Validate correctness at small scale, monitor optimization and data quality, and make recovery reproducible before spending a large training budget.

## Detailed answer

Check token shifting, masks, padding, chat templates, loss normalization, and packed-sequence boundaries. Track gradient norms, numerical overflow, throughput, data mixtures, and held-out quality. Verify a checkpoint can resume with optimizer and data state intact. Use appropriate mixed precision, clipping, and activation checkpointing. Change one major factor at a time so improvements and regressions remain attributable.

Use small tests that expose silent mistakes. Train on a tiny batch until loss falls sharply; if it does not, inspect targets, masks, gradients, and optimizer updates. Decode the tokenized inputs and labels to catch double shifting, missing answer tokens, or duplicated role markers. Compare a resumed run with an uninterrupted run closely enough to detect lost optimizer or data-position state.

During scaled training, distinguish numerical problems from data changes. A loss spike might follow a corrupted source batch, a longer sequence, a learning-rate transition, or overflow. Record source IDs, token counts, gradient norms, and relevant scheduler state so the event can be reproduced. Gradient clipping limits extreme updates but should not hide a persistent upstream bug.

Measure useful throughput as supervised or training tokens per second under a clear convention, and track quality per compute budget. Faster hardware utilization is not useful if packing leaks examples or masks remove most answer tokens. Preserve checkpoints with enough metadata to recover and compare experiments. Make large changes one at a time where practical, because simultaneous data, optimizer, and architecture changes make failures hard to attribute.
