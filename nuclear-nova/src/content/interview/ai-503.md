## Question

Implement a chunker for a legal document that never splits a clause and carries enough context for each retrieved chunk to be self-contained.

## Brief answer

Parse the document into structural clauses first, then pack whole clauses under a token budget. Carry section identity and referenced definitions with each chunk. “Never split a clause” means an oversized clause must be explicitly rejected or stored as an oversized unit; it cannot also satisfy an arbitrary hard token cap without a policy choice.

## Detailed answer

This core accepts already-parsed clauses and resolved definitions. It counts the complete rendered chunk, including repeated context, and rejects an oversized individual clause. PDF/DOCX parsing and legal interpretation remain separate upstream work.

```python
def clause_chunks(clauses, definitions, count_tokens, limit):
    # clause = {'id': str, 'text': str, 'terms': [str]}
    def render(group):
        terms = sorted({t for c in group for t in c['terms']})
        missing = set(terms) - definitions.keys()
        if missing:
            raise ValueError(f'unresolved terms: {sorted(missing)}')
        context = '\n'.join(f'{t}: {definitions[t]}' for t in terms)
        body = '\n\n'.join(f"{c['id']}\n{c['text']}" for c in group)
        return context + '\n\n' + body
    batch = []
    for clause in clauses:
        if count_tokens(render([clause])) > limit:
            raise ValueError(f"oversized clause: {clause['id']}")
        proposed = batch + [clause]
        if batch and count_tokens(render(proposed)) > limit:
            yield render(batch)
            batch = []
        batch.append(clause)
    if batch:
        yield render(batch)

clauses = [{'id': '2.1', 'text': 'A Party may terminate.', 'terms': ['Party']}]
chunks = list(clause_chunks(clauses, {'Party': 'A signatory'}, lambda s: len(s.split()), 30))
assert len(chunks) == 1 and 'A signatory' in chunks[0] and '2.1' in chunks[0]
```

Resolve definitions transitively with cycle detection before packing, and include amendment/version scope. Test nested numbering, tables, missing definitions, repeated terms, and a single clause exceeding the cap. A chunk is self-contained only relative to the dependencies successfully identified.

### Preserve the clause dependency contract

Suppose clause 8.2 says a party may terminate after a “Material Breach,” and that term is defined in section 1.1. A chunk containing only 8.2 is grammatically complete but not semantically self-contained. The renderer therefore includes the relevant definition and the clause identifier before checking the token budget. Repeated definitions consume tokens too; excluding them from counting would violate the cap despite correctly preserving clause boundaries.

The upstream parser must distinguish section headings, subclauses, tables, and cross-references. A character-based splitter cannot guarantee that “(b)” is a new clause rather than text inside a quotation. Resolve definitions within the same contract and amendment scope, and detect cycles such as A referring to B while B refers to A.

This implementation repeatedly renders candidate groups, so the packing loop can perform substantially more work than a linear token-count pass. Precompute stable clause and dependency information where safe, but verify the final serialization because shared definitions and tokenizer boundaries affect total size. When a single clause plus required context is oversized, surface that conflict explicitly; silently splitting it would contradict the promised invariant.
