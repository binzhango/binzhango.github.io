## Question

What are the problems with traditional attention?

## Brief answer

Dense attention has quadratic sequence-length work during full-sequence processing, and naive implementations materialize a large attention matrix.

## Detailed answer

For length $n$ and hidden width $d$, the score/value products cost $O(n^2d)$; projections add $O(nd^2)$. A naive multi-head implementation stores $O(Hn^2)$ attention entries. During cached one-token decoding, attention over an existing context is linear in that context length, but reading the growing KV cache can become a bandwidth bottleneck. Large context windows also create a modeling challenge: access to distant evidence does not guarantee its effective use.

For an 8,192-token sequence, one head's score matrix contains $8192^2=67,108,864$ entries. At two bytes per entry that is 128 MiB for one matrix, before additional intermediates. Thirty-two heads would require 4 GiB just for that materialized matrix. Doubling sequence length quadruples this term. This calculation explains why a model can run out of memory even when its parameter weights fit comfortably.

Training and prefill compute many query positions at once, allowing large matrix multiplications. Cached decoding computes only one new query per sequence but reads earlier keys and values. Its arithmetic may be modest while transferring cache data consumes substantial time. Weight reads, FFN work, and communication can also dominate depending on batch size and hardware.

Diagnose by measuring the intended phase and shape. An optimization that accelerates long-prompt prefill may have little effect on short-context decoding. Finally, resource efficiency and reasoning quality are separate: avoiding an out-of-memory error does not establish that the model can combine facts spread across a long document.
