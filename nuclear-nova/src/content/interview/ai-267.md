## Question

Implement top-k MoE routing with a shared expert in PyTorch, and point out the efficiency and correctness traps.

## Brief answer

Compute router scores, select k distinct routed experts per token, normalize their selected weights, and add an always-active shared expert. Preserve token order when scattering expert outputs back, and accumulate contributions when a token visits multiple experts.

## Detailed answer

This educational PyTorch implementation uses an expert loop and `index_add`; it is differentiable but not a fused, distributed production kernel. Input shape is `[tokens, width]`. It uses softmax routing and is not an exact reproduction of DeepSeek's sigmoid/bias router.

```python
import torch
from torch import nn

class SharedMoE(nn.Module):
    def __init__(self, width, expert_count, k):
        super().__init__()
        if not 1 <= k <= expert_count:
            raise ValueError('invalid k')
        self.k = k
        self.router = nn.Linear(width, expert_count, bias=False)
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(width, 2*width), nn.SiLU(),
                          nn.Linear(2*width, width))
            for _ in range(expert_count)
        ])
        self.shared = nn.Linear(width, width)

    def forward(self, x):
        logits, indices = self.router(x).topk(self.k, dim=-1)
        weights = logits.softmax(dim=-1)
        output = self.shared(x)
        for expert_id, expert in enumerate(self.experts):
            token, slot = torch.where(indices == expert_id)
            values = expert(x[token]) * weights[token, slot, None]
            output = output.index_add(0, token, values)
        return output

torch.manual_seed(4)
model = SharedMoE(8, 4, 2)
x = torch.randn(5, 8, requires_grad=True)
y = model(x)
assert y.shape == x.shape
assert model(torch.empty(0, 8)).shape == (0, 8)
y.square().sum().backward()
assert torch.isfinite(x.grad).all()
assert model.router.weight.grad is not None
```

For linear experts of width d, dominant work is O(Nkd²) plus router O(NdE), with N tokens and E experts; parameter storage includes all experts. Top-k ties and hard selection affect gradients and reproducibility. Production concerns include load balancing, capacity/overflow policy, fused grouped matmuls and cross-device all-to-all costs. Compare against a dense reference mixture on small inputs and test empty experts, k=1 and k=E before optimizing.

A critical training edge case is k=1: softmax over one selected logit is exactly one, so this task loss gives the router zero gradient despite the gradient tensor existing. Top-1 training needs an additional differentiable routing objective or a different gating rule, such as preserving selected probabilities from a softmax over all experts. Those choices change the model and must be evaluated; the example intentionally exposes the limitation.

### Token order and accumulation are invariants

`topk` returns a selected expert index and logit for each token slot. Softmax over those selected logits gives normalized combination weights. For each expert, `torch.where` identifies the tokens and slots assigned to it, the expert computes their outputs, and `index_add` accumulates contributions at the original token positions. Ordinary indexed assignment would overwrite a prior expert contribution when k exceeds one.

The shared path runs for every token regardless of routing. Empty assignments must remain valid so rarely selected experts do not crash a batch; the test also covers an empty overall input. Compare the sparse result with a dense reference that evaluates every expert and masks unselected contributions on small tensors. Check gradients as well as forward values, including the documented k=1 limitation. Production dispatch groups tokens into efficient expert batches and may cross device boundaries, requiring token-index provenance, synchronization, and an explicit overflow policy. These system optimizations must preserve the selected mixture rather than silently dropping contributions to achieve speed.
