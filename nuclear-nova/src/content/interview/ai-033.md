## Question

How do you choose between a sparse retriever (BM25) and a dense retriever? When do you need both?

## Brief answer

Sparse retrieval is strong for exact terms, identifiers and rare names; dense retrieval helps with paraphrases and semantic similarity. Hybrid retrieval is useful when both patterns occur and evaluations demonstrate complementary errors.

## Detailed answer

Run both retrievers on a labeled query set, inspect failures by query type, and fuse ranked lists rather than blindly adding incomparable raw scores. Reciprocal-rank fusion is a simple starting point. Apply permission and version filters consistently in both paths, deduplicate passages, then optionally rerank. More candidates cost latency and can increase distractors. Choose the smallest candidate budget that meets recall targets for the downstream answer task.

BM25 uses lexical overlap weighted by term rarity and document length, making an exact error code or part number highly informative. A dense retriever maps query and passage into vectors, allowing “reset my password” to match “recover account access” without shared words. Dense similarity can also confuse closely related but wrong entities, while lexical search can miss paraphrases entirely.

For a query such as “ZX-91 won't charge,” use both the rare identifier and the semantic symptom. Retrieve candidate lists independently, apply identical access/version filters, then merge by rank. Reciprocal-rank fusion can score a document as $\sum_j1/(c+r_j)$, where $r_j$ is its rank in retriever $j$ and $c$ controls the influence of top ranks. This avoids pretending BM25 scores and cosine similarities use the same scale.

Judge whether the combined set contains more answer-bearing evidence at the same candidate budget. A union of two large lists can improve recall while lowering precision and increasing reranking cost. Inspect slices for acronyms, identifiers, multilingual queries and conceptual questions. If one retriever adds no unique useful results, the operational complexity may be unnecessary. Retrieval quality should ultimately be checked against the downstream answer, because a semantically related document is not always sufficient evidence.
