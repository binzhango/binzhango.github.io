## Question

Implement multi-head attention, then convert it to grouped-query attention.

## Brief answer

Project queries into many heads and keys/values into either the same number of heads or fewer shared groups. Multi-head attention is the special case where the key/value head count equals the query-head count. GQA reduces cached keys/values; simply repeating KV tensors is a correctness reference, not a memory-efficient production implementation.

## Detailed answer

This runnable PyTorch module supports both configurations. The input is `(batch, tokens, model_width)` and each query-head group shares one KV head.

```python
import torch
from torch import nn

class GroupedAttention(nn.Module):
    def __init__(self, width, heads, kv_heads):
        super().__init__()
        if width % heads or heads % kv_heads:
            raise ValueError('head counts must divide evenly')
        self.h, self.g, self.d = heads, kv_heads, width // heads
        self.q = nn.Linear(width, width, bias=False)
        self.k = nn.Linear(width, kv_heads * self.d, bias=False)
        self.v = nn.Linear(width, kv_heads * self.d, bias=False)
        self.out = nn.Linear(width, width, bias=False)
    def forward(self, x):
        b, t, _ = x.shape
        q = self.q(x).view(b, t, self.h, self.d).transpose(1, 2)
        k = self.k(x).view(b, t, self.g, self.d).transpose(1, 2)
        v = self.v(x).view(b, t, self.g, self.d).transpose(1, 2)
        k = k.repeat_interleave(self.h // self.g, dim=1)
        v = v.repeat_interleave(self.h // self.g, dim=1)
        s = q @ k.transpose(-1, -2) / self.d ** .5
        mask = torch.ones(t, t, dtype=torch.bool, device=x.device).triu(1)
        y = s.masked_fill(mask, -torch.inf).float().softmax(-1).to(v.dtype) @ v
        return self.out(y.transpose(1, 2).contiguous().view(b, t, -1))

for groups in (1, 2, 4):
    m = GroupedAttention(16, 4, groups)
    assert m(torch.randn(2, 5, 16)).shape == (2, 5, 16)
```

For conversion of a trained MHA checkpoint, reshape each K/V projection by head and average the heads assigned to a group, leaving Q and the output projection unchanged. This changes model behavior and normally needs additional training.

For width 16 and four query heads, each head has four features. With two KV heads, the K and V projections each output eight features rather than sixteen. Query heads 0–1 share the first KV head and 2–3 share the second, but their distinct queries yield different attention weights. The output still concatenates four head results before projecting back to width 16.

A useful equivalence test sets `kv_heads == heads` and compares against an independent multi-head reference using identical weights. For GQA, verify the head-group mapping explicitly, then test gradients and causal masking. `repeat_interleave` expands KV data here for clarity, so this code demonstrates semantics rather than the intended memory saving. Real kernels broadcast or address shared KV without copying it. Also validate positive head counts and nonempty sequence lengths in a hardened implementation. Shape tests alone cannot detect an incorrect grouping or an attention softmax over the wrong axis.
