## Question

What are the optimization strategies for retrieval and generation modules?

## Brief answer

Optimize the stage responsible for the measured error: source coverage and retrieval, evidence packing, or grounded generation.

## Detailed answer

For retrieval, improve parsing, chunk boundaries, hybrid search, filters, embeddings, and candidate recall before reranking. For generation, preserve sufficient context, reduce distractors, use clear evidence instructions, and test grounded tuning when needed. Cache only with suitable freshness and access scoping. Change one stage at a time and track quality, latency, and cost on the same evaluation set; adding components everywhere obscures causality.

Use controlled experiments at the failing boundary. If a known answer passage is absent from candidates, compare parsing repair, lexical/dense retrieval, metadata filters, and query interpretation. If it appears low in a broad pool, evaluate a reranker. If it is highly ranked but missing from the final prompt, fix deduplication, context expansion, or token-budget selection.

For generator failures, first supply a clean minimal context containing the answer. If that works, distractors or evidence organization are likely contributors. If it still fails, clarify the requested operation, use deterministic extraction or computation where applicable, or compare a stronger generator. Grounded tuning is justified when a recurring evidence-use behavior needs to be learned.

Change one major component at a time and use the same question set and source snapshot. Track unsupported claims, abstention, latency, and cost as well as accuracy. Cache keys should include relevant source versions, access scope, and prompt/model configuration so stale or unauthorized answers are not reused. Complexity should be added where evidence demonstrates a failure, rather than applying every available RAG technique to every request.
