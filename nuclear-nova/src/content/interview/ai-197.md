## Question

On average, how many fair coin flips until you see two heads in a row? Walk me through it.

## Brief answer

The expected number of fair coin flips until two consecutive heads is six. Track whether the current suffix is no heads or one head, then write expectation equations. Counting only the probability of a particular two-flip block misses overlapping attempts and gives the wrong reasoning.

## Detailed answer

Let $E_0$ be the expected remaining flips with no current head streak, and $E_1$ the expectation after one head. From state zero, a tail returns to zero and a head moves to one:

$$E_0=1+\tfrac12E_0+\tfrac12E_1.$$

From state one, a head completes the task while a tail resets:

$$E_1=1+\tfrac12E_0.$$

Substitute the second equation into the first: $E_0=1+E_0/2+1/2+E_0/4$, hence $E_0=6$ and $E_1=4$.

For a coin with head probability p greater than zero, the same equations give $E_0=(1+p)/p^2$. At p=1, the answer is two; as p approaches zero it diverges. These checks support the derivation. Simulation can verify the estimate statistically but is not a replacement for the exact state-based argument.

The state must retain exactly the history relevant to future success. After a tail, previous heads no longer matter, so the process returns to state zero. After one head, another head finishes, while a tail loses that partial progress. This two-state description handles overlapping attempts automatically.

The tempting answer four comes from treating disjoint pairs as independent trials with success probability one quarter. But the actual process checks overlapping pairs and the waiting-time accounting differs; that shortcut does not model what happens after a single head. The expectation equations charge one flip for every transition, including transitions back to the same state.

For a biased coin, $E_0=1+(1-p)E_0+pE_1$ and $E_1=1+(1-p)E_0$. Solving yields $(1+p)/p^2$, recovering six at $p=0.5$. At $p=1$, two flips are necessary and sufficient; at $p=0$, completion never occurs. These endpoint checks are useful whenever deriving a waiting-time formula from a state machine.
