## Question

What are components and chains in LangChain?

## Brief answer

Components perform individual operations; chains compose operations into a defined flow.

## Detailed answer

For example, a workflow can format a prompt, call a model, and parse its response. Runnable-style interfaces support composition and invocation across compatible components. A chain can be conditional or parallel, but its control flow is still specified by the application rather than necessarily chosen by an agent. Handle retries and side effects explicitly: retrying a model call is different from repeating a tool that changes external state.

A useful chain has explicit input and output contracts. For instance, a retriever takes a question and access scope, returns source records, a formatter turns them into model messages, and a parser converts the response into an application object. Each stage can be tested with fixed fixtures before an expensive model call is introduced.

Composition does not remove error semantics. If retrieval returns no evidence, the next stage should receive that fact and produce an insufficient-evidence response rather than silently inventing context. If parsing fails, a bounded retry may be appropriate. If an earlier component sent a payment or modified a record, rerunning the entire chain could repeat the side effect; separate pure computation from operations that require idempotency.

Conditional branches can route simple queries to one model and difficult ones to another, while parallel branches can retrieve from independent sources. The application still owns how branches are selected and combined. Use an agent only when choosing the sequence dynamically provides a real benefit; a fixed chain is often easier to reason about, profile, and validate for a known workflow.
