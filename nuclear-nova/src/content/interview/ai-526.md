## Question

A serving system’s cost is dominated by KV cache rather than model weights. How could you reduce KV memory by an order of magnitude, and what would you give up?

## Brief answer

Estimate KV memory from active sequences, cached tokens, layers, KV heads, head dimension, and bytes per element. An order-of-magnitude reduction usually needs several levers: shorter retained context, fewer KV heads, lower precision, sharing repeated prefixes, and better allocation. No single safe drop-in technique guarantees 10× on every workload.

## Detailed answer

For standard attention, approximate KV bytes per sequence as `2 × layers × tokens × KV_heads × head_dim × bytes_per_value`. An illustrative 32-layer, 8-KV-head model with head dimension 128, 32,768 cached tokens, and 2-byte values uses about 4 GiB per sequence before overhead. Reducing retained tokens 4× and element storage 4× could yield 16× raw reduction, but requires quality and kernel validation.

PagedAttention targets allocation waste and sharing; it does not erase the intrinsic bytes of unique retained tokens. Grouped-query attention changes model architecture and may require a different checkpoint. KV quantization can affect quality; eviction loses exact history; host offload adds transfer latency. Measure useful throughput, p95 latency, long-context accuracy, and cache hit rates together before claiming the target achieved.

### Separate mathematical savings from practical savings

The example's raw cache is `2 × 32 × 32768 × 8 × 128 × 2 = 4,294,967,296` bytes, exactly 4 GiB. Reducing the retained length to 8,192 tokens and using four-bit values instead of sixteen-bit values gives a theoretical 16-fold reduction in value storage. Scales, alignment, paging metadata, and unsupported kernels make realized savings smaller, and the quality impact must be tested on tasks that use old context.

These levers remove different costs. Prefix sharing saves repeated identical tokens across requests but does little when every conversation is unique. Paging reduces wasted allocation, not the intrinsic size of occupied unique tokens. GQA reduces KV heads only when the model architecture supports it; it is not a runtime switch that preserves any arbitrary checkpoint's function.

Start by measuring occupied versus reserved memory, repeated-prefix share, and retained-context usefulness. If fragmentation is small and prefixes are unique, promising tenfold savings from an allocator change is implausible. Quantization, selective retention, or a different model may be necessary, with explicit tradeoffs in accuracy, recomputation, and latency.
