## Question

Why do benchmark scores improve while users say the system got worse? Enumerate the reasons.

## Brief answer

Benchmark and user experience can diverge because of distribution mismatch, contamination, proxy metrics, latency regressions, formatting changes or reduced reliability on important slices. Aggregate gains can mask severe minority-case failures.

## Detailed answer

Replay recent complaints against old and new versions using identical context and tools. Check whether the benchmark scores isolated responses while users need complete multi-step outcomes. Inspect refusal rate, verbosity, calibration, citation quality and time to useful answer. Verify the evaluation harness and judge did not change. Add confirmed production failures to development coverage while retaining a separate untouched release set.

Several distinct explanations can produce the same complaint. The benchmark may emphasize short factual answers while users need long workflows. Its test set may be contaminated or overused for model selection. An automatic judge may favor verbosity, while users value directness. A model upgrade can improve raw reasoning but become slower, refuse more valid requests or break a format expected by downstream software.

Aggregate scores can also hide population shifts. A large English slice may improve enough to mask a substantial regression in a smaller language or specialist domain. Infrastructure changes can alter retrieval, tool reliability or prompt truncation even when the benchmark evaluates only a standalone model. User perception reflects the whole product, including how failures are recovered and communicated.

Investigate with concrete paired examples rather than arguing from the headline score. Reproduce complaints using the same source context, tools and settings on both versions, then classify the failures. Verify the judge and harness themselves. Add the missing task types to development evaluations, preserve an untouched release set and track the user outcome that motivated the product. A benchmark is useful when its measured improvements predict better real tasks; when that relationship breaks, revise the measurement and the system rather than dismissing the feedback.
