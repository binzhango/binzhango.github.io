## Question

Implement a client pool over multiple LLM providers with failover: providers fail, time out, or rate-limit, and callers should just get a completion.

## Brief answer

Give the request one overall deadline, classify retryable failures, and fail over only before returning output. Respect provider eligibility and normalize responses without pretending that models are interchangeable. A timeout may leave a provider still computing, so cancellation and retry limits are necessary to bound cost; a pool cannot promise success when every provider fails.

## Detailed answer

This Python 3.11+ core tries each eligible provider once, preserves cancellation, and shares one deadline. Provider adapters expose `complete(prompt)` and translate only transient failures into `TransientError`; authentication and invalid-input errors propagate.

```python
import asyncio

class TransientError(Exception):
    pass

async def complete(providers, prompt, total_timeout=10, attempt_timeout=3):
    loop = asyncio.get_running_loop()
    deadline = loop.time() + total_timeout
    errors = []
    for provider in providers:
        remaining = deadline - loop.time()
        if remaining <= 0:
            break
        try:
            async with asyncio.timeout(min(remaining, attempt_timeout)):
                return await provider.complete(prompt)
        except (TransientError, TimeoutError) as exc:
            errors.append(type(exc).__name__)
    raise RuntimeError(f"No completion before deadline; failures={errors}")
```

Add shared cooldowns for `Retry-After`, per-provider semaphores, circuit breakers, and a request correlation ID around this core. Never send restricted data to an unauthorized fallback. After streaming begins, surface interruption rather than concatenating another model's response. Test first-provider failure, all-provider failure, timeout, caller cancellation, and permanent errors. For tool-producing completions, retries must not execute duplicate side effects.


### Follow one request through failure

With a ten-second overall budget and three seconds per attempt, a first provider can time out at three seconds, a second return a rate-limit error immediately, and a third receive only the budget still remaining. Resetting a fresh ten-second timeout for each provider would break the caller's deadline and amplify load during an outage. The event loop's monotonic clock avoids wall-clock adjustments changing elapsed-time accounting.

The exception boundary is deliberate. Invalid credentials or a malformed prompt will often fail everywhere; treating them as transient would waste capacity and obscure the real error. Caller cancellation propagates because the core does not catch it as an ordinary provider failure. Adapters must honor cancellation and close response streams; a deadline is not a guarantee that remote work has stopped or become free.

This function is the failover core, not a complete pooled transport. Reuse long-lived HTTP clients, bound connections with semaphores, and reject work early when the remaining deadline is too short. In a real pool, add jittered retries only within a capped request budget and update circuit-breaker state from many requests, not from one isolated failure.
