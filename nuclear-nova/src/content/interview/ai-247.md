## Question

Mistral 7B shipped with grouped-query attention and sliding-window attention. What does each buy you, and what does each cost?

## Brief answer

GQA shares KV heads across query-head groups, reducing cache storage and bandwidth. Sliding-window attention limits each layer's direct attention range, bounding cache growth when the runtime actually evicts old entries. These are separate mechanisms with different quality tradeoffs.

## Detailed answer

The original Mistral 7B v0.1 paper uses both. Fewer KV heads reduce representation flexibility relative to independent heads; a window removes direct access to distant positions, although information can propagate through stacked layers. Neither change guarantees a particular speedup on every kernel. Confirm the exact checkpoint and runtime configuration: later models carrying the Mistral name need not share the same window policy. Evaluate long-distance evidence retrieval and short-context quality, and profile actual cache allocation rather than assuming the configured attention mask automatically releases memory.

### Head sharing and windowing reduce different dimensions

With 32 query heads and eight KV heads, each group of four query heads uses the same keys and values. Relative to 32 independent KV heads at the same width, persistent KV storage is one quarter. Query projections remain distinct, so the model retains several attention patterns over shared representations. The quality and kernel efficiency of that sharing must be evaluated.

A sliding window of W tokens limits each layer's direct causal attention to the recent window. For a long sequence, a rolling cache can then retain O(W) historical KV values per layer rather than O(T). Stacked layers can propagate information farther than one window, but that does not give a new token direct access to every old fact. Test distant evidence retrieval and tasks requiring exact old details. The serving implementation must honor absolute positions and safe overwrite timing, especially during chunked prefill. A mask that ignores old tokens but still allocates their cache does not deliver the expected capacity saving.
