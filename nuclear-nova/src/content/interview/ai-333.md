## Question

How do bagging and boosting differ? What is the computational difference between XGBoost and Random Forest?

## Brief answer

Bagging trains multiple models on resampled data and averages them, primarily reducing variance. Boosting builds an additive model sequentially so later learners address the current ensemble's errors or gradients. Random forests add feature subsampling to bagged trees; XGBoost is a regularized gradient-boosted tree system with optimized tree construction, not merely a faster random forest.

## Detailed answer

Forest trees can generally be trained independently, enabling broad parallelism. Boosting rounds depend on previous predictions, limiting parallelism across rounds, although split finding and operations within a round can be parallelized. Their actual runtime depends on tree depth, number of trees, histogram construction, sparsity, hardware, and stopping rules; neither is always faster.

Random forests often provide a strong low-tuning baseline and are comparatively robust to individual noisy trees. Boosted trees can fit complex tabular patterns efficiently but need control of learning rate, depth, sampling, and number of rounds. Use early stopping on a valid holdout and compare quality at matched latency and memory budgets.

### How the ensemble is constructed

Bagging fits multiple predictors on resampled data and averages or votes their outputs. Random Forest also randomizes feature choices at splits, reducing correlation between trees so averaging can reduce variance. Boosting builds a sequence: each new tree corrects errors expressed through the current objective's gradients, and its contribution is scaled by a learning rate.

In XGBoost, a candidate split is evaluated using accumulated first- and second-order loss information plus regularization. Histograms reduce the number of candidate thresholds that need examination, and column/row subsampling further change the cost. A forest can train trees concurrently, whereas the next boosting round depends on prior predictions. At inference both generally traverse many trees, so depth and tree count determine latency more directly than the label “boosting.” For noisy labels, aggressive boosting can keep fitting hard mislabeled examples; a forest is not immune but averages independently constructed trees. Compare tuned configurations under the same validation split and resource budget.
