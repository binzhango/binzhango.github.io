## Question

Why did Hugging Face create safetensors when pickle-based checkpoints already worked everywhere?

## Brief answer

Pickle can execute Python code during deserialization, making untrusted checkpoints dangerous. Safetensors stores tensor metadata and raw tensor data in a constrained format that does not require arbitrary object reconstruction, while supporting efficient loading and partial access. It reduces a serialization attack surface, but does not make an entire model repository or its custom code trustworthy.

## Detailed answer

A tensor loader needs shapes, dtypes, offsets, and bytes, not the ability to instantiate arbitrary Python objects. Safetensors validates its metadata and supports efficient memory-mapped access where the runtime permits it.

Trade-offs include restrictions around tensor layouts, shared storage, and arbitrary Python metadata. Conversion from an untrusted pickle is itself risky because reading the original may execute code; do not perform that conversion casually in a privileged environment. Pin trusted artifacts, validate checksums and dimensions, and separately review any `trust_remote_code` path. A safe file format does not prevent malicious model behavior, poisoned weights, or resource-exhaustion bugs elsewhere in the stack.

### Data loading should not require executing objects

Pickle can encode instructions to construct Python objects, which may invoke arbitrary code during loading. A weights file only needs typed tensor metadata and a byte region for each tensor. Safetensors restricts the representation to that data-oriented contract, making it possible to inspect shapes and offsets without granting the file Python execution semantics.

Memory mapping can let a runtime access tensor bytes without first copying the entire file into a separate Python buffer, though actual copies depend on device placement and implementation. Metadata and offset validation prevent malformed layout assumptions, but callers should still bound tensor sizes and resources. Shared storage and unusual layouts may need explicit handling during serialization rather than arbitrary object preservation. Safe loading does not establish provenance or model behavior: verify artifact identity and separately inspect any remote modeling code. Converting an unknown pickle file is dangerous precisely because conversion begins by reading the unsafe format; do it only through an appropriately trusted or isolated process.
