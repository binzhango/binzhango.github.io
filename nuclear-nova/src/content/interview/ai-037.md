## Question

How does agentic RAG differ from standard RAG, and when is the extra complexity justified?

## Brief answer

Standard RAG follows a mostly fixed retrieve-then-answer path. Agentic RAG lets a controller choose searches, inspect results and perform additional steps, which is useful for genuinely multi-hop or underspecified tasks.

## Detailed answer

For a question requiring two sources, the first retrieval can identify an entity and the second locate its relevant record. Expose bounded search tools with structured outputs, track evidence by source, and stop on sufficient support or a budget limit. Extra loops add latency and new failure opportunities, including repeated searches and prompt injection from documents. Prefer a fixed pipeline when one retrieval already meets the task’s quality requirements.

Consider “Which customers affected by incident X also have contracts expiring this month?” One search identifies the affected accounts; a second authorized query checks contract dates. The second query depends on the first result, so a fixed single retrieval is an awkward fit. An agent can decompose the task and combine evidence while retaining entity IDs to avoid confusing similarly named customers.

Represent the process as bounded state: goal, unresolved subquestions, evidence collected, tools available and remaining budget. After each observation, the controller decides whether another search is necessary. Stop when every required claim has support, when a tool cannot supply it, or when cost/time limits are reached. Repeating a query with no new evidence should trigger a changed strategy or a partial answer, not another identical loop.

The additional freedom creates failure paths: query drift, unsupported joins, inconsistent source versions and instruction injection inside retrieved material. Keep permissions and execution limits outside the model. Evaluate complete tasks, tool counts, latency and unsupported claims against a simpler fixed pipeline. Agentic retrieval is worthwhile when adaptive steps measurably solve cases that the fixed pipeline misses, not merely because a loop can be inserted around search.
