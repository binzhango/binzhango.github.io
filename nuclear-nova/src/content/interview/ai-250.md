## Question

You need to quantize a model for a customer's hardware. How do you choose a scheme, and how do you prove quality hasn't regressed?

## Brief answer

Choose quantization jointly with the customer's hardware kernels, memory budget and acceptable quality loss. Establish an unquantized baseline, use representative calibration/evaluation data, and test the exported artifact on the real serving path.

## Detailed answer

Decide separately for weights, activations and KV cache. Weight-only compression may solve capacity without accelerating unsupported matrix shapes, while activation outliers can require finer scales or mixed precision. Include rare entities, numerical outputs, long contexts and tool schemas in paired evaluation. Measure peak memory, TTFT, token latency and throughput at realistic concurrency; bits per parameter alone do not establish savings. Keep conversion configuration and checkpoint versions reproducible. If a scheme fails a critical slice, try a higher-precision layer/group policy or a different model rather than relaxing the quality gate silently.

### Choose the numerical contract with the runtime

Start from the hardware's efficient supported formats and kernels: a four-bit file is not useful if each operation expands it through a slow unsupported path. Specify weight and activation precision, group size, scales, excluded layers, and KV precision separately. Calibration should represent the deployed languages, prompt lengths, and task types, including activation outliers.

Use paired evaluation on identical requests and decoding settings. Compare task correctness, critical numerical/entity errors, structured-output validity, and long-context behavior, with uncertainty and explicit acceptable regression thresholds. “No regression” means no unacceptable difference under the evaluated contract, not proof that every possible input is unchanged. Profile the actual exported engine for peak memory, startup, first-token latency, decode latency, and energy or cost. If one fragile layer causes most loss, retain higher precision there rather than discarding all compression. Version the conversion and keep the full-precision baseline so future runtime updates can reproduce both quality and performance comparisons.
