## Question

How to load a BERT model using transformers?

## Brief answer

Load a matching tokenizer and BERT encoder with `AutoTokenizer` and `AutoModel`, then tokenize text into tensor inputs.

## Detailed answer

This example requires PyTorch, Transformers, and access to the checkpoint on the first run. `AutoModel` returns the encoder without a task-specific classification head; use the appropriate task class when needed.

```python
import torch
from transformers import AutoModel, AutoTokenizer

checkpoint = "google-bert/bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
model = AutoModel.from_pretrained(checkpoint).eval()
inputs = tokenizer(
    ["A short sentence.", "Another example."],
    padding=True, truncation=True, return_tensors="pt",
)
with torch.no_grad():
    outputs = model(**inputs, output_hidden_states=True, return_dict=True)
print(outputs.last_hidden_state.shape)  # [batch, tokens, 768]
```

Pin checkpoint revisions and package versions for reproducible runs.

The tokenizer maps strings into vocabulary IDs and adds the model's expected special tokens. Batched examples are padded to a common length, and the attention mask identifies which positions are real input. `AutoModel` chooses the encoder class from the checkpoint configuration; it does not attach a sentiment classifier or make the checkpoint a sentence-embedding model.

Calling `.eval()` disables training-time behavior such as dropout, while `torch.no_grad()` avoids building a gradient graph for this inference example. These operations solve different problems, so use both when appropriate. To run on an accelerator, move both the model and all input tensors to the same device. Padding to the longest example in a batch avoids unnecessary work compared with always padding to the maximum supported length.

`truncation=True` can silently discard important text after the supported limit. For long documents, decide whether to chunk, aggregate, or use another model rather than assuming the complete document was read. Check the output dimensions against batch size and tokenized length. Reproducible deployment needs the tokenizer, model revision, package environment, and preprocessing policy together, not just a saved weight file.
