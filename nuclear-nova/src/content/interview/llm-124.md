## Question

How to build an effective prompt template?

## Brief answer

An effective RAG prompt states the task, separates instructions from evidence, specifies source attribution, and explains what to do when evidence is insufficient or conflicting.

## Detailed answer

For example, supply the question and numbered excerpts, require support for factual claims, and ask the model to identify unresolved conflicts. Keep source IDs stable and include dates or titles when they affect interpretation. Avoid filling the context with redundant text. Retrieved content is untrusted data: prompt wording helps, but authorization, tool permissions, and output checks must also exist outside the model.

A practical prompt contract has four parts: the task, the evidence boundary, the output format, and the behavior when support is missing. For example: answer the user's policy question using the supplied excerpts; attach source IDs to factual claims; distinguish conflicting versions by their effective dates; and state which requested fact cannot be established. This is more actionable than simply saying “be accurate.”

Place the question and excerpts in clearly identified sections, with each source's title, version, and excerpt ID. Keep those IDs unchanged through retrieval and packing. A model cannot produce reliable citations if the prompt changes identifiers or loses the relation between a passage and its source. Reserve tokens for the answer and remove redundant excerpts before removing essential qualifications.

Test the same prompt on sufficient, missing, contradictory, and adversarial evidence. A retrieved page may contain instructions aimed at the assistant; treat that text as untrusted source content. Prompt wording can guide interpretation, but server-side permissions and output checks must enforce application boundaries. Validate the actual claims and citations rather than equating compliance with a template to correctness.
