## Question

Your agent spends over half its first turn just finding the relevant code. How do you fix that?

## Brief answer

Measure where repository discovery time goes, then improve the search funnel and persist trustworthy repository structure. Use exact lexical and symbol search before expensive semantic exploration, reuse current indexes, and provide targeted context rather than dumping files. The objective is faster arrival at relevant evidence without increasing wrong-file edits.

## Detailed answer

Instrument tool calls, bytes read, duplicate searches, and time until the first correct file or symbol is found. Build a lightweight map of modules, entrypoints, tests, ownership, and dependency edges keyed by commit. Search errors and identifiers exactly, then expand from promising hits through callers and tests. Include changed files and the user's active context as useful priors.

Cache discovery artifacts only with version validation; stale summaries can waste more time than fresh search. Improve tool outputs so they include paths, snippets, and bounded surrounding context without truncating decisive lines. Evaluate on held-out tasks using relevant-file recall, exploration cost, and final task success. Avoid optimizing “time to first edit” alone: premature edits can make the overall task slower and less reliable.

### Improve the discovery funnel

For a bug report containing an error string, begin with an exact search for that string, then inspect the emitting function, its callers, and the nearest tests. For a conceptual feature request without identifiers, search a repository map or semantic index, but validate every hit against current source before editing. Different query types need different entry points.

Useful measurements include repeated identical searches, files read but never used, relevant-file recall after the first few calls, and time spent loading oversized tool output. A map that saves one search but omits an essential dependency can make the final task slower. Cache paths and symbol relationships with the commit or content hash that supports them, and invalidate only affected regions after changes.

An experiment might compare the existing tools with bounded search results containing path, symbol, matching line, and nearby tests. Keep the agent model and task budget fixed, then inspect both discovery cost and final correctness. The goal is to reduce unnecessary exploration while preserving enough evidence to make the first implementation decision sound.
