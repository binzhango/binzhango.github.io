## Question

Where do vision-language models and foundation models genuinely help in an autonomy stack, and where are they a liability?

## Brief answer

Foundation models are useful for semantic scene understanding, data mining, labeling assistance, and high-level reasoning where their errors can be checked. They become liabilities when uncalibrated outputs directly control time-critical physical behavior or when runtime cost exceeds the onboard budget. Evaluate the actual role, not the model's general benchmark reputation.

## Detailed answer

**Suggested approach.** Start with offline scenario retrieval, annotation proposals, or explanations for engineers, where review can catch mistakes. For onboard use, bound the interface to validated semantic features or proposals and measure worst-case latency, power, and uncertainty. Keep deterministic constraints and a tested fallback independent of free-form reasoning.

Test unfamiliar signage, unusual objects, adverse weather, contradictory sensor evidence, and prompt-like text in the environment. Compare gains on the specific operating domain against simpler models. Watch dataset leakage and overconfident explanations: a fluent rationale is not evidence of correct perception. Promote a foundation-model component only when its contribution survives closed-loop and failure-mode evaluation under the intended hardware constraints.

### Promote capability through bounded roles

An offline model can search for unusual construction scenes or propose labels for engineering review. Errors are comparatively easy to inspect and correct before they affect driving. A model used onboard has a stricter contract: its outputs arrive within a deadline, use a defined schema, and feed a component that understands uncertainty and failure.

For example, a semantic model might flag a scene as potentially containing an unusual temporary instruction. That can trigger a conservative validated behavior or request further analysis. Allowing free-form text to directly choose steering or override a traffic constraint creates a much less bounded interface. Printed text in the environment should be treated as observed data, not as instructions to the software system.

Measure incremental benefit against the existing stack. If a foundation model improves rare-scene labeling but adds unacceptable onboard latency, retain it offline. Distillation or a narrower model may capture the useful capability more efficiently, subject to fresh validation.

Evaluate adverse weather, unseen objects, sensor disagreement, and misleading visual text under the target hardware limits. Check whether explanations correspond to evidence rather than simply sounding convincing. The strongest use case is a demonstrable improvement in a specific pipeline role with controlled failure behavior; general visual-language benchmark performance is insufficient to justify a safety-critical runtime dependency.
