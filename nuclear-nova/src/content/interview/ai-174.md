## Question

Design and build a webhook delivery system that reliably delivers events to customer-registered URLs.

## Brief answer

Persist events before delivery, queue one delivery attempt per subscription and retry transient failures with backoff. Sign payloads and give each event a stable ID so recipients can deduplicate. Promise at-least-once delivery within a retention window, because a timeout after the recipient committed the event makes exactly-once delivery impossible to infer from HTTP alone.

## Detailed answer

Suggested design: the producer writes an event and outbox entry in the same transaction. A dispatcher creates durable delivery records, and workers send signed requests with bounded timeouts. Record attempt count, response class and next-attempt time. Move exhausted deliveries to a dead-letter state with explicit replay controls.

Validate destination URLs and defend against SSRF, including redirects and DNS changes. Rotate signing secrets with overlap and include a timestamp to limit replay. Rate-limit per endpoint so one slow customer cannot consume all workers. Decide whether ordering is required; per-subscription serialization preserves order at the cost of head-of-line blocking.

Test duplicate events, receiver success followed by a lost response, invalid signatures, endpoint deletion and long outages. Expose delivery status without logging sensitive payloads unnecessarily. Manual replay should preserve event identity while creating a new attempt history.

The transactional outbox prevents a dual-write gap: the business event and the intent to deliver it commit together. Without it, a process could update the database and crash before enqueueing the webhook, permanently losing the notification. Delivery attempts are separate records so retries preserve the original event identity while adding an auditable history.

A receiver may commit the event and then lose the HTTP response. The sender cannot distinguish that from non-delivery, so it retries and the receiver must deduplicate by event ID. Sign the exact payload bytes plus relevant timestamp/version metadata, and document how secret rotation and replay windows work. Changing JSON serialization after signing can otherwise break verification.

Use per-destination concurrency and retry budgets to isolate unhealthy endpoints. Ordering requirements should be explicit: strict order can block later events behind one failure, while unordered delivery requires receiver-side version handling. Test the ambiguous-success case and manual replay, not only clean 200 responses. The promise is durable, observable delivery attempts with a clear retention policy, not magical exactly-once effects across independent systems.
