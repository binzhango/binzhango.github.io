## Question

What is Multi-head Latent Attention (MLA) and why did DeepSeek introduce it?

## Brief answer

MLA compresses keys and values into a shared low-dimensional latent representation that can be cached. DeepSeek-V2 introduced it to reduce the memory and bandwidth required for autoregressive attention.

## Detailed answer

The cache stores a latent vector per token rather than independent full-sized keys and values for every head, plus the position-related information required by the architecture. Projection weights can be rearranged or absorbed into surrounding operations for efficient inference. Consequently, the ordinary GQA cache formula cannot be applied unchanged. Quality depends on the trained compression dimension; MLA is not merely post-training deletion of KV dimensions.

Conceptually, an input hidden state $h_t$ is compressed to $c_t=W_{down}h_t$. Head-specific projections then recover content keys and values from $c_t$. Caching $c_t$ avoids storing all recovered vectors. In a naive implementation, repeatedly expanding the entire history would erase much of the benefit. An optimized implementation rewrites the dot products so that part of the key projection is absorbed into the query transformation, and similarly combines value/output projections.

Position information needs special treatment because ordinary rotary transformations depend on token position and obstruct a simple absorption of the key projection. MLA separates the rotary position component from the compressed content component. The per-token cache therefore includes both a content latent and the required positional key component, rather than a single unexplained compressed vector.

For an illustrative latent width 512 and positional width 64 at two bytes per element, one layer stores $(512+64)\times2=1,152$ bytes per token. This is a layout example, not a universal DeepSeek configuration. Multiply by actual layers and tokens when sizing a deployment. The tradeoff includes extra projections, specialized kernels and a trained information bottleneck. MLA saves cache bandwidth and capacity; it does not remove attention's need to process the retained history.
