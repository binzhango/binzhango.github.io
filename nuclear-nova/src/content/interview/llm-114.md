## Question

How do indexes and retrievers differ?

## Brief answer

An index organizes data for search; a retriever accepts a query and returns relevant documents or records.

## Detailed answer

A vector store can back a retriever, but retrieval can also use BM25, a database, an API, or several sources together. Preserve stable IDs, source metadata, and authorization filters. Index construction and query-time retrieval are separate lifecycle stages: changing embedding models usually requires re-embedding compatible documents. A retriever's interface does not guarantee useful recall or proper access control; those require implementation and evaluation.

An index is a prepared search structure: an inverted index maps terms to documents, while a vector index organizes embeddings for similarity lookup. A retriever is the query-time behavior that decides which structures to search, what filters to apply, and how to return candidates. One retriever can combine lexical and vector indexes; another can query a relational database without a vector index at all.

Separate ingestion from serving. Ingestion parses documents, assigns stable IDs and versions, computes representations, and updates indexes. Query serving encodes or parses the request, applies access and freshness constraints, searches, and returns evidence records. Deleting a document should remove or invalidate its searchable representations, not only its visible source file.

Evaluate recall and ranking on known questions. A retriever returning ten records successfully does not establish that any supports the answer. If embedding models change, rebuild or version the document vectors coherently with the query encoder. Keep original source text and provenance because an embedding alone cannot support a citation or explain which sentence established the answer.
