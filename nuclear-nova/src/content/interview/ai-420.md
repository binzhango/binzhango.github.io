## Question

Write the server-side handler for streaming token generation. Handle client disconnects correctly.

## Brief answer

Run token production and disconnect monitoring concurrently, apply backpressure while sending, and cancel the upstream generation when the client leaves. Cleanup must release the engine request and KV state even during cancellation or send failure. Streaming syntax, timeout policy, and partial-response semantics belong in the handler contract; emitting tokens alone is not enough.

## Detailed answer

This runnable ASGI-style handler assumes authentication, request parsing, and admission control already occurred. `factory` returns an async generator whose `finally` releases the backend request. Each event contains JSON so token newlines cannot corrupt SSE framing.

```python
import asyncio
import json

async def stream_tokens(receive, send, factory):
    async def disconnected():
        while True:
            if (await receive())['type'] == 'http.disconnect':
                return

    async def produce():
        stream = factory()
        try:
            await send({'type': 'http.response.start', 'status': 200,
                        'headers': [(b'content-type', b'text/event-stream')]})
            async for token in stream:
                body = ('data: ' + json.dumps({'token': token}) + '\n\n').encode()
                await send({'type': 'http.response.body', 'body': body,
                            'more_body': True})
            await send({'type': 'http.response.body', 'body': b'',
                        'more_body': False})
        finally:
            await stream.aclose()

    tasks = [asyncio.create_task(produce()), asyncio.create_task(disconnected())]
    try:
        done, _ = await asyncio.wait(tasks, return_when=asyncio.FIRST_COMPLETED)
        for task in done:
            await task  # propagate backend, send, and receive errors
    finally:
        for task in tasks:
            if not task.done(): task.cancel()
        await asyncio.gather(*tasks, return_exceptions=True)

async def test():
    events, closed = asyncio.Queue(), []
    async def receive(): return await events.get()
    async def generator():
        try:
            yield 'first\nline'
            await asyncio.Event().wait()  # simulate a slow next token
        finally: closed.append(True)
    sent = []
    async def send(event):
        sent.append(event)
        if event.get('body'):
            await events.put({'type': 'http.disconnect'})
    await asyncio.wait_for(stream_tokens(receive, send, generator), 1)
    assert closed == [True]
    assert b'first\\nline' in sent[1]['body']

asyncio.run(test())
```

In production, bound generation and send deadlines, cap output, sanitize logged errors, and ensure the backend's abort operation is idempotent and bounded. Once headers are sent, a later failure cannot become a new HTTP status; define an error event or terminate the stream. Test disconnect before first token, during a stalled send, and after normal completion, plus backend exceptions.

### Cancellation is a resource-lifetime problem

Two tasks run concurrently: one produces and sends token events, while the other listens for disconnection. Whichever finishes first triggers cleanup of the other. Awaiting canceled tasks prevents orphaned coroutines, and closing the generator invokes its `finally` block so the backend can release KV state and stop scheduling tokens.

Awaiting `send` provides a backpressure point: a slow client should not cause an unbounded in-memory token queue. Add a send deadline and a total generation deadline in a real server. JSON encoding preserves newlines inside token text without creating accidental SSE event boundaries. Normal completion sends a final body with `more_body=False`; errors after response headers require a defined stream-level error or termination. Test early disconnect, a blocked sender, backend failure, and simultaneous completion. The handler does not guarantee backend cleanup unless the generator's abort path is itself correct and bounded; integrate and test that contract rather than assuming Python cancellation automatically stops GPU work.
