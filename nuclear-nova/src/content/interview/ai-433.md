## Question

Fine-tune an 8B model on a single 24 GB GPU. Walk me through the memory maths and the exact stack you'd use.

## Brief answer

Use QLoRA: keep the 8B base weights frozen in four-bit form and train low-rank adapters, with gradient checkpointing and a small microbatch. Full Adam fine-tuning typically exceeds 24 GB by a wide margin. Feasibility still depends on architecture, sequence length, vocabulary, adapter targets, and temporary activations; an 8B label alone is not a memory guarantee.

## Detailed answer

Raw four-bit weights are about 4 GB, plus quantization scales and higher-precision exceptions. For comparison, a common mixed-precision full-training budget can approach 16 bytes per parameter for weights, gradients, master weights, and Adam moments: about 128 GB before activations. Adapter state is much smaller but activations can dominate.

A concrete stack is PyTorch, Transformers, bitsandbytes NF4 with double quantization, PEFT LoRA, and TRL SFTTrainer. Start with rank 16 on attention projections, microbatch one, 2K-token sequences, gradient accumulation, BF16 compute if supported, checkpointing, and training-time KV caching disabled. Pin a mutually compatible set of versions after a smoke test; these settings are a starting configuration, not universal optimum. Measure peak allocated and reserved memory before increasing sequence length. Validate heldout loss and task quality, save adapters with the exact base revision, and avoid inference-oriented automatic device maps for training.

### Account for each memory term

Let P be base parameters and A trainable adapter parameters. Four-bit base storage is approximately P/2 bytes before scales and exceptions. Adapter training adds adapter weights, gradients, and optimizer state proportional to A, while activations depend on microbatch, sequence length, hidden dimensions, and checkpointing. This is why a small adapter does not make arbitrarily long contexts fit.

For one 4,096×4,096 projection, rank-16 LoRA adds 131,072 trainable parameters. Across many selected projections and layers, calculate A explicitly instead of assuming a percentage. Gradient accumulation increases the effective batch without keeping every microbatch's activations live, but does not reduce the memory for one too-long sequence. Activation checkpointing recomputes intermediates during backward to trade compute for memory. Begin with a forward/backward/optimizer smoke test, inspect peak allocated and reserved memory, then expand sequence length gradually. Validate formatting and label masking before expensive runs. Save the adapter, exact base revision, tokenizer, template, and quantization/training configuration so evaluation and deployment reproduce the trained behavior.
