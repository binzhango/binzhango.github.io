## Question

Estimate the KV-cache memory for serving Mistral 7B, and design the rolling-buffer cache that sliding-window attention enables.

## Brief answer

For original Mistral 7B v0.1, use 32 layers, eight KV heads, head dimension 128 and a 4,096-token window. BF16 keys and values then require 512 MiB per fully populated sequence cache, excluding allocation metadata and workspaces.

## Detailed answer

The calculation is $2\times32\times8\times128\times2\times4096=536870912$ bytes. Without eviction, an 8,192-token full cache would be 1 GiB. A ring buffer stores logical position $t$ in slot $t\bmod W$, but attention must retain absolute position information and read slots in the correct logical order. Never overwrite keys still needed by another token in the current prefill chunk; use chunk scheduling or temporary state consistent with the causal/window mask. Test the first wrap boundary, partially filled buffers and batches with different lengths. This applies to the v0.1 architecture, not every later Mistral checkpoint.

### A rolling cache needs logical positions

For a small illustrative window W=4, tokens at absolute positions 0,1,2,3 occupy slots 0,1,2,3. Token 4 overwrites slot 0 only after position 0 is no longer needed. The logical history is now positions 1,2,3,4, even though its physical slot order is 1,2,3,0. Attention must pair values with their correct absolute positions and causal/window mask.

During a multi-token prefill chunk, later writes can overwrite cache entries still needed by earlier computations in that chunk. Schedule reads and writes safely or maintain temporary storage rather than applying a naive modulo assignment concurrently. Track each sequence's valid length and write position independently; padding or one shorter request must not expose another request's state. The 512 MiB calculation counts live BF16 KV values for the stated architecture, not allocator reserve or workspaces. Verify memory stops growing after the window fills, and test output parity against a simple masked full-cache reference around wrap boundaries.
