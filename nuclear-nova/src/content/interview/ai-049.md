## Question

How does multi-agent orchestration work, and when does it break down?

## Brief answer

Multi-agent orchestration assigns bounded tasks to separate model contexts and combines their outputs through an explicit coordinator or workflow. It helps when subtasks are independent or need distinct tools and evidence.

## Detailed answer

Define ownership, inputs, outputs and acceptance checks before dispatch. Parallel work can reduce elapsed time but duplicates context and increases cost. Shared-state edits need serialization or isolated workspaces. Failures include conflicting assumptions, circular delegation, repeated research and unverified consensus. Measure against a single-agent baseline; add agents only when independent progress outweighs coordination overhead, and keep final integration responsibility explicit.

A coordinator should dispatch tasks with a concrete deliverable, ownership boundary and acceptance criterion. For instance, one agent can inspect database query performance while another reviews frontend rendering, provided they do not both rewrite the same shared configuration. The coordinator integrates evidence and resolves contradictions rather than assuming multiple confident answers constitute independent verification.

Communication has a cost. Every agent needs enough context to act correctly, but copying an entire history multiplies tokens and can distract from its bounded task. Prefer compact briefs and structured results containing findings, evidence, changes and unresolved assumptions. Shared files need disjoint ownership, locks or isolated branches; parallel text generation does not make concurrent mutations safe.

Multi-agent systems break down when subtasks are tightly coupled, the decomposition is wrong, or agents repeatedly delegate without producing artifacts. Correlated models can repeat the same misconception, so agreement is weak evidence. Use an external test, source record or deterministic check to settle important disputes. Measure wall time, total cost and final correctness against a single-agent baseline. Parallelism is most useful for independent research or implementation work; sequential workflows are often clearer for tasks whose next step depends heavily on the previous result.
