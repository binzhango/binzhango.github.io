## Question

The space of possible conversations is effectively infinite. How do you evaluate a conversational agent before launch?

## Brief answer

Sample conversations by business intent, risk, user behavior, and system state, then test both successful paths and adversarial transitions. Combine scripted stateful simulations with human role-play and production-shadow evidence. Infinite possible wording does not prevent systematic coverage of the finite policies and failure mechanisms that matter.

## Detailed answer

Build a scenario matrix covering identity, permissions, missing information, ambiguity, interruptions, tool failures, and policy boundaries. Generate paraphrases and multi-turn variations while keeping expected outcomes explicit. Grade backend state, required confirmations, factual support, and conversation clarity separately. Use independent checks for severe policy invariants rather than relying on an LLM judge alone.

Run multiple seeds to estimate nondeterministic failure rates and hold out scenario families. Human reviewers assess empathy, confusion, and handoff quality on sampled traces. Before launch, shadow real workflows with no writes, then canary a narrow population. Report confidence intervals and worst-performing categories. Passing many easy conversations must not offset a small number of unauthorized refunds or fabricated order confirmations.

### Test transitions rather than every sentence

A cancellation workflow has a manageable set of important states: unidentified customer, identified reservation, cancellation proposed, approval received, request submitted, and confirmed or unknown outcome. Vary the language within each state, then test transitions such as withdrawing approval, changing the reservation, or interrupting after submission. This covers mechanisms that many paraphrases share.

Use a cross-product selectively: pair high-risk policy boundaries with tool faults and ambiguous user language instead of generating only random conversations. A user simulator can produce varied traces, but its mistakes must not become the sole judge of success. Check durable backend state and authorization invariants with independent code.

For rare failures, report the number and nature of trials. Observing zero violations in n independent trials gives only an approximate upper 95% failure-rate bound of 3/n, not proof of zero risk; correlated scenarios weaken that interpretation further. That is why representative sampling, targeted adversarial cases, staged rollout, and monitoring complement one another. No finite test set exhausts conversation, but it can expose and bound specific failure mechanisms.
