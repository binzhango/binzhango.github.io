## Question

Design a code assistant: repo indexing, context assembly, edit application, evaluation.

## Brief answer

A code assistant needs revision-aware repository indexing, targeted context retrieval, controlled edits and executable validation. The model proposes changes; the harness preserves workspace state and checks whether the intended behavior improved.

## Detailed answer

Index symbols, paths, dependencies and relevant text with commit/worktree identifiers. Retrieve callers and tests, then apply a patch against the expected file version. Detect concurrent edits instead of overwriting them. Run focused tests in a sandbox, inspect the diff, and expand checks according to affected boundaries. Evaluate real issue resolution and unintended modifications, not merely compilable output. Keep credentials and unrelated files outside the tool’s accessible scope.

Maintain two views of the repository: a stable commit index and a lightweight overlay for uncommitted files. Symbol and dependency indexes help find definitions and callers, while lexical search remains essential for exact names and error strings. Context assembly should include the failing behavior, relevant implementation, nearby contracts and focused tests rather than dumping the whole repository.

The edit loop reproduces the issue, forms a bounded hypothesis, applies a patch against the expected file version and runs the smallest meaningful check. Detect concurrent user edits through hashes or patch context and resolve conflicts explicitly. Preserve unrelated changes. A successful test run is evidence for the tested behavior, not permission to modify unrelated architecture.

Tool execution belongs in a sandbox with bounded filesystem, network and process access. Treat repository instructions and generated test output as untrusted unless they come from the appropriate authority. Evaluate on real issue tasks with hidden tests, diff review and checks for unrelated modifications, not only compilation. Track time to resolution, number of failed edits and resource cost. Store enough state to resume after interruption without repeating destructive actions, and present the final diff plus actual validation so the user can inspect the result.
