## Question

Cognition published an argument against multi-agent systems and later published what actually works. Reconcile those two positions.

## Brief answer

The positions are compatible when you distinguish parallel reasoning from uncontrolled parallel writes. Cognition's earlier argument emphasized lost shared context and conflicting implicit decisions; its later account describes narrower arrangements where several agents contribute while writes remain serialized. Coordination structure and ownership matter more than the number of model instances.

## Detailed answer

The June 2025 earlier post argues that agents making independent implementation choices can produce incompatible pieces because task summaries omit consequential context. The April 2026 follow-up retains that concern for parallel-writer swarms while reporting useful patterns with single-threaded writes. Those are dated claims about the authors' experience, not a theorem that all parallel editing fails.

The follow-up gives two concrete patterns: a coding agent and an independent reviewer iterate through findings, and a smaller primary agent consults a stronger “smart friend” for difficult decisions. In both cases, the primary agent retains control of the implementation. A reviewer can benefit from a clean context because it inspects the actual diff without inheriting the author's assumptions; the coordinator then evaluates each finding against the full task context. This qualifies “share all context”: independent criticism can use less shared history, while applying changes still requires coherent decisions. It does not endorse multiple writers silently making incompatible choices.

In a proposed coding harness, parallelize evidence gathering, independent review, or bounded experiments, but give one coordinator authority over the final implementation. If parallel edits are used, isolate ownership and define contracts, integration tests, and conflict resolution. Compare end-to-end quality and elapsed time including integration overhead. More simultaneous tokens are useful only when the decomposition preserves the information needed for coherent decisions.

### The conflict is in shared decisions

Suppose one agent changes an API to return a nullable result while another writes a caller assuming exceptions. Both patches can be locally reasonable and individually tested, yet the combined program is wrong. The missing information is the cross-cutting contract, not merely a merge conflict that Git can detect. Two agents editing separate files are not independent when their decisions constrain each other.

A useful decomposition instead asks one worker to locate failure evidence, another to propose test cases, and a coordinator to choose and implement the contract. Parallel implementation can also work when ownership is genuinely bounded, such as independent adapters against a frozen interface, with a final integration check.

Estimate the benefit using total elapsed time: parallel work saves only the portion that can proceed independently, while planning, communication, review, and repair remain. Measure incorrect assumptions and integration rework in addition to token cost. The dated arguments are best read as observations about coordination designs; neither “never use multiple agents” nor “more agents always means faster delivery” follows from them.
