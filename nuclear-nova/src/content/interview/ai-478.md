## Question

An agent needs to iterate on code (run builds, tests, lints) without disturbing what the user sees in their editor. Architect that.

## Brief answer

Run the agent in an isolated worktree or snapshot with its own build outputs, dependencies, processes, and logs. Share immutable caches where safe, but never the user's active buffers or mutable build directories. Return a diff and verification evidence, then reconcile with the user's current branch before applying changes.

## Detailed answer

**Suggested approach.** Pin the base commit and environment image, provision a per-task filesystem, and run commands under CPU, memory, disk, and network limits. Namespace ports and databases so tests do not collide with the user's development server. Persist task state and logs independently of the process so interruption does not erase the investigation.

Cache dependencies by lockfile and platform, with read-only sharing or copy-on-write isolation. Do not copy ambient credentials wholesale. At completion, collect the patch, test commands, exit codes, and relevant artifacts. A three-way merge detects changes made by the user since the snapshot. Test crashes, disk exhaustion, long-running child processes, and cleanup after cancellation. Isolation has startup and storage costs, but it makes experimentation reversible and results reproducible.

### Isolate mutable state beyond source files

Two worktrees can still interfere if their tests share a database name, fixed port, temporary directory, or writable dependency cache. Assign a task namespace to those resources and pass it explicitly into the execution environment. A shared cache should expose immutable entries keyed by lockfile, platform, and toolchain; installation writes belong in the task's own layer.

If the user has uncommitted changes that the task depends on, capture an explicit working snapshot rather than silently starting from an older commit. Preserve that snapshot as the merge base. At handoff, compare the agent result with the user's current checkout, carrying forward nonconflicting changes and surfacing overlaps.

A durable task record stores the base, patch, command history, and artifact locations. If a worker dies midway through a test, a replacement can restore the last known filesystem state and rerun the interrupted check. Do not infer success from an absent process. This architecture costs extra disk and environment startup, but prevents experiments, cleanup commands, and background servers from unexpectedly modifying the user's active development session.
