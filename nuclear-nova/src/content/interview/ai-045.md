## Question

How do you handle tool-call errors, timeouts and retries in an agentic loop?

## Brief answer

Classify tool failures into retryable, permanent and uncertain outcomes. Use bounded retries with backoff and jitter for transient failures; validate arguments and avoid blindly repeating actions that may already have succeeded.

## Detailed answer

A timed-out read can usually be retried, but a timed-out payment or write needs an idempotency key and a status lookup. Return structured errors to the controller, including whether execution occurred and what recovery is allowed. Cap elapsed time, attempts and total cost, propagate cancellation, and escalate when uncertainty remains. Keep an action ledger so recovery after a crash does not silently duplicate effects.

Use a failure taxonomy tied to execution semantics. Invalid arguments and permission denials are normally permanent for that call and should return a clear corrective error. Rate limits and transient connection failures may be retried within a deadline. A timeout after a write was accepted is an unknown outcome, which requires reconciliation rather than an automatic second write.

For example, create an idempotency key before requesting a refund and persist it with the intended amount and account. If the connection drops, query the provider with that key. Retry only according to the provider's idempotency contract; a locally generated key is useless if the remote system ignores it. Keep the same key across retries of one logical operation and reject reuse with a changed payload.

Retries need exponential backoff, jitter, maximum attempts and a total time budget so many agents do not amplify an outage. Propagate cancellation into pending calls and release reservations. Return structured errors with retryability, correlation ID and whether effects may have occurred, while omitting secrets. Test failures before dispatch, after remote commit and during result persistence. The final user response must distinguish confirmed success from an unresolved outcome instead of converting a timeout into an invented completion.
