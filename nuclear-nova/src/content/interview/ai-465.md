## Question

Build a hash tree to organise data in a repository.

## Brief answer

Build a Merkle tree: hash file bytes at leaves and hash a canonical sequence of child names and hashes at each directory. The root commits to both content and repository structure. Include type tags and unambiguous encoding so different trees cannot collide merely because strings were concatenated ambiguously.

## Detailed answer

This implementation constructs a tree from normalized relative paths. It rejects path traversal and file/directory collisions. Hash equality is a practical content-identity test under the hash's collision-resistance assumption, not a mathematical proof of identical bytes.

```python
import hashlib
import json

def merkle(snapshot):
    root = {}
    for path, content in sorted(snapshot.items()):
        parts = path.split('/')
        if any(p in ('', '.', '..') for p in parts):
            raise ValueError('invalid path')
        node = root
        for part in parts[:-1]:
            node = node.setdefault(part, {})
            if not isinstance(node, dict):
                raise ValueError('file/directory collision')
        if parts[-1] in node:
            raise ValueError('file/directory collision')
        node[parts[-1]] = bytes(content)
    def digest(node):
        if isinstance(node, bytes):
            return hashlib.sha256(b'file\0' + node).hexdigest()
        entries = [(name, digest(value)) for name, value in sorted(node.items())]
        return hashlib.sha256(b'dir\0' + json.dumps(entries).encode()).hexdigest()
    return digest(root)

assert merkle({'a': b'x', 'b': b'y'}) == merkle({'b': b'y', 'a': b'x'})
assert merkle({'a': b'x'}) != merkle({'a': b'y'})
```

Initial construction must read all bytes. For efficient subsequent diffs, persist node hashes and recompute only ancestors of changed files. Include permissions or symlink targets if they are part of the repository identity contract.

### Follow the hashes upward

For `src/a.py` and `README`, hash each file's bytes with the file type marker. Hash the `src` directory from the ordered pair containing `a.py` and its file hash. Finally hash the root's ordered entries for `README` and `src`. Changing one byte of `a.py` changes its hash, the `src` hash, and the root hash, while `README` remains reusable. Sorting makes insertion order irrelevant; including names makes a rename visible even when file bytes do not change.

The encoding must be canonical across every writer. Fix text encoding, Unicode path policy, separator semantics, and serialization rules before using hashes as portable object IDs. A concatenation such as `ab` plus `c` must not be confused with `a` plus `bc`; explicit structured encoding prevents that ambiguity.

If B is total file bytes and N is the number of entries, initial work includes O(B) hashing plus sorting costs for child names. Incremental updates read only changed content and recompute affected ancestors. Persisting those node records, rather than only returning the root string as this demonstration does, is what enables fast subtree comparison and content-addressed storage.
