## Question

What is MCP (Model Context Protocol) and how does it differ from traditional function calling?

## Brief answer

MCP standardizes communication between AI applications and servers exposing tools, resources and prompts. Function calling is the model-facing mechanism for proposing a tool use; an application can map MCP tools into that mechanism.

## Detailed answer

The host manages clients and server connections, while capability negotiation establishes supported operations. MCP does not decide whether a model should act or whether the user authorized an action. Authentication, least privilege and consent remain application responsibilities. Pin a protocol version and validate transport and authorization behavior against the MCP specification; do not assume all servers implement every capability.

Think of function calling as the model-facing vocabulary and MCP as one possible application-to-tool-server interface. A host application connects through clients to servers that advertise capabilities. The host can discover tool schemas, present selected tools to the model, execute a proposed call through the protocol and return the result to the model. Resources and reusable prompts are other protocol concepts, not model-generated function calls.

For a documentation server, a resource might expose a document, while a tool performs a parameterized search. The host decides which user session can access that server and whether the search is allowed. Transport authentication does not imply that every advertised operation is authorized for every user. Tool descriptions and returned content must also be treated as untrusted inputs.

The value is interoperability: the same server can serve compatible hosts without each integration inventing a bespoke wire format. It does not guarantee consistent tool semantics, trustworthy results or safe automatic execution. Negotiate a supported protocol version, validate schemas and result sizes, and enforce timeouts and least privilege in the host. For a small fixed internal API, direct integration may be simpler; MCP becomes useful when reusable integrations and capability discovery outweigh an additional protocol layer.
