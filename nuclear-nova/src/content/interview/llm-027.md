## Question

What’s the difference between prefix LM and causal LM?

## Brief answer

A causal LM masks future positions everywhere; a prefix LM allows bidirectional attention inside its input prefix and causal attention in its generated suffix.

## Detailed answer

For prefix length $P$, prefix queries can attend only to prefix positions, while a suffix query at position $i$ can attend to every position up to $i$. Both usually include the position itself; the representation predicts the next token. Prefix language modeling is not prefix tuning: prefix tuning learns small task-specific continuous prefixes and need not change a causal model's mask.

For an input prefix of two tokens followed by two output positions, the allowed attention pattern is conceptually:

```text
          p1 p2 o1 o2
p1         1  1  0  0
p2         1  1  0  0
o1         1  1  1  0
o2         1  1  1  1
```

A one means that the row may read the column; zeros are masked. The ordinary causal mask would replace the first row's second entry with zero. The prefix therefore gets bidirectional contextualization without revealing future output to suffix predictions.

The loss must respect this information flow. Applying ordinary next-token loss indiscriminately inside the bidirectional prefix can leak the next token through attention. Prefix-LM training generally treats the designated prefix as conditioning information and supervises the continuation according to the chosen objective. At generation time, cache the fully processed prefix, then append suffix tokens causally. Changing a pretrained model's mask at inference without compatible training is not a reliable substitute for training it to use that mask.
