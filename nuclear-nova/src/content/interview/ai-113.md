## Question

Implement an LRU cache with O(1) get/put, then add TTL.

## Brief answer

Use a hash map plus a doubly linked recency list for constant-time lookup, insertion and eviction. TTL adds expiry metadata and a clock; reading an expired key removes it. Lazy expiry preserves O(1) operations but may leave expired entries occupying capacity until accessed or evicted.

## Detailed answer

Python's `OrderedDict` supplies the recency list. TTL is measured from insertion or update, not from access. Injecting a monotonic clock makes boundary tests deterministic.

```python
from collections import OrderedDict
from time import monotonic

class LRU:
    def __init__(self, capacity, clock=monotonic):
        if capacity < 0: raise ValueError('negative capacity')
        self.capacity, self.clock, self.data = capacity, clock, OrderedDict()
    def get(self, key, default=None):
        if key not in self.data: return default
        value, expiry = self.data[key]
        if self.clock() >= expiry:
            del self.data[key]; return default
        self.data.move_to_end(key)
        return value
    def put(self, key, value, ttl=float('inf')):
        self.data.pop(key, None)
        if ttl <= 0 or self.capacity == 0: return
        self.data[key] = (value, self.clock() + ttl)
        if len(self.data) > self.capacity: self.data.popitem(last=False)

now = [0.]
c = LRU(2, lambda: now[0]); c.put('a', 1, ttl=2); c.put('b', 2)
assert c.get('a') == 1
c.put('c', 3); assert c.get('b') is None
now[0] = 2; assert c.get('a') is None
```

Background expiry needs another structure, often a min-heap with versioned entries, and adds $O(\log n)$ maintenance. State whether expired-but-unaccessed entries may cause eviction of a live entry. Add a lock for multithreaded compound operations; individual container methods do not make the overall protocol atomic.


A successful `get` moves the key to the most-recent end; `put` removes an old version before inserting the new value at that end. When capacity is exceeded, the oldest entry is removed. In the example, reading `a` makes `b` least recent, so inserting `c` evicts `b`. At time exactly two, `a` expires because the lifetime is half-open.

TTL and recency answer different questions. A frequently read key can still expire under insertion-based TTL, and a never-read expired key can remain in memory until eviction. If that behavior wastes too much capacity, add an expiry heap and version each update so an old heap entry cannot delete a refreshed value. Test capacity zero, updating an existing key, expiry boundaries and values equal to the default return value. A distinct missing sentinel is preferable when `None` is a legitimate cached value. Distributed caches need an explicit consistency and invalidation policy beyond this local data structure.
