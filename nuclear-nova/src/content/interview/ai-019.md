## Question

How does PagedAttention work, and what problem of KV-cache fragmentation does it solve?

## Brief answer

PagedAttention maps a sequence’s logical KV blocks to separately allocated physical blocks. Requests can grow without reserving one large contiguous cache region, reducing fragmentation and enabling controlled sharing of identical prefixes.

## Detailed answer

A block table translates token positions to physical locations. Completed requests release blocks; shared prefix blocks need reference counts and copy-on-write when modified. Some internal waste remains in partially filled final blocks, and smaller blocks increase metadata and lookup overhead. This paging manages GPU cache allocation; it does not itself mean every block can be fetched cheaply from CPU storage.

Suppose cache blocks hold 16 tokens. A sequence of 35 tokens uses three blocks: two full blocks and one with three occupied slots. It can append tokens into the last block and request another block only when needed. The sequence's logical block numbers map through a table to physical blocks that can be anywhere in the cache pool.

A contiguous allocator might reserve room for a maximum 4,096-token output even when the request stops after 35 tokens. Paging replaces that large reservation with bounded last-block waste. With block size 16, a live sequence wastes at most 15 token slots in its final block, excluding metadata and other runtime overhead. Freed blocks can be reused by unrelated requests without compacting all surviving sequences.

Identical prefixes can share immutable blocks. If one request extends a partially shared block, copy-on-write prevents it from altering another request's history. Cache keys must also include model, adapter and position semantics so apparent text matches do not reuse incompatible state. Paging improves memory utilization and enables larger effective batches; it does not reduce the number of attention comparisons or remove bandwidth limits. Block size should be tuned against kernel efficiency, metadata overhead and typical sequence lengths.
