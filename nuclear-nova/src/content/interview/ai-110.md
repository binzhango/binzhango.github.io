## Question

Implement a KV cache and single-step decode.

## Brief answer

Keep each layer's previous keys and values, append the new token's projections, and compute attention for only the new query. Apply positional encoding at the token's absolute position before caching keys. Cache storage grows with tokens, layers, KV heads and head width; query heads alone do not determine its size.

## Detailed answer

Here is a one-head NumPy cache with fixed capacity. It accepts already projected, position-encoded vectors. This isolates the caching mechanism from the rest of a Transformer.

```python
import numpy as np

class KVCache:
    def __init__(self, capacity, width):
        self.k = np.empty((capacity, width))
        self.v = np.empty((capacity, width))
        self.n = 0
    def step(self, q, k, v):
        if self.n == len(self.k):
            raise OverflowError('cache full')
        if any(np.shape(x) != (self.k.shape[1],) for x in (q, k, v)):
            raise ValueError('head-width mismatch')
        self.k[self.n], self.v[self.n] = k, v
        self.n += 1
        s = self.k[:self.n] @ q / self.k.shape[1] ** .5
        p = np.exp(s - s.max()); p /= p.sum()
        return p @ self.v[:self.n]

c = KVCache(2, 2)
assert np.allclose(c.step(np.ones(2), np.ones(2), [1, 3]), [1, 3])
assert np.allclose(c.step(np.ones(2), np.ones(2), [3, 5]), [2, 4])
```

No future mask is needed here: the cache contains only the prefix and current token. Chunked prefill does require an offset-aware causal mask. Test cached output against full-prefix attention at every position, reset between requests, and handle beam branching explicitly. This avoids recomputing old projections but still reads the prefix KV state on each decoding step.

At each step, the cache first appends the current token's key and value, then scores the query against entries `0..n-1`. With equal keys, attention becomes an average of the retained values, explaining why the second example returns `[2,4]`. Only the newly projected token is computed; previous keys and values remain unchanged.

For history length $n$ and width $d$, one step takes $O(nd)$ attention work and the fixed arrays occupy $O(Cd)$ space for capacity $C$. Generating a long sequence still incurs increasing history reads, so caching removes repeated projection work without making full-attention decoding constant-time. Test capacity exhaustion without overwriting existing entries, request reset, dtype consistency and full-prefix equivalence. A multi-layer model needs a separate cache per layer; batched requests also need independent valid lengths. Beam search or shared prefixes require copying or reference-counted ownership, because one sequence's appended token must not mutate another sequence's history.
