## Question

Code a trivial web crawler using Go.

## Brief answer

Use a queue and visited set, resolve relative links against the current page, and keep traversal inside one allowed origin. Set HTTP timeouts and response-size limits. For a small Go exercise, inject the page-link helper so crawling logic is testable without a live network; an HTML parser belongs in the fetch adapter.

## Detailed answer

This complete Go program uses a synthetic page graph. It handles cycles and relative links while enforcing a maximum page count.

```go
package main

import (
    "fmt"
    "net/url"
)

func Crawl(seed string, limit int, links func(string) ([]string, error)) ([]string, error) {
    base, err := url.Parse(seed)
    if err != nil || base.Host == "" || limit < 1 { return nil, fmt.Errorf("invalid seed or limit") }
    queue, seen, out := []string{seed}, map[string]bool{seed:true}, []string{}
    for len(queue) > 0 {
        current := queue[0]; queue = queue[1:]; out = append(out, current)
        found, err := links(current); if err != nil { continue }
        parent, _ := url.Parse(current)
        for _, link := range found {
            relative, err := url.Parse(link); if err != nil { continue }
            target := parent.ResolveReference(relative); target.Fragment = ""
            if target.Scheme != base.Scheme || target.Host != base.Host { continue }
            key := target.String()
            if !seen[key] && len(seen) < limit { seen[key] = true; queue = append(queue, key) }
        }
    }
    return out, nil
}

func main() {
    pages := map[string][]string{"https://example.test/": {"/a"}, "https://example.test/a": {"/"}}
    result, err := Crawl("https://example.test/", 10, func(u string) ([]string,error) { return pages[u],nil })
    if err != nil || len(result) != 2 { panic("crawl failed") }
}
```

A real fetcher should use `context.Context`, restrict redirects and parse HTML with a proper parser. Origin checks on discovered URLs do not by themselves prevent redirects or DNS rebinding to private services. Concurrency requires synchronized ownership of the visited set and per-host politeness, not simply launching a goroutine for every link.


The visited set is updated when a URL is enqueued, preventing cycles from creating duplicate work. Relative links are resolved against the current page, not always the original seed, which matters for nested paths. Removing fragments treats anchors within one page as the same fetch target, while retaining query strings preserves potentially distinct resources.

With $V$ visited pages and $E$ discovered links, traversal work is $O(V+E)$ aside from URL parsing and network cost, and the queue/set use $O(V)$ space up to the limit. The injected helper makes these properties testable with a finite graph; it deliberately does not claim to be an HTTP/HTML implementation.

For a network adapter, configure a client timeout, request context, redirect policy, content-type check and response-size cap. Close response bodies promptly. Add concurrency through a fixed worker pool with synchronized claiming, not one goroutine per discovered URL. Test failed pages, self-links, malformed URLs and off-origin redirects, and keep politeness and allowed network destinations explicit even for a “trivial” crawler.
