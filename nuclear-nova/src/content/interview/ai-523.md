## Question

Design the evaluation framework for an enterprise AI assistant when you cannot look at customer data.

## Brief answer

Run evaluation inside the customer's trust boundary and export only approved aggregate metrics and sanitized diagnostics. Let the customer own representative questions, evidence labels, and review workflows. Synthetic data can test mechanics, but cannot establish quality on private vocabulary and real permission structures by itself.

## Detailed answer

**Suggested approach.** Package a versioned evaluation runner that operates on local documents, tools, and user identities. It computes retrieval recall, supported-answer quality, permission violations, and latency, with customer-controlled sampling and retention. Provide reproducible failure IDs and local trace views so support can discuss an issue without receiving raw content.

Use synthetic fixtures for connector contracts, authorization invariants, and fault injection. Calibrate any automated judge against customer-reviewed examples, and document what aggregate statistics may leave the environment. Prevent small-cell reporting or logs from leaking sensitive facts. Compare releases using paired runs on the same local suite and canary cohorts. When debugging needs content access, use an explicit approved process rather than quietly broadening telemetry.

### Bring the evaluator to the data

Ship a signed, versioned runner into the customer environment with a documented input/output contract. It executes a locally held question set against pinned index and model versions, computes the agreed metrics, and stores full traces locally. Export only approved aggregates, software versions, and opaque failure IDs. A support engineer can then discuss “case 184 failed at ACL filtering” while an authorized customer reviewer opens the underlying evidence.

For paired release testing, run both versions on the same local inputs and report per-category differences with sample sizes. This reduces noise without requiring the vendor to see the text. Synthetic corpora remain useful for testing connector pagination, schema validation, and permission invariants, but cannot establish semantic quality for the customer's actual terminology.

Aggregates can still leak information when groups are tiny or queries are repeatedly differenced. Apply a reviewed export policy, suppress small cells where appropriate, and keep raw prompts and generated content out of default logs. If an incident truly requires a sample, use a separate explicit access process instead of quietly expanding telemetry under the label of debugging.
