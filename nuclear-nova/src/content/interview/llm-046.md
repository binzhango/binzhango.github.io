## Question

Compare Multi-head, Multi-Query, and Grouped-Query Attention.

## Brief answer

MHA has one KV head per query head; MQA has one KV head total; GQA shares each KV head across a group of query heads.

## Detailed answer

For $H$ query heads and $G$ KV heads:

<div class="article-table" role="region" aria-label="Attention head sharing comparison" tabindex="0">

| Variant | KV heads | Relative KV storage |
| --- | --- | --- |
| MHA | $H$ | $1$ |
| GQA | $1<G<H$ | $G/H$ |
| MQA | $1$ | $1/H$ |

</div>

The ratios assume equal layers, batch size, context length, head dimension, and dtype. GQA offers a tunable compromise; quality and speed depend on the checkpoint and implementation.

For 32 query heads and 8 KV heads, partition the query heads into eight groups of four. Each group reads its assigned K/V representation, but each query still computes independent scores. At one token position, MHA stores 32 key vectors and 32 value vectors, GQA stores eight of each, and MQA stores one of each. Queries are transient for the new token; keys and values accumulate in the cache.

The ratio in the table applies to KV storage, not to total model memory or latency. Weights, activations, output projections, and temporary buffers remain. If model weights dominate the memory budget, a fourfold cache reduction does not mean a fourfold reduction in overall GPU use.

Selecting a variant is an architectural and serving decision. More KV heads provide more separate feature representations; fewer can improve cache capacity and bandwidth use. Existing checkpoint conversion must account for training and quality effects. At deployment, confirm the backend supports the intended grouping without expanding the cache into duplicated heads, and compare equal sequence lengths, batch sizes, precision, and quality targets.
