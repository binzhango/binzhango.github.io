## Question

How do BERT token vectors differ from CLS, pooler and masked-mean sentence vectors?

## Brief answer

Use `last_hidden_state` for final token vectors and `hidden_states[k]` for intermediate token vectors; pooling is a separate choice.

## Detailed answer

First run the complete [BERT loading example](#question-llm-061), which defines `model`, `inputs` and `outputs` with hidden states enabled. The code below is the next step in that same Python session.

Continuing the BERT example:

```python
final_tokens = outputs.last_hidden_state
intermediate_tokens = outputs.hidden_states[8]
cls_vector = final_tokens[:, 0, :]
mask = inputs["attention_mask"].unsqueeze(-1).to(final_tokens.dtype)
mean_vector = (final_tokens * mask).sum(1) / mask.sum(1).clamp_min(1)
assert mean_vector.shape == (inputs["input_ids"].shape[0], 768)
```

This mean excludes padding but includes special tokens. `pooler_output` applies a learned transformation to the CLS representation and is not identical to the raw CLS vector. Neither raw CLS nor mean pooling from an untuned BERT is guaranteed to provide strong semantic-search embeddings.

A token vector answers a local representation question: what information does this layer associate with this token in its surrounding context? A sentence vector requires an aggregation rule. Raw CLS uses the first special token's final state. Mean pooling averages token states and can distribute information across the sentence. The pooler applies a learned dense transformation and nonlinearity to CLS; it is a separate output, not a generic semantic average.

Masking is essential. If a three-token example is padded to ten positions, a plain mean over all ten incorporates padding representations and depends on batch padding length. The masked mean divides only by valid positions. The supplied code still counts special tokens; excluding them requires a second explicit mask. Empty effective input needs a defined policy rather than treating the clamp as evidence of a meaningful embedding.

Which aggregation works best depends on training. BERT pretraining did not directly optimize arbitrary sentence pairs for cosine retrieval, so two semantically similar sentences are not guaranteed to have ideal pooled-vector geometry. Compare pooling and layers on the target task, or choose a model trained specifically for sentence embeddings. Keep query/document encoding conventions compatible.
