## Question

Design the execution environment for thousands of concurrent cloud coding agents. It must survive the agent waiting forty minutes for CI.

## Brief answer

Use durable orchestration with ephemeral isolated compute. Persist task state, repository snapshots, artifacts, and event subscriptions outside the worker, so an agent waiting forty minutes for CI can release expensive resources and resume when a signed completion event arrives. Waiting is a workflow state, not a reason to keep a GPU or full container busy.

## Detailed answer

**Suggested approach.** A coordinator records state transitions and schedules sandbox jobs with leases and heartbeats. Store the worktree diff, dependency cache references, tool history, and pending CI identifiers in durable storage. On suspension, checkpoint and terminate idle execution; on an event or timeout, restore the environment and reconcile the latest repository/CI state.

Use idempotent event handling because webhooks may duplicate or arrive out of order. Enforce tenant isolation, short-lived credentials, egress policy, and per-task budgets. A reconciler recovers orphaned leases and missed events. Measure active compute per completed task, wake-up latency, resume failures, and leaked resources. Test worker loss during an edit, CI completion during suspension, repository deletion, and cancellation while an external job continues running.

### Waiting and execution are different states

A task can move from running to checkpointing, waiting-for-CI, ready-to-resume, and running again. Persist the checkpoint and expected CI run ID before releasing the worker lease. When a webhook arrives, verify its identity and compare the run ID and revision with the pending state. A stale successful run from an earlier commit must not wake the task as though its latest patch passed.

Webhooks are commonly delivered at least once, so resuming must be idempotent. Atomically move a waiting task into a resumable state and let only one worker acquire the next lease. A periodic reconciler polls outstanding runs whose notifications may have been lost. Cancellation marks the task terminal before cleanup, preventing a late callback from silently resurrecting it.

For thousands of agents, charge resources to active execution rather than elapsed wall time. Keep lightweight metadata and subscriptions during a forty-minute wait while releasing CPU-heavy containers where restoration is reliable. Some processes cannot be checkpointed safely; restart them from durable application state instead of assuming arbitrary process memory can always be restored.
