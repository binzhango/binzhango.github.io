## Question

Design the data engine: fleet triggers → upload → labelling → retraining → shadow-mode validation → release.

## Brief answer

Suggested approach: build a versioned feedback pipeline that turns fleet observations into validated data and controlled model releases. Triggers select informative scenes, upload policy manages bandwidth and privacy, labeling produces auditable ground truth, and retraining feeds independent evaluation. Shadow mode supplies evidence about proposed behavior but does not by itself prove a release is safe.

## Detailed answer

Use triggers for uncertainty, model disagreement, novel conditions, and important operational events, plus random sampling to avoid selection bias. Deduplicate scenes and record sensor calibration, software version, location class, and collection permissions. Prioritize labeling using expected information value and scenario coverage.

Train reproducibly with immutable dataset/model versions, then run perception tests, scenario simulation, and system-level regressions. In shadow mode, compare proposed decisions with observed conditions without controlling the vehicle; recognize that counterfactual outcomes remain uncertain. Release through defined operational domains and small cohorts with rollback. Track coverage gaps, label quality, regression severity, upload cost, and exposure-adjusted outcomes. Keep ownership explicit at every stage so an unlabeled queue or stale trigger does not silently stall improvement.

### Make the loop auditable end to end

A fleet trigger creates an upload request containing a bounded time window around an event. The ingestion service validates timestamps and calibration, deduplicates overlapping clips, applies privacy controls, and records provenance. A prioritization queue assigns clips to automatic labeling and human review; an immutable dataset manifest identifies exactly what enters training.

After training, compare against the current model on fixed regression scenarios and newly collected slices. Shadow deployment records what the challenger would predict without taking control, but cannot reveal every counterfactual outcome of a different action. Use simulation and controlled tests for those gaps. A release service promotes only approved model/configuration bundles and can restore the previous bundle. Track the time from discovered failure to validated correction, as well as label yield and regression rate. Without these links, a large upload and training pipeline can repeatedly collect the same easy cases while failing to fix the important gap.
