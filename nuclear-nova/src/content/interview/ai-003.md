## Question

What are Multi-Query Attention (MQA) and Grouped-Query Attention (GQA), and what do they trade away?

## Brief answer

MQA gives all query heads one shared KV head; GQA shares each KV head among a group of query heads. Both reduce cache memory and KV bandwidth compared with independent KV heads, potentially sacrificing model quality or flexibility.

## Detailed answer

If there are 32 query heads, ordinary multi-head attention might use 32 KV heads, GQA eight, and MQA one. KV storage scales with the latter number, while each query head still produces its own attention distribution. Changing this layout is an architectural or adaptation choice, not a safe tensor reshape of arbitrary pretrained weights. Benchmark accuracy and throughput on the intended context lengths. GQA studies the quality/efficiency compromise and uptraining.

In multi-head attention, each head has separate query, key and value projections. GQA retains separate query projections while restricting the number of independent key/value projections. For 32 query heads and eight KV heads, query heads 0–3 can share KV head 0, heads 4–7 KV head 1, and so on. The queries still differ, so those four heads generally assign different weights to the shared values.

The raw KV cache in this example is one quarter of the multi-head version; MQA reduces it to one thirty-second. Query projections, output projection and feed-forward layers are not reduced by the same factor. Consequently the cache saving can be much larger than the end-to-end speedup. Efficient kernels must reuse the shared KV data rather than materializing repeated copies, which would give back the bandwidth benefit.

The restriction reduces representational freedom: heads cannot each maintain an entirely separate value subspace. Quality depends on the training recipe and task, especially at long context. An existing model can sometimes be adapted by initializing shared projections from groups of heads and continuing training, but a direct conversion without evaluation is not equivalent. Choose the number of KV groups by quality, cache capacity and measured decode latency together.
