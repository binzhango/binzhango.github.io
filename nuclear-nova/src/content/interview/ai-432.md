## Question

What problem do chat templates solve, and what goes wrong when they're ignored?

## Brief answer

Chat templates serialize roles, messages, tool calls, and turn boundaries into the exact token format a checkpoint was trained to interpret. A conversation is not inherently a structured object to a language model; it is a token sequence. Ignoring the template can blur roles, duplicate control tokens, produce malformed tool calls, or make the model continue the wrong speaker.

## Detailed answer

Use the tokenizer or processor's template for the pinned checkpoint and pass the appropriate generation-prompt option when starting a new assistant response. Training examples and inference prompts must agree about message termination, assistant headers, and multimodal placeholders.

If rendering text first and tokenizing later, avoid adding special tokens a second time when the template already includes them. Test multi-turn conversations, empty messages, tool round trips, system messages, and assistant continuations. Do not invent markers from another model family, and keep template revisions under evaluation because small whitespace changes can alter tokenization. Templates organize input; they do not make untrusted message content authoritative.

### Message objects are not the model's raw input

A chat application stores roles and content as structured objects, but a causal model consumes a token sequence. The template serializes system, user, assistant, and tool messages with the checkpoint's learned delimiters and end markers. Those markers tell the model where a turn starts, who is speaking, and whether it should continue an assistant response or begin a new one.

Using another model family's markers can make the model treat role labels as ordinary text, continue the user, expose control text, or mishandle tool results. Even duplicate beginning-of-sequence tokens can shift the expected distribution. Test a minimal single turn, multiple turns, a tool round trip, and an assistant-prefix continuation with exact expected token IDs. Include the template in training/evaluation versioning and avoid manually concatenating strings in a separate code path. Correct formatting improves compatibility but does not enforce permission or make document text trustworthy; authorization remains outside the model's token sequence.
