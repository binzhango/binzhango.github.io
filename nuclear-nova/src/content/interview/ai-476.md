## Question

The model is streaming a multi-file edit while the user keeps typing in one of those files. How do you apply the edits without corrupting the buffer?

## Brief answer

Apply model edits against the exact buffer version they were generated from, then reconcile with current user edits. Use versioned patches, range tracking, and three-way merge; overlapping changes become explicit conflicts. Streaming is a presentation feature and must not bypass consistency checks or destroy the user's undo history.

## Detailed answer

**Suggested approach.** Capture a base snapshot and assign each model edit an operation ID, target path, base version, and expected text. Stage streamed changes separately while the user types. Transform non-overlapping ranges through intervening editor operations or merge base, current buffer, and proposed output. If both sides change the same semantic region, show a conflict preview rather than guessing.

Commit accepted edits as an editor transaction with coherent undo behavior. Multi-file changes need a staged plan and partial-failure handling because most editors do not provide a filesystem-wide transaction. Revalidate the target immediately before application. Test insertions at range boundaries, line-ending changes, file renames, user undo during streaming, and cancellation. Preserve rejected or conflicting proposals for review without marking them applied.

### A three-version example

Let B be the model's base file, U the user's current buffer, and M the model's proposed file. If U changes a comment at the top while M changes a return expression at the bottom, a three-way merge can carry both changes forward. If both replace the same return expression, a textual merge should report a conflict even if one replacement arrived later. Arrival order is not evidence of user intent.

Range offsets alone are insufficient because an insertion near the top shifts all later offsets. Track positions through editor operations and verify expected old text before applying a hunk. A base hash guards the full file, while anchored old text helps determine whether a proposed local change still applies.

Stage a multi-file proposal as a unit for preview, but acknowledge that underlying writes can fail individually. Record which operations committed and support rollback or a recoverable partial state. If the user cancels generation, retain their edits and discard unaccepted model changes. Never report “applied” merely because the model finished streaming; report the result of the editor transaction and any unresolved conflicts.
