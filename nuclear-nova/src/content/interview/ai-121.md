## Question

Build an in-memory database: SET/GET/DELETE first, then filtered scans, then TTL with timestamps, then file compaction.

## Brief answer

Store values with optional expiry timestamps, make all reads and scans use one visibility rule, and compact only a consistent snapshot of live records. Define whether time is supplied by the caller and whether expiration is inclusive. Compaction rewrites storage; it must not resurrect deleted or expired keys after restart.

## Detailed answer

This illustrative single-process store uses half-open lifetimes: a value expires when `now >= expiry`. Scans return sorted key/value pairs with a prefix. Compaction atomically replaces a JSON snapshot; it is not a write-ahead log.

```python
import json, os
from pathlib import Path

class Store:
    def __init__(self): self.rows = {}
    def set(self, key, value, now=0, ttl=None):
        self.rows[key] = (value, None if ttl is None else now + ttl)
    def get(self, key, now=0):
        row = self.rows.get(key)
        if row is None: return None
        value, expiry = row
        if expiry is not None and now >= expiry:
            del self.rows[key]; return None
        return value
    def delete(self, key, now=0):
        self.get(key, now)
        return self.rows.pop(key, None) is not None
    def scan(self, prefix='', now=0):
        return [(k, self.rows[k][0]) for k in sorted(list(self.rows))
                if k.startswith(prefix) and self.get(k, now) is not None]
    def compact(self, path, now=0):
        self.scan(now=now)
        tmp = Path(str(path) + '.tmp')
        tmp.write_text(json.dumps(self.rows))
        os.replace(tmp, path)

s = Store(); s.set('a', 'x', 0, 2)
assert s.get('a', 1) == 'x' and s.get('a', 2) is None
```

Here `None` is reserved for absence; arbitrary nullable values require a distinct missing sentinel. Concurrent writers require snapshot/version coordination. Crash durability additionally needs flushing and directory synchronization appropriate to the filesystem. Test expiry exactly at the boundary, overwrite after expiry, deleted entries and restore from a compacted snapshot.

All operations must share one visibility predicate: a row exists only if present and not expired at the supplied timestamp. Otherwise `get` may hide a value while `scan` still exposes it, or a deleted expired entry may reappear after compaction. The example treats `now == expiry` as expired, making adjacent lifetimes unambiguous.

Compaction takes the currently live rows and atomically replaces a snapshot file. Atomic replacement prevents readers from observing a partially written filename, but does not by itself guarantee power-loss durability or a consistent snapshot under concurrent writes. A production design needs a lock, copy-on-write version or log position that defines exactly which writes the snapshot includes.

Expected `get` and `set` work is constant-time; sorted scans cost at least $O(n\log n)$ here, and compaction writes the retained dataset. Tests should restore a snapshot and verify that expired/deleted records remain absent. Distinguish a nullable stored value from absence with a sentinel if the API allows `None`; otherwise scans can incorrectly omit a legitimate record.
