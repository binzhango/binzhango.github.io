## Question

How do you prevent context loss during retrieval and compression?

## Brief answer

Context loss happens when retrieval or compression separates a claim from information needed to interpret it, such as a heading, qualifier, or table header.

## Detailed answer

Retrieve smaller units for matching, then expand to neighboring sentences or a parent section with stable source metadata. Preserve relationships among table cells and retain exceptions during summarization. Inspect the exact packed prompt rather than only the original document. More context is helpful only when it restores missing meaning without overwhelming the generator with irrelevant passages.

A chunk saying “the limit is 30” is unusable without the heading that establishes whether 30 means days, requests, or dollars. Similarly, a rule followed by an exception can change meaning when only the first sentence is retrieved. Compression can create the same problem by retaining the apparent main point and dropping a qualification.

Use fine-grained chunks for matching, but preserve source offsets and parent IDs so the system can expand the selected region intelligently. Include the nearest relevant heading, table header, and exception rather than automatically adding an arbitrary fixed number of characters. For tables, preserve row/column associations; for code, preserve function signatures and necessary surrounding definitions.

Check the exact prompt supplied to the model against the original evidence. Ask whether a reader could answer correctly from that prompt alone. Test questions designed to require exceptions, units, and cross-sentence references. Compression should be evaluated for support preservation, not just reduced token count. When a summary is used, retain provenance and retrieve original spans for exact claims instead of treating the summary as lossless storage.
