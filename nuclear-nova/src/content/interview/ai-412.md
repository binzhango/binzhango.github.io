## Question

An LPU has no HBM at all, just on-die SRAM. Redo the decode roofline argument for that machine and tell me what changes.

## Brief answer

Without HBM, the relevant roofline uses SRAM bandwidth, compute throughput, and inter-chip communication, while SRAM capacity becomes a major deployment constraint. Keeping weights resident can remove repeated external-memory reads, improving batch-one decode. It does not make memory free: weights, activations, and KV state must fit across chips or move through another tier.

## Detailed answer

Estimate per-token arithmetic and bytes moved at each hierarchy level. The achievable rate is bounded by compute, local SRAM bandwidth, and fabric traffic on the critical path. Sharding a large model across many small SRAMs can trade the HBM bottleneck for synchronization and activation-transfer latency.

Long-context attention may require a separate cache placement strategy because KV grows with context and concurrency. Batch size changes arithmetic reuse and scheduling, but less dramatically than when each token rereads weights from slower external memory. State the hardware generation and actual memory hierarchy rather than using one vendor's marketing bandwidth as sustained end-to-end throughput. Groq's published tensor-streaming architecture provides a concrete design reference.

### Replace one roofline with several bounds

For GPU batch-one decode, repeatedly reading a large weight set from HBM often dominates. If all relevant weight shards remain in local SRAM, that external weight-read bound disappears, but local SRAM reads, matrix operations, activation transfers, and sequential layer dependencies remain. A lower bound on token time is the largest resource-demand ratio plus unavoidable dependency latency; summing every component assumes no overlap, while taking only the maximum assumes ideal overlap.

Suppose a layer's local work takes 20 microseconds and required fabric synchronization adds 5 microseconds that cannot overlap. Across 80 sequential layers, those costs alone imply 2 ms per token, before attention and other overhead. This illustrative calculation shows why enormous aggregate SRAM bandwidth does not directly equal end-to-end speed. Capacity also forces model shards across many chips, increasing the importance of topology. For long contexts, account explicitly for where KV state resides and how it is accessed; SRAM-first does not mean unlimited cache capacity.
