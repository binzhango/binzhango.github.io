## Question

Find duplicate files in a file system.

## Brief answer

Group regular files by size, hash only size groups with multiple members, then byte-compare hash matches before reporting duplicates. Stream large files in blocks and define how to handle symlinks and hard links. Do not delete anything as part of detection; content equality is different from deciding which copy is safe to remove.

## Detailed answer

The core below accepts caller-selected paths, excludes symlinks, and reports hard-linked paths only once. It assumes files remain unchanged during scanning; production scans should use snapshots or verify metadata before and after reading.

```python
from pathlib import Path
from collections import defaultdict
import hashlib
import filecmp

def duplicate_files(paths):
    sizes, seen = defaultdict(list), set()
    for value in paths:
        path = Path(value)
        if path.is_symlink() or not path.is_file():
            continue
        st = path.stat()
        identity = (st.st_dev, st.st_ino)
        if identity not in seen:
            seen.add(identity)
            sizes[st.st_size].append(path)
    result = []
    for group in sizes.values():
        if len(group) < 2:
            continue
        hashes = defaultdict(list)
        for path in group:
            h = hashlib.sha256()
            with path.open('rb') as stream:
                for block in iter(lambda: stream.read(1024 * 1024), b''):
                    h.update(block)
            hashes[h.digest()].append(path)
        for candidates in hashes.values():
            verified = []
            for path in candidates:
                for bucket in verified:
                    if filecmp.cmp(path, bucket[0], shallow=False):
                        bucket.append(path)
                        break
                else:
                    verified.append([path])
            result.extend(bucket for bucket in verified if len(bucket) > 1)
    return result
```

Reading costs O(total bytes in candidate groups). Test empty files, same-size different content, nested paths, unreadable files, symlinks, and hard links. Surface I/O errors instead of mislabeling an incomplete scan as exhaustive.

### Minimize I/O without weakening equality

Suppose a scan finds files of sizes 10, 10, 20, and 30 MB. The unique-size files cannot be byte-identical to another scanned file and need no content hashing. Only the two 10 MB candidates are streamed through the hash function. If their digests differ, comparison stops; if they match, a byte comparison establishes equality without relying solely on collision resistance.

The implementation identifies hard links using device and inode because two paths to one object are not two independent copies consuming duplicate storage. Symlinks are excluded to avoid following arbitrary targets or cycles; a different product requirement should make that policy explicit. Empty files form a valid duplicate group, though their storage savings are negligible.

A live file can change after `stat` or while being read. For a dependable inventory, scan a filesystem snapshot or open stable handles and verify change indicators around reading, reporting uncertain files rather than claiming complete results. Permission errors and disappeared paths should be surfaced as incomplete coverage. Detection must remain separate from deletion because application references, backups, and retention requirements can make identical files independently necessary.
