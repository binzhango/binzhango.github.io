## Question

What issues exist in multi-head attention?

## Brief answer

Multi-head attention can require a large KV cache, repeated memory reads, and substantial compute; some heads can also learn redundant patterns.

## Detailed answer

Separate KV projections for every query head increase stored state during autoregressive decoding. The cost depends on head dimensions, sequence length, batch size, and layer count. GQA/MQA reduce KV heads, while optimized kernels address memory traffic. Redundant heads are an empirical finding for some models, not proof that arbitrary heads can be removed without retraining or quality loss.

Each MHA head has its own projected key and value features. During generation, those features for earlier tokens must remain available, so storage grows with layers, sequences, tokens, heads, and head width. With a fixed model width, increasing head count while proportionally decreasing head width does not necessarily increase total KV elements; compare actual dimensions rather than head count alone.

Separate heads can learn different relationships, such as local syntax or distant references, but useful diversity is not guaranteed. Pruning a head based only on a low average attention weight is unreliable: a rare but important query may depend on it. Measure quality after pruning, preferably with adaptation, rather than treating apparent redundancy as proof of dispensability.

For serving, alternatives include GQA or MQA to reduce KV projections, quantizing cached tensors where supported, and optimized kernels to reuse memory efficiently. These have different accuracy and compatibility implications. Converting a trained MHA checkpoint by simply dropping most KV heads changes the function; it requires an explicit conversion and validation strategy. Profile first because FFN compute or inter-device communication may dominate the complete model.
