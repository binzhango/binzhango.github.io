## Question

Why was FlashAttention introduced? Briefly explain its core idea.

## Brief answer

FlashAttention was introduced to reduce the expensive memory transfers of dense attention without approximating its softmax computation.

## Detailed answer

It tiles Q, K, and V into on-chip memory and uses an online softmax calculation to accumulate outputs without storing the full score/probability matrix in GPU high-bandwidth memory. Backward computation recomputes selected intermediates. Dense attention still has quadratic arithmetic in sequence length; the improvement is IO efficiency and intermediate memory use, with normal floating-point differences.

A naive implementation writes attention scores to device memory, reads them to apply softmax, writes probabilities, then reads those probabilities to multiply by values. The large intermediate matrices can cause expensive traffic even when the final output is only one vector per token. Tiling keeps smaller blocks near the compute units and accumulates their contribution directly.

The online softmax must remain correctly normalized as new key blocks arrive. Maintain a running maximum, a running exponential sum, and a weighted value sum for each query row. If a later block raises the maximum, rescale the earlier sums before combining them. After all allowed blocks, divide the weighted sum by the normalizer. This is why the algorithm can avoid retaining every score while producing the same mathematical softmax result.

“Exact” describes the attention operation, not bit-for-bit identity across different floating-point reduction orders. Check output and gradient tolerances, causal masks, padding, and supported shapes. Dense pairwise arithmetic still grows quadratically during full-sequence processing; reduced memory traffic does not turn dense attention into a linear-attention model.
