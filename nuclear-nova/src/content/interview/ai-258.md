## Question

How would you evaluate multilingual retrieval quality when employees query in French and Korean over mostly-English documents?

## Brief answer

Build a cross-lingual evaluation set where French and Korean queries are judged against the English evidence users actually need. Separate semantic retrieval ability from translation quality and from downstream answer generation.

## Detailed answer

Sample realistic tasks, names and domain terminology, then obtain bilingual judgments for sufficient evidence rather than literal wording overlap. Compare multilingual embeddings, query translation plus retrieval, and hybrid variants at the same candidate budget. Slice recall/ranking metrics by language, script, query length and rare terminology. Audit transliteration and exact identifier behavior; dense similarity may miss a product code even when it understands the sentence. Supply known-good English context to the generator to isolate answer-language issues. Review cases where translation changes negation or scope, and track latency and cost before selecting a more complex pipeline.

### Use evidence judgments across languages

A French query asking for an exception to a policy and a Korean query containing an English product code may need the same English source but stress different retrieval behavior. Native bilingual reviewers should identify sufficient passages and relevant qualifiers, rather than reward shared words. Include original user phrasing, transliteration, negation, abbreviations, and domain-specific names.

Compare multilingual embedding retrieval with translating the query into English, then with a hybrid that combines lexical exact matches and dense candidates. Keep the candidate count and latency budget comparable. An oracle experiment supplies the correct English passages to generation; if the answer is still wrong in French or Korean, the failure is downstream of retrieval. Measure recall at k, ranking quality, and complete answer support separately, with per-language uncertainty. Translation can accidentally broaden a restriction or alter a proper noun, so retain the original query during reranking. Do not infer multilingual competence from translated English benchmarks alone.
