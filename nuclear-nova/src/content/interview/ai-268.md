## Question

Sketch how you would serve a 671B-parameter MoE model with low latency under GPU-memory constraints.

## Brief answer

Budget memory from all 671B parameters, then map experts and shared computation onto the available devices with measured communication costs. A small active parameter count lowers per-token arithmetic but does not make the other expert weights disappear.

## Detailed answer

Raw BF16 weights alone are about 1,342 GB; one byte per parameter would be about 671 GB before scales and other state. Divide only after accounting for replication, expert placement, KV cache and workspace. Keep frequently communicating expert groups on fast links, batch enough tokens for efficient expert kernels and monitor hot-expert queues. Evaluate quantization and prefill/decode separation against transfer overhead. CPU expert offload may solve capacity while failing interactive latency. The DeepSeek-V3 report provides a concrete 671B/37B-active reference; the proposed deployment still requires hardware-specific benchmarks and headroom for failures.

### Capacity determines the minimum group, not the best one

At BF16, 671B parameters need about 1.342 TB in decimal units before KV and workspace. Dividing by an accelerator's usable memory yields only a storage lower bound; expert placement, shared-layer replication, supported parallelism, and failure headroom can require a larger group. A one-byte weight format roughly halves payload but adds scale metadata and must pass quality tests.

Place shared computation and expert shards according to the interconnect topology, keeping frequent dispatch on fast links. Batch compatible tokens to avoid tiny expert operations, but enforce inter-token latency and monitor hot experts. Continuous batching and cache-aware routing improve utilization only if memory admission remains correct. Compare quantization, smaller models, and workload routing before relying on host-memory offload for an interactive SLO. A full model group is the scaling and failure unit; spare one-device capacity may not restore a failed replica. Benchmark representative prompt/output distributions and report cost per successful task, since active-parameter count alone omits most provisioning constraints.
