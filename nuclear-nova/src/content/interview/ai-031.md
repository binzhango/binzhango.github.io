## Question

Explain disaggregated prefill/decode serving and when it pays for itself.

## Brief answer

Disaggregated serving runs prefill and decode on separate worker pools, transferring KV state between them. It pays when independent scaling or interference reduction saves more than cache transfer and orchestration cost.

## Detailed answer

Estimate bytes transferred per request with the architecture’s KV formula, then divide by effective network bandwidth and include queueing. Prefill workers can favor compute throughput while decode workers favor memory capacity/bandwidth. Route requests with compatible weights, cache layout and precision; handle failed transfers and bounded cache lifetimes. Shared-prefix locality and long prompts can change the economics. Compare the same SLO-compliant throughput against a colocated scheduler before introducing a second fleet.

The architectural boundary is the completed prompt KV state. An ingress scheduler sends the prompt to a prefill worker, which computes the cache and transfers its ownership or contents to a compatible decode worker. The decode pool then maintains the stream until completion. This permits separate scaling policies: long prompts can increase prefill demand without consuming all the capacity reserved for active conversations.

The handoff can be substantial. If a prompt cache is 2.5 GiB and effective transfer bandwidth is 25 GiB/s, the payload alone takes approximately 100 ms. Protocol overhead, contention and synchronization add more. A topology with much faster device-to-device links may change that calculation, but nominal link bandwidth is not effective application bandwidth.

Use a bounded handoff queue, transfer acknowledgments and explicit ownership so failed requests do not leave orphaned cache allocations. Weight revision, adapter, precision and cache layout must match across the boundary. Maintain a fallback or retry policy for failed transfers without duplicating visible tokens. Compare separate pools against an efficient colocated scheduler with chunked prefill: disaggregation is attractive when interference or independent scaling dominates, but can lose on short prompts, low load or slow interconnects.
