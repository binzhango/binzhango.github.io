## Question

Compare tensor, pipeline, data, sequence and expert parallelism. When do you combine them?

## Brief answer

Tensor parallelism splits layer computations; pipeline parallelism assigns different layers to stages; data parallelism replicates models over different examples; sequence/context parallelism divides sequence work; expert parallelism places experts across devices.

## Detailed answer

Tensor parallelism needs fast collective communication within layers. Pipeline parallelism introduces bubbles unless enough microbatches are in flight. Data parallel training synchronizes gradients, while replicated inference mainly requires request routing. Context parallelism addresses long-sequence activation or attention costs. Expert parallelism adds token dispatch and load skew. Combine dimensions to fit memory and topology, usually keeping frequent communication on the fastest links. Training and inference can require different decompositions.

Consider a model that fits across eight GPUs on one fast-interconnect host. Tensor parallelism can split each matrix across those eight devices, but layers then need collectives to combine partial results. Adding more tensor shards eventually spends too much time communicating. Pipeline parallelism instead gives different groups successive layers, reducing the frequency of large cross-group exchanges while creating idle bubbles when microbatches are scarce.

Data parallelism runs independent copies for different batches. During training those copies synchronize gradients or shard optimizer state; during serving independent replicas mainly share routing and operational infrastructure. Sequence parallelism commonly shards token-wise activations around normalization and related operations, while context parallelism distributes the attention sequence itself; implementations use these names differently, so specify which tensors move.

With a sparse MoE, expert parallelism assigns experts to devices and dispatches selected tokens to them. It can be combined with tensor parallelism inside an expert and data parallelism across replicas. Place frequent all-reduces and token dispatch on high-bandwidth links, and use slower network boundaries for less frequent transfers when possible. Evaluate maximum per-device memory, communication volume, microbatch availability and failure recovery. A decomposition optimized for a giant training batch may be unsuitable for latency-sensitive batch-one inference.
