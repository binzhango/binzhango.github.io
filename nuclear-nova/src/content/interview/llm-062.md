## Question

How to output a specific hidden_state from BERT using transformers?

## Brief answer

Request `output_hidden_states=True`, then index the returned tuple; index 0 is the embedding output and index 1 is the first encoder layer's output.

## Detailed answer

First run the complete [BERT loading example](#question-llm-061), which defines `model`, `inputs` and `outputs` with hidden states enabled. The code below is the next step in that same Python session.

Using `model`, `inputs`, and `outputs` from the preceding example:

```python
layer_index = 8
assert 0 <= layer_index <= model.config.num_hidden_layers
layer_vectors = outputs.hidden_states[layer_index]
assert layer_vectors.shape[:2] == inputs["input_ids"].shape
assert len(outputs.hidden_states) == model.config.num_hidden_layers + 1
```

BERT-base has 12 encoder layers, so there are 13 entries including embeddings. Each has shape `[batch, sequence_length, hidden_size]`. Requesting all hidden states increases output memory; use it when needed for analysis or feature extraction.

The tuple follows the computation order rather than zero-based layer numbering alone. Entry 0 contains the embedding-stage output; entry 8 contains the output after the eighth Transformer encoder layer. Negative index `-1` selects the final layer. The first two axes remain batch and token position, so selecting a layer does not pool a sentence or choose a particular token.

For one input with ten tokenized positions, a BERT-base layer gives ten vectors of width 768. If only the representation of one word is needed, use the tokenizer's alignment information to identify its subword positions and decide how to combine them. A word split into several pieces cannot reliably be located by counting whitespace-separated words in the original string.

All hidden-state outputs can be useful for probing or feature selection, but retaining them increases memory roughly with layer count times batch size times sequence length times hidden width. The model still computes earlier layers to reach a later one. Choose a layer using a development task and keep the final evaluation independent; selecting whichever layer scores best on the test set is another form of tuning leakage.
