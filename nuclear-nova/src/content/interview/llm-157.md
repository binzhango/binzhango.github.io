## Question

What should you do when the generator fails to extract an answer from available evidence?

## Brief answer

If the answer is present in the supplied evidence but the model fails to extract it, test evidence presentation, question clarity, and generator capability.

## Detailed answer

Remove distractors, restore structure, identify the relevant section, or request constrained extraction with source spans. Use deterministic parsing or code for exact fields and arithmetic when appropriate. Compare a stronger model or grounded SFT only after confirming retrieval is sufficient. Validate the result against the source; a fluent answer with a citation can still misread a negation or numerical unit.

Perform an oracle-context experiment with the smallest source passage that contains all required evidence. If the generator succeeds there but fails with the production prompt, examine distractors, source order, lost headings, and token truncation. If it fails even on the clean passage, the task may require clearer instructions, a different output representation, or stronger reasoning capability.

For “What is the invoice total excluding tax?”, ask for the subtotal and tax fields separately and calculate the requested result deterministically. For a policy question, request the applicable rule and its exception with source spans before producing a concise answer. These are controlled extraction steps, not proof that any generated rationale is correct.

Validate against the source, including negation, units, version, and arithmetic. A citation that points to the right document does not establish that the claim was extracted accurately. Consider grounded SFT only when repeated evidence-use failures remain after presentation and task design are improved. Keep an abstention or review path for ambiguous evidence rather than forcing every prompt to produce a confident complete answer.
