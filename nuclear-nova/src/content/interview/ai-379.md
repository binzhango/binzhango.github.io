## Question

How would you detect and handle distribution shift between fleet data and your training set?

## Brief answer

Suggested approach: Separate input drift, label drift, and performance degradation. A fleet distribution can change without harming the model, while a small shift in a safety-critical slice can matter greatly. Monitor sensor and environment statistics, model uncertainty, and delayed reviewed outcomes, then use targeted data collection and controlled retraining rather than automatically retraining on every drift alarm.

## Detailed answer

Track geography, weather, lighting, camera calibration, object sizes, class mix, and feature embeddings. Investigate whether changes reflect a pipeline bug, hardware revision, seasonal pattern, or genuinely new scenario. Compare uncertainty and disagreement signals with reviewed examples; confidence is not a reliable detector of every unfamiliar input.

Set operational-domain boundaries and fallbacks for unsupported conditions. Preserve historical regression suites when adding new data, and test both new and old slices before release. Use shadow mode and controlled rollout to validate the new model, with rollback for severe regressions. Report exposure-normalized outcomes and uncertainty, since raw error counts are confounded by how much and where the fleet drove.

### Diagnose the type of shift

Covariate shift changes input distributions, such as more night driving. Label shift changes class prevalence, such as more cyclists. Concept shift changes the relationship between observations and the target, perhaps after a sensor revision or labeling-policy change. A drift alarm alone does not identify which occurred or whether performance degraded.

Compare matched geographic, weather, and sensor slices, then label a targeted sample from the new distribution. If a camera firmware update changes color statistics but accuracy remains stable, retraining may be unnecessary; if rain obscures small pedestrians, the problem is operationally significant even with modest embedding drift. Use random sampling alongside uncertainty triggers so confidently wrong novel cases can still be discovered. Roll back pipeline defects promptly, collect representative new evidence for genuine shifts, and maintain old-domain regression tests. Report rates normalized by exposure so a busier fleet is not mistaken for a worse model.
