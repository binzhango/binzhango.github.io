## Question

What’s the input/output format for domain fine-tuning?

## Brief answer

The format follows the objective: continued pretraining uses text sequences, while SFT uses prompt-response or role-based conversation examples.

## Detailed answer

A conceptual conversation record is:

```json
{
  "messages": [
    {"role": "user", "content": "Summarize the supplied maintenance report."},
    {"role": "assistant", "content": "The inspection found ..."}
  ]
}
```

The trainer applies the model's chat template and constructs input tokens, attention masks, and labels. Decide explicitly which tokens receive loss; assistant-only supervision is common but not automatic for every trainer and template. Preserve tool-call structure and end-of-turn tokens when present.

The JSON record is a storage format; the model ultimately receives token IDs and target labels. A chat template might serialize role markers, the user's report, an assistant-start marker, and the assistant answer into one sequence. The attention mask marks valid input positions. A separate loss mask decides which next-token targets should teach the model, often excluding user and system content while supervising assistant output.

Inspect one example after serialization and decoding. Verify that the answer is present, ends correctly, and has not been removed by truncation. If a long report consumes the whole sequence limit, a row can contain zero assistant targets even though its JSON looked valid. Multi-turn examples require a deliberate choice about which assistant turns receive loss.

For continued pretraining, ordinary documents can be packed into text sequences with meaningful boundaries, rather than converted into artificial question-answer records. For tool training, preserve the relationship between a call ID, arguments, result, and subsequent response. A schema-valid dataset is not automatically an objective-correct dataset; the tokenizer, trainer, template, and masks jointly determine what is learned.
