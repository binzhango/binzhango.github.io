## Question

For MHA, GQA and MQA, derive KV-cache storage and compare 32, 8 and 1 KV heads at an 8,192-token context.

## Brief answer

The key serving difference is the number of KV heads: MHA stores the most state, MQA the least, and GQA lies between them.

## Detailed answer

For ordinary cached attention, estimate KV bytes as:

$$
M_{\mathrm{KV}}=2BLnH_{\mathrm{KV}}d_hs,
$$

where $B$ is batch size, $L$ layers, $n$ cached tokens, $d_h$ head dimension, and $s$ bytes per element. The factor 2 is for keys and values. Calculated example: with $B=1$, $L=32$, $n=8192$, $d_h=128$, and $s=2$, 32 KV heads use 4 GiB, 8 use 1 GiB, and 1 uses 128 MiB. Allocator overhead and other tensors are excluded.

Derive the formula from one token in one layer. Each KV head stores one key and one value, each with $d_h$ elements, so it needs $2H_{\mathrm{KV}}d_hs$ bytes. Multiply by the number of tokens $n$, layers $L$, and simultaneously cached sequences $B$. Query heads do not add a persistent query cache because old queries are not needed to predict the next token.

In the example, a single KV head across 32 layers costs $2\times32\times128\times2=16,384$ bytes per cached token. At 8,192 tokens this is 134,217,728 bytes, or 128 MiB. Multiplying by eight gives 1 GiB; multiplying by 32 gives 4 GiB. Doubling batch size or cached length doubles each result.

Real serving systems may allocate token blocks, keep partially filled blocks, replicate or shard state across devices, and use different cache precisions. Sliding-window layers can have bounded cache length, while hybrid or latent-attention models require different formulas. Treat this calculation as the tensor payload for ordinary attention, then measure allocator and runtime overhead before deciding how many requests fit.
