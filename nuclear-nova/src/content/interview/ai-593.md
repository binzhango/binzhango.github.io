## Question

Design a sync system between two employee record systems.

## Brief answer

Define field-level ownership, identity mapping, conflict policy, and deletion semantics before building bidirectional synchronization. Use durable change events or cursors, idempotent upserts, and version tracking to prevent loops and lost updates. “Last write wins” is unsafe when clocks differ or one system is authoritative for a field.

## Detailed answer

**Suggested approach.** Assign a stable cross-system employee ID and record each source revision and last applied change. For example, HR may own employment status while an IT system owns device assignment; route updates only in the permitted direction for each field. Queue ambiguous identity matches or concurrent edits for review.

Use tombstones and explicit deactivation behavior, with higher urgency for access-related changes. Retry transient errors without duplicating accounts, and periodically reconcile full inventories to catch missed events. Test renames, rehires, merged records, clock skew, partial outages, and deletion followed by recreation. Monitor lag, conflicts, orphan accounts, and rejected writes. Keep personal data and audit access scoped to the business purpose.

### Prevent echoes and lost updates

Each change event carries source system, stable employee identity, source revision, changed fields, and an event ID. The synchronizer applies only fields owned by that source and records the applied revision. An update copied to the second system must not return as a new independent change and overwrite the first; retain origin metadata or compare versions to break the echo loop.

For example, HR owns legal name and employment status while IT owns assigned device. Concurrent changes to those different fields can merge, but two authoritative edits to the same field need an explicit conflict policy. Use optimistic concurrency and a durable retry queue. Deactivation should propagate promptly and be reconciled even after outages; a lost termination event can leave access active. Tombstones distinguish deletion from absence in a partial export. Periodic full reconciliation catches missed events and orphan records. Test rehires, ID reuse, renamed accounts, clock skew, and retries after partial success rather than relying on wall-clock last-write-wins.
