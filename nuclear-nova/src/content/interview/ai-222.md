## Question

You're dropped into an unfamiliar multi-file codebase with a failing behaviour and an LLM assistant available. Walk me through how you'd fix it.

## Brief answer

First reproduce the behavior and identify the smallest relevant code path. Use the assistant to inspect callers, state assumptions and propose a focused patch, then verify the change with a test that fails for the original bug.

## Detailed answer

Inspect repository instructions, existing modifications and the current test command before editing. Trace an actual failing input through interfaces and dependencies; do not trust a plausible explanation without evidence. Give the assistant bounded context and require it to explain the proposed behavioral change. Preserve unrelated work, inspect the final diff and run checks covering the affected boundary. If reproduction fails, narrow the environment difference instead of making speculative cleanup changes. A useful deliverable contains the cause, patch, reproduction/regression test and any unresolved limitation. The assistant accelerates investigation, while execution and review determine correctness.

### Use one failing example to constrain the search

Suppose an API returns duplicate results only on the second page. Reproduce with a small fixture, inspect pagination callers and ordering, and trace the cursor through the service and database query. Ask the assistant for candidate causes supported by those files, then inspect the actual query and state transition. A missing tie-breaker in ordering requires a different fix from a cursor decoded with the wrong type.

Write a regression that exercises the observed boundary, verify it fails before the patch, and apply the smallest behaviorally complete change. Include adjacent cases such as empty pages or equal sort keys when they test the same mechanism. Run the focused test and relevant integration checks, inspect the diff for unrelated edits, and document the cause and validation. Treat generated code as a proposal: the assistant may overlook repository conventions or invent API behavior. If the bug cannot be reproduced locally, compare environment and data assumptions explicitly rather than using a cleanup patch as a substitute for diagnosis.
