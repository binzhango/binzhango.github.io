## Question

Here is a scheduler class from a small LLM inference engine. One method, \_admit_requests, is a stub: no spec, no docstring, no tests. Walk me through your first thirty minutes.

## Brief answer

Spend the first thirty minutes reconstructing the scheduler's contract from callers, state transitions and resource accounting. Establish a tiny deterministic workload before filling the admission stub; an apparently reasonable policy can violate cache ownership or fairness.

## Detailed answer

Inspect request states, token budgets, KV allocation/release, cancellation and the scheduler's existing decode path. Find whether admission reserves future output capacity, whether prefill can be chunked and how priorities are represented. Write a trace for an empty queue, one fitting request, an oversized prompt and a completed/canceled request. Add assertions that allocated blocks stay within capacity and every admitted request has a valid state transition. Then implement the smallest policy consistent with those observations, with explicit assumptions documented. Avoid optimizing throughput before proving no request is lost, admitted twice or allowed to starve indefinitely.

### Reconstruct the state machine first

In the first ten minutes, inspect callers and neighboring methods to identify states such as waiting, prefilling, decoding, finished, and canceled. Determine which component owns KV allocation and when memory becomes reusable. Next, trace one request by hand through a scheduler iteration and write a tiny test harness that records queues and block counts.

For the remaining time, cover boundary cases before implementing policy: no capacity, a request exactly fitting, a prompt larger than any admissible budget, cancellation while waiting, and a request already admitted. An oversized head request must not silently block every smaller request forever unless that is an intentional fairness policy. If the existing engine preallocates an output budget, admission must honor it; if it grows blocks incrementally, reserve the safety margin required by the next step. Implement the smallest supported transition and document unresolved assumptions. The result of thirty minutes should be a testable contract and a safe initial policy, not an invented high-throughput scheduler detached from the engine's ownership rules.
