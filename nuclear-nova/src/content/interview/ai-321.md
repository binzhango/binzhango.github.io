## Question

Design a Copilot feature that answers questions over a user's work email, documents and meetings, without ever leaking content the user can't access.

## Brief answer

Suggested approach: enforce source permissions before retrieval and recheck them before content is returned. Every document, chunk, cache entry, and citation needs tenant and authorization metadata. The model must never receive content merely because it promises not to reveal it; a prompt is not an access-control boundary.

## Detailed answer

Connectors ingest versioned mail, document, and meeting records with ownership and access rules. Search applies security trimming using the caller's identity and current entitlements, followed by source-level checks for sensitive or changing permissions. Use delegated credentials and least-privilege tool scopes. Preserve provenance through chunking and generated citations.

Invalidate caches on permission or document changes, and partition them so one user's answer cannot serve another without equivalent authorization. Watch for indirect leakage through titles, snippets, counts, embeddings, logs, and error messages. Treat retrieved instructions as document content, never as higher-priority commands. Test cross-tenant requests, group removal, revoked sharing, malicious documents, and stale indexes. On uncertain authorization, omit the item or fail closed with an actionable explanation.

### Permission changes must reach every copy

Suppose a user could read a project document yesterday but is removed from its group today. The source document, search index, answer cache, and saved citation may all contain copies or derived information. An index-time ACL snapshot alone is stale. Carry a document identity and permission version through the pipeline, and perform an authoritative check at the boundary where content will enter the prompt or reach the user.

The request path is identity → tenant-scoped search → authorized evidence fetch → generation → citation validation. Reject inaccessible candidates before exposing titles or snippets, and keep logs subject to equivalent restrictions. Search failure must not trigger a fallback that queries an unfiltered global index. For highly dynamic permissions, trade some retrieval latency for source revalidation; for stable domains, carefully bounded caches can reduce overhead. Test revocation during a request, cross-tenant identifiers, group nesting, deleted documents, and answers cached under a more privileged identity.
