## Question

Given exports from three customer systems, each with its own customer records, write code to produce one deduplicated set of entities and explain your design.

## Brief answer

Normalize records, preserve source IDs, and merge only on identifiers whose semantics justify equivalence. Keep ambiguous matches for review rather than forcing every record into a cluster. A deduplicated entity should retain conflicting attributes and provenance; choosing one name does not make the other source disappear.

## Detailed answer

This conservative example assumes an explicitly verified email is a valid unique person identifier in this dataset. Unverified or missing emails remain separate. In domains with shared mailboxes or recycled addresses, replace that assumption with a stronger matching contract.

```python
from collections import defaultdict

def deduplicate(records):
    groups = defaultdict(list)
    identities = set()
    for record in records:
        identity = (record['source'], record['id'])
        if identity in identities:
            raise ValueError('duplicate source identity')
        identities.add(identity)
        email = record.get('email', '').strip().casefold()
        key = ('email', email) if email and record.get('email_verified') else ('source', *identity)
        groups[key].append(dict(record))
    return [
        {'members': [(r['source'], r['id']) for r in group],
         'names': sorted({r['name'].strip() for r in group if r.get('name')}),
         'records': group}
        for group in groups.values()
    ]

records = [{'source': 'a', 'id': '1', 'name': 'Lee', 'email': 'LEE@example.test', 'email_verified': True},
           {'source': 'b', 'id': '9', 'name': 'Lee S', 'email': 'lee@example.test', 'email_verified': True}]
assert len(deduplicate(records)) == 1
```

Expected grouping time is O(n), apart from sorting attribute variants. For fuzzy matching, block candidates, score multiple fields, and review uncertain edges; transitive clustering can accidentally merge distinct people through one weak link. Test shared addresses, missing fields, source-ID collisions, and conflicting verified identifiers.

### Entity resolution needs reversible evidence

The example merges records only when a verified email is declared unique in the domain. Source-plus-ID remains the identity for unverified or missing email, so two records named “Lee” are not automatically merged. Each output retains all member identities and original records, allowing a reviewer to inspect and undo a mistaken merge.

Even normalization is a policy choice: case-folding the whole address assumes that this dataset treats email case equivalently. Shared mailboxes, recycled addresses, and provider-specific alias behavior can violate person uniqueness. In a richer system, first block candidates using plausible identifiers, then score independent fields such as name, address, and verified phone. A weak bridge A≈B and B≈C does not prove A and C are the same person; review cluster consistency before transitive merging. Separate entity grouping from selecting a canonical display value, and preserve conflicting attributes with provenance. Evaluate false merges separately from missed merges because their costs differ. Test reimports and changed identifiers with stable entity IDs and a correction workflow.
