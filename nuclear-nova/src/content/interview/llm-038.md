## Question

What’s the formula of a GLU block using Swish?

## Brief answer

SwiGLU replaces the GLU gate with Swish, usually SiLU.

## Detailed answer

The common bias-free form is:

$$
\operatorname{FFN}_{\mathrm{SwiGLU}}(x)=W_o\left[\operatorname{SiLU}(W_gx)\odot(W_vx)\right].
$$

The elementwise product is projected back to the model width. For comparable parameter counts, a gated FFN's hidden width is often reduced relative to a standard FFN, though exact ratios depend on the architecture and rounding. The activation alone does not guarantee an accuracy or speed improvement.

Let the gate branch output $a=W_gx$ and the value branch output $b=W_vx$. The expanded vector is $a\sigma(a)\odot b$, which then passes through $W_o$. The value branch remains independently learned; multiplying SiLU by its own input again would compute a different function. Some implementations name the projections `gate_proj`, `up_proj`, and `down_proj`, but the tensor operation is the defining property.

For one coordinate with $a=1$ and $b=2$, the gated value is about 1.4622. With $a=-1$, it is about -0.5379. SiLU gates are not bounded between zero and one and need not suppress every negative feature entirely.

The approximate parameter count is $3dh$, so choosing $h\approx8d/3$ gives the projection count of a standard $4d$ FFN. This is a budget calculation, not a required hidden-size rule. During inference, fused kernels can reduce intermediate memory movement; during training, the expanded branches still contribute activation memory. Benchmark the actual implementation rather than inferring speed from the activation's name.
