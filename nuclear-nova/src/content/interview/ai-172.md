## Question

How would you build an LLM-powered enterprise search system?

## Brief answer

Build enterprise search around permission-aware ingestion and retrieval, then add grounded answer generation with citations. Combine lexical retrieval for exact terms with embeddings for semantic matches, rerank candidates and supply only authorized evidence to the model. Index freshness and access-control correctness are first-class quality requirements.

## Detailed answer

Suggested pipeline: connectors ingest documents with stable IDs, version timestamps and ACL metadata; parsers preserve headings, tables and source locations; chunking produces retrievable units linked to their parent documents. Maintain lexical and vector indexes with deletion propagation and tenant isolation.

At query time, resolve the user's permissions, retrieve candidates, rerank a bounded set and generate an answer with source references. Apply authorization before exposing candidates to the model or logs. Distinguish no matching evidence from retrieval failure, and avoid presenting unsupported synthesis as a sourced fact.

Evaluate retrieval recall, ranking quality, citation support and final task success on real employee queries. Include stale documents, conflicting policies, multilingual queries and permission changes. Monitor connector lag and empty-result rates. A model upgrade cannot compensate for an inaccessible or missing authoritative document.

Begin with a source inventory and authority rules. Employees may have several documents about the same policy, including drafts and outdated versions. Store effective dates and source ownership so retrieval can prefer the current authoritative record rather than the most semantically similar text. Connector freshness and deletion handling should be visible in operations dashboards.

A query path should authenticate, apply coarse tenant filters, retrieve lexical and vector candidates, perform exact authorization checks, rerank and assemble evidence. Generate only after those checks, because removing unauthorized text from the final answer is too late if it already entered a model or log. Cache answers only under compatible permissions and source revisions.

For evaluation, collect real search tasks with known useful documents and unanswerable questions. Compare finding a document with completing the employee's task; a correct search result may still produce a misleading synthesis. Add tests for acronyms, exact IDs, languages and group-membership changes. Start with a small pilot whose sources and failures can be inspected before expanding connector breadth.
