## Question

How do you prevent an agent with tool access from exfiltrating data via a malicious web page?

## Brief answer

Prevent exfiltration by limiting data access and outbound destinations in the execution layer. A malicious page must not be able to authorize sending internal content, even if its instructions persuade the model.

## Detailed answer

Treat retrieved text as untrusted, avoid placing unrelated secrets in context, and bind tools to the user’s least-privilege identity. Block arbitrary outbound URLs or require a reviewed destination for sensitive transfers. Inspect query strings, attachments and tool arguments as potential channels. Keep approvals tied to exact payloads and audit denied attempts. Test multi-step attacks where one page first requests a secret and another supplies an apparent reason to transmit it.

Model the attack as a data-flow chain: an untrusted page influences the model, the model requests protected data, then it proposes sending that data through an outbound channel. Break the chain at multiple points. Do not include unrelated secrets in context, limit internal retrieval to the user's authorized scope, and restrict outbound tools to known operations and destinations.

A URL query string, search query, image fetch, attachment name or webhook body can all carry data. Checking only an email's visible recipient misses other channels. Use structured tools that separate internal reads from external writes, validate destination ownership, and require an approved exact payload for sensitive transfers. A page claiming that transmission is required for verification has no authority to expand the user's request.

Carry provenance or sensitivity labels through tool results where practical and enforce policy before execution. Test both obvious “send the secret” instructions and multi-step pretexts embedded in otherwise relevant content. Audit denied attempts without copying the protected data into broad-access logs. Network egress controls and least-privilege credentials reduce consequences even if the model follows the malicious text. Prompt instructions are useful guidance, but the security boundary must survive a model that makes the wrong decision.
