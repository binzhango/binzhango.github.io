## Question

Parse bigrams: extract two-word phrases from strings for NLP feature engineering.

## Brief answer

Tokenize each string under a stated normalization rule, then emit adjacent token pairs. Decide whether punctuation ends a sentence and whether bigrams may cross sentence boundaries; those choices affect the features. Fit any vocabulary on training data only, and preserve counts rather than merely a set when frequency is informative.

## Detailed answer

This illustrative implementation lowercases Unicode word tokens and prevents bigrams from crossing `.`, `!` or `?` boundaries. It is a simple English-oriented rule, not a multilingual tokenizer.

```python
import re
from collections import Counter

def bigrams(text):
    result = Counter()
    for sentence in re.split(r'[.!?]+', text):
        words = re.findall(r"\b\w+(?:'\w+)?\b", sentence.casefold())
        result.update(zip(words, words[1:]))
    return result

assert bigrams('Red fox. Red fox jumps!') == Counter({('red','fox'):2, ('fox','jumps'):1})
assert bigrams('one') == Counter()
```

Processing is linear in text length plus emitted pairs. Hyphenated words, abbreviations, numbers and scripts without spaces need a domain-appropriate tokenizer. For machine-learning features, use a fixed vocabulary or hashing and document out-of-vocabulary handling. Do not concatenate documents before extracting pairs, because that creates artificial bigrams across document boundaries.

The output is a frequency map over ordered pairs, so `('red','fox')` differs from `('fox','red')`. Sentence boundaries prevent artificial pairs such as `('fox','red')` between “Red fox.” and the next sentence. Repeated occurrences increment the count rather than disappearing as they would in a set.

Tokenization is part of the feature definition. The rule keeps apostrophe-containing words together but treats punctuation and hyphens according to its simple regex. Abbreviations such as “Dr.” can create incorrect sentence breaks, and languages without whitespace need another segmenter. Test these cases before interpreting the resulting counts as linguistic phrases.

For an ML pipeline, learn a vocabulary only from training data, map pairs to stable feature indices and choose count, binary or weighted features deliberately. A hashing representation avoids storing a vocabulary but introduces collisions. Do not extract after concatenating unrelated documents, and maintain the same normalization at inference. The algorithm is simple; consistency of preprocessing often determines whether the features are useful.
