## Question

You want to serve a 70B-parameter model on a single 80 GB GPU. Walk me through whether it fits and what single-stream tokens/sec you'd expect.

## Brief answer

At FP16, 70B raw weights require about 140 GB, so they do not fit on one 80 GB GPU. Eight-bit weights nominally require 70 GB and leave little headroom; four-bit weights nominally require 35 GB before scales and runtime overhead. Feasibility and speed depend on quantization support, architecture, context, and cache size, so no honest fixed tokens/sec answer follows from parameter count alone.

## Detailed answer

For batch-one decode, a useful rough lower bound on time per token is weight bytes read divided by sustainable memory bandwidth, plus KV reads and other work. As an illustrative ceiling, 35 GB divided into 2 TB/s yields about 57 tokens/sec if every token streams those weights perfectly. Real throughput is lower when dequantization, attention, launch overhead, or poor bandwidth utilization intervene; this is not a hardware benchmark.

Budget KV cache, activations, temporary buffers, and allocator reserve. Test representative prompt/output lengths and sustained generation using a supported quantized engine. Report measured first-token and inter-token latency separately, including precision and quality differences.

### Establish the memory envelope first

Seventy billion weights at two bytes each need 140 GB, so ordinary BF16 weights do not fit on an 80 GB GPU. Eight-bit raw weights need about 70 GB, leaving little room for scales, cache, and buffers. Four-bit raw weights need about 35 GB and are more plausible, provided the runtime supports the format and quality remains acceptable.

The decode estimate assumes weights are streamed for each generated token at batch one. At larger batches, one weight read serves several tokens and arithmetic can become more important. Long context adds KV reads; prefill has a different compute profile entirely. An 80 GB memory capacity does not imply a particular bandwidth, compute throughput, or kernel efficiency, so a model name and VRAM figure cannot determine tokens per second. Measure the actual quantized engine at representative context lengths and sustained output. Include spare allocator capacity and avoid sizing to the last byte, where minor workload variation causes failure.
