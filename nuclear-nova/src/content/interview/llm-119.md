## Question

How does a sliding window manage recent conversation context?

## Brief answer

A sliding window retains recent conversation turns to bound context use, but can drop important older facts.

## Detailed answer

Trim by token budget rather than an arbitrary number of messages, and keep complete tool interactions. Preserve essential instructions and durable task state separately; consider a summary or retrieval for older information. Summaries are lossy and should retain links to original messages when precision matters. Evaluate delayed references such as “use the constraint I gave earlier” to detect failures caused by truncation.

A token-based window adapts to message size. Ten short chat turns may fit easily, while one pasted log can consume thousands of tokens. Reserve a fixed budget for instructions, new evidence, and the model's answer, then select complete recent interactions within the remainder. If a single required interaction exceeds the budget, summarize or extract its relevant information deliberately rather than slicing arbitrary bytes.

Keep durable constraints outside the disposable window. A user's requirement such as “all dates must be UTC” may remain relevant after the message that introduced it falls out. Store that as explicit task state with provenance, and update it if the user changes the requirement. Similarly, preserve pending tool actions and their outcomes as complete records.

A window sacrifices direct access to older detail. Summaries reduce that loss but can omit exceptions or exact numbers; retrieval can recover original passages when needed. Test a conversation where an important constraint appears early, many irrelevant turns follow, and a later request depends on that constraint. A system that merely retains the last few messages will fail even though its token budget is respected.
