## Question

Implement a token-bucket rate limiter, then make it distributed.

## Brief answer

A token bucket refills at a fixed rate up to a burst capacity, then atomically spends the request's cost. In a distributed system the read–refill–debit sequence must run at one authoritative partition or in an atomic datastore operation; independent worker buckets multiply the effective allowance.

## Detailed answer

```python
from time import monotonic
from threading import Lock

class Bucket:
    def __init__(self, capacity, rate, clock=monotonic):
        if capacity <= 0 or rate < 0: raise ValueError('invalid limits')
        self.cap, self.rate, self.clock = capacity, rate, clock
        self.tokens, self.last, self.lock = capacity, clock(), Lock()
    def allow(self, cost=1):
        if cost <= 0: raise ValueError('positive cost required')
        with self.lock:
            now = self.clock()
            self.tokens = min(self.cap, self.tokens + max(0, now-self.last)*self.rate)
            self.last = max(now, self.last)
            if cost > self.tokens: return False
            self.tokens -= cost
            return True

now = [0.]
b = Bucket(2, 1, lambda: now[0])
assert b.allow() and b.allow() and not b.allow()
now[0] = 1; assert b.allow()
```

For distribution, shard by tenant and perform the calculation plus update in one Redis script or transactional service. Use authoritative time, include an expiry longer than a full refill interval, and define whether a datastore outage fails closed or uses a bounded local allowance. Multi-region exact limits introduce cross-region latency; leased quotas trade exact instantaneous global enforcement for availability. Return a retry delay based on the deficit rather than continuously retrying rejected requests.

The invariant is that stored tokens remain between zero and capacity. Elapsed monotonic time adds `rate × elapsed` credits, capped at the burst limit, then an accepted operation atomically subtracts its cost. A rejected request does not consume credits. With capacity two and rate one per second, the example accepts a burst of two and admits one more after one second.

Each local operation is $O(1)$ time and state. A request whose cost exceeds capacity can never pass without changing policy; for rate zero, depleted credits never return. A distributed implementation must apply refill and debit together, not read a balance and later write it, because concurrent callers could both spend the same credits. For weighted requests, calculate retry delay as deficit divided by refill rate when the cost is feasible. Test simultaneous callers, backward clock inputs, long idle periods and datastore failures. Leased regional quotas need a documented maximum overshoot rather than a claim of exact global enforcement.
