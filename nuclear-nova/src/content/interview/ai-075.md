## Question

How do you manage prompt versioning and rollbacks in production?

## Brief answer

Treat prompts as versioned application artifacts bundled with model, tool schema and retrieval configuration. Roll back the complete compatible bundle rather than editing a live string without a record.

## Detailed answer

Store templates and tests in version control, pin releases and label traces with a bundle ID. Validate formatting and representative responses before a canary. Keep feature flags or routing rules that can restore the previous bundle quickly, and account for cache keys that include prompt versions. Database or tool schema migrations may need backward compatibility. Record why a change shipped and which regressions would trigger rollback.

Keep prompt templates, variable schemas and representative rendered examples in version control. A release record should include the model revision, decoding settings, tool schemas, retrieval profile and safety policies that the template assumes. Validate missing variables and escaping before a model call, because a malformed prompt can silently omit the most important instruction.

For example, a new prompt may expect tools to return `status: confirmed`, while the old schema returns only a boolean. Rolling back the prompt alone can leave incompatible assumptions in production. Use a versioned bundle or maintain backward-compatible interfaces during rollout. Include the bundle ID in traces and cache keys so stored answers from different behaviors are not confused.

Run paired offline evaluations, canary the candidate and define rollback triggers in advance. Keep the previous artifact and compatible dependencies available rather than relying on a hurried manual edit. Inspect whether a rollback also needs to invalidate prompt-prefix or application-answer caches. Record the intended behavioral change, supporting evidence and known tradeoffs. Prompt history becomes useful engineering evidence only when it can reproduce the exact configuration that produced an answer; a document containing the latest text is not sufficient release management.
