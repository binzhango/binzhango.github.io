## Question

Do the GPU memory maths for full fine-tuning a 7B model in bf16 with Adam. Now with LoRA.

## Brief answer

A common mixed-precision Adam estimate is about 16 bytes per trainable parameter: BF16 weights and gradients, FP32 master weights, and two FP32 optimizer moments. For 7B parameters that is about 112 GB before activations and temporary buffers.

## Detailed answer

The exact number depends on optimizer implementation and gradient precision. LoRA freezes the 14 GB BF16 backbone and stores training state only for adapter parameters, plus activations needed for backpropagation. For a 4096-by-4096 projection at rank 16, an adapter has 131,072 parameters; multiply by the number of targeted projections. Quantizing the frozen base reduces its storage further but adds metadata. Sharding changes per-device storage and communication, not the total logical state.

Break the common 16-byte estimate into terms: two bytes for BF16 weights, two for BF16 gradients, four for FP32 master weights, and eight for Adam's two FP32 moments. Multiplying by seven billion yields 112 billion bytes, approximately 104.3 GiB. Some implementations store gradients differently or avoid a master copy, so inspect the actual optimizer before using this as a capacity guarantee.

For a simplified LoRA example, target two $4096\times4096$ projections in each of 32 layers at rank 16. There are 64 adapters, each with 131,072 parameters, totaling 8,388,608. At the same illustrative 16-byte training-state budget, those adapters need about 134 MB. Add the 14-GB frozen BF16 backbone, not another full optimizer state for it. Real models have differently shaped projections, so sum the actual targeted dimensions.

This large reduction does not bound the full training peak. Backpropagation still requires activations through the network; sequence length, microbatch size and checkpointing can dominate memory. Gradient accumulation changes the effective batch without retaining every microbatch's activations simultaneously. Sharding distributes parameters, gradients or optimizer moments but adds communication. Validate the calculation with one representative forward/backward/optimizer step, then test the longest sequence and largest microbatch intended for the run.
