## Question

How do you make an agent's actions reversible, or at least auditable, in a production system?

## Brief answer

Put external actions behind a durable execution layer that records intent, authorization, inputs, idempotency keys and outcomes. Use reversible changes or compensating operations where the target system supports them.

## Detailed answer

Prefer drafts, staged updates and versioned records before irreversible publication. Save before/after identifiers and a correlation ID for every write. Recovery must distinguish a failed action from an unknown outcome; consult the target’s state before retrying. Compensation is not always true rollback, especially after notifications or third-party effects. Explain that limitation in the action model and retain enough evidence for investigation without logging secrets.

Represent a consequential action as a durable state machine: proposed, approved if necessary, dispatched, confirmed or uncertain, and optionally compensated. Persist the intent before execution so a crash does not erase the reason for a remote mutation. Save the target identifier, payload version, authorization context and remote receipt without copying unnecessary secrets into the log.

For a document edit, version history may support genuine rollback to the previous contents. For an email that has already been delivered, deleting the local sent record does not undo delivery. A correction email is compensation, with a new external effect. The interface and recovery logic must distinguish these cases instead of promising universal undo.

Use idempotency keys and conditional writes where the target supports them. Before retrying an unknown outcome, inspect remote state. For multi-step workflows, record each completed step and define compensations in reverse dependency order; some steps may require manual review because compensation can fail too. Audit records should answer who requested the action, what was authorized, what executed and what evidence confirms it. Test crashes between every pair of state transitions, especially between remote success and local persistence, where duplicate effects are most likely.
