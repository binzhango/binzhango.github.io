## Question

Design a file-sharing / distribution system.

## Brief answer

Separate file metadata and authorization from blob storage. Upload large files in resumable chunks, finalize only after integrity checks, and distribute downloads through scoped URLs or an authenticated edge. Sharing is an access-control relationship with expiry and revocation rules, not merely an obscure object path.

## Detailed answer

Suggested architecture: metadata service stores owner, version, checksum, size and ACL; object storage stores immutable blobs; an upload coordinator issues multipart upload capabilities. Finalization verifies parts and commits a new file version atomically. Background jobs scan content and remove abandoned uploads.

For downloads, authorize before issuing a short-lived capability, cache public or appropriately scoped content at the edge, and support range requests. Deduplication can save storage but must not reveal another tenant's possession of a file. Revocation of a previously issued signed URL takes effect only according to its lifetime or an edge revocation mechanism.

Test interrupted uploads, duplicate completion, checksum mismatch, concurrent version edits and deleted-file retention. Define whether sharing grants read, write or resharing permission. Measure upload success and download latency by file size; a small-file benchmark does not reveal multipart or long-distance distribution bottlenecks.

A multipart upload has a provisional upload ID and a set of expected parts. Completion should verify part integrity and the final checksum, then publish a new immutable file version in metadata. Repeating completion with the same upload ID must not create multiple versions. Expired incomplete uploads need garbage collection so abandoned sessions do not accumulate storage indefinitely.

Downloads should authorize against current sharing rules before issuing a capability. A short-lived signed URL reduces repeated authorization load but creates a bounded revocation delay; immediate revocation requires an additional check or edge mechanism. State that tradeoff explicitly for sensitive files.

Keep logical deletion, retention and physical garbage collection distinct. A deleted metadata record should become inaccessible immediately under the product contract even if the blob remains for recovery. Test concurrent uploads to the same filename, stale share links and cross-tenant deduplication. Content-addressed storage can save bytes, but exposing whether a hash already exists can leak another user's data possession if the API is careless.
