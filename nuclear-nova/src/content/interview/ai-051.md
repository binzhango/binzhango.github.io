## Question

How does an agent decide when to call a tool versus answer from its own knowledge?

## Brief answer

Use tools when the answer requires fresh facts, private state, exact computation or an external action. Answer directly when stable knowledge is sufficient and no required verification or execution is missing.

## Detailed answer

The controller can enforce mandatory retrieval or calculation for designated tasks, while the model selects among allowed tools for other cases. Estimate the expected benefit against latency and cost, but do not use model confidence alone as a correctness test. If evidence is unavailable, describe the uncertainty rather than inventing a result. Log unnecessary calls and unsupported direct answers to improve the routing policy.

Separate mandatory tool use from discretionary information gathering. A request to change an account, inspect a private document or report current service status requires access to external state; the model's memory cannot satisfy it. Stable explanations may need no tool, while arithmetic with many terms benefits from a calculator because the result can be checked cheaply.

A practical routing policy asks what evidence would change the answer and whether a tool can provide it. If a user asks “What is the status of ticket 314?”, an authorized ticket lookup is necessary. If the user asks “What does exponential backoff mean?”, a direct explanation may be sufficient. If the lookup fails, the agent should report that it could not verify the ticket rather than infer status from an old conversation.

Tool use also has costs: latency, rate limits, exposure of sensitive inputs and new error paths. Use a small test set containing fresh facts, private state, exact computation and stable knowledge to measure both missed required calls and unnecessary calls. Confidence expressed in fluent language is not a calibrated routing signal. Application rules can require verification for sensitive or rapidly changing domains, while allowing the model flexibility within a clearly bounded set of low-risk information tools.
