## Question

What’s the overall workflow of LLM+VectorDB document chat?

## Brief answer

Document chat typically ingests and indexes documents offline, then retrieves and assembles evidence before generating a cited answer online.

## Detailed answer

Offline: parse content, preserve structure and source metadata, chunk, embed, and index. Online: interpret the question, apply access filters, retrieve candidates, rerank, expand relevant context, and pack a bounded prompt. Generate an answer with source references, then check citation validity and support. Log retrieval and generation separately so an incorrect answer can be traced to the actual failing stage.

Keep the offline and online paths explicit. Offline ingestion converts each source into clean, structured text, creates retrievable units, and stores embeddings or lexical entries together with source IDs and versions. Reprocessing should replace or invalidate outdated chunks so multiple contradictory copies do not accumulate silently.

At query time, resolve the user's question and permissions, retrieve a broad enough candidate set, and rerank for answer support. Expand a small matching chunk when a heading, table header, or exception is needed to interpret it. Pack evidence into the prompt with stable identifiers and dates, leaving room for the answer. Generation should distinguish supported conclusions from missing information.

For a refund-policy question, the correct passage might state a general 30-day rule while a neighboring paragraph excludes a product type. Retrieving only the first sentence produces a plausible but incomplete answer. Trace the source passage through parsing, chunking, ranking, packing, and citation to find where that exception disappeared. Store stage-level outputs and latency so changes can be evaluated causally instead of switching the generator whenever any final answer is wrong.
