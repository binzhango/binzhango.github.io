## Question

Explain Multi-Query Attention (MQA).

## Brief answer

Multi-query attention gives many query heads one shared key head and one shared value head.

## Detailed answer

Each query head still computes its own attention weights, so shared K/V does not mean identical attention outputs. With $H$ query heads, KV cache storage can fall by roughly $H$ relative to MHA at the same head dimension. The Q projection and output projection remain, and score computation still serves every query head. This trades some representational flexibility for lower memory traffic.

With 32 query heads and head width 128, MHA produces 4,096 key features and 4,096 value features per token per layer. MQA produces only 128 of each. Every query head compares its own 128-dimensional query with that shared key sequence and mixes the shared values using its own weights. The resulting head outputs can differ because the queries differ.

An implementation should preserve sharing in storage. Physically repeating the one KV head 32 times into a cache would discard much of the memory benefit, even if it produces the correct mathematical output. A suitable attention kernel reuses the compact K/V representation across queries.

The tradeoff is that the keys and values have fewer independently learned feature subspaces. This can affect quality, particularly if applied to an existing MHA model without appropriate training. GQA offers an intermediate number of KV heads. Compare accuracy together with latency and maximum useful batch size; a smaller cache can allow more concurrent requests even when a single request's latency changes only modestly.
