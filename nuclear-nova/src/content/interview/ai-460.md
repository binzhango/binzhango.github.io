## Question

Design Comet's hybrid browser architecture combining on-device privacy with cloud AI assistance.

## Brief answer

Keep sensitive browser state and immediate page interactions local, and send only explicitly scoped task context to cloud assistance. Use a broker that mediates what the model can read and which actions it can request. This is a proposed hybrid browser architecture, not a description of Comet's private implementation.

## Detailed answer

**Suggested approach.** A local component extracts the active page's accessible structure, redacts selected sensitive fields, and resolves local-only tasks. The cloud handles heavier reasoning over a minimal task bundle. Bind every returned action to tab, origin, frame, and page-version identifiers so stale plans cannot act on a changed page. Authentication cookies and password-manager secrets never become prompt text.

Treat page content as untrusted instructions. Require confirmation for purchases or messages and enforce that requirement in the browser action broker. Keep history retrieval permissioned, with explicit retention and deletion controls; cache keys must not cross profiles. Evaluate useful task completion, unauthorized data exposure, action-target errors, and latency on dynamic pages. The tradeoff is weaker cloud context and more local engineering in exchange for narrower data exposure and responsive control.

### Bind an action to what the user saw

Consider a task to summarize an invoice and draft a reply. Local extraction can send invoice text and the selected email thread while withholding cookies, other open tabs, and payment credentials. The cloud returns a proposed reply and structured actions. Before applying them, the local broker checks that the target is still the same thread and that the page has not navigated to a different origin or account.

Permission should be attached to an operation and its target, not to the model's entire session. Authorization to read an invoice does not imply authorization to pay it; authorization to draft a reply does not imply permission to send it. A broker can enforce those distinctions even if a page includes hidden text instructing the model to transfer data elsewhere.

Cloud plans may become stale while the network is slow. Use page-version checks and reacquire necessary context when a target changes. Local execution should report observed postconditions, such as a saved draft ID, instead of treating a successful click as proof of completion. This adds synchronization work but prevents cloud reasoning from silently acting on the wrong current page.
