## Question

You need to run a ~3B-parameter language model on a phone with tight memory and power budgets. What changes versus serving the same model in a datacenter?

## Brief answer

On a phone, the model shares memory, power, and thermal headroom with the entire device, and requests usually arrive at small batch sizes. A 3B model at four bits needs about 1.5 GB of raw weights before quantization metadata, KV cache, and runtime buffers. Optimize sustained user experience, not only a short peak tokens-per-second benchmark.

## Detailed answer

Profile cold loading, prefill, decode, and background interference independently. Choose a device-native backend with supported quantized operators, limit context, and keep critical numerical operations in adequate precision. Avoid weight swapping that creates unpredictable stalls. Evaluate quality on the actual feature after quantization and any adapter specialization.

Datacenter serving can amortize weights across many concurrent users and scale capacity; a phone must remain responsive, function offline where promised, and avoid draining the battery. Test older devices, low memory, thermal throttling, and interrupted sessions. Use cancellation and graceful degradation. Server fallback, if offered, needs an explicit data-transfer policy and a useful offline behavior rather than being hidden inside the local feature.

### Work within a complete memory budget

Three billion parameters at four bits require about 1.5 GB of raw weights. Quantization scales, nonquantized layers, KV cache, activations, and the application add overhead. A 4K cache can consume hundreds of MiB depending on the architecture, and operating-system limits may be tighter than physical RAM. Measure the peak resident working set during prefill, which can differ from steady decoding.

The phone also shares compute with rendering, camera, and background applications. Sustained generation may lower clocks through thermal throttling, so a short cold benchmark overstates long-session performance. Choose the smallest task-adequate model, a supported low-bit kernel path, and a context/output budget compatible with the device class. Use adapters for feature behavior rather than loading independent full models. Evaluate first useful output, energy per completed task, UI responsiveness, and quality together. Offline guarantees require a useful local fallback when network access or user consent prevents cloud routing.
