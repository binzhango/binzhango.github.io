## Question

How should chat message history be stored and used?

## Brief answer

Chat message history stores conversation turns, while the context for a model call is the selected portion of that history and other relevant state.

## Detailed answer

Store role, content, and tool-call relationships under a correctly scoped conversation identifier. Persistence can outlive a process, but storing messages does not mean every message should be sent on every call. Apply token budgeting, retention rules, and authorization. Current LangGraph-backed agents can checkpoint thread state; cross-conversation memory needs a separately designed storage and retrieval policy.

A persisted transcript and a model's current context are different objects. The transcript may contain every event needed for audit and recovery; the context should contain the subset needed for the next decision. Sending the entire transcript repeatedly increases cost and can include stale instructions, large tool outputs, or irrelevant earlier tasks.

Store messages with role, order, timestamp or sequence, and tool-call identifiers. A tool result should remain associated with the call that produced it. Scope the conversation key to the authorized user or tenant and avoid using a client-supplied ID as the sole access check. Keep durable preferences or task state separate from an unstructured transcript when they must survive summarization.

When constructing context, preserve current instructions, relevant recent turns, and necessary tool pairs. Summarize or retrieve older material with provenance, and explicitly handle corrections that supersede older facts. Test reload and continuation after a process restart. Persistence enables continuity; it does not automatically choose the correct context or ensure that concurrent updates and side effects are processed exactly once.
