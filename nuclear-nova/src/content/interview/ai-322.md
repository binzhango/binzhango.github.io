## Question

Design an agent that can take actions in a spreadsheet (“insert a pivot table of Q3 sales by region”): orchestration, tools and failure handling.

## Brief answer

Suggested approach: translate the request into a typed spreadsheet operation, resolve ranges and columns against the actual workbook, preview the intended change, and execute it transactionally where possible. The agent should use spreadsheet APIs with validated arguments rather than issue arbitrary UI gestures or generated macros by default.

## Detailed answer

For “Q3 sales by region,” identify date, region, and numeric sales fields, confirm the year if ambiguous, and determine the destination sheet. Validate data types, missing rows, currencies, and whether the source is already filtered. Generate a pivot specification with date bounds, row dimensions, aggregation, and output location.

Use a workbook version or revision check before applying the operation. Group related edits into an undoable transaction, assign an idempotency key, and inspect the resulting table totals and layout. If the workbook changes during planning, re-read and revalidate instead of applying stale coordinates. Keep formula text and cell content untrusted. Test protected sheets, merged cells, empty data, duplicate names, and partial failures; report what actually changed with a route to undo.

### Make the proposed operation inspectable

Represent the pivot as a plan: source table `Sales`, date filter July 1 through October 1 for the selected year, row field `Region`, value `sum(Revenue)`, and a new destination sheet. Resolve column identities from the workbook instead of relying on visual positions. Before execution, count included rows and calculate an independent aggregate total so the result has a simple verification target.

Acquire or check the workbook revision, create the pivot through a constrained API, then verify row labels and grand total. If the API times out, inspect whether the named result already exists before recreating it. If some operations are not transactional, record each completed step and offer an undo or compensation path. Treat hidden rows, filters, mixed currencies, and duplicate column names as semantic issues requiring explicit handling. Success is a correct workbook artifact and a verifiable change summary, not merely valid tool-call JSON.
