## Question

What is the KV cache, and what are its memory implications at scale? Derive the formula.

## Brief answer

The KV cache stores each layer’s previous keys and values so decoding does not recompute them. Its size grows linearly with stored tokens, batch size, layer count, and the number of KV heads.

## Detailed answer

For uniform full attention, cache bytes are $2LBT H_{kv}d_hs$: two tensors, $L$ layers, $B$ sequences, $T$ cached tokens each, $H_{kv}$ KV heads, head dimension $d_h$, and $s$ bytes per element. With 32 layers, 8 KV heads, head dimension 128 and two-byte elements, one token costs 131,072 bytes. An 8,192-token sequence therefore needs 1 GiB before allocator overhead. Sum actual sequence lengths for variable batches. Sliding windows, quantization, shared prefixes, and MLA change the accounting; weights are separate.

Derive the expression from one layer and one token: there are $H_{kv}d_h$ key elements and the same number of value elements. Multiply by the element size, then by layers and retained tokens. Query vectors are not retained because the next step creates a new query. During decoding, the new query attends to all retained keys, reads their values, and appends its own key/value pair for later steps.

The same 32-layer example with 32 independent sequences of 8,192 tokens consumes 32 GiB of raw KV cache. Doubling context doubles this requirement even though model weights remain unchanged. For unequal lengths, replace $BT$ with $\sum_i T_i$; reserving every sequence at its maximum wastes capacity. A paged allocator reduces unused reservations but does not shrink the mathematical cache.

Serving admission should reserve room for generated tokens as well as the prompt. At high concurrency, KV can exhaust memory before the weight tensor does. Lower KV precision, fewer KV heads, prefix sharing and sliding attention each save different portions of the footprint and have different correctness conditions. When distributing across GPUs, inspect whether KV heads are sharded or replicated; simply dividing the total by the GPU count can understate per-device memory.
