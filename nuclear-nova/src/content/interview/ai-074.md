## Question

What observability does a production LLM system need: traces, spans, costs, feedback?

## Brief answer

Trace the full request path: input handling, retrieval, model calls, tools, retries and final delivery. Record versions, durations, token usage, outcome and feedback so a failure can be localized and reproduced.

## Detailed answer

Use correlation IDs and parent/child spans across services. Store sensitive payloads only when necessary, with access controls and retention limits; sanitized metadata often suffices. Track cost per successful task, queue delay, cache hit savings and tool error rates. Preserve sampled examples for qualitative review, since token metrics cannot reveal factual correctness. Alert on changes in user outcomes as well as infrastructure health.

A useful trace starts with the user request and follows retrieval, reranking, prompt assembly, model calls, tool execution and delivery. Record span start/end times, model and prompt versions, token counts, cache coverage, retry reasons and a task outcome. Without the parent-child relationships, a slow final response cannot be traced to a queue, a third-party tool or repeated generation.

Separate operational telemetry from sensitive content. Most requests can log identifiers, sizes and status codes, while a controlled sample stores redacted payloads for quality analysis under explicit access and retention rules. Redaction must cover tool results and retrieved passages, not only the user's prompt. Avoid logging secrets just because they help reproduce a bug.

Build dashboards for successful-task cost, p99 time to useful output, unsupported-answer rate from sampled review, tool failure rate and incomplete/canceled workflows. Link user feedback to the exact bundle and evidence revision used, because “bad answer” without context is hard to diagnose. Sample rare errors more heavily for debugging while maintaining an unbiased baseline sample for rate estimates. Alerts should capture behavior changes as well as infrastructure failures; a service returning HTTP 200 with systematically wrong answers is operationally alive but failing its purpose.
