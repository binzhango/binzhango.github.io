## Question

Explain FlashAttention. It does not reduce FLOPs, so why is it faster?

## Brief answer

FlashAttention accelerates exact attention by reducing expensive GPU memory traffic. It tiles the computation and maintains an online softmax, avoiding materializing the full attention-score matrix in high-bandwidth memory.

## Detailed answer

For long sequences, writing and rereading an $n\times n$ matrix can dominate execution. Keeping tiles and softmax statistics in on-chip memory changes data movement even when the mathematical attention operation is unchanged. Backward computation can deliberately recompute values to save memory. Arithmetic work is therefore not guaranteed to decrease, and speedups depend on shape, hardware and kernel support. It still has quadratic attention arithmetic.

A conventional attention implementation computes scores, writes them to GPU memory, reads them for softmax, writes probabilities, then reads those probabilities to multiply by values. For 32,768 positions, one attention matrix has over a billion entries per head. Even when the accelerator can perform the multiplications quickly, moving these intermediates is expensive.

FlashAttention visits key/value tiles while holding a query tile and its output accumulator in fast on-chip memory. For each row it retains a running maximum $m$, normalization sum $\ell$ and weighted-value accumulator. When a later tile introduces a larger maximum, the previous sum and accumulator are rescaled by the appropriate exponential factor before adding the new tile. Thus the final normalized output matches the full softmax without retaining every probability.

This is an exact algorithm in the sense of computing the same attention definition, subject to floating-point ordering differences; it is not sparse attention. During training, recomputing probabilities in the backward pass can cost extra arithmetic while still saving time through less memory traffic. Short sequences, unsupported masks, awkward head sizes or low occupancy can limit the improvement. Assess peak allocated memory and wall-clock forward/backward time, not just a theoretical FLOP count.
