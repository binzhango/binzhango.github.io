## Question

You are receiving an unbounded stream of event IDs. Return the k most frequent IDs seen so far, at any point, with bounded memory.

## Brief answer

Exact top-k frequencies over an unbounded stream with an unbounded ID universe cannot generally be maintained in fixed memory. State that limitation, then offer an approximate heavy-hitter algorithm such as Misra–Gries or Space-Saving with an explicit error guarantee. If exactness is required, bound the universe/window or use external storage.

## Detailed answer

This Misra–Gries implementation keeps at most `m` candidate counters. Its values are lower-bound estimates, not exact frequencies; a second pass can count candidates exactly when replay is available.

```python
class HeavyHitters:
    def __init__(self, m):
        if m < 1: raise ValueError('positive capacity required')
        self.m, self.counts, self.n = m, {}, 0
    def add(self, item):
        self.n += 1
        if item in self.counts: self.counts[item] += 1
        elif len(self.counts) < self.m: self.counts[item] = 1
        else:
            for key in list(self.counts):
                self.counts[key] -= 1
                if self.counts[key] == 0: del self.counts[key]
    def candidates(self): return dict(self.counts)

h = HeavyHitters(2)
for x in ['a','a','a','b','c']: h.add(x)
assert 'a' in h.candidates() and len(h.candidates()) <= 2
```

With m counters, every item occurring more than $N/(m+1)$ times is retained, and undercount is at most $N/(m+1)$. That does not guarantee the exact ordering of the top k when counts are close. Time per update is worst-case O(m) here. Define whether “seen so far” or a sliding time window is needed; window expiration changes the algorithm.


The decrement step cancels a group of $m+1$ distinct items: the arriving untracked item plus one count from each of the $m$ tracked candidates. At most $\lfloor N/(m+1)\rfloor$ such cancellations can occur, so no item's count can be underestimated by more than that amount. Any item occurring more often than the bound must survive among the candidates.

This guarantee identifies sufficiently frequent items, not necessarily the exact top k. If the largest counts are all close together, the summary may not preserve their ordering. Choose more counters than k when the desired frequency/error threshold requires it, and count retained candidates in a second pass if the stream is replayable.

State whether memory is bounded in counters or bits: storing arbitrary unbounded identifiers and growing counts still requires representation space. A finite retention window changes the semantics because old contributions must expire. Test all-distinct streams, one dominant item, ties and adversarial sequences against exact counts on small inputs, verifying the stated error bound rather than demanding impossible exact equality.
