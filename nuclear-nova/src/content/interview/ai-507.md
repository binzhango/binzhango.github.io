## Question

Present the architecture for a workflow reviewing 5,000 contracts against an 18-question diligence checklist, returning a review grid.

## Brief answer

Build a resumable document-processing workflow whose output is an evidence-linked 5,000-by-18 review grid. Each cell should contain a structured finding, cited passage, uncertainty or missing-data state, and review status. Separate extraction completeness from interpretation quality so an unreadable scan cannot become an unsupported “not present.”

## Detailed answer

**Suggested approach.** Inventory and deduplicate documents, preserve versions, parse/OCR with quality checks, and map the 18 checklist items to retrieval queries and dependency expansion. Batch compatible questions per document when useful, but validate every cell independently. Store immutable intermediate artifacts and idempotent job keys so failures resume without repeating the entire room.

Prioritize human review for high-risk findings, contradictions, poor extraction, and uncertain absence claims. Show source highlights directly from the grid and track reviewer overrides. Measure document coverage, cell-level precision/recall, false negatives by clause type, cost, throughput, and review effort. At 90,000 cells, even a small error rate can create substantial review work; release criteria should reflect severity, not just average accuracy. Treat the grid as a diligence aid subject to professional review.

### Model each grid cell as evidence plus state

Use a cell schema containing document revision, checklist version, finding, evidence spans, extraction status, confidence category, and reviewer decision. Distinguish “present,” “not found after adequate review,” “unreadable,” and “requires interpretation.” A blank cell or default false value must not silently convert failed processing into a substantive absence finding.

The job graph parses each document once, builds reusable evidence, answers the checklist, validates cell structure and support, and routes exceptions to review. Job keys include document and model/prompt versions so retries are idempotent and a revised checklist invalidates the right outputs. The UI can then show progress by documents processed and cells ready for review rather than only a single completion percentage.

At 90,000 cells, a hypothetical 1% cell error rate implies 900 errors in expectation; it does not mean each contract is 99% dependable. Correlated parsing failures can affect every cell in a document. Sample both across checklist items and within entire documents, and prioritize missed consequential provisions separately from harmless formatting corrections. Release a traceable grid with unresolved states visible instead of forcing every cell to look complete.
