## Question

Implement a minimal agent loop with tool dispatch, error handling and a step budget.

## Brief answer

Make the model propose either a final answer or a typed tool request. Validate and authorize requests in code, invoke only allowlisted tools, return bounded structured observations, and stop on a final answer or exhausted budget. Tool output is untrusted data; it cannot grant new permissions or change the execution policy.

## Detailed answer

The minimal synchronous implementation below accepts injected model and tool functions. Authorization occurs before execution and failed tool calls become observations the model can handle.

```python
import json

def agent(user, model, tools, allowed, steps=5):
    history = [{'role':'user', 'content':user}]
    for _ in range(steps):
        action = model(history)
        if action.get('type') == 'final': return str(action.get('text', ''))
        name, args = action.get('tool'), action.get('args')
        if name not in tools or not isinstance(args, dict):
            result = {'error':'invalid tool request'}
        elif not allowed(name, args):
            result = {'error':'not authorized'}
        else:
            try: result = {'ok': tools[name](**args)}
            except Exception as e: result = {'error':type(e).__name__}
        history.append({'role':'assistant', 'content':action})
        history.append({'role':'tool', 'content':json.dumps(result)[:4000]})
    raise RuntimeError('step budget exhausted')

responses = iter([{'tool':'add', 'args':{'x':2,'y':3}}, {'type':'final','text':'5'}])
assert agent('add', lambda _: next(responses), {'add':lambda x,y:x+y}, lambda n,a:True) == '5'
```

Before production, add per-tool schemas, timeouts, cancellation, durable checkpoints and idempotency keys for writes. Truncating serialized output is acceptable for this string observation but not a valid JSON transport; a real adapter should return a structured truncation marker. Confirm external side effects against the actual user-approved operation and arguments, not merely a model-generated claim that approval exists.

The loop's authority comes from `tools` and `allowed`, not from model output. An unknown tool name or a denied argument set becomes an observation without execution. A successful tool result is added to history so the model can use external evidence in the next step. The hard step limit prevents an endless series of proposals even if the model never emits a final answer.

This minimal contract assumes the injected model returns a dictionary and tools return JSON-serializable values. A real boundary must validate those assumptions, cap nested result sizes and handle model/provider errors separately from tool errors. Model-declared final text should also be checked against the task's success predicate when external state matters.

Test a denied write, malformed arguments, a tool exception, repeated identical failures and budget exhaustion. For consequential operations, persist intent and outcome under an action ID so a crash between execution and history update cannot cause duplicate effects. A step budget bounds call count but not the duration or price of one call; add deadlines, token limits and cost accounting independently.
