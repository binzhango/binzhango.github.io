## Question

Implement a set of shape classes that compute area, then extend them to handle a new shape.

## Brief answer

Give each shape an `area()` method under a common interface, validate dimensions at construction, and add new shapes by implementing that interface. This keeps callers independent of a growing type-switch. State units explicitly: area is in the square of the dimensions' unit, and invalid or nonfinite dimensions should not silently propagate.

## Detailed answer

```python
from dataclasses import dataclass
from math import pi, isfinite
from typing import Protocol

class Shape(Protocol):
    def area(self) -> float: ...

def dimension(x):
    if not isfinite(x) or x < 0:
        raise ValueError('dimension must be finite and nonnegative')

@dataclass(frozen=True)
class Rectangle:
    width: float
    height: float
    def __post_init__(self):
        dimension(self.width); dimension(self.height)
    def area(self):
        return self.width * self.height

@dataclass(frozen=True)
class Circle:
    radius: float
    def __post_init__(self): dimension(self.radius)
    def area(self): return pi * self.radius ** 2

@dataclass(frozen=True)
class Triangle:
    base: float
    height: float
    def __post_init__(self):
        dimension(self.base); dimension(self.height)
    def area(self): return self.base * self.height / 2

def total_area(shapes):
    return sum(s.area() for s in shapes)

assert total_area([Rectangle(2, 3), Triangle(4, 3)]) == 12
assert Circle(0).area() == 0
```

Adding `Triangle` does not change `total_area`. Each area computation is O(1), and summing n shapes is O(n). Test zero dimensions, negatives, NaN/infinity, and known values. For a triangle specified by three sides, use a different constructor with triangle-inequality validation; base and perpendicular height are the contract here.

### Extend behavior through the common contract

`Shape` is a structural interface: a caller needs an `area()` method, not a switch over every concrete class. The frozen dataclasses validate dimensions once at construction and then expose immutable geometry. Adding a triangle supplies its own formula while `total_area` continues to operate on any compatible object. For dimensions in meters, Rectangle(2,3) has area 6 square meters and Triangle(4,3) also has area 6.

The triangle's height is perpendicular to its base, not an arbitrary side length. A three-side triangle needs a different validated representation; silently reusing this constructor would compute the wrong quantity. Zero dimensions represent degenerate shapes under the stated contract, while negative and nonfinite inputs are rejected. Very large finite dimensions can still overflow floating-point area, so an application needing guaranteed finite outputs must validate the result or use suitable bounded/exact arithmetic. Test extensibility with a new shape and verify callers require no modification. Avoid a deep inheritance hierarchy when a small behavior interface is enough.
