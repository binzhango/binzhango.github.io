## Question

Convert nested stack traces into discrete start and end events.

## Brief answer

Compare consecutive sampled call stacks by their longest common prefix. End frames from the old suffix in reverse order, then start frames from the new suffix in forward order. This produces properly nested events, but samples only reveal observed transitions; they cannot recover calls that began and ended between samples.

## Detailed answer

Assume each sample is `(timestamp, [outermost, ..., innermost])`. A frame identity must include more than a display name if recursion or same-name functions matter.

```python
def stack_events(samples, end_time=None):
    previous, events, last = [], [], None
    for time, stack in samples:
        if last is not None and time < last: raise ValueError('timestamps must be ordered')
        common = 0
        while common < min(len(previous), len(stack)) and previous[common] == stack[common]:
            common += 1
        events.extend((time, 'end', f) for f in reversed(previous[common:]))
        events.extend((time, 'start', f) for f in stack[common:])
        previous, last = list(stack), time
    if end_time is not None:
        if last is not None and end_time < last: raise ValueError('invalid end time')
        events.extend((end_time, 'end', f) for f in reversed(previous))
    return events

assert stack_events([(0,['a','b']), (2,['a','c'])], 3) == [
    (0,'start','a'), (0,'start','b'), (2,'end','b'),
    (2,'start','c'), (3,'end','c'), (3,'end','a')]
```

Work is linear in the total number of sampled frames and emitted events. Leave the last stack open unless the caller supplies an observation end time. Test empty stacks, identical samples, complete replacement and recursive stacks such as `a, a, b`.

Suppose the old sample is `[main, parse, read]` and the new sample is `[main, parse, validate]`. The first two frames are shared, so emit `end(read)` before `start(validate)`. If the new stack is only `[main]`, end `read` and then `parse` in reverse nesting order. Ending outer frames first would produce an invalid event tree.

These timestamps represent observation boundaries, not exact entry/exit times. A function can execute entirely between samples and never appear. Likewise, a frame that disappears and reappears between identical samples is indistinguishable from one continuous call. State this limitation when the events are used for profiling or duration estimates.

Maintain separate previous stacks per thread or async execution context; interleaving unrelated stacks in one comparison would invent transitions. Test recursion with repeated function names, empty samples, identical timestamps and out-of-order input. Use stable frame identities that distinguish code locations when needed, while preserving nesting depth so recursive occurrences remain separate events. Explicit end time closes the observation interval without pretending the trace supplied an exact function return.
