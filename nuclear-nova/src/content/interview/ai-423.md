## Question

Price a dedicated endpoint: estimate cost per million output tokens for a 70B model, and explain the throughput-latency trade.

## Brief answer

Price from the endpoint's all-in hourly cost divided by delivered output throughput at the required latency and utilization. Model size alone is insufficient: hardware count, precision, input lengths, output lengths, concurrency, availability, and prompt processing all affect cost. Distinguish infrastructure cost from selling price and reserve margin for operational risk and support.

## Detailed answer

Illustrative assumptions: an endpoint costs $16 per hour and sustains 400 output tokens/sec while meeting its SLO. Raw cost is $16\times10^6/(400\times3600)\approx$11.11 per million output tokens. At 50% effective utilization, that becomes about $22.22, before other costs. These are hypothetical inputs, not current market prices or a claimed 70B benchmark.

Include prefill, networking, storage, control-plane expense, redundancy, and idle reserved capacity. Larger batches can increase throughput while worsening queue and token latency; plot the capacity curve instead of using a single peak number. Benchmark the customer's request-length distribution and quality constraints, then choose a billing model that reflects reserved versus shared service. Update the estimate when model or hardware configuration changes.

### Derive the unit cost explicitly

If a provisioned endpoint costs C dollars per hour, sustains r output tokens per second at its required latency, and achieves utilization u, output capacity costs approximately $10^6C/(3600ru)$ dollars per million tokens. This allocates the full endpoint cost to output; if input tokens are billed separately, choose an allocation that does not charge the same infrastructure twice.

An interactive workload with long prompts may spend substantial time on prefill, so using a decode-only r overstates useful capacity. Measure a mixed workload including prompt lengths, output lengths, cache reuse, and burstiness. Reserve capacity for failures and rolling updates. Pricing then adds the chosen margin and commercial commitments; raw infrastructure cost is not itself the selling price. Offer separate SLO classes when low-latency reserved traffic and flexible batch traffic use capacity differently. Recalculate after quantization or model changes because quality, cache size, and achievable throughput can all change together.
