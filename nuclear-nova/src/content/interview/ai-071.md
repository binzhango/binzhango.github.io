## Question

Design the regression gate that decides whether a prompt or model change ships.

## Brief answer

Gate releases on paired evaluation against the current version, with thresholds for task quality, critical failure rates, latency and cost. Use a fixed regression suite plus fresh cases representing recent production failures.

## Detailed answer

Version model, prompts, tools, retrieval index and judge configuration together. Require no new known critical failures and bound acceptable metric regressions using uncertainty rather than one noisy score. Run a canary with predefined rollback conditions after offline approval. Preserve the prior deployable bundle, including compatible index and schema versions. A passing benchmark is evidence for the tested scope, not proof that all future traffic is safe.

A release bundle includes more than a prompt: model revision, decoding settings, tool schemas, retrieval configuration and any output validators can all change behavior. Assign one immutable bundle ID and run the candidate and current bundle on the same evaluation inputs. Paired comparisons reduce noise and reveal which specific cases improved or regressed.

Set thresholds before looking at results. Require critical permission and action-safety cases to pass, establish acceptable bounds for quality and latency, and define what evidence is needed when confidence intervals overlap. Some failures are vetoes rather than quantities to average away. A two-point aggregate gain cannot compensate for a new path that exposes another tenant's documents.

After offline acceptance, route a small randomized production cohort to the candidate with predefined rollback triggers. Observe user corrections, tool errors, completion rate, latency and cost, while retaining a representative quality-review sample. Rollback must restore a compatible set of artifacts, including cache keys and index/model pairings. Keep the old bundle deployable until the new one has cleared the observation period. Confirmed incidents become regression cases, but retain a separate fresh holdout so repeated tuning does not gradually turn the gate into training data.
