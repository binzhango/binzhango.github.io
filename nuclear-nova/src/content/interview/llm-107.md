## Question

How to select GPU accelerators?

## Brief answer

Select accelerators by usable memory, sustained workload throughput, memory bandwidth, interconnect, supported precision, and total cost.

## Detailed answer

Fit the intended sequence length and microbatch with headroom, then measure tokens per second using the actual model and kernels. Multi-GPU training depends heavily on communication, so peak FLOPs alone can be misleading. Include software compatibility, availability, reliability, power, and checkpoint storage. A faster GPU can reduce total cost if it shortens the run enough; a cheaper one can win when utilization or communication limits performance.

Begin with feasibility: can the chosen parallel strategy hold parameters, optimizer state, gradients, activations, and peak temporary buffers? A device with attractive peak arithmetic but insufficient usable memory may force offload or tiny microbatches that erase its apparent advantage. Long contexts and large batches also increase memory traffic, so bandwidth matters alongside FLOPs.

Next measure a representative workload with the intended dtype and kernels. Peak numbers may assume sparsity or precision modes the model does not use. In multi-device training, include collective communication, data loading, and checkpoint I/O. A fast accelerator can spend much of its time waiting on another subsystem.

Compute total run cost as device count times wall-clock duration times effective hourly cost, then include failures, availability, and engineering effort. For inference, compare cost per successful request at the target latency and concurrency instead. Record software versions and warmup conditions so measurements are reproducible. Prefer measured sustained performance and operational reliability over a single advertised specification; hardware selection is a system-level decision involving model shape, communication, memory, and workload.
