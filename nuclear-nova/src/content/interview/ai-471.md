## Question

Long context windows keep getting cheaper. Why not drop retrieval and stuff the whole repo into context for every request?

## Brief answer

Retrieval still controls relevance, freshness, permissions, latency, and cost even when long context is affordable. A repository includes generated files, obsolete paths, secrets, and unrelated code; placing everything in every prompt increases distraction and can obscure the exact dependency that matters. Long context and retrieval are complementary tools.

## Detailed answer

Compare actual token distributions and outcomes. An illustrative 100,000-file repository averaging 500 tokens per file is 50 million tokens before dependencies or history, far beyond a modest interactive budget. Even a smaller repository fitting the model window incurs prefill and KV costs and can lose cache reuse after changes.

Use broad context for a bounded subsystem when cross-file reasoning genuinely needs it, and retrieval for discovery followed by dependency expansion. Always include the current unsaved buffer version over stale indexed content. Evaluate task success, edit locality, missed dependencies, latency, and cost at equal quality targets. Retrieval can fail by omitting evidence; mitigate that with lexical search, symbol graphs, and explicit exploration, not by assuming that maximum context guarantees understanding.

### Choose context by the dependency of the task

A request to rename a public interface may need the declaration, callers, tests, and generated bindings across a subsystem. A request to fix a local null check may need only the function and its immediate contract. A useful retrieval loop starts with exact symbols, expands along dependencies, and asks for more evidence when checks reveal missing context. It should not make the same fixed-size selection for both tasks.

Even when a whole subsystem fits, context has opportunity cost. Every irrelevant token competes with instructions, useful examples, and the model's output budget, and changes near the beginning can invalidate cached prefixes. A large window is an upper bound on accepted input, not evidence that the model uses every position equally well.

Run an ablation with retrieved context, whole-subsystem context, and an oracle evidence set. The oracle separates retrieval omissions from reasoning limitations. Include unsaved edits and branch changes in the experiment, because a huge but stale context can be less useful than a small current one. Use whole-repository input only when the repository is genuinely small, authorized, and the measured task benefits.
