## Question

Design an LLM gateway: routing across providers, failover, caching, budgets and rate limits.

## Brief answer

An LLM gateway centralizes authentication, quotas, routing, observability and provider adapters while preserving provider-specific capabilities. It needs explicit retry and failover semantics, especially for streams and tool calls.

## Detailed answer

Route using task quality, capacity, privacy constraints and cost budgets. Normalize the common interface without pretending all tokenization, structured-output or tool semantics are identical. Retry only safe operations; after streaming begins, restarting elsewhere can duplicate or contradict output. Cache with model, prompt, authorization and freshness keys. Record actual usage, reconcile estimates and provide circuit breakers so one provider failure does not cascade through retries.

Split the gateway into authentication/admission, policy routing, provider adapters and usage accounting. Admission validates tenant quotas and reserves an estimated token budget. Routing considers model capability, privacy constraints, latency class, current capacity and cost. Adapters normalize common request/response fields while exposing unsupported capabilities explicitly instead of silently dropping them.

A provider failure before any response may permit a safe retry. Once streaming begins, a second provider may generate a different continuation, so transparent restart can duplicate text or contradict what the user already saw. Tool calls are even more sensitive: track call IDs and confirmed effects, and never replay an external action just because generation moved to another provider.

Cache exact responses only when model, prompt, authorization and data freshness match. Semantic caching requires a much stronger equivalence check, especially for personalized or time-sensitive questions. Reconcile estimated reservations with actual input/output usage, including canceled streams and retries. Use circuit breakers and bounded retry budgets so one outage does not overload every fallback. Evaluate routing quality by task success and cost, and test failover under realistic provider rate limits rather than assuming backup capacity is unlimited.
