## Question

When would you choose vLLM vs SGLang vs TensorRT-LLM vs a custom stack?

## Brief answer

Choose a serving engine by model and hardware support, workload behavior, operational maturity and measured service-level performance. Avoid choosing from a universal speed ranking.

## Detailed answer

Build the same benchmark corpus for every candidate: short and long prompts, mixed output lengths, concurrency ramps, structured decoding and cancellation. Record accepted quality, p99 TTFT/ITL, memory headroom, tokens per dollar and failure recovery. vLLM, SGLang and TensorRT-LLM evolve quickly, so pin exact versions and verify the needed model, quantization and accelerator paths in their official documentation. A custom stack is justified only when a demonstrated bottleneck outweighs maintenance and correctness costs.

Start with a capability matrix that names the exact checkpoint, accelerator, quantization format, context limit and required output constraints. A candidate that cannot support a required path correctly should be rejected before throughput comparisons. Among supported candidates, test a representative trace rather than a single uniform prompt. Include cache-cold requests, multi-turn reuse, long prefills and early client cancellation.

vLLM is a natural candidate when a general-purpose model-serving engine and broad integration are priorities. SGLang is a candidate when its execution and prefix-reuse behavior matches the application's repeated structured workloads. TensorRT-LLM is worth testing when deployment is centered on NVIDIA hardware and its optimized execution paths match the model. These are evaluation starting points, not immutable product rankings or guarantees about a particular release.

Set acceptance criteria first: quality parity, p99 TTFT and inter-token gaps, cost per successful request, memory margin and restart time. Test overload and rolling upgrades as well as steady state. A custom scheduler or kernel is justified when profiling identifies a valuable bottleneck that the supported engines cannot address, and the team can maintain model correctness, security updates and operational tooling. Record exact versions and configurations so the decision is reproducible after the next upgrade.
