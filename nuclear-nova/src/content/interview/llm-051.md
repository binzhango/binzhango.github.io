## Question

Which models implement FlashAttention?

## Brief answer

FlashAttention is an execution backend, not a fixed model-family property; compatible implementations of models such as Llama or Mistral can use it.

## Detailed answer

Actual dispatch depends on the framework version, hardware, dtype, mask, and requested features. A PyTorch scaled-dot-product-attention call may choose a fused kernel or fall back to another implementation. Requesting attention weights can also affect the path. Verify the configured backend and profiler output rather than inferring it from the checkpoint name.

The checkpoint defines weights and architecture, while the runtime chooses how to execute compatible operations. The same Llama checkpoint can run with an eager attention implementation, a framework-dispatched scaled-dot-product kernel, or another supported fused backend. Which path actually runs can differ from the requested configuration if an unsupported dtype, mask, or feature triggers fallback.

A practical verification uses one representative forward pass with the exact serving configuration, then inspects profiler traces and memory use. Check both prefill and decoding because they have different shapes and may use different kernels. Requesting full attention weights for visualization can force materialization that the efficient path was intended to avoid.

Correctness comes first: compare a small example against a reference implementation, including padded batches and causal masking, within suitable floating-point tolerances. Then measure warm-run latency and peak memory. Backend availability changes with library and hardware versions, so record those versions with results. Merely observing that a model loads successfully, or that a configuration contains a backend name, is insufficient evidence that the intended optimized kernel executed.
