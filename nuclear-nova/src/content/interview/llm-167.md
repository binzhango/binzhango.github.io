## Question

How does classic adapter tuning differ from full fine-tuning?

## Brief answer

Full fine-tuning updates the backbone's weights, while classic adapter tuning freezes the backbone and trains added task-specific modules.

## Detailed answer

Full tuning offers broader parameter freedom but usually needs more gradient and optimizer memory and a full task checkpoint. Adapter tuning stores a smaller task artifact but still loads the base model and may add inference computation. Neither guarantees better generalization. Classic nonlinear adapters generally cannot be merged into an existing linear weight the way a standard LoRA update can; deployment behavior depends on the method.

Compare three resource categories separately. Full tuning stores gradients and optimizer states for the backbone, while adapter tuning stores those states mainly for the added modules. Both need the base weights and substantial activation computation. At checkpoint time, full tuning usually produces a full task-specific weight set; adapter tuning can save a much smaller artifact that depends on an exact base model.

At inference, full-tuned weights keep the original architecture, whereas classic bottleneck adapters add nonlinear operations in selected layers. That can increase latency even when the number of added parameters is small. A standard LoRA update has different deployment properties and can often be merged into a dense matrix; do not attribute that property to every method called an adapter.

Full tuning offers more parameter freedom and may help larger shifts when data and compute support it. Adapter tuning is attractive for multiple tasks, constrained training memory, and modular switching. Both can memorize or degrade general behavior. Compare independently held-out task performance, regressions, training cost, checkpoint size, and serving latency. The best choice depends on those measured tradeoffs rather than an assumption that fewer trainable parameters necessarily generalize better.
