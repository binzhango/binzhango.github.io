## Question

What’s the computational complexity of attention and how can it be improved?

## Brief answer

Dense full-sequence attention costs $O(n^2d)$ for score/value products plus $O(nd^2)$ for projections; cached single-token attention costs $O(nd)$ for those products.

## Detailed answer

Naive training additionally stores an $n\times n$ matrix per head. FlashAttention avoids that materialization while preserving quadratic dense arithmetic. A window of size $w$ gives approximately $O(nwd)$ attention work over a full sequence. Linear or compressed methods can reduce length scaling but change assumptions or model behavior. State whether an estimate concerns training, prefill, one decode step, or generating an entire sequence.

For $n$ tokens and head width $d_h$, forming scores for one head costs proportional to $n^2d_h$; multiplying probabilities by values has the same order. Summing across heads gives $O(n^2d)$ when their widths total $d$. The Q, K, V, and output projections contribute $O(nd^2)$, which can dominate for shorter sequences or large hidden width.

A causal mask removes about half the token pairs in principle, but the asymptotic order remains quadratic. During a cached decode step, there is only one new query, so its score/value work is $O(nd)$. Generating $m$ tokens after an $n$-token prompt sums contexts of lengths roughly $n$ through $n+m$, producing $O(mnd+m^2d)$ attention work across the generation.

For a fixed window $w$, each query reads at most $w$ positions, giving $O(nwd)$ full-sequence work. That saves computation by changing accessible information. Efficient dense kernels instead save intermediate memory and traffic while preserving pairwise work. Specify FLOPs versus memory and the phase of execution whenever giving a complexity claim.
