## Question

Design the Claude chat service.

## Brief answer

Design a chat service around durable conversations, streaming generation, user identity and a separate model-serving layer. Store ordered message events and attachment references, route generation through a bounded queue, and make retries idempotent. Conversation durability should not depend on keeping one GPU process or one network connection alive.

## Detailed answer

Suggested flow: the client creates a message with an idempotency key; the service authenticates ownership, persists the user turn and generation job, then streams tokens with event sequence numbers. Persist final assistant content and status; interruption is a visible state rather than an apparently complete answer. A reconnect endpoint resumes known events or returns the finalized message.

Store large attachments in object storage with scoped access. A context builder selects messages, summaries and retrieved documents under a token budget, preserving provenance and instruction boundaries. Model routing can choose tiers by explicit product policy, with no silent switch that violates capability or data-handling expectations.

Use regional routing, rate limits, abuse controls, encrypted storage and retention controls. Measure queue delay, first-token latency, completion rate and conversation consistency. Cross-device edits and branches need explicit parent-message IDs instead of assuming one mutable linear array. This is a reference design, not a description of a proprietary service.

Use a message graph rather than assuming every conversation is one mutable list. Each user message points to its parent, and each generation records the exact context branch and model bundle used. Editing an earlier message can create a new branch without rewriting the evidence for a previous answer. Concurrent browser tabs then have explicit conflict semantics.

Persist a generation status such as queued, streaming, completed, canceled or failed. A broken network connection is not equivalent to model completion; the client should reconnect using event sequence IDs or fetch the final status. Cancellation needs to reach the worker and release reserved compute and KV capacity promptly.

Test duplicate message submissions, stale clients, partial streams and attachment deletion. Access checks must cover both conversation metadata and underlying files. Operationally, keep storage availability and inference availability separable so users can still inspect their history during a model-serving outage. Measure consistency and recovery alongside token latency, because a fast answer attached to the wrong branch is a product failure.
