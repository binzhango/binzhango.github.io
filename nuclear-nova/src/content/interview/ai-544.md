## Question

Turn a conversation into billable diagnosis codes. What is the accuracy bar, and how do you build to it?

## Brief answer

Produce evidence-linked coding suggestions for qualified review, not autonomous final billing from a transcript. The system must distinguish documented diagnoses, symptoms, uncertainty, and historical conditions, and use the applicable versioned coding rules. There is no universal accuracy percentage that makes billing safe; thresholds depend on error severity and workflow controls.

## Detailed answer

**Suggested approach.** Extract clinical assertions with speaker, temporality, negation, and transcript spans. Reconcile them with clinician-confirmed documentation, then map candidates through a maintained terminology/rule service. Show the supporting evidence and reasons for missing specificity. Do not infer a billable diagnosis simply because a medication or test is mentioned.

Evaluate against independently reviewed cases with code-level precision/recall, overcoding, undercoding, and unsupported diagnoses separated. Stratify by specialty and complexity, and audit disagreement rather than assuming one coder is infallible. Block submission until the authorized reviewer confirms the final record and coding workflow. Changes to coding standards or payer rules require reviewed updates; model training data is not an authoritative current rulebook.

### Separate language extraction from coding authority

An encounter may contain “rule out pneumonia,” “history of pneumonia,” and “pneumonia confirmed.” These are different assertions. Preserve status and evidence through extraction, clinician documentation, terminology mapping, and coder review. The model should not collapse them into the same confident diagnosis merely because the disease name appears in all three.

Use a versioned terminology service to retrieve candidate codes and required specificity. If the documentation lacks a necessary detail, expose that gap for the responsible reviewer rather than supplying a statistically likely value. The correct output can be “insufficient documented information to suggest this code.” The accepted final documentation, setting, and applicable coding rules determine what is reportable.

Set separate acceptance thresholds for harmful unsupported suggestions and missed valid suggestions. Report code-level results alongside encounter-level results: one correct code among several unsupported additions can produce misleading recall. Use independent adjudication for disputed cases and preserve the initial model suggestion separately from the reviewer's final selection.

Release through assistance first, with monitored review burden and error severity. A high aggregate accuracy figure is insufficient if the rare failures systematically overstate diagnoses or affect a particular specialty. Trace every suggestion to the specific evidence and rule version used so audits can reconstruct the decision and corrections can target the failing component.
