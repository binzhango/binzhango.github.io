## Question

GLM-4.5 is a hybrid reasoning model with a thinking mode and a direct-response mode. How do you build one model that does both, and what are the training and serving implications?

## Brief answer

Train mode-conditioned behavior in shared weights, then make the serving contract explicit. A thinking mode may spend more tokens before the final answer; a direct mode should answer promptly. Use supervised examples and rewards that balance correctness, instruction following, and budget adherence, while evaluating each mode separately for quality and safety.

## Detailed answer

GLM-4.5's 2025 report documents hybrid reasoning support. A general implementation uses clear mode markers, mixed-mode supervised examples, and reasoning-task RL where verifiers are reliable. Maintain direct-response data so the model does not overthink simple requests.

At serving time, count all generated tokens against compute and context limits, even if some are not displayed. Bound latency, enforce structured tool-call formats, and ensure a budget stop produces a usable final response rather than a truncated intermediate stream. Keep parsers aligned with the checkpoint's template. Compare accuracy at equal budgets, route easy tasks economically, and validate that mode changes do not bypass authorization or output policies. The detailed training recipe is model-specific.

### Mode control must be learned

A direct-mode example should connect the user's request to a concise final answer. A thinking-mode example has a different valid output structure and may allocate computation to intermediate reasoning before its final response. The model learns both from a deliberate mixture; a serving flag cannot create a capability absent from training. Supervised examples establish formatting and behavior, while suitable post-training can improve problem-solving under bounded resources.

For “convert 5 km to meters,” direct mode avoids unnecessary tokens. For a difficult debugging task, a larger reasoning budget may improve success. Route by task requirements and measured performance, not a universal rule that thinking is better. A stop condition must respect the model's protocol so it does not expose an unfinished internal segment as a user answer. Test malformed transitions, tool calls made from either mode, exhausted budgets, and refusal handling. Model-specific templates and parser versions belong in the same deployment bundle.
