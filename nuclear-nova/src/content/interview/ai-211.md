## Question

Find the minimum window in S which will contain all the characters in T.

## Brief answer

Use a sliding window with required character counts and track how many target characters remain missing, including duplicates. Expand the right edge until the window covers the target, then shrink the left edge while preserving coverage. Each character enters and leaves once, giving linear time in the two string lengths.

## Detailed answer

```python
from collections import Counter

def minimum_window(s, t):
    if not t: return ''
    need, missing, left = Counter(t), len(t), 0
    best = None
    for right, char in enumerate(s):
        if need[char] > 0: missing -= 1
        need[char] -= 1
        while missing == 0:
            if best is None or right-left+1 < best[1]-best[0]:
                best = (left, right+1)
            old = s[left]; need[old] += 1; left += 1
            if need[old] > 0: missing += 1
    return '' if best is None else s[best[0]:best[1]]

assert minimum_window('ADOBECODEBANC', 'ABC') == 'BANC'
assert minimum_window('aa', 'aa') == 'aa'
assert minimum_window('a', 'aa') == ''
```

Negative counts represent surplus occurrences inside the window. The critical transition is when removing a character makes its count positive: coverage is then lost. This implementation compares Unicode code points; grapheme clusters and normalization require a preprocessing policy. Ties preserve the first shortest window. Avoid repeatedly constructing or sorting every candidate substring, which loses the linear bound.

`need[c]` starts as the required multiplicity. Decrementing it on expansion means zero is exactly satisfied and a negative value is surplus. `missing` counts required characters still absent, not the number of distinct character types, which is why a target like `AAB` is handled correctly.

Once coverage is complete, shrinking removes unnecessary surplus until the next removal would make a requirement unsatisfied. Every valid left boundary for a fixed right boundary is considered through this process, and each index advances at most once. This gives linear scanning time rather than checking all substrings.

Test repeated target characters, empty target, no possible window, irrelevant characters and equal-length ties. The counter may store characters not in the target with negative counts; that is harmless but can grow with the alphabet present in the input. The function operates on Unicode code points, so visually identical composed/decomposed text requires a normalization policy before matching. Keep that policy explicit rather than changing the string after computing offsets used to return the window.
