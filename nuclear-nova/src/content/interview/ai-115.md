## Question

Write an async batch processor over an API with concurrency limits, retries with jitter and error isolation.

## Brief answer

Use a fixed worker pool over a bounded queue, retry only transient failures with capped exponential backoff and jitter, and record each item's result independently. Keep retry sleeps outside the active-request semaphore. Cancellation should propagate, while one failed document should not cancel unrelated work.

## Detailed answer

This runnable Python core accepts an injected async API function. `Transient` represents classified retryable failures, including a parsed retry-after delay.

```python
import asyncio, random

class Transient(Exception):
    def __init__(self, retry_after=0): self.retry_after = retry_after

async def process(items, call, workers=8, attempts=3, timeout=30):
    if workers < 1 or attempts < 1: raise ValueError('positive limits required')
    queue = asyncio.Queue(maxsize=workers * 2)
    results = {}
    async def worker():
        while True:
            pair = await queue.get()
            try:
                if pair is None: return
                i, item = pair
                for attempt in range(attempts):
                    try:
                        results[i] = ('ok', await asyncio.wait_for(call(item), timeout))
                        break
                    except (Transient, TimeoutError) as error:
                        if attempt == attempts-1:
                            results[i] = ('error', type(error).__name__); break
                        delay = max(getattr(error, 'retry_after', 0), random.uniform(0, min(8, 2**attempt)))
                        await asyncio.sleep(delay)
                    except Exception as error:
                        results[i] = ('error', type(error).__name__); break
            finally: queue.task_done()
    async with asyncio.TaskGroup() as group:
        for _ in range(workers): group.create_task(worker())
        for pair in enumerate(items): await queue.put(pair)
        for _ in range(workers): await queue.put(None)
    return results

async def twice(x): return x * 2
assert asyncio.run(process([1, 2], twice)) == {0: ('ok', 2), 1: ('ok', 4)}
```

This bounds workers and queued inputs but retains all results. For large jobs, write results durably as they finish. Retrying a timed-out write requires idempotency because the server may already have completed it.

The bounded queue provides backpressure: the producer pauses when workers cannot keep up, so scheduling memory does not grow with the entire input corpus. Each worker owns one item's retry loop and records success or failure under its original index. Results can complete out of order without losing correspondence to inputs. A persistence layer can replace the result dictionary when jobs are too large to retain in memory.

This implementation has at most `workers` active calls, but a worker sleeping between retries also occupies one worker slot. A separate retry scheduler can improve utilization under widespread throttling, though it adds complexity. Concurrency limits do not enforce requests-per-minute or tokens-per-minute quotas; those need separate admission controls. Test permanent errors, retry exhaustion, caller cancellation and failures during result storage. The adapter must decide whether a timeout is safe to retry, because `wait_for` canceling the local coroutine does not prove that a remote server canceled the operation.
