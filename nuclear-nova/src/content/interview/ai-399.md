## Question

Implement a thread-safe batching logger: many producer threads call log(msg); a background thread flushes batches of up to 100 messages every second or when full.

## Brief answer

Use a bounded producer queue protected by a condition variable and one worker that flushes when 100 messages accumulate or the oldest message reaches one second. Perform sink I/O outside the queue lock. Define backpressure, shutdown, and sink-failure behavior explicitly; thread safety alone does not provide durable or exactly-once logging.

## Detailed answer

This runnable implementation blocks producers when full, drains on close, and records sink failures for callers rather than silently dropping them. The sink must finish in bounded time. Deadlines are best effort because a slow sink can delay subsequent batches.

```python
from collections import deque
from threading import Condition, Thread
from time import monotonic

class BatchingLogger:
    def __init__(self, sink, capacity=1000, batch_size=100, interval=1.0):
        if capacity < 1 or not 1 <= batch_size <= 100 or interval <= 0:
            raise ValueError("invalid limits")
        self.sink, self.capacity = sink, capacity
        self.batch_size, self.interval = batch_size, interval
        self.queue, self.cv = deque(), Condition()
        self.closed, self.error, self.failed_batch = False, None, None
        self.worker = Thread(target=self._run, daemon=True)
        self.worker.start()

    def log(self, message):
        with self.cv:
            while len(self.queue) >= self.capacity and not self.closed and not self.error:
                self.cv.wait()
            if self.error: raise RuntimeError("sink failed") from self.error
            if self.closed: raise RuntimeError("logger closed")
            self.queue.append((monotonic(), message))
            self.cv.notify_all()

    def _run(self):
        while True:
            with self.cv:
                while not self.queue and not self.closed:
                    self.cv.wait()
                if not self.queue: return
                remaining = self.queue[0][0] + self.interval - monotonic()
                if not self.closed and len(self.queue) < self.batch_size and remaining > 0:
                    self.cv.wait(remaining)
                    continue
                batch = [self.queue.popleft()[1]
                         for _ in range(min(self.batch_size, len(self.queue)))]
                self.cv.notify_all()
            try:
                self.sink(batch)
            except Exception as exc:
                with self.cv:
                    self.error, self.failed_batch = exc, batch
                    self.cv.notify_all()
                return

    def close(self):
        with self.cv:
            self.closed = True
            self.cv.notify_all()
        self.worker.join()
        if self.error: raise RuntimeError("sink failed") from self.error

batches = []
logger = BatchingLogger(batches.append)
producers = [Thread(target=lambda n=n: [logger.log((n, i)) for i in range(70)])
             for n in range(4)]
for thread in producers: thread.start()
for thread in producers: thread.join()
logger.close()
messages = [message for batch in batches for message in batch]
assert len(messages) == len(set(messages)) == 280
assert all(1 <= len(batch) <= 100 for batch in batches)
```

A sink may partially persist a batch before failing, so blind retries can duplicate records. Production logging needs a durable spool and message IDs if stronger delivery guarantees are required. Bound message size as well as queue length, and prohibit calling `close()` from the sink worker itself.

### The condition variable protects one queue contract

Producers append under the condition lock and wait when capacity is exhausted. The worker checks the oldest message's monotonic deadline or a full batch, removes up to 100 messages under the lock, then calls the sink after releasing it. That prevents a slow sink from holding the queue lock, although producers eventually block if the bounded queue fills.

Ordering follows lock acquisition, not an invented total order between simultaneous caller timestamps. `close` stops new writes and lets the worker drain queued messages. Sink failure records the failed batch and wakes blocked producers so they receive an error instead of hanging forever. Memory is bounded by message count only if message sizes are also bounded; a single giant string defeats a byte-budget claim. Append is amortized constant time and a flush performs O(batch size) queue work plus sink cost. This in-memory implementation is not durable: process death can lose buffered messages, and partial sink success requires an idempotent persistence protocol for stronger delivery guarantees.
