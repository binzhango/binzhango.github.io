## Question

Can Llama handle infinitely long inputs? Why or why not?

## Brief answer

No. Llama checkpoints have finite supported context lengths, limited memory and compute, and finite training experience with positional ranges.

## Detailed answer

Rotary position formulas can be evaluated beyond the training range, but that does not guarantee accurate long-range behavior. With a conventional KV cache, memory grows with stored context; full dense prefill also has quadratic attention work. Sliding windows can bound stored attention context but discard direct access to older tokens. Retrieval, external memory, or recurrent processing can handle longer streams without making a single forward pass have infinite context.

There are three separate limits. The implementation may enforce a maximum position or cache size; GPU memory limits how many keys and values fit; and the model's training determines whether it can use distant positions effectively. Removing an input-length check addresses only the first of those, and can lead to out-of-memory errors or degraded answers.

If an ordinary KV cache needs one GiB for 8,192 tokens, it needs roughly two GiB for 16,384 under the same layer, head, batch, and dtype assumptions. Dense prefill attention work grows faster: doubling input length approximately quadruples its pairwise component. Efficient kernels can reduce temporary memory without changing that fundamental pair count.

For an arbitrarily long document stream, process bounded segments, retain summaries or selected evidence, and retrieve older source material when needed. This is a system with external memory, not an infinite-context forward pass. Summaries can lose exact details, while sliding windows discard direct access to old tokens. Test long-range questions and source provenance so the chosen strategy makes its information loss visible rather than silently pretending the full history remains available.
