## Question

What are the core technologies in a RAG system?

## Brief answer

Core RAG technologies include document parsing, chunking, embeddings or lexical indexing, retrieval, reranking, context assembly, generation, and evaluation.

## Detailed answer

The important interfaces are often more consequential than any individual library: source IDs must survive parsing, embedding queries must match the index, filters must respect permissions, and citations must resolve to evidence. A useful baseline may combine BM25 with dense retrieval and a reranker. Measure each stage before adding query rewriting, graph traversal, or complex agent orchestration.

Each stage solves a distinct information problem. Parsing turns page or file structure into usable content. Chunking decides the units that can be retrieved. Embeddings and lexical indexes make candidates searchable. Reranking compares the specific question with candidate content. Context assembly selects and restores enough evidence for the generator to interpret it. Evaluation determines which of these stages is actually limiting the result.

For example, a table answer may fail because parsing detached units from values. No embedding change can reliably repair that missing relationship. A paraphrased question may fail because lexical retrieval never finds the right passage, in which case dense retrieval could help. If the right passage is present but the model ignores its exception, the issue lies in context presentation or generation.

Build stable interfaces with IDs, source versions, access metadata, and clear token budgets. Measure candidate recall before tuning the final prompt, and inspect the packed evidence before blaming the model. Query rewriting, graphs, and agents can help specific failures, but each adds latency and new opportunities for drift. A strong simple baseline makes those additions measurable rather than decorative.
