## Question

How to align query/document semantic spaces?

## Brief answer

Use query and document encoders trained to share a compatible retrieval space, with matching preprocessing and similarity conventions.

## Detailed answer

Asymmetric retrieval can use distinct encoders or different query/document prompts; compatibility does not require identical text transformations. Match embedding version, dimensions, normalization, and metric. Training on relevant query-positive-negative triples can improve alignment. Never mix document vectors from one embedding model with arbitrary query vectors from another merely because their dimensions match; migrate or rebuild the index coherently.

Query and document text often have different forms: a short question asks for information, while a passage states it. Training can align those forms by increasing similarity for answer-supporting pairs and decreasing it for verified negatives. Some systems use one encoder with different prefixes; others use separate query and document encoders trained together.

Compatibility is more than equal dimensionality. Two unrelated models can each produce 768-dimensional vectors whose coordinate systems have no shared meaning. Likewise, changing normalization or pooling can alter the metric even with the same model. Store the encoder revision, preprocessing, and similarity convention as part of the index version.

To migrate, build a new document index with the new representation, route matching query encodings to it, and compare retrieval before switching traffic. Avoid a partially migrated collection that mixes incompatible vectors. For domain improvement, train on realistic questions, supporting passages, and challenging false-positive passages, then evaluate held-out entities and wording. A shared space supports matching; it does not establish source correctness, access permission, or that the generator will use the retrieved passage faithfully.
