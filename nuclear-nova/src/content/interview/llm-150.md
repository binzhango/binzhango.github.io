## Question

How to enhance context using knowledge graphs (KGs)?

## Brief answer

Knowledge graphs augment context with explicit entities and relationships that can connect evidence across documents.

## Detailed answer

Resolve the question's entities, traverse relevant typed relationships, and retrieve the source passages supporting those edges. A product-dependency question can follow service-to-library-to-vulnerability links more directly than a single vector lookup. Retain dates, confidence, and provenance for every relationship. An extracted graph can contain errors or omissions, so treat its paths as evidence candidates and verify claims against sources.

Represent a fact as an entity-relation-entity edge with provenance, such as `Checkout — depends_on → Payments` supported by a deployment document. A question about the owner of Checkout's dependency requires following that edge, then `Payments — owned_by → Platform team`. A graph makes the join explicit instead of hoping one text chunk contains the complete answer.

Entity resolution is essential: “Payments,” “payment-service,” and an unrelated billing vendor should not be merged merely because their names look similar. Store stable entity IDs, typed relations, effective dates, and the source span supporting each edge. A stale ownership relation can otherwise produce a well-formed but incorrect path.

At query time, identify candidate entities, traverse only relevant relation types within a bounded depth, and retrieve the supporting text. Combine graph and lexical/vector candidates when a question also needs descriptive detail. Generated edges or summaries require validation because extraction can invent links. The graph is a structured retrieval aid; final claims should remain traceable to sources and should distinguish a verified path from an absence of evidence.
