## Question

What is a test dataset used for, and why is it essential in evaluating a model’s performance?

## Brief answer

A test set estimates generalization after model development, provided it is independent and representative of the intended deployment distribution.

## Detailed answer

Keep it out of training, hyperparameter tuning, prompt selection, and repeated model selection. Use group-based or chronological splits when examples share users, documents, or time dependencies. Report uncertainty and important slices alongside the aggregate score. A test set does not automatically give an unbiased estimate of real-world performance if its sampling or labels are flawed.

The test set answers a specific question: how well does this fully selected system perform on examples drawn in this way? It does not automatically answer how the system will perform everywhere. A fraud model deployed next month needs a time-based test with features available at decision time; a medical-image model intended for new hospitals needs separation by institution or patient rather than individual image.

Define the evaluation unit before splitting. Ten photographs of one object are not ten independent objects; placing copies across splits rewards recognition of that object rather than generalization. Fit scalers, vocabularies, and other learned preprocessing without using test data.

Report the denominator as well as the score. Ninety correct predictions out of 100 provide less precise evidence than 9,000 out of 10,000, and correlated examples reduce effective sample size. Include relevant error categories and uncertainty estimates. When deployment changes materially, construct a new representative test rather than assuming an old benchmark remains sufficient. An independent test supports a bounded empirical claim, not a guarantee about unseen conditions.
