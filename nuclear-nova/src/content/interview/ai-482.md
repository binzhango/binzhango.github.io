## Question

You have eight hours to build a coding agent from scratch. Describe what you build and, more importantly, what you cut.

## Brief answer

Build one single-agent loop that can inspect a repository, edit files, run tests, and produce a reviewable diff in an isolated checkout. Spend the eight hours on correctness, observability, and a few representative tasks. Cut multi-agent coordination, elaborate memory, autonomous deployment, and broad tool integrations.

## Detailed answer

**Suggested approach.** Allocate roughly one hour to scope and fixtures, two to tool execution and isolation, two to the model loop and structured state, one to verification/reporting, and two to end-to-end debugging. These are planning allocations, not a universal schedule. Define stop conditions for success, repeated errors, budget exhaustion, and user intervention.

Expose a small tool set: list/search/read, patch, and bounded shell commands. Record commands, outputs, and the evolving diff. Require tests or an explicit explanation when no runnable check exists; never let the final message invent successful verification. Demonstrate a bug fix, a small feature, and a failing task. The result is a narrow prototype with known limitations, not a secure production service for arbitrary repositories.

### Build a complete control loop

The minimal task state contains the request, base revision, accumulated observations, remaining budget, pending tool call, and final diff. Each loop iteration requests a structured action, validates it, executes it with a deadline, records the result, and returns the observation to the model. A malformed tool call produces a clear error; it must not fall through into a shell command assembled from unvalidated text.

Use three fixture tasks: a small deterministic bug, an edit needing changes in two files, and an intentionally impossible request. The last one tests whether the agent stops and explains the limitation rather than inventing success. Keep hidden acceptance checks outside the editable repository so the agent cannot pass by removing them.

The hardest prototype decision is refusing extra features. A vector database, planner hierarchy, and elaborate memory are unnecessary if the agent cannot reliably read a file, apply a patch, and report a failed test. End the demo with the patch and actual check results, including any unfinished work. Those artifacts establish that the entire loop functions within its stated narrow scope.
