## Question

Design guardrails for a consumer-facing assistant. Input filters, output filters, or both?

## Brief answer

Use both input and output controls where the threat model warrants them, plus execution-time authorization for tools. Each layer addresses different failures and introduces latency and false positives that must be measured.

## Detailed answer

Input checks can detect abuse or route sensitive requests; output checks can catch unsafe or unsupported responses before display. Streaming complicates output moderation because already-sent text cannot be withdrawn, so buffer high-risk segments or restrict streaming in those flows. Validate structured actions before execution. Include appeals and human escalation for ambiguous cases, and measure benign refusal rates alongside detection rates across languages and contexts.

Place controls at the boundaries they can actually enforce. An input layer can identify unsupported workflows, abusive traffic or requests that need a specialized response. The generation layer supplies task and policy context. An output layer checks material before display. A separate action layer validates tool arguments, resource ownership and authorization immediately before execution. No single classifier covers all four responsibilities.

For streaming, decide which risks require buffering. If text is sent before review, later detection cannot retract what the user already saw. Buffer complete sentences or high-risk outputs where needed, balancing safety and conversational latency. Tool calls should not execute speculatively while an approval or authorization check is pending.

Use severity-aware thresholds and a fallback that remains helpful, such as clarification or human escalation, instead of one generic refusal. Evaluate both false negatives and benign refusals with realistic context, languages and accessibility needs. A quoted harmful statement in a moderation task differs from an instruction to perform harm. Log decision reasons and versions, audit disagreements and test bypass attempts after each update. Guardrails should constrain concrete failure paths while preserving legitimate use; stacking uncalibrated filters can simply compound false positives.
