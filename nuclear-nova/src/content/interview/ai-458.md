## Question

Design the retrieval pipeline pulling from 100B web pages with sub-second latency and freshness guarantees.

## Brief answer

Build distributed serving indexes over a continuously processed crawl, rather than scanning 100 billion pages per query. Separate broad historical coverage from a smaller fresh-content index. Define freshness by source class and timestamp, because a universal guarantee for every web page is impossible without control over publishers and crawl access.

## Detailed answer

**Suggested approach.** The ingestion path schedules crawls, canonicalizes URLs, extracts text, detects duplicates, versions content, and emits incremental index updates. Shard lexical postings and vector partitions by capacity, replicate hot shards, and fan out through a broker with deadlines. Search the fresh and main indexes concurrently, deduplicate results by canonical document/version, then rerank a small merged set.

At an illustrative 1 KB of indexed metadata per page, 100 billion pages already require 100 TB before replicas, postings, vectors, and raw content. Size those components separately and define tail-query behavior when shards time out. Track crawl lag, source update lag, index visibility lag, recall, and partial-result rate. Prioritize trusted feeds for fast-changing news; retain deletions and tombstones so removed content does not reappear from a slow replica.

### Separate coverage, freshness, and serving

The crawl frontier prioritizes URLs using observed update rate, importance, and fetch cost. Successfully fetched content passes parsing and deduplication before an index revision becomes visible. Record timestamps at each boundary; otherwise a “freshness” dashboard cannot distinguish a publisher update that was never fetched from a fetched update waiting in the indexing queue.

At query time, a broker routes to relevant partitions instead of broadcasting indiscriminately to every machine. Each shard returns a bounded ranked list plus its revision and completion status. The broker merges candidates, removes duplicate versions, and applies the remaining ranking stages within a shared deadline. Replication supports availability, but a stale replica cannot satisfy the same freshness promise as the newest one.

For illustration, a 768-dimensional two-byte vector for every one of 100 billion pages would require about 153.6 TB of raw vector values before search overhead and replication. Multi-vector or passage indexing multiplies that footprint. This motivates selective semantic indexing, tiered storage, compression, and explicit quality measurements. Define a measurable promise such as a target lag for enrolled trusted feeds; do not guarantee discovery of arbitrary web changes you cannot observe.
