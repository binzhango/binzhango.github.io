## Question

Write code to measure a tokenizer's fertility across languages, and explain what you would do with the result.

## Brief answer

Measure fertility as subword tokens per externally segmented word, using comparable corpora and a consistent definition of “word” for each language. Exclude special tokens and report distributions, not just one average. High fertility signals context and compute inefficiency, but does not by itself establish poor understanding or justify replacing a pretrained tokenizer.

## Detailed answer

This runnable function accepts a tokenizer-compatible encoding callable and language-specific word segmentation. The built-in test uses a toy encoder to verify aggregation without downloading a model.

```python
from collections import defaultdict

def fertility(rows, encode, segment):
    totals = defaultdict(lambda: [0, 0, 0])
    for language, text in rows:
        words = segment(language, text)
        if not words:
            continue
        ids = encode(text)
        counts = totals[language]
        counts[0] += len(ids)
        counts[1] += len(words)
        counts[2] += 1
    return {lang: {"tokens_per_word": t / w, "documents": n}
            for lang, (t, w, n) in totals.items()}

result = fertility([("en", "ab cd"), ("en", ""), ("hi", "एक दो")],
                   lambda text: list(text.replace(" ", "")),
                   lambda lang, text: text.split())
assert result["en"] == {"tokens_per_word": 2.0, "documents": 1}
assert result["hi"]["tokens_per_word"] == 2.0
assert fertility([], list, lambda lang, text: text.split()) == {}
```

For a real tokenizer use `lambda s: tokenizer.encode(s, add_special_tokens=False)`. Pair fertility with tokens per character/byte, truncation rates, latency, and native-language task quality. Use reliable segmentation for languages without whitespace. Compare matched domains; news versus conversational text confounds language differences. Adding vocabulary requires learning new embeddings and checking regressions in existing tokens.

### Interpret the aggregation correctly

The function reports total tokens divided by total segmented words. This weights longer documents more heavily than an average of document-level ratios. For documents with 10 tokens/5 words and 100 tokens/100 words, the corpus ratio is 110/105 ≈ 1.048, whereas the unweighted mean ratio is 1.5. Both can be useful, but they answer different questions; report the chosen denominator.

Encoding and segmentation dominate runtime, approximately linear in processed text for typical implementations, while aggregation stores only three counters per language. The toy encoder deliberately counts non-space characters and is not evidence about any real tokenizer. With production tokenizers, exclude control tokens from the comparison and keep normalization consistent. Inspect the highest-fertility examples manually: they may reveal malformed text, script fragmentation, or domain identifiers rather than a language-wide issue. Add percentile and document-length breakdowns before deciding to alter a model's vocabulary.
