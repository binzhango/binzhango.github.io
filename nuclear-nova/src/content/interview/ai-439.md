## Question

Given annotation sessions as (start, end) timestamps, return the peak number of concurrent annotators and the intervals at peak load.

## Brief answer

Sweep timestamp events using half-open sessions `[start, end)`. Combine all deltas at the same timestamp before measuring the following interval, so an annotator leaving exactly when another arrives does not inflate concurrency. Return every maximal contiguous interval at the global peak; ignore zero-length sessions and reject reversed ones.

## Detailed answer

This Python implementation takes O(n log n) time for sorting and O(n) auxiliary space. Aggregating equal timestamps also merges adjacent peak spans correctly.

```python
from collections import defaultdict

def peak_sessions(sessions):
    events = defaultdict(int)
    for start, end in sessions:
        if end < start:
            raise ValueError("reversed session")
        if start < end:
            events[start] += 1
            events[end] -= 1
    times = sorted(events)
    active = peak = 0
    spans = []
    for i, time in enumerate(times[:-1]):
        active += events[time]
        end = times[i + 1]
        if active > peak:
            peak, spans = active, [(time, end)]
        elif active == peak and active > 0:
            if spans and spans[-1][1] == time:
                spans[-1] = (spans[-1][0], end)
            else:
                spans.append((time, end))
    return peak, spans

assert peak_sessions([(0, 2), (2, 4)]) == (1, [(0, 4)])
assert peak_sessions([(0, 4), (1, 2), (3, 4)]) == (2, [(1, 2), (3, 4)])
assert peak_sessions([]) == (0, [])
```

The timestamps must share a comparable clock and unit. This computes concurrency of sessions, not distinct people; deduplicate or union each person's overlapping sessions first if the requirement counts people.

### Walk through the sweep

For sessions `[1,4)`, `[2,5)`, and `[4,6)`, the event deltas are `1:+1`, `2:+1`, `4:0`, `5:-1`, `6:-1`. Applying each timestamp's combined delta gives one active session on `[1,2)`, two on `[2,4)`, still two on `[4,5)`, and one on `[5,6)`. The peak is therefore two on the single maximal interval `[2,5)`. The zero net change at time four is why processing individual arrivals before departures would be misleading.

At every loop iteration, `active` is the number of sessions covering the entire interval until the next event. When a larger peak appears, previous spans are discarded because they no longer represent the global maximum. Equal positive peaks are appended or merged if adjacent. Empty input and exclusively zero-length sessions correctly have peak zero and no positive-duration spans.

If timestamps are floating-point measurements, do not merge nearby values with an arbitrary tolerance. Convert to the agreed measurement resolution first. For a reporting window, clip sessions to that window before creating events so sessions that began earlier still contribute correctly.
