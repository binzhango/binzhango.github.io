## Question

Estimate the cost and turnaround of running your diligence workflow over a 5,000-document data room, and tell me which lever you'd pull first.

## Brief answer

Estimate from document token volume, checklist structure, model rates, concurrency, extraction time, and human review, not document count alone. Measure a representative sample before quoting turnaround. The first lever is usually avoiding repeated full-document processing while preserving recall of important clauses.

## Detailed answer

For an illustrative 5,000 documents averaging 20,000 input tokens, one full pass is 100 million input tokens. At an assumed \$2/million, that is \$200 input cost; eighteen separate full passes would be \$3,600, excluding outputs, retries, OCR, and review. At 100 concurrent jobs averaging 30 seconds each, 5,000 jobs have an idealized 25-minute processing floor, before rate limits and tail tasks.

Batch checklist extraction per document, reuse parsing and evidence, and route difficult items to stronger models or reviewers. Benchmark quality before reducing context or model size. Track p95 document time and total completion time, including quarantined scans. Often professional review dominates cost, so optimize false positives and source navigation as well as inference. Label all assumptions and replace them with sampled measurements before making a delivery commitment.

### Include rate limits and human capacity

The idealized 25-minute floor assumes 100 jobs can run continuously for thirty seconds each. If the provider permits only one million input tokens per minute, the illustrative 100-million-token pass needs at least 100 minutes on that quota alone. Actual completion time is bounded by the slowest of parsing throughput, provider quotas, concurrent generation, and reviewer capacity, plus tail failures.

Estimate output volume separately. If each of 90,000 checklist cells uses an average of forty output tokens, the result is 3.6 million generated tokens before retries. That can be meaningful even when input caching is effective. Use the sampled distributions of document size and OCR difficulty; a few huge or damaged documents can determine the final delivery time.

First eliminate repeated parsing and repeated full-context reading when one coherent pass or reused evidence can answer multiple checklist items. Then measure whether batching raises omission rates or makes retries too coarse. A cheaper run that sends many more cells to professional review can cost more overall. Quote a range tied to explicit assumptions and distinguish initial machine output from a fully reviewed final grid.
