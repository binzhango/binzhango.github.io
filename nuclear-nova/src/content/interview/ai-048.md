## Question

How many tools is too many? How do you design tool schemas an LLM can actually use correctly?

## Brief answer

There is no universal maximum tool count. The practical limit depends on overlap, schema clarity, context cost and measured selection errors; expose the smallest task-relevant set that supports the user’s goal.

## Detailed answer

Give tools distinct verbs, narrow responsibilities and typed arguments with units, enums and required identifiers. Separate read operations from consequential writes. Return bounded structured results with pagination and explicit errors. If the model confuses similar tools, consolidate or introduce hierarchical discovery rather than adding longer descriptions everywhere. Evaluate wrong-tool rate, invalid arguments and task completion on realistic prompts as the catalog grows.

Tool ambiguity is often more harmful than raw catalog size. Two tools named `search_data` and `find_information` with overlapping descriptions force the model to guess. A clearer surface might distinguish `search_documents(query, project_id)` from `get_document(document_id, revision)`: one discovers candidates and the other fetches an exact authorized record.

Schemas should encode business meaning. Use `amount_minor_units` plus currency rather than an unexplained floating-point amount; use enumerated states and explicit resource IDs rather than free-form instructions. Separate discovery from mutation so a read cannot accidentally publish a change. Results should provide stable IDs, pagination tokens and typed errors rather than a giant unstructured dump.

For a large catalog, select a task-relevant subset or expose searchable tool discovery, then validate the chosen tool against the user's permissions. Hierarchical discovery introduces its own failure mode: the model may never find the needed capability. Build evaluation cases with confusing names, missing arguments, empty results and unauthorized requests. Track selection accuracy, argument validity, recovery and end-to-end completion as tools are added. Add a tool only when it contributes a distinct useful capability; longer descriptions are not a substitute for a coherent interface.
