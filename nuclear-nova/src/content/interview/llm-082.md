## Question

What can cause a sudden loss drop in the second epoch of SFT?

## Brief answer

There is no universal second-epoch loss drop. Investigate repeated examples, learning-rate changes, batch composition, and logging or masking bugs before attributing it to learning.

## Detailed answer

Plot loss against optimizer steps and supervised token counts, not only epoch summaries. Check scheduler boundaries, sampler resets, sequence lengths, packing, and whether an average was reset. A model may predict previously seen examples better in epoch two, but a dramatic discontinuity can also reflect a changed reduction or label mask. Compare held-out loss and task quality to distinguish useful learning from memorization.

Start by checking whether the plotted points are comparable. A running average may include difficult early batches in epoch one but reset at epoch two. A length-sorted sampler may start each epoch with shorter examples. If loss is averaged per sequence in one place and per supervised token in another, a changing length distribution can cause an apparent discontinuity without a corresponding improvement in predictions.

Then inspect the learning process. Repeated examples become easier, especially in a small dataset, and the learning-rate schedule may change at an epoch boundary. Compare losses on the same fixed batch before and after the boundary. Check that labels still exclude padding and that prompt masking, packed boundaries, and answer truncation have not changed.

If the drop is real, measure held-out task behavior. A model that now reproduces training answers verbatim but fails paraphrases is memorizing rather than improving useful generalization. Save the checkpoint and enough data-order state to reproduce the transition. “Second epoch” describes when the symptom appears, not a causal explanation or a universal stage in SFT learning.
