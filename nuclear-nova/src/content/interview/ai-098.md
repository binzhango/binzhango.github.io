## Question

Design an enterprise RAG assistant over 10M documents with per-user permissions.

## Brief answer

Build a permission-aware ingestion and search pipeline with versioned documents, hybrid retrieval, bounded reranking and cited generation. At ten million documents, correctness of access and updates matters as much as vector-search speed.

## Detailed answer

Connectors write durable change events into partitioned ingestion workers; store canonical documents and derived chunks separately. Query-time identity resolves current ACLs before context assembly. Partition indexes to bound fan-out without isolating relevant evidence, cache only within compatible authorization scopes, and recheck deletions/revocations. Measure retrieval recall, source-to-index lag, p99 latency and leakage tests. Roll out tenant by tenant with an exact-search evaluation baseline and recoverable index snapshots.

Estimate chunks, not only documents. If ten million documents average ten chunks, the vector store holds roughly 100 million embeddings. At 768 FP16 dimensions, raw vectors alone occupy about 153.6 GB before graph links, metadata, replicas and source text. This illustrative calculation helps decide partitioning and compression, but the actual distribution of document lengths and tenant sizes determines capacity.

The read path authenticates the user, resolves current groups, routes to permitted partitions, runs lexical and vector retrieval, reranks authorized candidates and assembles a token-bounded evidence bundle. Generation returns supported claims with document-version/span IDs. Recheck sensitive source access before display, and isolate answer caches by authorization scope and content revision.

The write path uses durable connector events, idempotent extraction, versioned chunks and atomic publication. Prioritize deletions and revocations, and run reconciliation scans to catch missed events. Large tenants may need dedicated partitions; small tenants can share infrastructure with strict logical isolation. Test exact identifier searches, long documents, cross-language queries and highly restrictive ACLs. Measure answer quality, denied-content leakage, freshness lag and p99 latency together. A fast ANN index does not compensate for stale permissions or an answer built from the wrong document version.
