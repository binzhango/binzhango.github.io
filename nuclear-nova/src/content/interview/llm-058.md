## Question

Provide a code implementation of Cross-Attention.

## Brief answer

Use projected queries from the target and keys/values from the source; PyTorch's `MultiheadAttention` implements the projections and head combination.

## Detailed answer

This CPU example uses batch-first tensors and explicitly masks padded source tokens. In this API, `True` in `key_padding_mask` means ignore that key; other attention APIs can use different boolean conventions.

```python
import torch
from torch import nn

torch.manual_seed(0)
attention = nn.MultiheadAttention(32, 4, dropout=0.0, batch_first=True)
attention.eval()
query = torch.randn(2, 3, 32)
source = torch.randn(2, 5, 32)
padding = torch.tensor([
    [False, False, False, True, True],
    [False, False, False, False, True],
])
with torch.no_grad():
    output, weights = attention(
        query, source, source,
        key_padding_mask=padding,
        need_weights=True,
        average_attn_weights=False,
    )
assert output.shape == (2, 3, 32)
assert weights.shape == (2, 4, 3, 5)
assert torch.allclose(weights.sum(-1), torch.ones(2, 4, 3))
assert torch.all(weights.masked_select(padding[:, None, None, :]) == 0)
print(tuple(output.shape))  # (2, 3, 32)
```

Every example needs at least one unmasked source token. Production code often sets `need_weights=False` to avoid materializing attention weights.

The constructor splits the 32-dimensional projected representation into four heads of width eight. `query` supplies three target positions for each of two examples; `source` supplies five possible source positions. Passing `source` as both the key and value input still allows the module to learn different K and V projection matrices. The output length follows the query length, hence `(2, 3, 32)`.

The returned weights retain the head axis because `average_attn_weights=False`. Their last axis sums to one in this zero-dropout evaluation example, and padded source columns have zero weight. A useful additional test changes only the padded source vectors and checks that the output is unchanged. Fully masked rows need an explicit policy because no probability distribution over available keys exists; do not let NaNs silently enter the next layer.

Score/value computation scales as $O(BHn_qn_kd_h)$, and requesting weights stores $O(BHn_qn_k)$ entries. Projection costs are additional. Keep the batch-first convention consistent, pass tensors on the same device, and distinguish padding masks from any causal or application-specific attention mask.
