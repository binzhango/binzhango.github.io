## Question

What is Graph RAG and how does it work? Show a code example and use case.

## Brief answer

Graph RAG retrieves graph-connected evidence for generation; Microsoft's GraphRAG additionally builds entity relationships and community summaries for local and global search.

## Detailed answer

A typical pipeline extracts entities and relationships with source links, resolves duplicates, builds graph structure, retrieves relevant subgraphs or summaries, and generates an answer grounded in supporting text. Microsoft's particular approach is one implementation of the broader idea.

This runnable Python example uses fictional, already-verified edges to demonstrate two-hop evidence retrieval. It does not perform extraction or call an LLM:

```python
edges = [
    ("Checkout", "depends_on", "Payments", "doc-1"),
    ("Payments", "owned_by", "Platform team", "doc-2"),
    ("Search", "owned_by", "Discovery team", "doc-3"),
]
sources = {
    "doc-1": "Checkout depends on Payments.",
    "doc-2": "The Platform team owns Payments.",
    "doc-3": "The Discovery team owns Search.",
}

def dependency_owners(service):
    results = []
    for src, relation, dependency, source_a in edges:
        if src != service or relation != "depends_on":
            continue
        for node, relation_b, owner, source_b in edges:
            if node == dependency and relation_b == "owned_by":
                results.append({
                    "dependency": dependency,
                    "owner": owner,
                    "evidence": [(sid, sources[sid])
                                 for sid in (source_a, source_b)],
                })
    return results

result = dependency_owners("Checkout")
assert result[0]["owner"] == "Platform team"
assert dependency_owners("Unknown") == []
print(result[0]["owner"])  # Platform team
```

An application can pass this evidence to a generator to answer “Who owns Checkout's dependency?” Production traversal must enforce authorization, entity disambiguation, edge freshness, and bounded expansion. Absence of a path means the graph lacks evidence, not that no relationship exists.

The example separates graph retrieval from generation deliberately. Each edge already has a verified source ID. The first loop selects Checkout's dependencies, and the second joins each dependency to an ownership edge. Returning both source records makes the two-hop conclusion inspectable. The unrelated Search edge is ignored, and an unknown service returns no evidence rather than an invented owner.

With $E$ edges, the nested scan has worst-case $O(E^2)$ work. An adjacency index keyed by source entity and relation can make the relevant joins much cheaper. A general traversal also needs a visited set, hop limit, relation filters, and result budget to avoid cycles or explosive expansion. Duplicate paths should not be counted as independent support when they repeat the same source.

In a real system, graph extraction and entity resolution precede this step and can introduce errors. Version edges, enforce source permissions during traversal, and retrieve the supporting passages before asking a generator to explain the result. Community summaries can help broad corpus questions, but are derived content and need provenance. The code demonstrates the evidence join; it does not implement automatic graph construction, a database, or reliable answer generation by itself.
