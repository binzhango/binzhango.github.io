## Question

What is the difference between L1 and L2 regularization? When would you use elastic net in an LLM fine-tune?

## Brief answer

L1 penalizes absolute weight magnitude and can encourage sparsity; L2 penalizes squared magnitude and encourages shrinkage. Elastic net combines them when both effects serve a measured objective.

## Detailed answer

With trainable parameters or updates $w$:

$$
L=L_{\mathrm{task}}+\lambda_1\lVert w\rVert_1+\lambda_2\lVert w\rVert_2^2.
$$

Elastic net can be useful for a sparse task head or adapter, but it is not a standard requirement for LLM fine-tuning. State whether the penalty targets adapter weights, full weights, or the update from the pretrained checkpoint. L1 can yield exact zeros with an appropriate optimization method; ordinary gradient steps do not guarantee them.

Neither penalty inherently makes the data-fitting loss robust to target outliers. L2's unique-solution property for strictly convex ridge regression does not extend to nonconvex neural networks. Sparse weights do not automatically accelerate dense GPU kernels. Also, AdamW's decoupled weight decay differs from adding an L2 penalty to Adam's loss.

For a single coefficient, the L2 penalty contributes gradient $2\lambda_2 w$, so its pull toward zero is stronger for larger weights and vanishes near zero. L1 contributes a magnitude-independent pull away from zero on either side, and has a kink at zero. With proximal optimization, a small coefficient can be set exactly to zero through soft thresholding. This explains the common sparsity difference without claiming that every neural optimizer produces sparse weights.

Suppose a frozen language model feeds a linear head with many correlated features. L1 may select a small set of features, but the selected set can change when similar features substitute for one another. Adding L2 can stabilize that selection. For a LoRA update, penalizing its factors is not identical to penalizing the product $BA$; rescaling one factor and inversely rescaling the other preserves the update while changing some penalties.

Choose penalties using held-out task quality and the intended goal, such as smaller updates or interpretable selection. If the goal is faster inference, verify that the resulting sparsity has a structure supported by the serving kernel.
