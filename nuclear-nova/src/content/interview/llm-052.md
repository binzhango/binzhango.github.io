## Question

What is a parallel Transformer block?

## Brief answer

A parallel Transformer block computes attention and the FFN from the same incoming residual stream, then adds both results.

## Detailed answer

One common schematic is:

$$
y=x+\operatorname{Attention}(\operatorname{Norm}_a(x))+\operatorname{FFN}(\operatorname{Norm}_f(x)).
$$

A sequential block instead feeds the attention-updated state into the FFN. Some parallel designs share a normalization; exact details vary. The parallel structure can improve execution scheduling but changes within-block information flow. It is not the same as tensor or pipeline parallelism across GPUs.

In a sequential block, attention first produces $u=x+A(\mathrm{Norm}(x))$, then the FFN operates on $u$ to produce the next state. The FFN can react immediately to information collected by that attention layer. In a parallel block, both branches read the original $x$; the FFN sees the new attention information only in a later block after the branch outputs have been combined.

This removes a dependency between the two branches and can permit scheduling or projection optimizations. It does not guarantee simultaneous execution on the hardware: both branches still compete for compute, memory bandwidth, and kernel resources. The actual benefit depends on the implementation and matrix shapes.

The residual sum requires both branch outputs to match the model width. Normalization may be shared or separate, and residual scaling can affect initialization and training stability. State those choices when describing a concrete model. Do not convert a sequential pretrained checkpoint by rearranging operations and assume equivalence, since the FFN input changes. Also distinguish this within-layer topology from distributing layers or tensor shards across multiple accelerators.
