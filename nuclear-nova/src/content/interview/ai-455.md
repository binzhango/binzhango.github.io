## Question

Discuss reranker architecture choices: cross-encoder, ColBERT, LLM-based.

## Brief answer

A cross-encoder jointly reads query and passage for accurate pairwise relevance at per-candidate compute cost. ColBERT precomputes token embeddings and uses late interaction, trading larger indexes for efficient fine-grained matching. LLM rerankers can apply rich instructions or compare lists, but cost, latency, positional bias, and prompt injection require control.

## Detailed answer

Use a cross-encoder for a bounded candidate set when labeled relevance data and predictable latency matter. ColBERT scores contextualized query/document token interactions rather than compressing each document into one vector; this preserves matching detail but increases storage and serving complexity.

An LLM can rank candidates using task-specific criteria such as recency or evidential usefulness, provided the criteria are explicit and document instructions are treated as untrusted content. Pointwise scoring parallelizes, pairwise comparisons cost more calls, and listwise ranking is sensitive to ordering and context length. Benchmark all choices on held-out queries with recall at candidate generation, nDCG or answer-support recall after reranking, p95 latency, and dollars per query. A stronger reranker cannot recover evidence absent from the candidate set.

### How the scoring paths differ

A cross-encoder constructs one sequence containing the query and one passage. Attention can mix their tokens at every layer, producing a relevance score specific to that pair. Document work cannot be fully precomputed because changing the query changes the joint representation. This makes it attractive for reranking 50 candidates but expensive for scoring millions directly.

In a ColBERT-style scorer, each query token compares with document token vectors; the best match for each query token contributes to an aggregate score. A query containing a rare product code can therefore preserve a strong local match that a single pooled vector might dilute. The price is storing and searching many vectors per document, often with compression and a separate candidate-generation strategy.

An LLM reranker can reason about instructions such as “prefer evidence about the enterprise tier,” but must not obey commands embedded in a candidate passage. Test order permutations and long distractors because a listwise model can change its ranking when candidates move. For an initial system, compare a bounded cross-encoder baseline with late interaction at the same quality and latency targets; add LLM judgment only where its extra reasoning measurably changes useful evidence selection.
