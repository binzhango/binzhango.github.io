## Question

Design permission-aware retrieval: users must never see content they can't access in the source system.

## Brief answer

Permission-aware retrieval must enforce the requesting user’s current access before evidence enters the model context, and recheck authorization before returning sensitive material. A prompt telling the model to respect permissions is insufficient.

## Detailed answer

Attach stable document IDs and access metadata during ingestion, resolve user/group membership through the source authority, and filter candidates in every retrieval path. Handle revocations with bounded propagation and fail closed when authorization is unavailable. Cache keys must include the relevant authorization scope; citations must not leak titles or snippets from denied documents. Test group changes, shared links, stale caches and deleted records. Audit decisions using identifiers without logging unnecessary sensitive content.

Use two distinct trust boundaries: candidate discovery and evidence release. The search layer should prefilter by tenant and coarse access attributes when supported, while a trusted authorization service checks the exact document IDs before text is assembled for the model. Postfiltering alone can waste the candidate budget on forbidden documents, so it may require deeper retrieval; it must never allow their snippets into the prompt first.

A user removed from a project illustrates the hard case. Their old group membership may still exist in a session cache, a vector index ACL and an answer cache. Define which source is authoritative, how quickly revocations propagate, and which cache entries are invalidated. For sensitive actions, recheck current authorization when returning the answer or opening a cited document, closing the gap between retrieval and display.

Separate document visibility from field-level restrictions: access to a CRM account may not imply access to its financial fields. Carry field or span provenance if the source model requires it. Test unauthorized titles, autocomplete, result counts, citations and cached answers, not just the final paragraph. A model instruction cannot enforce this boundary because denied information has already leaked once it reaches an untrusted generation or logging path.
