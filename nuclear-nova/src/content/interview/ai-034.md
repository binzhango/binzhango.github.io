## Question

What is a reranker, when should you use one, and what does a cross-encoder cost you?

## Brief answer

A reranker reorders an initial candidate set using a more expensive relevance model. A cross-encoder jointly reads the query and each candidate, usually improving fine-grained relevance at the cost of extra model work per pair.

## Detailed answer

Use a cheap retriever to reduce millions of passages to a manageable candidate set, then score those pairs in batches. The reranker cannot recover a missing passage, so first establish candidate recall. Long candidates increase token cost and may truncate the relevant evidence. Measure end-to-end answer gains at a fixed latency budget, and cache only when query, document revision and model version match. Prefer skipping reranking when retrieval is already sufficiently precise.

A bi-encoder independently embeds the query and document, allowing document vectors to be precomputed. A cross-encoder reads their token sequences together and lets query tokens interact directly with document tokens. That enables distinctions such as whether a document says a feature is supported or explicitly unsupported, which a coarse vector representation may blur.

An illustrative pipeline retrieves 200 candidates, deduplicates them, reranks the best 50 and supplies five passages to generation. These are tunable budgets. A cross-encoder cannot select a missing document, so compare recall before reranking with precision afterward. If an answer-bearing passage was never retrieved, making the reranker larger will not solve the error.

The cost scales with the number and length of query-document pairs, the model architecture and batching efficiency. Long documents may be truncated before the relevant sentence; reranking focused passages can be both cheaper and better. Measure p99 latency at concurrency, not only the time for one isolated batch. Evaluate whether improved ranking actually changes answer quality or simply rearranges equally adequate evidence. Use a confidence or workload gate when easy exact-match queries already have clear results, and version cache entries by query, document revision and reranker.
