## Question

Why did transformers displace RNNs for language modelling, and what exactly does the KV cache buy you at inference time?

## Brief answer

Transformers allow parallel processing of training tokens and offer short paths for interactions between distant positions, making large-scale training effective. RNNs process sequence state sequentially, which limits training parallelism. At autoregressive inference, a KV cache stores prior keys and values so each new token does not recompute all earlier hidden states; generation itself remains sequential.

## Detailed answer

During causal training, every position predicts its next token simultaneously under a mask. During decode, the new query attends to cached keys and values from preceding tokens, then appends its own KV state. This saves repeated projection and layer computation for old tokens but adds memory proportional to sequence length, batch size, layers, and KV dimensions.

Long contexts still increase attention reads and can become bandwidth-bound. Cache reuse is exact only for an unchanged prefix and compatible model configuration. RNNs retain advantages for some streaming and bounded-state tasks, while transformer variants alter the attention trade-off. The shift was driven by scalable performance, not a theorem that recurrence is always inferior.

### Parallel training does not imply parallel generation

An RNN computes a hidden state from the preceding hidden state, imposing a sequential dependency across training positions. A transformer processes all known training tokens in parallel with a causal mask, allowing large matrix operations and shorter paths between distant positions. At inference, the next token is still unknown until sampled, so ordinary autoregressive generation remains sequential.

Without a cache, generating token 1,001 would recompute representations for the 1,000-token prefix. With KV caching, earlier keys and values are retained layer by layer; only the new token's projections and its attention against the history are computed. The cache does not store a final answer or remove attention to history. For a fixed architecture its memory is proportional to batch × context × layers × KV width × element size. This trades repeated compute for persistent memory and bandwidth. Long context and concurrent requests can therefore become cache-bound even when model weights fit comfortably.
