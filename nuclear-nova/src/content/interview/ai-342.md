## Question

A customer's Bedrock-hosted workload costs too much. Cut inference cost dramatically without unacceptable quality loss.

## Brief answer

Measure spend by workload, model, token type, retries, and cacheability before changing the architecture. Reduce unnecessary calls and output, route simpler tasks to validated smaller models, and compare batching, caching, and capacity options against the actual latency target. Optimize cost per successful task so savings do not come from silently lowering quality.

## Detailed answer

Collect representative traces with sensitive content removed or protected. Separate expensive long prompts from long outputs, repeated requests, tool loops, and low-utilization provisioned capacity. Improve retrieval selectivity, summarize stable history carefully, and cache only where authorization and freshness permit.

Run a paired evaluation of cheaper models or quantized deployments on real tasks and severe-error slices. Use asynchronous batch execution for work that does not require interactive latency, and cap retries with clear failure handling. Verify current Bedrock model support and pricing before financial commitments; rates and feature availability vary by region and model. Stage the rollout with quality, latency, and spend alerts, retaining a fallback for cases the cheaper path cannot handle.

### Attribute cost before changing the model

Break a representative request into input tokens, output tokens, retrieval calls, retries, and provisioned idle time. A request with an unnecessarily repeated 50-page prompt needs prompt reduction or caching; a request trapped in a tool loop needs orchestration repair. Quantizing a model does not solve either root cause if the service still performs redundant work.

Create a paired task set and compare the existing path with a cheaper candidate using the same evidence and acceptance rubric. Route routine classification or short summaries to the cheaper path, retaining a stronger model for cases that demonstrably need it. Cache by document version and authorization scope, and invalidate on changes. Use batch processing for overnight workloads rather than paying for interactive readiness. Track total monthly spend and cost per correctly resolved request during a canary; lower token prices can be canceled by longer answers, extra retries, or increased human correction.
