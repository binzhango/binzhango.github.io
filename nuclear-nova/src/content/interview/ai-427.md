## Question

`transformers` famously repeats code: each model gets its own self-contained modeling file. Defend that decision, then critique it.

## Brief answer

Self-contained model files make an architecture easier to read, debug, modify, and copy without tracing a deep inheritance tree. The cost is repeated logic and the risk that fixes or optimizations diverge across models. Modern Transformers also supports modular source files that generate standalone modeling files, so the premise describes a user-facing design goal more accurately than a universal prohibition on reuse.

## Detailed answer

The benefit is local comprehensibility: a researcher can inspect a model's attention, normalization, and forward path together, including deliberate differences from related architectures. Heavy abstraction can hide subtle semantics or make one shared change break many checkpoints.

The critique is maintenance burden, duplicated tests, and delayed security or correctness fixes. Generated code introduces its own source-of-truth and review concerns. As of the documentation reviewed on 2026-09-23, modular Transformers allows inheritance in authoring and generates flattened standalone files; contributors should edit the modular source rather than generated output. Good boundaries retain model-specific clarity while reusing stable infrastructure and verifying generated parity.

### Local clarity versus shared maintenance

Model families often differ in apparently small but essential details: attention scaling, rotary positions, normalization placement, cache shape, or residual order. A self-contained modeling file lets contributors inspect the exact forward computation without traversing a deep inheritance tree. That helps research modifications and checkpoint-specific debugging.

The cost appears when a common bug fix must reach many copies. Pure duplication can drift; overgeneralized shared abstractions can hide semantics and break unrelated models. Modular authoring with generated flattened files is one compromise: contributors express reusable pieces in the source, while readers get a standalone implementation. The project must clearly identify which file is authoritative and verify generated output in CI. Reuse stable infrastructure such as loading and generation interfaces while preserving model-specific numerical behavior. Test checkpoint parity, caching, attention masks, and generation across affected architectures after a shared change. The right boundary is determined by semantic stability, not by minimizing line count alone.
