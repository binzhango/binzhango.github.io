## Question

How would you chunk and embed heterogeneous enterprise content: Slack threads, Jira tickets, Google Docs, PDFs?

## Brief answer

Chunk according to each source's conversational or document structure, while preserving stable identity, permissions, timestamps, and provenance. A Slack reply without its thread context differs from a Jira issue's state history or a PDF table. Use a common retrieval envelope but source-specific extraction and context rules.

## Detailed answer

**Suggested approach.** For Slack, group coherent thread segments with channel and parent message, excluding inaccessible replies. For Jira, separate current fields from chronological comments while linking status and issue identity. For Google Docs, use heading-aware sections and version metadata. For PDFs, preserve reading order, page coordinates, tables, and OCR confidence.

Embed concise coherent units and retain parent links for expansion after retrieval. Add lexical indexes for IDs, names, and exact phrases. Incremental updates use stable chunk IDs plus content hashes, and deletion/permission changes invalidate derived artifacts. Evaluate evidence recall across source types, especially short references such as “approved” whose meaning lives elsewhere. Avoid embedding boilerplate repeatedly or merging unrelated conversations simply to hit a token target.

### Use a shared envelope, not one universal splitter

Every chunk can share fields such as source ID, revision, parent ID, ACL reference, timestamps, and source coordinates. Its content boundary remains source-specific. A Slack message saying “approved” should expand to the relevant proposal and intervening clarification; a Jira ticket should distinguish its current status from an older comment predicting completion. A PDF table row needs its column headers and units to remain interpretable.

For updates, compute a content hash for each structural unit and replace only changed embeddings. Maintain tombstones for removed units so an old vector does not survive after the source deletes a paragraph. Permission changes often do not require re-embedding, but do require updating the authorization metadata and invalidating cached results.

Build source-specific evaluation cases where isolated text is misleading. Ask whether the selected bundle contains enough context to answer, not merely whether a similar phrase was retrieved. A common envelope simplifies indexing and auditing; specialized extraction preserves meaning. Parent expansion supplies additional context after retrieval without forcing every searchable vector to represent an oversized mixture of unrelated material.
